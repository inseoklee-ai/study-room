하네스를 강하게 만드는 두 번째·세 번째 방법입니다. MCP가 '새 능력'을 준다면, 스킬은 '반복 작업의 플레이북', 규칙 파일은 '프로젝트 상시 안내문'입니다.

문제 — 매번 같은 설명을 다시 하고 있지 않나요?

AI에게 "우리 브랜드 톤으로 정리해 줘", "이 형식으로 보고서 만들어 줘"를 매번 처음부터 설명하고 있다면 — 지겹고, 그때그때 결과도 달라집니다.

폴더 하나 · SKILL.md 하나

③ 스킬과 규칙
기술적으로는 아주 단순합니다.

기술적으로는 그냥 폴더 하나입니다

자주 하는 작업을 한 번 적어 두고 계속 꺼내 쓰는 설명서입니다. 폴더 안 SKILL.md에 "무엇을, 언제 쓰는지"를 적어 두면, AI가 관련된 일을 만났을 때 알아서 꺼내 씁니다.

💰 영리한 점 — 켜 두어도 거의 공짜입니다. AI는 평소엔 스킬의 이름과 한 줄 설명만 알고 있다가(약 30~50 토큰), 정말 필요할 때만 본문을 읽습니다
  • 그래서 수십 개를 켜 둬도 느려지지 않습니다
  • '토큰'은 AI가 읽고 쓰는 글자 단위이자 곧 요금 단위입니다 (자세한 건 소단원 ④에서)
  • 예 — "내가 쓴 글을 우리 서비스 말투로 다듬는 법"을 스킬로 만들어 두면, 다음부터는 "말투 스킬 써서 다듬어 줘" 한마디면 됩니다
출처: Claude Platform Docs, "Agent Skills". '거의 공짜'의 원리가 다음 슬라이드의 점진 공개입니다.

SKILL.md는 실제로 이렇게 생겼습니다

---
name: tone-polish
description: 사용자용 안내 문구를 우리 서비스 말투(정중하고 짧게)로 다듬을 때 사용
---

# 우리 서비스 말투로 다듬기

1. 한 문장은 40자 이내로 끊는다.
2. "~해야 합니다"보다 "~해 주세요"처럼 부탁형으로 쓴다.
3. 전문용어는 괄호로 짧게 풀어 준다.
4. 마지막에 도움받을 곳(고객센터 링크)을 붙인다.
  • 두 부분입니다 — 맨 위 머리말(이름·설명)과 그 아래 본문(실제 지시)
본문은 사람이 신입에게 설명하듯 쓰면 됩니다. 형식은 마크다운이고, 특별한 문법이 없습니다.

핵심 원리 — 점진 공개(progressive disclosure)

평소name·description만
수십 토큰
→
맞을 때만본문 전체를
읽어 온다
  • AI는 평소 머리말만 훑고 있다가, 지금 하는 일이 그 설명과 맞을 때만 본문을 읽습니다
  • 그래서 수십 개를 켜 둬도 평소엔 거의 공짜이고, 필요한 순간에만 '펼쳐집니다'
✍️ description을 잘 쓰는 게 중요한 이유가 여기 있습니다 — AI가 언제 이 스킬을 꺼낼지를 그 한 줄로 판단하니까요
출처: Claude Platform Docs, "Agent Skills". 과제에서 description을 평가 기준으로 삼는 이유가 이것입니다.

규칙 파일 — AGENTS.md · CLAUDE.md

"에이전트를 위한 README"

③ 스킬과 규칙
스킬과 비슷하지만 더 기본이 되는 것입니다.

매번 설명하기 지겨울 때 — 파일 하나에

AI에게 "우리 프로젝트는 이런 규칙이야"를 매번 설명하기 지겨울 때, 그걸 파일 하나에 적어 둡니다. 흔히 AGENTS.md 또는 CLAUDE.md라고 부르고, 공식 설명은 이걸 "에이전트를 위한 README"라고 합니다.

⚠️ 많은 도구가 대화를 시작할 때 이 파일을 자동으로 먼저 읽습니다 — 단, Claude Code는 CLAUDE.md만 자동으로 읽습니다
1프로젝트 개요 — 이게 무슨 서비스인지 한두 줄
2자주 쓰는 명령 — 실행·테스트 방법 (설명보다 명령어를 먼저)
3규칙·컨벤션 — 폴더 구조, 스타일 등
4하지 말 것 — "이 폴더는 건드리지 마" 같은 금지사항
출처: agents.md 공식 스펙. 여기 적은 건 매번 처음부터 아는 지식이 됩니다. 실습(소단원 ⑥)에서 직접 씁니다.

흐름 하나 — 이름이 통일됐습니다

예전엔 도구마다 파일 이름이 제각각이었는데, 2025년 여러 회사가 모여 AGENTS.md라는 공통 표준을 만들었습니다(수만 개 프로젝트가 채택).

헷갈리지 않기 — MCP vs 스킬 vs 규칙

결정 규칙 세 줄

③ 스킬과 규칙
셋이 비슷해 보이지만 역할이 다릅니다.

이 세 줄이면 충분합니다

내가 원하는 것무엇을 쓰나
AI에게 새 능력·연결을 주고 싶다 (내 DB·도구에 붙이기)MCP
AI가 항상 이런 식으로 행동하게 하고 싶다규칙 (CLAUDE.md / AGENTS.md)
반복하는 다단계 작업을 자동화하고 싶다스킬(Skill)
스킬은 선반에서 꺼내 쓰는 '방법서'
규칙은 프로젝트의 '상시 안내문'
MCP는 도구를 꽂는 '어댑터'
  • 서로 경쟁이 아니라 함께 씁니다
출처: Totalum, "Claude Code Skills in 2026". 이 표는 학습자가 실무에서 가장 많이 다시 볼 슬라이드입니다.

❓ 미니 퀴즈 — MCP? 스킬? 규칙?

Q1. AI가 우리 회사 DB를 직접 조회하게 하고 싶다
A1. MCP — 새 능력·연결을 주는 일
Q2. "보고서는 항상 우리 양식으로"를 늘 지키게 하고 싶다
A2. 규칙 (CLAUDE.md / AGENTS.md) — 항상 지킬 행동
Q3. "경쟁사 조사 → 표로 정리"라는 다단계 작업을 매번 반복한다
A3. 스킬(Skill) — 반복하는 다단계 작업
🎯 새 능력 = MCP · 항상 = 규칙 · 반복 작업 = 스킬. 이 세 갈래만 기억하면 됩니다
세 문제를 손으로 먼저 골라 보게 한 뒤 정답을 보여 주세요. 자기 프로젝트로 바꿔 말해 보면 더 좋습니다.

❓ 이해도 확인

Q4. 스킬을 수십 개 켜 둬도 느려지지 않는 이유는?
A4. 점진 공개 — 평소엔 name·description만(약 30~50 토큰) 훑고, 지금 하는 일이 그 설명과 맞을 때만 본문을 읽는다.
Q5. description을 잘 써야 하는 이유는?
A5. AI가 언제 이 스킬을 꺼낼지를 그 한 줄로 판단하기 때문.
Q6. Claude Code에서 규칙 파일 이름은?
A6. CLAUDE.md만 자동으로 읽는다. AGENTS.md를 쓰려면 CLAUDE.md에서 불러오면 된다.
Q6은 실습에서 바로 걸리는 함정입니다. AGENTS.md만 만들고 "왜 안 읽지?"가 되는 경우가 많습니다.

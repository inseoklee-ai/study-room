Omni LLM으로
처리하기

전문 도구 여럿인가, 하나가 다 받는가

지금까지는 소리를 글자로 바꿔 언어 모델에 넘기는 받아쓰기 방식이었습니다. 강의를 연 질문이 이 지점 — 전문 도구를 여러 개 붙일 것인가, 하나가 다 받게 할 것인가.

🗺️ 이 덱의 여정

  • 옴니 모델 — 글·소리·이미지·영상을 어떤 조합으로든 받는 하나의 모델(GPT-4o의 'o', Gemma 4)
  • 함정 — 모델이 받는다고 내가 쓸 수 있는 건 아니다(실행 도구에 따라 입력이 다름)
  • 추론 엔진이란 무엇이고, 개인용 vs 서버용이 왜 다른가
  • 한 모델이 다 받으면 무엇이 달라지나 — 중간 손실↓ vs 검증 자리↓
선택은 정확도가 아니라 무엇을 검증해야 하는가로 갈린다
🎯 한 줄 — "이 모델이 무엇을 할 수 있나"와 "내 환경에서 무엇을 쓸 수 있나"는 따로 확인해야 한다.
후자를 부르는 이름이 옴니 모델(omni model) — 모든 것이라는 라틴어. 만든 쪽이 직접 그렇게 부릅니다.

🌐 옴니 모델 — 하나가 다 받는다

  • 오픈AI는 GPT-4o를 "글·소리·이미지·영상을 어떤 조합으로든 입력으로 받는 옴니 모델"이라 설명 — 이름 끝 o가 그 뜻
  • 이런 모델을 노트북에서도 만져 볼 수 있다 — 구글 Gemma 4는 가중치를 내려받아 쓰고, 글·이미지에 더해 소리·영상까지 받는다
무엇을 받는가어느 크기에서
글, 이미지, 영상전 크기
소리E2B · E4B · 12B
이름의 숫자가 크기 — 12B=120억. E2B·E4B는 실제로 더 크지만 돌 때 2B·4B만큼만 메모리를 쓰게 만든 것(노트북 시작은 E4B 무난). 12B는 시각·청각 인코더를 따로 두지 않고 입력을 곧바로 모델 안으로 투영 — 공유 공간의 중간 단계를 없앤 쪽.
맥락 길이는 작은 것 128K, 중간 256K. GPT-4o System Card / Gemma 4 overview.

⚠️ 모델이 받는다고 내가 쓸 수 있는 건 아니다

같은 모델을 로컬 실행 도구(Ollama ollama run gemma4:e4b)로도 받을 수 있다. 그런데 무엇으로 돌리느냐에 따라 넣을 수 있는 입력이 달라진다.

무엇으로 돌리나넣을 수 있는 것
간편한 로컬 실행 도구글, 이미지
서버용 추론 엔진글, 이미지, 소리, 영상
모델 가중치는 하나인데 받는 게 다르다. 심지어 한 도구의 문서끼리도 어긋난다(소개엔 소리를 받는다는데 판본 표기엔 글·이미지만). 모델이 못 하는 게 아니라 그 도구가 아직 안 열어 준 것.
새 기능은 모델이 먼저 나오고 실어 주는 도구가 뒤따라옵니다. 그래서 "이 모델이 무엇을 하나"와 "내 환경에서 무엇을 쓰나"를 따로 확인해야 합니다. vLLM 문서의 T+I+V+A가 글·이미지·영상·소리.

🔧 실행 도구(추론 엔진)란

  • 내려받은 가중치는 그 자체론 숫자가 잔뜩 든 파일
  • 이걸 돌리려면 — 메모리에 올리고, 입력을 모델이 먹을 형태로 바꾸고, 계산을 GPU에 실어 보내고, 나온 숫자를 다시 글자로. 그 일을 하는 프로그램이 추론 엔진

개인 노트북, 하나씩

중요한 건 설치가 쉽고 메모리를 적게. GPU 없어도 돌고, 명령 한 줄로 끝나야.

서버 한 대, 수십 명 동시

중요한 건 GPU를 놀리지 않는 것. 요청을 겹쳐 밀어 넣고, 앞 요청을 안 기다리고 끼워 넣고, 같은 앞부분 계산을 재사용.

"한 사람이 하나씩"과 "서버로 수십 명 동시"는 완전히 다른 문제라 도구가 갈린다.
요청이 하나씩 들어올 때마다 처리하면 GPU가 대부분의 시간을 쉽니다.

🔀 어느 갈래인지만 알아보면 된다

갈래무엇을 잘하나이름
내 기기에서 혼자설치 쉽고 GPU 없어도 돈다로컬 실행 도구, C++ 구현(llama.cpp)
서버에서 여럿이요청을 겹쳐 GPU를 꽉 채운다vLLM · SGLang · LMDeploy
애플 기기 전용통합 메모리에 맞춰 최적화애플 전용 프레임워크
직접 서버 엔진을 세울 일은 당장 없어도 알아 둘 이유 셋 — ① 넣을 수 있는 입력이 다르다 ② 회사 배포 때 도구가 바뀐다(노트북서 잘 되던 게 열 명만 붙어도 느려짐) ③ 속도 비교 글은 어느 엔진으로 잰 건지부터 본다(같은 모델도 두세 배 차이).
이름을 외울 필요는 없고, 어느 갈래인지 알아보는 것이면 충분합니다.

⚖️ 한 모델이 다 받으면 무엇이 달라지나

중간에서 잃는 게 줄어든다

소리를 글자로 바꾸면 억양·침묵이 사라진다. 소리째로 받는 모델엔 그 단서가 남아 — "긴 침묵 뒤 낮은 목소리로 말했다"를 나중에 물어볼 수 있다.

검증할 자리가 줄어든다 (대가)

받아쓰기·요약을 나누면 어느 단계에서 틀렸는지 짚을 수 있다(제안→제한도 중간 산출물로 잡음). 한 모델이 곧바로 결론을 말하면 그 중간이 없다.

선택은 정확도가 아니라 무엇을 검증해야 하는가로 갈린다근거를 되짚어야 하면 나누고, 실시간 상황 파악이면 한 번에 받는다
회의록처럼 나중에 근거를 되짚어야 하는 일은 나눠 두는 편이 낫고, 실시간 안내처럼 상황을 즉시 파악해야 하면 한 번에 받는 편이 낫습니다.

📌 이것만은 꼭 — 핵심 5문장

1옴니 모델은 글·소리·이미지·영상을 어떤 조합으로든 받는다(GPT-4o·Gemma 4).
2모델이 받는다 ≠ 내가 쓸 수 있다 — 같은 가중치도 실행 도구에 따라 넣을 입력이 다르다.
3추론 엔진은 가중치 파일을 실제로 돌리는 프로그램. 개인용(쉬움)과 서버용(GPU 꽉 채움)이 다르다.
4이름을 외우지 말고 어느 갈래인지만 — 입력·배포 도구·속도 비교에서 필요하다.
5한 모델이 다 받으면 중간 손실↓·검증 자리↓ — 선택은 무엇을 검증해야 하나로.
2번과 5번이 핵심 — 환경 확인, 그리고 검증 기준의 선택.

Q2. "모델이 받는다 ≠ 내가 쓸 수 있다"를 실행 도구로 설명하면?

✅ 정답 & 해설

A1. 글·소리·이미지·영상을 어떤 조합으로든 입력으로 받는 하나의 모델. o=omni(모든 것).
A2. 같은 가중치도 로컬 도구는 글·이미지, 서버 엔진은 소리·영상까지 — 도구가 안 열어 준 입력은 못 쓴다.
A3. 가중치 파일을 메모리에 올리고 계산해 글자로 되돌리는 프로그램. 개인용은 쉬움·저메모리, 서버용은 요청을 겹쳐 GPU를 꽉 채움.
A4. ① 입력이 다름 ② 배포 때 도구가 바뀜(열 명만 붙어도 느려짐) ③ 속도 비교는 어느 엔진으로 잰 건지 봐야.
A5. 정확도가 아니라 무엇을 검증해야 하나 — 근거를 되짚으면 나누고, 실시간이면 통합.
A5를 자기 업무에 대보면 통합/분리 판단이 섭니다.

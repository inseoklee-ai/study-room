관찰 도구로 n8n을 고릅니다

그래프가 곧 실행되는 구조

③ 인스턴스 관찰
관찰 학습에 알맞은 이유를 먼저 확인합니다.

n8n — nodemation에서 온 이름

  • 2019년 베를린에서 태어난 워크플로 자동화 도구
  • 이름은 노드(node)와 오토메이션(automation)을 합친 nodemation에서 왔습니다 — 노드를 잇는 그래프가 곧 실행되는 구조 자체가 이름의 출발점
  • 화면에서 노드라 부르는 블록을 연결해 흐름을 그리면 그 그래프가 그대로 돌아갑니다
  • 메일·폼·스프레드시트·채팅 같은 외부 서비스와 공개 API를 노드로 묶을 수 있고, 실행할 때마다 어느 노드가 무엇을 주고받았는지 기록이 남습니다
📌 그래프가 화면에 그대로 보이므로 흐름과 데이터의 이동을 눈으로 따라갈 수 있습니다 — 관찰 학습에 알맞은 이유입니다
소단원 ②에서 정의한 그래프의 네 요소(점·화살표·분기·기록)가 여기서 실제 화면 요소로 대응됩니다.

수치를 인용하면서 그 수치가 말하지 않는 것을 함께 적는 방식은 이 대단원 전체의 규칙입니다.

실습 — 공개 정보를 읽는 짧은 흐름

설계한 흐름과 실행 뒤 기록을 나란히

③ 인스턴스 관찰
도구가 보여 준 사실과 아직 확인하지 못한 사실을 구분하는 것이 목표입니다.

접속과 계정 만들기

  • 수업용 n8n 접속 주소 — https://n8n.vibemakers.kr
  • 계정은 수업에서 안내한 설문 폼에서 만듭니다. 폼 진입 시 아이디·비밀번호를 물으면 수업에서 안내받은 값을 입력합니다
  • 폼을 제출하면 수업용 계정이 만들어지고, 그 계정으로 접속 주소에 로그인합니다
  • 로그인 뒤 화면에 표시되는 버전은 그대로 기록해 둡니다
⚠️ 개인 가입, 초대 수락, 비밀번호 설정처럼 인증 방법을 추정하여 진행하지 않습니다 — 여러 방식으로 계정을 만들려 하면 수업 계정의 권한 경계와 기록이 흐려집니다. 멈춘 화면, 오류 문구, 접속한 주소를 남기는 편이 더 정확한 관측입니다
설문 폼 주소와 진입용 아이디·비밀번호는 LMS 원문에 있습니다. 이 슬라이드는 공개 페이지이므로 값 자체는 적지 않았습니다.

실행 기록에서 원 응답을 찾습니다

  • 실행이 끝나면 실행 목록에서 방금 흐름의 기록을 엽니다
  • HTTP Request 노드의 출력에는 HTTP 상태코드와 서버가 돌려준 원 응답이 함께 보입니다
  • 응답에서 찾을 필드 — title · description · timestamp · content_urls
📌 실행 기록은 워크플로 전체가 한 번 실행된 단위이므로 — 노드 화면과 실행 한 건을 구별해 살핍니다
선으로만 보이던 흐름이
실제 데이터를 가져왔다는 사실을 기록으로 확인합니다
이 '실행 한 건' 개념이 소단원 ②의 execution 과금 단위와 같은 개념입니다.

❓ 이해도 확인

Q1. 관찰 학습에 n8n이 알맞은 이유는?
A1. 노드와 선이 곧 실행되는 그래프여서 흐름과 데이터의 이동을 눈으로 따라갈 수 있고, 실행마다 어느 노드가 무엇을 주고받았는지 기록이 남기 때문.
Q2. 로그인이 안 될 때 해야 할 일은?
A2. 여러 인증 방식을 추정해서 시도하지 않는다. 권한 경계와 기록이 흐려지므로 — 멈춘 화면, 오류 문구, 접속한 주소를 남긴다.
Q3. 별 11만·MAU 170만이 뜻하는 것과 뜻하지 않는 것은?
A3. 생태계가 있다는 뜻은 되지만 사용 규모가 곧 신뢰라는 뜻은 아니다.
Q2는 관측 규율에 관한 질문입니다 — 추정하지 않고 화면을 남기기.

SWE-agent ACI ablation — 구성요소를 바꿔 봅니다

검색, 편집, 관측 형식처럼 인터페이스 구성요소를 바꾸고 결과를 비교할 수 있음을 보였습니다.

  • 같은 모델이라도 — 무엇을 읽고 어떤 형식으로 행동했는지를 고정해야 구성요소의 기여를 물을 수 있습니다
  • 이 결과는 SWE-bench Lite와 논문에 적힌 실행 조건의 결과입니다
⚠️ 다른 모델이나 저장소에서도 같은 구성요소가 같은 기여를 한다고 해석해서는 안 됩니다
출처: Yang 외, NeurIPS 2024, arXiv:2405.15793. SWE-bench Lite ablation 결과이며 모델·저장소·실행 조건 밖으로 일반화하지 않습니다.

실제 GitHub 이슈와 저장소로 코딩 에이전트를 측정하는 벤치마크입니다.

SWE-bench Verified — 인간 검증 500문제

  • 12개 저장소에서 인간이 검증한 500개 문제를 제공하는 공식 데이터셋 카드
  • 사후 PR 테스트 행동을 정답 대리물로 둡니다 — 검수자 수와 합의 절차는 확인하지 못했습니다

출처: Princeton NLP 공식 데이터셋 카드, SWE-bench_Verified. 소단원 ⑦의 mini-swe-agent 74% 초과도 이 데이터셋 위의 자체 보고였습니다.

trajectory가 하는 일과 못 하는 일

❌ 못 하는 일

모델의 의도나 패치의 정답성을 스스로 증명하지 못합니다

✅ 하는 일

1차 근거로 남깁니다 — 어느 검색이 먼저였는지, 테스트 실패 뒤 무엇을 편집했는지, 어떤 명령이 실행됐는지

  • 이 기록에서 다시 확인할 것 — 다음 행동을 바꾼 관측이었는지, 같은 탐색을 반복했는지, 승인한 권한이 과도했는지
소단원 ②의 사실/해석 분리가 여기서도 그대로 적용됩니다 — 기록은 사실, 적절성 판단은 해석입니다.

통과 결과만으로는 충분하지 않습니다

정적 벤치마크의 테스트 통과는 장기 유지보수 · 설명 가능성 · 코드 검토 · 의존성 변화 대응을 모두 재지 못합니다. 공개된 문제와 해답이 학습 또는 도구 설정에 섞였을 가능성도 비교를 흐릴 수 있습니다.

1결과 점수와 함께
2실행 환경 · 모델 · 권한 정책
3비용 · 승인 횟수
4trajectory를 남기고 실제 검토를 별도로 합니다

❓ 이해도 확인

Q1. 결과와 궤적을 왜 분리하나?
A1. 패치가 맞았다는 사실만으로는 검색 낭비 · 우연한 성공 · 과도한 권한 사용을 구분할 수 없기 때문.
Q2. trajectory가 증명하는 것과 증명하지 않는 것은?
A2. 모델의 의도나 패치의 정답성은 증명하지 못한다. 다만 검색 순서·편집 시점·실행 명령을 1차 근거로 남긴다.
Q3. SWE-bench Verified 등급이 뜻하는 것은?
A3. 해결 가능성 검토의 근거일 뿐 특정 하네스가 낫다는 근거가 아니다. 사후 PR 테스트 행동을 정답 대리물로 삼는다.
Q3은 벤치마크 수치를 도구 광고로 읽지 않기 위한 방어선입니다.

단원 3 · LLM과 로컬 실행 (6)

비용은
어디서 발생하는가

판단의 두 번째 축 · 비용 · 손익분기의 함정 · 병목 찾기

API 비용은 청구서에 숫자로 찍히지만, 로컬 비용은 전기요금·담당자 시간·기다림 속에 섞입니다. 청구서가 없다고 비용이 없는 건 아닙니다.

🗺️ 이번 강의의 지도

파트내용핵심
1손익분기의 함정남의 손익분기 숫자를 인용하면 안 되는 이유
2내 업무 비용 구조직접 계산하고 병목에 동그라미
3판단 연습"10개월이면 회수" 제안 해부
🎯 핵심 한 줄: 비용은 같은데 모양이 다릅니다. API는 눈에 띄고, 로컬은 여기저기 섞여 숨습니다.
비용 이야기가 회의에서 자주 어긋나는 건, 같은 비용이 서로 다른 모양으로 나타나기 때문입니다.

💬 왜 비용 대화는 자꾸 어긋날까

"API 비용이 부담됩니다"

매달 청구서에 숫자로 — 눈에 띄고, 결재선을 타고, 누군가 줄이라고 지시

"로컬로 돌리면 공짜 아닌가요"

장비 품의로 한 번 크게 나온 뒤 — 전기요금·담당자의 목요일 저녁·기다리는 몇 초 속에 섞임

🔑 두 사람 다 틀리지 않았는데 대화가 진전되지 않습니다. 같은 비용이 다른 모양으로 나타나기 때문. 청구서가 없다고 비용이 없는 것은 아닙니다.
API 비용은 눈에 띄어 관리 대상이 되고, 로컬 비용은 여기저기 섞여 관리 사각지대가 됩니다.

📊 같은 압력, 다른 청구서

무엇이 늘 때API에서는로컬에서는
처리량↑요청·토큰 수에 비례해 청구액↑대기열이 길어지고 GPU를 추가 구매
입력 문서가 길 때입력 토큰 비용↑메모리 부족 → 모델 축소 or 문서 쪼개기
출력이 길 때출력 토큰 비용↑ (보통 입력보다 단가 높음)생성 시간이 그대로 늘어남
실험 반복실험 횟수만큼 그대로 과금전기 + 담당자 시간 + 기회비용
품질이 흔들릴 때재시도·평가 호출 비용사람이 검토·수정하는 시간
🔑 마지막 행(품질이 흔들릴 때)이 실무에서 가장 자주 무시되고, 가장 자주 판단을 뒤집습니다.
재작업·검토 시간은 청구서에도 안 찍히고 워크북에서도 빠지기 쉬운데, 실제로는 총액을 좌우하는 경우가 많습니다.

🏢 API로 빌리는 건 모델만이 아닙니다

API를 쓸 때 함께 빌리는 것:

  • 이 방의 전기와 냉방
  • 장애에 대비한 이중화
  • 새벽에 알람을 받고 일어나는 사람
🔑 로컬로 옮긴다는 것은, 이 방의 아주 작은 축소판을 직접 갖는다는 뜻입니다. 전기·냉방·당직·이중화가 전부 내 몫이 됩니다.
(원 강의의 데이터센터 사진을 개념으로 표현했습니다.) API 요금 안에는 인프라 운영과 사람 값이 이미 포함돼 있습니다. 로컬은 그걸 직접 떠안는 것입니다.
1

손익분기 숫자를 인용하면 안 되는 이유

공개 분석들이 천 배씩 어긋난다

전제가 다르다
"몇 토큰부터 로컬이 유리한가"는 당연히 궁금하지만, 남의 숫자를 그대로 붙이면 안 됩니다.

📉 같은 질문, 천 배 차이 나는 답

어떤 분석하루 50만 토큰
다른 분석하루 1천만 토큰
또 다른 분석월 5억 토큰

"몇 토큰부터 로컬이 유리한가"에 대한 공개 분석들 — 천 배 가까이 차이가 납니다.

🔑 계산이 틀려서가 아닙니다. 전제가 다르기 때문입니다. 그러니 남의 손익분기 숫자를 회의 자료에 붙이는 대신, 자기 숫자를 넣어야 합니다.
남의 결론 숫자는 그 사람의 전제에서만 맞습니다. 전제가 다르면 결론도 천 배 달라집니다.

🎚️ 결과를 가르는 세 가지 전제

1무엇을 대체하는가 — 값싼 소형 API를 대체하면 손익분기점이 멀어짐(저렴 단가를 장비 감가로 못 따라잡음). 상위 모델 + 긴 문서를 매일 쓰고 있었다면 훨씬 가까움
2사람 시간을 비용으로 세는가 — 모니터링·업데이트·장애 대응이 월 10~20시간. 인건비를 곱하면 하드웨어 감가보다 큰 항목. 빼면 로컬이 이기고 넣으면 짐
3가동률 — 하루 종일 vs 업무 시간에만 몇 번 → 토큰당 비용 10배 넘게 차이. 안 써도 감가는 진행. 로컬 비용을 부풀리는 최대 원인은 비싼 장비가 아니라 낮은 가동률
세 전제 중 특히 '사람 시간'과 '가동률'을 빼먹으면 로컬이 실제보다 훨씬 싸 보입니다.

🧩 미리 알 것 ① — 모델이 장비에 들어가나

4비트 → 파라미터 10억 개당 약 0.5GB
24GB급 소비자 GPU 한 장결과
가중치만 놓고30~35B급까지
긴 문서 업무(KV 캐시 얹힘)14B 안팎으로 내려잡아야 여유
70B급4비트로도 35GB↑ → 한 장에 안 들어감
넘치면 계산이 CPU로 넘어가 속도 급락. "상위 API 모델을 로컬로 대체한다"는 계획은 비용 계산 이전에 여기서 먼저 막히는 경우가 많습니다.
비용을 따지기 전에, 대체하려는 모델이 애초에 내 장비에 들어가는지부터 확인해야 합니다.

⚡ 미리 알 것 ② — 전기요금은 직접 계산

400W × 24시간 = 9.6kWh/일 → 월 ≈ 288kWh
× 150원/kWh ≈ 월 4만원대
  • 여기에 CPU·메인보드·냉방까지 더하면 실제로는 더 나옴
  • 여러분 사무실의 실제 단가·실제 가동 시간으로 다시 계산 — 산수라 회의에서 반박당하지 않음
⚠️ 하드웨어 가격도 API 단가도 계속 움직입니다. 특히 API 단가는 계속 내려와 회수 기간이 긴 계획에 불리. 원칙은 하나 — 결정하는 날 공식 가격표를 열고 그날 날짜를 함께 적기.
남의 전기요금 숫자를 빌릴 필요가 없습니다. 직접 계산하면 반박 불가능한 근거가 됩니다.

🎯 병목이 어디냐에 따라 할 일이 다르다

병목먼저 할 일
API · 출력 토큰로컬 장비가 아니라 출력 길이를 줄이는 프롬프트 설계부터
API · 입력 토큰프롬프트 캐싱 + 문서 사전 요약
로컬 · 운영 인력 시간장비를 더 좋게 바꿔도 총액은 거의 안 줆
  • 프롬프트 캐싱 — 매 요청마다 똑같이 들어가는 앞부분(긴 역할 지시·고정 자료)을 제공사 쪽에 잠시 보관해 두 번째 요청부터 다시 계산 안 함 → 그 구간 단가 크게↓
  • 배치 처리 — 급하지 않은 요청을 모아 제공사가 한가할 때 돌리게 맡기고 할인을 받음
병목을 모르고 장비부터 사면, 정작 총액을 지배하는 항목은 그대로 남습니다.

🤖 [프롬프트] 비용 비교 계산기

목적: 우리 업무의 LLM 실행 위치를 비용 기준으로 비교한다.
입력: 입력·출력 100만 토큰당 단가, 월 요청 수, 요청당 평균 입력·출력 토큰,
      로컬 월 고정비(장비 감가, 전기, 운영 인력 시간, 품질 검토 시간).
출력: API 월비용, 로컬 월비용, 두 값이 같아지는 월 요청 수.
조건: 가정값은 파일 맨 위에 상수로 모아 한눈에 바꿀 수 있게 한다.
      각 단가 옆에는 출처 URL과 확인 날짜를 주석으로 남긴다.
      가동률을 입력받아 로컬 토큰당 비용에 반영한다.
🔑 여러분이 할 일은 코드를 외우는 게 아니라, 나온 숫자를 보고 "이 가정이 우리 업무에 맞는가"를 묻는 것. 계산기는 가정을 검증해주지 않습니다.
가동률을 입력에 반드시 넣게 하는 것이 핵심입니다. 가동률을 빼면 로컬 토큰당 비용이 비현실적으로 낮게 나옵니다.
3

판단 연습

"10개월이면 회수됩니다" — 어디를 짚을까

검토자의 눈으로
비용이라는 단어 하나로 결정을 밀어붙이지 않게 하는 것이 이 연습의 목적입니다.

⚖️ 이 제안, 어디를 짚어야 할까

"현재 월 API 비용이 300만원입니다. 3천만원짜리 GPU 서버를 사면 10개월이면 회수됩니다. 그 뒤로는 계속 이득이니 로컬 전환을 추진하겠습니다."

숫자가 명확하고 결론이 깔끔합니다. 그래서 통과되기 쉽습니다. 짚어야 할 곳이 여섯 군데 있습니다. (다음 두 장에 해설)
깔끔한 회수 계산일수록 빠진 항목이 숨어 있습니다. 하나씩 뜯어봅니다.

💡 짚어야 할 곳 (1/2)

① 같은 일을 할 수 있나 (먼저) — 300만원짜리가 상위 모델이면 서버 한 대로 부족할 가능성. 대체 모델을 정하고 실제 샘플로 품질 비교가 없다면, 이건 비용 비교가 아니라 다른 제품으로 갈아타자는 제안.
② 3천만원 안에 사람이 없다 — 서버 가격은 시작점. 설치·모니터링·업데이트·장애 대응 시간 × 담당자 시급을 더해야. 넣으면 10개월이 대개 15~20개월.
③ 가동률이 빠졌다 — 호출이 업무 시간에 몰리면 서버는 하루 대부분 논다. 놀아도 감가는 진행. 실제 가동 시간 기준 토큰당 비용으로 봐야.
①은 비용 이전의 질문입니다. 같은 품질을 못 내면 회수 계산 자체가 의미 없습니다.

💡 짚어야 할 곳 (2/2)

④ 더 싼 방법을 먼저 써봤나 — 프롬프트 캐싱·배치·소형 모델 라우팅만으로 청구액이 크게 줄기도. 인프라 안 늘리는 절감이니 먼저 시도. 해보고도 300만원인지, 안 하고 300만원인지는 완전히 다른 이야기.
⑤ 회수 기간 동안 상대도 움직인다 — API 단가는 내려오는 추세. 10개월 뒤 절반이면 회수 시점이 영영 안 올 수도. 사용량이 3배면 훨씬 빨리 옴. → 회수 기간은 하나의 숫자가 아니라 시나리오 2~3개로.
⑥ 그래도 로컬이 답일 수 있다 — 위를 다 반영했는데도 유리하면 근거 있는 판단. 데이터가 밖으로 못 나가는 업무라면 비용과 무관하게 로컬이 유일한 선택지.
이 연습은 로컬을 말리는 게 아니라, "비용" 한 단어로 결정을 밀어붙이지 않게 하는 것입니다.

📌 이것만은 꼭 — 핵심 6문장

1비용은 같은데 모양이 다르다 — API는 청구서, 로컬은 여기저기 섞여 숨는다
2가장 자주 무시되고 판단을 뒤집는 건 품질이 흔들릴 때의 재작업·검토 시간
3남의 손익분기 숫자는 전제가 달라 천 배씩 차이 — 대체 대상·사람 시간·가동률
4로컬 비용을 부풀리는 최대 원인은 비싼 장비가 아니라 낮은 가동률
5워크북으로 내 숫자를 넣고 양쪽 병목에 동그라미 — 병목별로 할 일이 다르다
6회수 계산엔 사람·가동률·더 싼 대안·단가 하락이 들어가야. 회수는 시나리오 2~3개로
워크북 합계 두 줄이 다음(주권)을 거쳐 최종 결정문의 비용 근거로 들어갑니다.

Q1. 비용 대화가 자주 어긋나는 이유는? API 비용과 로컬 비용은 각각 어떤 모양으로 나타나나?
Q2. 비용이 늘어나는 상황 중 가장 자주 무시되고 판단을 뒤집는 행은?
Q3. 손익분기 숫자가 천 배씩 차이 나는 세 가지 전제는?
Q4. 로컬 비용을 부풀리는 가장 큰 원인은?
Q5. 400W 카드를 24시간 한 달 돌리면 전기는 대략? (직접 계산)
Q6. "300만원→3천만원 서버 10개월 회수" 제안에서 빠진 것들은?
Q3와 Q6이 실무에서 가장 자주 틀리는 지점입니다.

✅ 정답 & 해설

A1. 같은 비용이 다른 모양으로 나타나서. API=매달 청구서 숫자(눈에 띔). 로컬=장비 품의 한 번 뒤 전기·담당자 시간·기다림에 섞여 숨음.
A2. 품질이 흔들릴 때 — API는 재시도·평가 호출, 로컬은 사람이 검토·수정하는 시간. 워크북에서 빠지기 쉬운데 총액을 좌우.
A3. ①무엇을 대체하는가(소형 vs 상위+긴 문서) ②사람 시간을 세는가(월 10~20h) ③가동률.
A4. 낮은 가동률. 안 써도 감가는 진행 → 토큰당 비용이 10배 넘게 벌어짐.
A5. 9.6kWh/일 × 30 ≈ 288kWh, ×150원 ≈ 월 4만원대(냉방·부품 더하면 더). 실제 단가·가동 시간으로 다시.
A6. ①같은 품질 가능한지 ②사람 비용 ③가동률 ④더 싼 대안(캐싱·배치·라우팅) ⑤API 단가 하락(시나리오화) — 데이터 반출 금지면 비용과 무관하게 로컬.
A6의 여섯 항목을 다 반영하고도 로컬이 유리하면, 그때는 근거 있는 결정입니다.

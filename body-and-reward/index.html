몸을 얻은 모델

VLA · 200달러 팔 · 세계 모델

⑧
모델이 낸 답이 물건을 실제로 움직입니다.

🦾 좌표를 적는 대신 화면과 말을 넣는다

  • 전통 방식은 좌표 적기 — "여기서 저기로 몇 도씩". 카메라를 붙여도 "빨간 물체 중심을 찾아 그 좌표로"처럼 사람이 규칙을 다 적었다(물체·조명이 바뀌면 다시)
  • 최근 방식은 카메라 화면과 사람 말을 함께 넣고 곧바로 관절을 얼마나 움직일지를 낸다. 규칙 적는 단계가 없다 — 조종기로 시범을 여러 번 보이면 그 기록으로 학습. 시각·언어·행동의 앞글자를 따 VLA
앞 발상들이 겹친다 — 이미지·문장 이해는 이미 잘 학습된 모델을 그대로(기반 모델), 그 뒤에 관절 각도를 내는 머리를 붙이고, 이어지는 동작을 부드럽게 만드는 데 확산. 행동도 시간에 따라 이어지는 좌표의 나열이라 그림 만들듯 만든다.
🔬 장면 — 화장품 회사 포장 담당자가 매일 다른 조합 샘플 세트를 손으로 담습니다. 로봇 팔 앞에서 조종기로 스무 번 시범 보이고 "분홍 튜브를 왼쪽 칸에"라고 말합니다. 품목이 바뀌면 프로그램을 다시 짜는 게 아니라 시범을 다시 스무 번.

🎬 왜 동작 한 묶음을 한꺼번에 내놓나

  • 다음 동작 하나씩만 내놓으면 갈림길에서 흔들린다 — 컵을 왼쪽으로 돌아 잡아도 오른쪽으로 잡아도 되는데, 순간마다 하나씩 고르면 왼·오를 오가다 가운데로 가 컵을 친다(시범에 두 방식이 섞여 평균 내면 그렇게)
  • 매 순간 새로 정하면 동작이 떨린다
앞으로 몇십 단계를 한 묶음으로 한꺼번에여기서 확산 — 시간축을 따라 늘어선 관절 각도 전체를 한꺼번에 걷어 낸다
그러면 묶음 안에서 앞뒤가 자연스럽게 이어지고, 왼쪽·오른쪽도 묶음 단위로 하나가 정해져 평균으로 안 뭉개진다. 만든 묶음을 다 쓰지 않고 앞부분만 실행하고 새 묶음을 — 계획은 길게, 실행은 조금씩 하며 바뀐 상황을 반영.
그림을 만들 때 픽셀 전체를 한꺼번에 잡음에서 걷어내듯, 관절 각도 전체를 한꺼번에 걷어냅니다. 왜 지금인가 — 여러 연구실 기록을 하나로 모아 공개했고, 이미지·말 모델이 받아 쓸 수 있게 공개됐고, 결정적으로 로봇 팔이 싸졌습니다.

🛠️ 이백 달러대의 팔, 로봇 없이 시작

SO-101

설계도 공개(하드웨어 아파치 2.0). 부품표 기준 팔 하나 ~122달러, 조종용까지 두 팔 ~230달러. 조립형 기본, 완성품·국내 판매처도 등재

LeRobot

팔이 없어도 시작 — 물리 시뮬레이터 위에서 수집·학습·평가가 전부 돈다. 공식 문서가 로컬에 GPU 없으면 코랩을 쓰라고 안내

장비값이 내려가면 공개 학습 자료가 다시 는다이 가격이 갈래 전체를 바꿨다 — 연구실 밖 사람이 실물을 만진다
공식 코랩(SmolVLA 학습)은 T4에서 시작까지 된다. 노트북 자체는 A100·2만 스텝 5시간을 권하지만, 수업에서 볼 것은 손실이 내려가기 시작하는 것까지(손실 = 낸 답과 정답이 벌어진 정도, 내려가면 자료를 붙들기 시작한 것).
스텝은 가중치를 한 번 고치는 것을 세는 단위입니다. T4에서 한 스텝 12초쯤이라 2만 스텝은 며칠짜리입니다.

🕳️ 지시문 함정 둘과 라이선스

  • 로그인 셀 둘은 건너뛴다(wandb login·hf auth login은 사람이 키를 쳐 넣어야 해 전체 실행이 멈춤. 학습 셀에 -wandb.enable=false가 이미 있음)
  • 자료를 lerobot/svla_so101_pickplace로 바꾼다(자리표시자 그대로 두면 못 찾고 멈춤). -policy.repo_id는 지우지 말고 -policy.push_to_hub=false로 — 그냥 지우면 "repo_id 없음"으로 자료 받기도 전에 멈춘다. 올릴 곳을 지우는 게 아니라 안 올리겠다고 말해 줘야
라이선스 조심 둘 — SmolVLA는 모델 카드에 라이선스 항목이 아예 없다(바탕이 아파치라 정황상 자유롭지만 확인 필요). OpenVLA는 페이지 태그가 MIT인데 저장소 설명은 특정 대형 모델 약관을 물려받는다고 못 박는다 — 태그와 실제가 어긋난다.
자료를 3분쯤 받은 뒤 스무 스텝 안에 손실이 눈에 띄게 내려가면 자료·설정이 맞물린 것이고, 처음부터 평평하면 자료 형식부터 다시 봅니다. 낱말: VLA·모방 학습·원격 조작 시범·정책(policy = 학습된 행동 규칙).

🌍 곁들여 — 세계 모델은 노트북이 낫다

  • 로봇을 학습시키려면 시행착오시킬 환경이 필요한데, 그 환경 자체를 모델이 만들어 낸다 — 지금 화면과 누른 키를 넣으면 다음 화면을 그린다. 계속 이으면 게임 엔진 없이 게임이 돈다(다음 화면에 확산, 같은 뼈대)
  • 손에 잡히는 DIAMOND(MIT)는 아타리용이 매개변수 441만·가중치 54MB — 오늘 가장 작다(세포 1.15GB·단백질 3.47GB와 자릿수가 다르다)
필요한 건 카드가 아니라 화면(창)창은 코랩에 없고 노트북엔 있다 — 카드 없는 노트북 초당 22장 vs 코랩 T4 16장
그 화면 뒤에 게임이 없다 — 공이 튀는 각도도 벽돌 판정도 그때그때 모델이 그린다. 학습 때 안 본 조작을 넣으면 흐물거리는데, 그 경계를 찾는 게 가장 빨리 이해하는 길. 큰 것은 담장 밖(슈팅판 1.5GB, Genie 비공개, Cosmos 26GB↑).
설치 명령은 외울 게 아니라 에이전트에게 물어봅니다("이 저장소를 내 노트북에서... README 보고 순서대로"). 다만 파이썬 판(3.10)은 직접 확인 — 안 맞추면 ale-py를 못 찾고 멈춥니다. m을 눌러 조종권을 받고 상태는 창이 아니라 터미널에 찍힙니다.

채점이 되는 곳에 걸리는 보상

검증 가능한 보상 · GRPO · Lean 정리 증명

⑨
마지막 갈래는 대상이 바깥세상이 아니라 모델 자신입니다. 네 발상 중 아직 제자리에서 풀지 않은 넷째, 검증 가능한 보상이 여기서 풀립니다.

🎯 사람이 채점하던 자리를 기계가

  • 정답을 하나로 못 정하는 일엔 정답표 대신 낸 답에 점수만 매기고 점수 높은 답이 더 자주 나오게 숫자를 옮긴다(강화학습, 그 점수가 보상). 병목은 늘 점수를 누가 매기느냐
  • 사람 취향 맞추기는 사람이 병목이었다 — 답 하나 채점에 사람 시간, 취향은 제각각, 정답 분명한 영역도 일일이 봐야
기계가 정답 여부를 확인할 수 있는 문제에만 보상수학 답이 맞았나, 코드가 통과했나, 증명이 검사기를 통과했나 — 사람이 필요 없어 몇백만 번이든
이 방식이 검증 가능한 보상. 규칙 채점 자체는 그전부터 쓰였고 이 이름을 붙인 게 2024년 11월. 몇 달 앞선 2024년 2월엔 이 학습을 훨씬 가볍게 돌리는 GRPO가 나왔다.
표 갈래에서 기준선을 세운 것과 뿌리가 같습니다 — 사람이 좋고 나쁨을 매기는 대신 기계가 스스로 점수를 낼 자를 먼저 세운다는 것.

더 나오게
  • 기존 방식은 "이 답이 평균 어느 정도 받을까"를 예측하는 별도 모델을 하나 더 둬야 했다(모델 둘, 메모리 두 배)
  • GRPO는 그 모델을 없앤다 — 같은 문제에 답을 여러 개 뽑아 그 안에서 서로 비교. 기준을 예측하는 대신 그때그때 만들어 쓴다. 별도 모델이 사라져 무료 코랩에서도 돈다
이것이 경계이기도 — 잘 쓴 보고서인지, 친절한 상담인지는 기계가 채점 못 한다. 그래서 폭발한 곳이 수학·코드·논리처럼 답이 자동 확인되는 영역에 몰려 있다. 회사 업무에 붙이려면 먼저 물을 것: 내 문제에 자동 채점기를 만들 수 있는가.
여덟 개를 뽑아 평균보다 잘한 답은 더 나오게, 못한 답은 덜 나오게 밉니다. 고쳐진 모델로 다시 답을 뽑는 고리를 반복합니다.

⏳ 이 갈래는 시간에서 걸린다

  • 도구가 닫혀서가 아니다 — 작은 모델용 GRPO 노트북에서 이름에 A100이 안 붙은 걸 고르면 무료 T4에서 시작은 된다. 막는 건 조건이 아니라 시간
  • 같은 문서가 보상이 오르는 걸 보려면 최소 300스텝, 쓸 만한 결과는 12시간 이상이라 적었다 — 수업 안에서는 곡선이 올라가는 것조차 보기 어렵다
그래도 이름은 값어치가 있다 — 시간 되는 날 켜 두고 다른 일을 하면 되고, 그때 검색어가 GRPO와 검증 가능한 보상. 대신 이 고리의 심장인 채점기 쪽은 손에 잡힌다(설치가 아예 없다).

조건도 볼 거리 — 핵심 꾸러미는 아파치 2.0인데 지원 라이브러리와 노트북 모음 저장소가 LGPL 3.0. LGPL은 가져다 쓰는 건 자유, 고쳐서 배포하면 고친 부분을 내놔야 하는 조건. 학습엔 걸릴 것 없고 제품에 넣을 때 무엇을 고쳤는지가 기준

📚 DeepSeekMath, arXiv:2402.03300 · huggingface/trl, GitHub · Qwen3 (4B) GRPO, unslothai/notebooks.

🧮 채점기가 가장 엄격한 곳 — Lean

  • 증명은 원래 사람이 읽고 판단한다. 그런데 기계가 검사할 수 있는 언어로 쓰면 달라진다 — Lean 같은 언어로 정의·논리를 엄격한 문법으로 적으면 검사기가 한 줄씩 확인해 통과 여부를 알려 준다. 사람의 판단이 개입할 여지가 없다
  • 그러면 틀릴 일이 없는 채점기가 생긴다 — 모델이 증명을 쓰고, 검사기가 통과 여부를 알려 주고, 통과한 걸 더 나오게 민다. 사람이 한 명도 필요 없다
왜 지금인가 — 검사기는 오래됐고, 바뀐 건 셋: 사람이 손으로 형식화한 수학 라이브러리가 수십만 줄로 쌓였고, 검증 가능한 보상이 자리 잡았고, 모델이 자기 증명을 검사기에 넣어 실패 메시지를 받아 고쳐 쓰는 고리까지 갖췄다(마지막이 특히 크다 — 어디가 왜 틀렸는지 알려 주니까).
참인 것 같은데 시작을 모르겠는 명제를 기계 형식으로 적어 후보 증명 서른 개를 뽑고, 검사기가 스물아홉을 떨어뜨리고 하나가 통과하면 그 증명은 맞다는 것이 이미 확인된 것 — 읽을 가치를 고민할 필요가 없습니다.

거짓 명제거부. omega 전술을 쓰면 반례가 만족할 조건까지
거짓 명제가 이 절을 요약 — 자연수에서 a - b + b = a가 참이라 주장하고 omega로 확인하면, 검사기가 거부하며 반례 조건으로 b가 a보다 크다는 것을 집어낸다(자연수 뺄셈은 0에서 잘려 실제로 거짓). "기계가 채점한다"가 추상이 아니다 — 1초도 안 돼 참·거짓이 갈리고 어디가 왜 틀렸는지까지.
검사기가 한 일을 만드는 게 전술(tactic) — "양변에서 빼라", "경우를 나눠라" 같은 명령 하나하나. 증명을 쓰는 모델이 하는 일도 다음 전술을 고르는 것입니다. 처음이면 NNG4 자연수 게임으로 전술을 배웁니다. Lean 4·표준 라이브러리 모두 아파치 2.0.

🧭 증명 모델 — 헷갈리기 쉬운 둘

  • 증명 쓰는 모델도 공개돼 있다 — Goedel-Prover-V2(80억·320억 아파치 2.0) 등. 다만 저장소에 라이선스 파일이 없는데 가중치만 조건이 붙거나, 저장소는 자체 라이선스인데 모델 카드에 태그가 없는 경우가 섞여 하나씩 확인
  • 실제로 채점하려면 Lean까지 함께 돌려 한 노트북에 두 세계를 얹는다 — 오늘은 사람이 쓰고 기계가 채점받는 데까지가 목표
헷갈리는 것주의
주소표준 문제집 원 저장소가 2023 보관 상태 → 지금은 포크(miniF2F 등). 옛 주소 그대로 걸면 안 됨
이름값올림피아드 금메달 시스템은 가중치가 안 나와 있다. 대신 표준 문제집 상위권 증명 모델이 아파치로 이미 받아 쓸 수 있다
이름이 큰 쪽이 열려 있는 쪽은 아니다 — 가중치가 어디에 어떤 조건으로 올라가 있는지로 갈라 봐야. 낱말: 검증 가능한 보상·GRPO·형식 정리 증명·Lean 4·전술·자동 형식화.
자동 형식화(autoformalization)는 사람 말로 적힌 수학 명제를 기계가 읽는 형식으로 옮기는 일로, 요즘 이 분야에서 가장 활발한 쪽입니다.

✅ 정답 & 해설

A1. 좌표·규칙을 사람이 적는 대신 화면과 말을 넣으면 관절 움직임을 낸다(시범으로 학습). 기반 모델(이미지·말 이해)과 확산(부드러운 동작)이 겹친다.
A2. 하나씩이면 갈림길에서 왼·오를 오가다 뭉개지고 동작이 떨린다. 묶음으로 내면 앞뒤가 이어지고 방향이 하나로 정해진다 — 앞부분만 실행하고 새 묶음.
A3. "평균 점수를 예측하는 별도 모델"을 없애고 같은 문제에 답 여러 개를 뽑아 그 안에서 비교 — 메모리가 줄어 무료 코랩에서도 돈다.
A4. 기계가 채점 못 하는 것(잘 쓴 보고서·친절한 상담)엔 못 건다 — 수학·코드·논리에 몰린 이유. 먼저 물을 것: 내 문제에 자동 채점기를 만들 수 있는가.
A5. 거부하고, omega 전술을 쓰면 반례가 만족할 조건까지 집어낸다(예: a-b+b=a는 b가 a보다 클 때 거짓). 어디가 왜 틀렸는지를 1초 안에.
A5가 "기계가 채점한다"가 추상이 아님을 보여 줍니다 — 이 채점기가 있어 그 위에 강화학습을 얹습니다.

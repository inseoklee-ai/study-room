단원 4 · AI는 문서와 사진에서 무엇을 꺼낼까 (5)

도구를 외우지 말고
AI로 선택하기

플립드 인터뷰 · 후보 조사 · 반박 · 실제 시험 · 사람의 결정

새 모델·서비스는 자주 나오고 같은 이름 아래 기능·가격·라이선스·데이터 조건도 바뀝니다. 다 외운 뒤 고르려 하면 공부가 끝나기 전에 목록이 낡습니다.

🗺️ 오늘의 흐름

  • 제품 목록을 외우는 게 아니라 선택하는 과정을 익힌다
  • 바로 추천받지 말고 먼저 질문받기(플립드 인터랙션) → 업무로 답하기
  • 요구사항 확인 후 현재 후보를 웹으로 조사 → 추천을 반박하고 실제 과제로 시험
  • AI의 조언과 사람의 결정을 분리하고 기록으로 남긴다
🎯 한 줄: AI는 질문자·조사원, 사람은 목적·허용 못 할 실패·데이터 반출·최종 책임을 결정합니다. 도구가 바뀌면 같은 과정을 다시 적용하면 됩니다.
Mollick: 공개 벤치마크만으론 내 일에 맞는지 알기 어렵고, 새 모델이 나오면 실제 업무 평가를 주기적으로 다시 해야 합니다.

🧭 외우기가 아니라 과정

외우기

OCR·문서 VLM·멀티모달·탐지·분할의 모든 제품을 외운 뒤 고르기 → 공부가 끝나기 전에 목록이 낡음

과정

1

바로 추천받지 말고, 먼저 질문을 받는다

Flipped Interaction Pattern

AI가 질문을 주도
Mollick: 충분한 맥락을 주고 원하는 결과를 분명히 하며, 한 번의 답으로 끝내지 말고 왕복 대화를. 요구사항을 잘 모르면 AI가 질문하게 해도 좋다.

🙋 플립드 인터랙션 — AI가 질문을 주도

Vanderbilt Jules White 팀: 사용자는 달성할 목표와 질문을 멈출 조건을 알려 주고, 필요하면 한 번에 하나씩 묻게 지정.

▼ 프롬프트 ① 상담 시작
문서나 사진을 처리할 AI 도구를 고르려고 해.
도구를 추천하기 전에 내 업무와 제약을 이해하도록 질문해 줘.
추천에 필요한 정보가 충분해질 때까지 질문하고,
내가 답하기 쉽도록 한 번에 질문 하나만 해 줘.

내 답을 추정해서 채우지 말고 모르는 것은 미확인으로 남긴다.
질문이 끝나면 네가 이해한 요구사항·가정한 것·아직 모르는 것을
구분해 요약하고 내가 확인할 때까지 추천을 시작하지 않는다.
'현재까지 요약해 줘' 하면 질문을 멈추고 같은 형식으로 요약한다.

상담 중에는 실제 기밀 파일이나 개인정보 업로드를 요구하지 않는다.
첫 질문을 시작해 줘.
목표 + 질문 멈출 조건 + 한 번에 하나 — 이 세 가지를 미리 지정하는 것이 플립드 인터랙션의 뼈대입니다.
2

질문엔 기술 이름이 아니라 업무로

"최신 모델을 쓰고 싶다"는 도움이 안 된다

모르는 건 미확인
선택에 유용한 건 기술 이름이 아니라 업무 정보입니다.

📋 선택에 유용한 업무 정보

  • 무엇을 입력하고 어떤 형태의 결과를 받아야 하나
  • 잘 나온 예가 아니라 실제로 어려운 입력은 무엇인가
  • 무엇을 놓치거나 잘못 만들면 피해가 큰가 · 원문의 근거(위치)를 남겨야 하나
  • 파일을 외부로 보내도 되나 · 처리량·대기 시간·예산·실행 장치는
  • 결과를 누가 검토하고 최종 승인하나
🔑 모르는 조건은 AI가 대신 정하게 하지 말고 미확인으로. 외부 전송·법적 의무·사람에게 영향을 주는 자동 판정은 담당자가 확인. 확인 전에는 공개·직접 만든 예시만 쓰고 실제 파일·개인정보·자격 증명·내부 주소는 대화에 올리지 않음.
이 목록은 표준이 아니라, 이 수업의 문서·사진 사례에서 AI에게 줄 맥락의 예입니다.
3

요구사항 확인 뒤, 현재 후보를 조사

기억에 의존한 추천은 쓰지 않는다

공식 근거 우선
도구가 자주 바뀌므로 기억에 의존한 추천은 쓰지 않습니다. OpenAI도 모델 답을 최종 출처가 아닌 초안으로 보고 직접 확인하라고 안내합니다.

🔎 현재 후보를 웹으로 조사

▼ 프롬프트 ② 후보 조사
내가 확인한 요구사항을 기준으로 오늘 선택할 수 있는 도구를 웹에서 조사해 줘.
기억에만 의존하지 말고 원 논문·공식 문서·저장소,
공식 가격·라이선스·데이터 처리 정책을 우선 확인한다.

먼저 내 필수 조건을 충족하지 못해 탈락하는 후보와 이유를 적고,
남은 후보만 비교 가능한 표로 정리한다.
각 후보: 정확한 제품·모델·패키지 이름, 확인 날짜, 근거 URL,
지원 입력·출력, 로컬·클라우드 실행 조건, 비용·라이선스·데이터 전송,
확인된 사실 / 자료에서 한 추론 / 아직 모르는 것.

웹 검색·링크 열기가 불가능하면 조사한 척하지 말고
무엇을 확인할 수 없는지 알려 줘.
검색 못 하는 AI엔 교안의 공식 링크를 붙여 "링크만 읽고 비교, 확인 못 하면 미확인"으로. 링크를 붙였다는 사실만으로 검증 끝이 아님 — 직접 열어 문구·날짜 확인. 공식 문서의 "지원한다"는 내 자료에서 "잘된다"가 아니므로 성능은 실제 표본 시험으로.
탈락 후보와 이유를 먼저 적게 하면, 남은 비교표가 훨씬 신뢰할 만해집니다.
4

추천을 반박하고, 실제 과제로 시험

아첨 편향을 먼저 흔든다

논리 검토 ≠ 실제 출력
AI는 사용자가 드러낸 견해에 지나치게 동의하는 아첨 편향(sycophancy)을 보일 수 있습니다.

🥊 아첨 편향을 흔드는 반박

Anthropic 연구: 여러 AI가 사용자 견해에 맞추는 아첨 행동을 보였고, 평가자·선호 모델도 견해와 일치하는 답을 더 선호. 한쪽만 들은 상담의 과도한 확신은 위험.

▼ 프롬프트 ③ 추천 반박
이 추천을 결론으로 확정하지 말고 다시 검토해 줘.
- 어떤 가정 위에서 추천했는가
- 어떤 사실이 확인되면 추천이 뒤집히는가
- 가장 강한 다른 후보는 무엇이며 어떤 조건에서 더 나은가
- 실제 자료 없이 판단할 수 없는 것은 무엇인가

나의 선호에 맞추지 말고 확인된 사실·추론·미확인을 구분해 답해 줘.
🔑 그다음은 논리가 아니라 실제 출력을 시험 — 벤치마크만 X, 실제 업무와 닮은 과제를 만들고 여러 번 실행해 비교, 판단할 수 있는 사람이 평가, 주기적 반복. 반론을 잘 쓰는 것과 실제 자료에서 잘 작동하는 것은 다른 검증.
AI가 반박을 잘 써 준다고 후보가 좋은 건 아닙니다. 두 검증(논리·실제 출력)을 분리하세요.
5

AI의 조언과 사람의 결정을 분리한다

그리고 기록으로 남긴다

NIST AI RMF
AI는 후보 조사·빠진 조건 찾기·비교 시험 초안을 도울 수 있지만, 결정은 책임 있는 사람이 합니다.

⚖️ 역할 분리 & 기록

AI가 돕는 일

후보 조사 · 빠진 조건 찾기 · 비교 시험 초안

사람이 결정

외부 전송 여부 · 감수할 오류 · 법률·보안 충족 · 사람에게 영향을 주는 자동 승인

NIST AI RMF도 사람·AI의 역할과 감독 책임을 구분하고, 시험·평가·검증 절차와 결과를 문서화하도록 제시.

▼ 프롬프트 ④ 기록 (outputs/tool_choice.md)
이 대화에서 확인된 내용만 사용해 Markdown 기록을 만들어 줘.
- 조사한 업무와 자료 / 공식 근거를 확인한 후보
- 확인된 사실 / 추론 / 미확인
- AI가 판단할 수 없어 사람이 결정할 사항
- 실제 업무와 닮은 비교 자료와 평가 방법
- 선택을 다시 조사해야 할 변화나 실패
확인하지 않은 정책·기준은 추정하지 말고 [사람이 결정]으로 남긴다.
기록이 있어야 도구가 바뀌었을 때 무엇을 다시 조사할지 판단할 수 있습니다.

🧪 상담과 실제 시험을 나눠 진행

  • 세 프롬프트 순서: 질문으로 요구사항 → 사람 확인 → 후보 조사 → 가정·반대안 검토. 웹 조사·기록·직접 실행은 실제 선택이 필요할 때
  • 뒤 PDF·YOLO 실습의 고정 도구는 상담 추천과 같다는 보장이 없음 → "그 후보를 검증"이라 말하지 않고, 상담에서 드러난 평가 기준(출력·근거·위험 오류·데이터 처리)을 고정 도구에 적용하는 공통 예제로 사용
  • 비교엔 잘 나온 자료만 고르지 않음 — 문서=기울어짐·도장 겹침·복잡한 표, 사진=가림·역광·작은 대상
🔑 목표는 이름을 다 외우는 게 아니라 — 내 일을 질문하게 하고, 현재 후보·공식 근거를 조사하게 한 뒤, 닮은 과제로 평가하고 사람이 결정. 도구가 바뀌면 같은 과정을 반복.
한 번의 좋은 출력만 보고 결정하지 않고, 같은 평가 기준으로 어려운 자료까지 비교합니다.

1제품을 외우지 말고 선택하는 과정을 익힌다 (도구는 목록보다 빨리 낡음)
2바로 추천받지 말고 플립드 인터랙션 — 목표+멈출 조건+한 번에 하나
3질문엔 기술 이름이 아니라 업무로 답하고, 모르는 건 미확인으로

5아첨 편향을 반박으로 흔들고, 실제 닮은 과제로 출력을 시험(주기적 반복)

✅ 정답 & 해설

A1. 모델·가격·라이선스·데이터 조건이 자주 바뀌어 다 외우면 목록이 낡음. 대신 내 일 설명 → 후보 찾기 → 실제 자료로 갱신하는 과정을 익힌다.
A2. AI가 목표 달성에 필요한 질문을 주도하는 방식. 사용자는 달성할 목표 + 질문을 멈출 조건(+한 번에 하나)을 지정.
A3. 입력·출력, 실제 어려운 입력, 피해 큰 실수, 근거 보존, 외부 전송 가부, 처리량·시간·예산, 검토·승인자. 모르는 조건은 미확인으로 두고 담당자가 확인.
A4. "지원한다"는 기능 유무일 뿐 내 자료에서 잘된다는 보장이 아님(성능은 표본 시험으로). 링크는 직접 열어 문구·날짜를 확인해야 검증.
A5. AI가 사용자의 견해에 지나치게 동의하는 경향. 한쪽만 들은 과도한 확신을 막으려고 가정·반대안·뒤집는 사실을 스스로 대게 반박시킨다.
A6. AI = 후보 조사·빠진 조건·비교 초안. 사람 = 외부 전송·감수할 오류·법률/보안·자동 승인 결정(NIST: 역할·감독 구분, 문서화).

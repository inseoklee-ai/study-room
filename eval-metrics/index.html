평가지표 사전 — 점수는 질문의 축소판

1

지표라는 자

점수는 질문의 축소판이다

자 하나가 길이·무게·온도를 다 못 잰다
시험지에는 답보다 먼저 문항·배점·채점 기준이 놓입니다. 평가지표도 답의 어느 성질을 숫자로 바꿀지 정한 자입니다. 자를 고르기 전에 무엇을 재려는지부터 정해야 합니다.

📏 지표 = 답의 성질을 숫자로 바꾸는 자

  • 자 하나가 길이·무게·온도를 다 못 재듯, 한 점수가 사실성·형식·유용성·안전성을 함께 뜻하지 않는다
  • 먼저 과업의 성공을 문장으로 쓰고, 그 문장을 가장 적게 왜곡하는 지표를 고른다
  • 시험 입력·실행 조건·판정 규칙을 고정하지 않으면, 숫자 차이는 지시 효과가 아니라 조건 차이일 수 있다
평가 = 마음에 드는 결과를 고르는 일이 아니라, 무엇을 어떤 근거로 통과시킬지 결과 전에 정하는 일.
같은 시험 입력·같은 실행 조건·같은 판정 규칙을 고정하지 않으면, A와 B의 점수 차이가 프롬프트 때문인지 조건이 달라서인지 구분할 수 없습니다. 지표를 고르는 일은 곧 무엇을 잃을 위험을 감수할지 고르는 일이기도 합니다.
2

참조와 겹침으로 재는 지표

기준 답이 있고 표면을 비교할 수 있을 때

이진 판정·exact match · F1 · BLEU · ROUGE
기준 답(golden answer)이나 참조 번역·요약이 있을 때 쓰는 지표들입니다. 값싸고 재현 가능하지만, 대부분 표현·표면을 볼 뿐 사실성 자체는 못 잰다는 공통 한계가 있습니다.

✔️ 이진 판정 · exact match

  • 이진 판정 = 조건 지키면 1, 아니면 0. exact match = 출력이 기준 답과 정확히 같을 때만 통과
  • 적합: 선택지 분류·고정 레이블·짧고 유일한 추출 답·정형 JSON·함수 호출
  • 예: 허용 답 긍정/부정이면 대체로 긍정은 뜻이 가까워도 계약 밖. JSON은 파싱 후 필드 순서·공백을 정규화해 비교하고 규칙을 문서화
값싸고 재현 가능하나, 표현만 다른 옳은 자유 답을 0점으로 만들고 사실성 자체는 못 잰다.
가장 싸고 빠른 자입니다. 결정적으로 채점 가능한 과업이면 여기부터 시작합니다. 단, 같은 뜻을 다르게 쓴 답을 실패로 처리하고, 형식이 맞아도 내용이 참인지는 보증하지 못합니다.

🎯 F1 — 정밀도와 재현율의 조화평균

정밀도(precision)맞다고 넣은 것 중
실제 정답 비율
·
재현율(recall)실제 정답 중
찾아낸 비율
→
F1둘의 조화평균
  • 적합: 개체 추출·키워드·다중 레이블처럼 답이 항목 집합인 과업
  • 두 위험(오탐·누락)을 함께 드러내지만, 어느 쪽이 더 위험한지는 숨길 수 있다
밝힐 것 — 양성 레이블·매칭 규칙, micro/macro/weighted 중 어떤 평균인지, 그리고 정밀도·재현율을 나란히.
F1은 오탐과 누락을 한 숫자로 묶습니다. 그래서 편리하지만, 누락이 더 위험한 과업인지 오탐이 더 위험한 과업인지는 F1 하나로 알 수 없습니다. 정밀도와 재현율을 함께 적어야 합니다.

🧮 F1 손 계산 — 기관명 추출

원문에 실제 기관명 12개. 모델이 10개를 냄 → 8개 맞음(TP), 2개 틀림(FP), 빠진 4개(FN).

값계산결과 · 뜻
정밀도 P8 / 100.80 — 오탐 위험
재현율 R8 / 12≈ 0.67 — 누락 위험
F12×(0.80×0.67) / (0.80+0.67)≈ 0.73 — 조화평균, 작은 쪽에 민감
산술평균은 한쪽 붕괴를 너무 부드럽게 본다 — P=1.0, R=0.0이면 산술 0.5, 조화 0.0.
조화평균은 두 값 중 작은 쪽에 민감해, 한쪽이 무너지면 F1도 함께 무너집니다. 암 마커는 재현율을 먼저, 스팸 차단은 정밀도를 먼저 보아야 합니다. F1 하나로 어느 피해가 더 큰지 대신 결정하지 않습니다.

🌐 BLEU — n-gram 중첩(정밀도 관점)

  • 후보와 참조 답의 n-gram 중첩을 주로 정밀도로. n-gram = 연속한 n개 토큰 조각
  • 번역처럼 참조가 있고 표면 겹침이 유용할 때 보조 지표. 짧은 답 벌점(brevity penalty) 포함

손 계산

참조 고양이가 매트 위에 앉았다 / 출력 고양이가 매트에 앉았다

단위겹침값
1-gram5 / 51.00
2-gram3 / 40.75

위가 빠지며 매트-위·위-에 2-gram이 끊긴다.

실제 BLEU는 여러 n-gram 결합 + clipped count. brevity penalty는 감점만 할 뿐 의미를 채점하지 않는다 — 부정어 하나가 바뀌어도 조각은 겹칠 수 있다.
clipped count는 참조에 있는 횟수까지만 겹침으로 세는 규칙입니다. 좋은 번역도 어순이 다르거나 동의어를 쓰면 낮은 BLEU를 받고, 반대로 겹친다고 자연스럽거나 사실이라는 보장은 없습니다.

📝 ROUGE — 재현율 관점의 요약 지표

무엇을 재나

참조 요약의 n-gram을 후보가 얼마나 포착했나, 특히 재현율 관점. ROUGE-N(n-gram), 문장열 ROUGE-L.

한계

길게 쓰면 재현율이 부풀고, 동의어·바꿔쓰기·사실 오류·흐름을 충분히 판단 못 함.

BLEU가 정밀도쪽이면 ROUGE는 재현율쪽 — 둘 다 표면 겹침이라 사람 표본 검토·구체 채점표와 결합한다.
번역은 참조와 얼마나 정확히 겹치나(BLEU), 요약은 참조 내용을 얼마나 담았나(ROUGE)로 짝지어 기억하면 편합니다. 둘 다 단어 겹침이라, 주문번호를 발명했는지 같은 사실성 문제는 잡지 못합니다.
3

참조 없이 재는 지표

확률·실행·사람 판단으로 재기

perplexity · pass@k · LLM-as-judge
기준 답을 일일이 준비하기 어려운 경우입니다. 모델 내부 확률(perplexity), 코드 실행 결과(pass@k), 강한 모델의 채점(LLM-as-judge)으로 재되, 각각 무엇을 못 재는지가 특히 중요합니다.

📉 perplexity — 모델 내부 확률 지표

  • 실제 다음 토큰에 준 확률의 평균 음의 로그우도를 지수화. 낮을수록 다음 말을 덜 놀라워함
  • 쓰임: 같은 모델·토크나이저·코퍼스에서 언어모델링 적합도·학습 변화 비교

직관 — 대한민국의 수도는 다음

서울에 0.90을 주면 실제로 서울일 때 덜 놀람(≈1/0.90) · 바나나에 0.001을 주면 큰 놀람(≈1000 규모)

⚠️ 프롬프트 품질 점수로 쓰면 안 됨 — 확신하는 답이 옳은 답은 아니다. 모델은 틀린 배송일도 매우 자신 있게 이어 쓸 수 있다.
실제 PPL은 문장 전체 로그확률의 평균이라 단순 역수와 같지는 않지만 직관은 같습니다. temp 0으로 세 번 돌려도 근거 없는 답이 반복될 수 있듯, 무작위성을 줄인 설정이 오답을 검증·교정해 주지는 않습니다. 프롬프트 비교엔 근거 없는 날짜 금지·확인 질문 여부처럼 과업 성공을 직접 판정하는 기준을 씁니다.

🧪 pass@k — 실행해 검증하는 코드 지표

  • 독립적으로 만든 후보 k개 중 적어도 하나가 단위 테스트를 통과할 확률(또는 추정치)
  • 적합: 코드·SQL·정형 프로그램처럼 실행해 검증 가능하고, 사용자가 여러 후보를 받을 수 있을 때

손 계산

후보 10개, 3개가 모든 테스트 통과 → pass@1 추정 3/10 = 0.3. 통과 = 설명이 그럴듯함이 아니라 실제 실행 결과(컴파일 오류·예외·틀린 반환값은 모두 실패)

후보 다양성이 성능의 일부 — temp 낮으면 비슷한 코드 반복, 높으면 다양하나 오류도↑. 테스트가 누락한 경계에선 통과 코드도 실패할 수 있어 완전한 보증으로 읽지 않는다.
k는 사용자가 몇 후보까지 받아 실행하는가입니다. 10개 중 3개가 통과라면 세 후보 묶음에 통과 코드가 들 기회가 한 후보보다 크지만, 어떤 셋을 보이는지와 다양성에 따라 달라집니다. 보고엔 온도·샘플링·후보 수·선택 규칙·테스트 커버리지를 함께 남깁니다.

⚖️ LLM-as-judge — 강한 모델의 채점

  • 강한 모델에 상세 rubric(채점 항목·기준)과 기준 답/문맥을 주어 다른 모델의 열린 답을 채점
  • 적합: 참조 답이 없고 유용성·문체·추론·사실성처럼 열린 생성 품질을 대량 비교할 때의 1차 신호
  • 편향: 답 순서·장황한 답 선호·자기 모델 계열 선호가 결과를 바꿀 수 있다
방어 — 모델·버전·rubric·문맥·기준 답 기록, 쌍대 비교 위치 무작위화, 사람 표본 검토와 맞춤. 중요 업무의 최종 기준은 사람이 맡는다.
심사 모델의 한 점수를 사람 정답처럼 취급해선 안 됩니다. 싼 지표로 비싼 판단을 흉내 내기보다, LLM-as-judge는 대량 1차 선별에 쓰고 남은 불확실성만 사람이 검토하는 편이 낫습니다.

❓ 지표 고르는 질문 3개 (대체로 비용 순서)

1결정적으로 채점 가능한가? → 테스트·validator·이진 판정부터 (가장 싸고 빠름, 단 사실성까지 보장 안 함)
2참조 답과 비교해야 하나? → 유일한 답은 exact match, 항목 집합은 F1, 표면 비교는 BLEU (정답·매칭 규칙 만드는 비용)
3사람 판단이 필요한가? → rubric + LLM-as-judge 보조 + 사람 표본 검토 (가장 비쌈)
싼 지표로 비싼 판단을 흉내 내기보다, 남은 불확실성에만 사람 검토를 붙인다.
비용은 대체로 1에서 3으로 올라갑니다. 형식 준수도 작은 판정으로 나눌 수 있습니다 — 파싱 가능·필수 필드·추가 필드 금지·빈값 처리·근거 원문 포함은 서로 다른 실패이고, 앞의 셋은 validator가 빠르게, 마지막은 입력과 대조해 확인합니다.

📌 이것만은 꼭 — 핵심 4문장

1지표는 답의 한 성질을 재는 자다 — 한 점수가 사실성·형식·유용성·안전성을 함께 뜻하지 않는다.
2참조 겹침 지표(exact·F1·BLEU·ROUGE)는 표면을 보고, 사실성 자체는 못 잰다.
3perplexity는 확신, pass@k는 실행, LLM-as-judge는 열린 품질 — 최종 기준은 사람이 맡는다.
4보고엔 평균 하나만 남기지 말고 사례 수·경계 사례·모델과 버전·생성 매개변수·정규화 규칙·분자와 분모를 남긴다.
점수 차이가 작거나 사람 검토와 어긋나면 승자를 억지로 선언하지 말고, 어느 사례에서 어떤 약속이 깨졌는지 원문 근거를 남깁니다. 지표를 고른 뒤에도 실패 사례 몇 개를 직접 읽어, 점수는 올랐는데 업무상 나빠진 답이 없는지 확인합니다.

🎯 이해도 확인 질문

Q1. exact match가 0점으로 만들어 버리는 옳은 답은 어떤 경우인가?
Q2. P=0.80, R=0.67일 때 F1은 얼마이며, 왜 산술평균과 다른가?
Q3. BLEU와 ROUGE는 각각 주로 정밀도·재현율 중 어느 관점인가?
Q4. perplexity를 프롬프트 품질 점수로 쓰면 안 되는 이유는?
Q5. 지표를 고르는 질문 3개는 대체로 어떤 순서로 놓이나?
답이 바로 떠오르지 않으면 앞 장으로 돌아가 확인해 보세요. Q2의 손 계산과 Q4의 한계가 오늘의 핵심을 가장 잘 가립니다.

✅ 정답 & 해설

A1. 표현만 다른 옳은 자유 답 — 허용 답이 긍정인데 대체로 긍정처럼 뜻은 가깝지만 계약 밖인 경우.
A2. F1 ≈ 0.73 = 2×(0.80×0.67)/(0.80+0.67). 조화평균이라 작은 쪽에 민감 — P=1.0·R=0.0이면 산술 0.5, 조화 0.0.
A3. BLEU = 정밀도 관점(번역), ROUGE = 재현율 관점(요약). 둘 다 표면 겹침이라 사실성은 못 잰다.
A4. 확신하는 답이 옳은 답은 아니기 때문. 모델은 틀린 배송일도 매우 자신 있게 이어 쓸 수 있다 → 과업 성공을 직접 판정하는 기준을 쓴다.
A5. ① 결정적 채점 가능? → ② 참조 답과 비교? → ③ 사람 판단 필요? — 대체로 비용이 오르는 순서.
A2를 손으로 다시 계산해 보고, A4를 자기 말로 설명할 수 있으면 오늘 목표는 달성입니다.

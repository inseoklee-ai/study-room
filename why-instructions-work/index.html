왜 지시가 통하는가

학습의 계보 — 지시 따르기는 형성된 행동이다

프롬프트에 따라 답이 달라진 사실은 분명하지만, 그 차이가 어디서 오는지는 아직 설명이 아닙니다. 이 소단원은 지시 따르기가 모델에 처음부터 있던 기능이 아니라 데이터와 피드백으로 형성된 행동임을 학습의 계보로 추적합니다.

1

지시를 이해한다는 말의 범위

모델이 지시를 "따른다"는 것은 무엇인가

형성된 행동 · 능력 ≠ 의도 준수
모델이 지시를 따른다고 할 때, 사람처럼 명령형을 논리적으로 해독한다고 단정하면 안 됩니다. 같은 문장이라도 모델 세대와 대화 형식에 따라 결과가 다른 이유가 여기서 출발합니다.

🧬 지시 따르기는 형성된 행동

  • 같은 문장이라도 모델 세대·대화 형식에 따라 결과가 다르다
  • 지시 따르기는 모델에 처음부터 있는 기능이 아니라 데이터와 피드백으로 형성된 행동이다

base LM — 사전학습된 모델

대규모 텍스트에서 다음 단어 예측으로 학습. 문장을 잇는 능력은 있어도 의도·안전한 거절·형식을 자동으로 우선하지 않는다.

"지시를 안 따른다"를 고집이 아니라 어떤 행동이 학습되었는가의 문제로 읽는다.
base LM은 언어를 잇는 능력을 가졌을 뿐입니다. 의도를 우선하는 성질은 이후 단계에서 형성됩니다. 그래서 실패를 성격이 아니라 학습 이력의 문제로 봅니다.

⚖️ 능력 ≠ 의도 준수

넓은 과업 수행 능력

다양한 문제를 풀어내는 힘. 커졌다는 관찰은 사실이다.

의도 준수

이번 요청의 경계·형식·금지를 안정적으로 따르는 성질. 능력과 구별된다.

GPT-4 기술 보고서는 능력이 커졌다는 관찰을 "사용자 의도를 자동으로 따른다"는 보장으로 바꾸지 않는다.

두 오해를 동시에 멈춰 세운다 — "더 큰 모델이니 지시는 짧아도 된다"와 "지시를 길게 쓰면 능력 부족도 해결된다".
새 모델을 도입할 때는 능력 시연과 의도 준수 평가를 분리해 적고, 우리 업무의 경계 입력에서 직접 재야 합니다. 크기만으로 지시 준수 품질을 예측하지 않습니다.
2

학습의 계보

지시-응답 관계와 선호는 어떻게 배우는가

SFT · instruction tuning · 선호 학습
이제 계보의 각 단계를 따라갑니다. 사전학습에서 시작해 지시-응답 관계를 배우는 단계, 선호를 반영하는 여러 길, 그리고 대화 템플릿까지 이어집니다.

역할·순서
SSFT(지도 미세조정) — 사람이 쓴 지시-응답 쌍으로 조정. 질문 뒤에 어떤 답이 이어져야 하는지 직접 배운다
Iinstruction tuning(지시 미세조정) — 자연어 지시로 표현한 여러 과업 묶음으로 학습. 한 문장 명령이 아니라 다양한 과업에서 지시-산출물 관계를 반복해서 본 이력
SFT는 "이 지시엔 이런 답"이라는 시연을 직접 배웁니다. instruction tuning은 그것을 여러 과업으로 넓혀, 지시-산출물 관계 자체를 반복 학습하는 것입니다.

평가 분포에서
1.3B InstructGPT가 175B GPT-3보다 선호단, 모든 과업·모델에서의 우월성이 아니다 — 모델 크기만으로 지시 준수 품질을 예측하지 말 것
'이 지시엔 이런 답'(시연)과 '여러 답 중 이런 답을 선호'(판단)를 구별한다.
1.3B가 175B보다 선호됐다는 결과는 강렬하지만, 특정 평가 분포에서의 선호일 뿐입니다. 모든 과업과 모델에 걸친 우월성으로 확대 해석하면 안 됩니다.

📈 FLAN — 지시로 배운 일반화

  • 60개 넘는 NLP 과업을 자연어 지시 템플릿으로 학습
  • 평가 25개 중 20개에서 zero-shot GPT-3보다 높음
  • 여러 지시-응답 관계를 배운 모델이 안 본 과업에도 어느 정도 일반화
25개 중 20개 과업에서 zero-shot GPT-3 상회단, 학습 분포 밖 낯선 규칙·희귀 언어·모순 조건까지 보장하진 않는다
새 지시가 실패하면 문장만이 아니라 그 모델이 본 과업 분포와의 거리를 의심한다.
FLAN은 지시 미세조정이 일반화를 낳는다는 증거입니다. 그러나 일반화는 학습 분포 근처까지입니다. 낯선 규칙이나 희귀 언어에서 실패하면, 프롬프트 문장보다 분포 거리를 먼저 봐야 합니다.

🛤️ 선호를 반영하는 여러 길

RRLHF — 사람 피드백 선호를 쓰는 강화학습(보상 모델+PPO). 유용하지만 보상 모델·강화학습 운영의 복잡성·안정성 문제. 친절한 답을 보장하는 마법이 아니라 특정 데이터·기준 아래 선택된 학습 경로
DDPO — 선호 쌍으로 별도 보상 모델·강화학습 없이 직접 정책 최적화. DPO의 존재는 모든 후속 모델이 같은 절차를 쓴다는 뜻이 아니라 선호 반영 구현이 하나가 아니라는 뜻
GGRPO — 한 문제에서 여러 답을 뽑아 그룹 내 상대적 보상으로 학습하는 PPO 변형(DeepSeekMath·DeepSeek-R1). RLHF의 동의어 아님 — 어떤 보상·검증을 넣었는지가 행동을 좌우
선호 학습 = 후보 응답 중 무엇을 더 낫다고 볼지의 신호로 행동을 조정하는 계열.
제품 답변이 공손하고 형식을 지켜도 특정 방법 하나의 효과로 단정할 수 없습니다. GRPO의 그룹 상대 보상이 반드시 사람 선호인 것도 아니어서, "추론을 더 요구하면 언제나 낫다"식 해석을 피해야 합니다.

🧭 계보를 설계 판단으로 압축

계보 단계학습 신호바뀌는 행동오해하면 안 될 것
사전학습다음 토큰 예측(대규모 텍스트)언어 규칙·넓은 지식 패턴 이어쓰기업무 절차·안전 경계가 자동 보장 안 됨
SFT사람이 만든 지시-모범 응답요청 형식·과업 수행 기본 습관예시에 없던 경계 입력까지 정확해진 증거 아님
선호 학습두 응답 중 나은 쪽 비교말투·거절·유용성 경향 조정모델 선호가 제품 정책·법적 판단 대신 못함
대화 템플릿역할 토큰·메시지 순서system·developer·user 구획 읽는 방식같은 문장을 다른 위치에 넣어도 항상 같은 효과는 아님
모델 스냅샷·템플릿을 바꾸면 성공 문의만 재실행하는 걸로는 부족 — 같은 판정표로 전후 비교한다.
고객지원 모델을 새 스냅샷으로 바꾸거나 템플릿을 교체하면, 주문번호 없는 배송일 질문, 문서에 지시처럼 보이는 문장이 섞인 문의, JSON이 비어야 하는 문의를 같은 판정표로 전후 비교해야 합니다. 이전 통과가 새 조합의 통과를 보증하지 않습니다.
3

형식과 긴장

대화 형식도 학습된 인터페이스다

few-shot · 인컨텍스트 러닝 · chat template
지시 따르기가 학습된 행동이라면, 그 지시를 담는 대화 형식 역시 학습된 인터페이스입니다. 이 파트에서 형식의 작동과 The Bitter Lesson이 남기는 긴장을 봅니다.

💬 대화 형식도 학습된 인터페이스

Ffew-shot — 입력에 입출력 예시 몇 개로 과업 경계·형식을 보인다
I인컨텍스트 러닝 — 가중치를 이 호출 중 업데이트하지 않은 채 예시·문맥으로 응답 패턴을 맞추는 능력. 예시는 학습된 능력을 호출하는 조건이지, 데이터 부족·모순 과업을 해결하는 증거가 아니다
Cchat template — system·user·assistant 역할을 특수 토큰·순서로 직렬화하는 대화 형식(모델마다 역할명·제어 토큰이 다를 수 있음)
같은 자연어라도 올바른 템플릿 안의 user 지시인지 평문에 섞인 문자열인지에 따라 다르게 작동 — 지시 따르기가 학습된 형식임을 보여 주는 실무 증거.
few-shot과 인컨텍스트 러닝은 별개의 학습이 아니라, 예시로 이미 학습된 능력을 불러내는 방식입니다. chat template은 같은 문장이 위치에 따라 다르게 작동함을 보여, 형식이 학습되었다는 사실을 실무에서 확인시킵니다.

🪨 The Bitter Lesson과 설계자의 긴장

Sutton(2019): 체스·바둑·음성·비전 역사에서 사람이 손으로 설계한 지식보다 계산 규모를 활용한 탐색·학습이 장기적으로 이겼다는 역사적 주장(실험 결과 아님).

학습에 맡길 수 있는 것

규모가 커질수록 사람의 조정 일부는 모델 안으로 들어갈 수 있다.

밖에 남는 것

고객의 실제 정책·이번 문서 원문·확인 기준 같은 과업 고유 맥락과 검증.

지시 설계는 인간 규칙을 다시 심는 일일까, 이번 과업의 목표·자료 경계를 전달하는 일일까 — 어디까지 학습에 맡길지는 계속 측정할 설계 선택이다.
The Bitter Lesson은 손으로 심은 지식이 규모에 밀렸다는 역사적 관찰입니다. 그렇다고 모든 조정이 사라지는 것은 아닙니다. 이번 고객의 정책과 문서 원문, 확인 기준은 여전히 밖에서 계약으로 적어야 하는 영역입니다.
4

설계자에게 남는 세 판단

계보를 알고 나면 무엇을 하는가

이식성 · 오진단 방지 · 독립 검증
계보를 이해했으면 실무의 판단으로 옮깁니다. 지시의 이식성, 실패 원인의 환원 금지, 안전과 권한의 독립 검증 — 세 가지입니다.

🧱 설계자에게 남는 세 판단

1지시는 모델 독립적 마법 문장이 아니다 — 모델·스냅샷·언어·대화 형식을 바꾸면 대표 평가셋에서 다시 측정. 성공 사례 한 개는 이식성의 증거가 아니다
2실패 원인을 지시문 한 줄로 환원하지 말 것 — 형식을 놓쳤다면 과업 모호성·chat template·디코딩 설정·SFT 데이터 분포가 함께 후보. 변경/고정 조건을 기록해 오진단 방지
3안전·권한은 지시 준수 학습에만 맡길 수 없다 — 거절을 잘해 보여도 도구 호출 권한·주문 변경·개인정보 접근은 애플리케이션이 독립 검사
지시는 기대 행동을 조정하는 층, 검증·권한 부여는 기대가 빗나가도 남아야 하는 층이다.
세 판단은 각각 이식성, 오진단 방지, 방어의 이중화를 겨눕니다. 특히 3번은 지시와 검증을 서로 다른 층으로 분리하라는 태도로, 이 강의 전체를 관통합니다.

📌 이것만은 꼭 — 핵심 4문장

2계보는 base LM → SFT → 선호 학습(RLHF·DPO·GRPO) → 대화 템플릿으로 이어진다.

✅ 정답 & 해설

A1. 넓은 과업 수행 능력과, 이번 요청의 경계·형식·금지를 안정적으로 따르는 성질은 별개다. 능력 증가가 의도 자동 준수를 보장하지 않는다.
A2. base LM(다음 토큰 예측) → SFT·지시 미세조정 → 선호 학습(RLHF·DPO·GRPO) → 대화 템플릿.
A3. 특정 평가 분포에서의 선호일 뿐 모든 과업·모델의 우월성이 아니다. 모델 크기만으로 지시 준수 품질을 예측하지 않는다.
A4. 올바른 템플릿 안의 user 지시인지, 평문에 섞인 문자열인지에 따라 작동이 갈린다 — 지시 따르기가 학습된 형식이기 때문.
A5. 거절을 잘해 보여도 도구 권한·주문 변경·개인정보 접근은 애플리케이션이 독립 검사해야 한다. 검증·권한은 기대가 빗나가도 남아야 하는 층.
A3과 A5를 자기 말로 설명할 수 있으면 오늘 목표는 달성입니다. 수치는 언제나 원 출처의 평가 조건과 함께 인용하세요.

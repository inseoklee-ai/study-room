텔레그램으로 부리기

입구는 열려 있지만 문은 잠긴 상태 — 페어링 승인이 열쇠입니다

채널은 메시지 서비스와 Gateway를 잇는 연결입니다. Telegram을 채널로 붙이면 폰에서 보낸 메시지가 Gateway에 도착합니다.

봇 토큰은 비밀값입니다

🔐 봇 토큰은 봇을 대신해 Telegram에 접속하는 비밀값입니다 — 채팅창, 화면 공유, 메모에는 토큰을 적지 않습니다
  • 이 절에서 할 일 — 수업용 봇을 만들고, 첫 메시지를 보낸 계정을 승인합니다
출처: docs/channels/telegram
1

BotFather로 봇을 만듭니다

사용자가 AI 봇을 손쉽게 만들게 해 주는 기능

④ 텔레그램
Telegram에서는 BotFather라는 서비스가 제공되고 있습니다.

봇 만들기

1Telegram에서 @BotFather를 찾아 접속합니다
2대화창에 /newbot을 보냅니다
3화면 안내에 따라 표시 이름과 bot으로 끝나는 봇 이름을 입력합니다
4발급 화면의 토큰을 복사해 안전한 비밀 보관 위치에 둡니다
⚠️ 토큰이 대화에 남았다면 — BotFather에서 새 토큰을 발급하고 이전 토큰은 쓰지 않습니다
출처: docs/channels/telegram

Gateway에 토큰을 연결합니다

openclaw config set channels.telegram.botToken "여기에_봇_토큰"
openclaw gateway
  • 큰따옴표 안을 방금 보관한 토큰으로 바꿉니다
  • Telegram은 channels login 명령으로 연결하지 않고 — 설정에 토큰을 넣은 뒤 Gateway를 시작합니다
  • Gateway가 이미 실행 중이면 수업 환경의 재시작 방법으로 다시 시작합니다
  • 폰에서 새 봇 대화창을 열어 짧은 인사말 하나를 보냅니다
채널마다 연결 방식이 다르다는 점(login vs config set)이 실무 함정입니다.

누가 말 걸었는지 구분합니다

페어링 — 입구의 신원 확인

④ 텔레그램
채널은 열려 있어도 바로 누구나 대화하는 곳은 아닙니다.

입구는 열려 있지만 문은 잠겨 있습니다

Telegram의 기본 DM 정책인 페어링(pairing)은 첫 메시지를 보낸 계정을 승인 대기 목록에 올리고, 승인된 계정만 봇과 대화하게 하는 규칙입니다.

openclaw pairing list telegram
openclaw pairing approve telegram <코드>
규칙내용
만료승인 전 대기 중인 코드만 1시간 뒤 만료
승인 후한 번 승인하면 이후에는 코드 없이 대화가 이어집니다
재발급승인이 안 된 채 시간이 지난 경우에만 새 코드를 받아 다시 승인
미승인 계정봇이 답하지 않습니다
📌 Telegram 계정을 사람 이름으로 추측하지 말고 — 승인 목록의 계정으로 구분합니다
페어링 승인이 열쇠입니다. 출처: docs/channels/telegram

세 가지 입구 정책

정책내용맞는 경우
pairing (기본 DM 정책)첫 메시지를 대기 목록에 올리고 승인된 계정만일반적인 개인 봇
allowlistnumeric Telegram ID를 허용 목록에 넣어 입구를 제한소유 계정 하나만 쓰는 봇
open모든 계정을 받음제한된 도구만 둔 공개 봇에만
정책 이름보다 "누가 말할 수 있는가"를 먼저 정하는 순서가 중요합니다.

다른 입구에도 같은 문을 둡니다

Discord · Slack

④ 텔레그램
오늘은 Telegram만 연결합니다. Discord와 Slack도 같은 순서로 열 수 있습니다.

Discord — 개발자 포털에서

1개발자 포털에서 애플리케이션을 만든 뒤 Bot 탭에서 봇을 만듭니다
2같은 탭의 Reset Token으로 토큰을 발급합니다
3Privileged Gateway Intents에서 Message Content Intent를 켭니다
4OAuth2 URL Generator에서 bot과 applications.commands 범위를 골라 서버에 초대
5토큰은 환경 변수로 둔 설정 파일을 등록한 뒤 Gateway를 시작
openclaw config patch --file ./discord.patch.json5
출처: docs/channels/discord

Slack — manifest에서

1Create New App에서 From a manifest를 골라 워크스페이스와 manifest JSON을 넣어 앱을 만듭니다
2App-Level Token에 connections:write를 더해 발급합니다
3Install to Workspace에서 Bot User OAuth Token을 받습니다
4두 토큰은 설정 파일로 등록합니다
openclaw config patch --file ./slack.socket.patch.json5
📌 기본 전송 방식인 Socket Mode는 공개 Gateway 주소가 필요 없습니다
출처: docs/channels/slack. 채널이 열렸습니다. 이제 무엇을 허용하고 무엇을 막을지 봅니다.

❓ 이해도 확인

Q1. Telegram 연결이 다른 채널과 다른 점은?
A1. channels login이 아니라 — 설정에 토큰을 넣은 뒤 Gateway를 시작한다.
Q2. 페어링 코드는 언제 만료되나?
A2. 승인 전 대기 중인 코드만 1시간 뒤. 한 번 승인하면 이후에는 코드 없이 대화가 이어진다.
Q3. open 정책은 어디에 맞나?
A3. 제한된 도구만 둔 공개 봇에만. 소유 계정 하나만 쓸 때는 allowlist로 numeric ID를 제한한다.
Q1은 문서를 안 읽고 유추하면 반드시 틀리는 지점입니다.

④ 기준선
같은 문제를 자동으로 고치는 방법은 하나가 아닙니다.

네 방법의 대가

방법대가
대화형 CLI를 셸 스크립트에서 여러 번 호출
(Claude Code CLI · opencode)		시작은 쉽지만 사람의 조작과 셸 환경이 끼어들어 조건을 고정하고 다시 재현하기 어렵습니다
Messages API 직접 호출도구 실행기·권한 승인·기록 형식을 모두 코드로 만들어야 하므로 — 실험 설계보다 실행 기반을 만드는 데 시간이 듭니다
범용 프레임워크 (LangGraph 등)추상화 문법을 익혀야 하고, 오늘 비교하려는 다음 행동의 결정 주체가 프레임워크 안에 가려집니다
Claude Agent SDKClaude Code의 도구 실행 · 권한 · 세션 JSONL 기록 · 서브에이전트 정의 · 구조화 출력을 파이썬 코드에서 제공
오늘은 세 실행에서 다음 행동을 정하는 주체만 바꾸고 모델·도구·기록 형식은 같게 두어야 공정합니다.

차이가 조율 주체로만 남습니다

실행코드 구조

B코드가 파일을 나누어 병렬 query()를 호출한 뒤 결과를 합침
Coptions.agents로 워커를 정의하고 리드가 위임 여부를 정함

실행 도우미와 기준선 실행(A)

async def _run_once(prompt, options):
    """(마지막 ResultMessage, 오류문) 반환.
    max_turns 소진은 SDK가 ResultError로 던지지만 실험에서는
    '턴 소진'이라는 관측 결과일 뿐이라 예외로 죽지 않고
    남은 상태를 그대로 채점한다."""
    last = None
    try:
        async for m in query(prompt=prompt, options=options):
            if type(m).__name__ == "ResultMessage":
                last = m
    except Exception as e:
        return last, f"{type(e).__name__}:{str(e)[:200]}"
    return last, None

if arm == "A":
    msg, err = await asyncio.wait_for(_run_once(
        f"Fix this bug:\n\n{problem}",
        ClaudeAgentOptions(cwd=str(repo), model=MODEL, max_turns=25,
                           system_prompt=SYS_A,
                           permission_mode="bypassPermissions")), 1500)
⚠️ 읽기 전용 도구 제한 allowed_tools=["Read","Grep","Glob"]은 기준선 실행(A)이 아니라 — 워크플로 실행(B)의 원인 탐색 호출에만 적용됩니다
턴 소진을 예외로 죽이지 않고 관측으로 다루는 것이 이 도우미의 설계 의도입니다. 기준선 실행(A)은 최대 25턴입니다.

❓ 이해도 확인

Q1. 세 실행에서 고정하는 것과 바꾸는 것은?
A1. 고정 — 문제·모델 별칭·저장소 준비·채점 방식. 바꾸는 것 — 다음 행동을 정하는 주체뿐.
Q2. common.py의 골드 패치 검증이 왜 필요한가?
A2. 이 확인이 없으면 에이전트의 수정이 아니라 시험 환경의 문제를 성공이나 실패로 읽을 수 있기 때문.
Q3. 25턴 소진을 어떻게 읽나?
A3. 단순 오류가 아니라 — 어디까지 탐색했고 어느 지점에서 멈췄는지 읽을 기록. changes.diff와 전사를 함께 본다.

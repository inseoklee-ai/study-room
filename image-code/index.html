🔌 세 줄이면 그림이 나온다

API = 사람이 화면을 눌러 쓰는 게 아니라 코드가 부르라고 만들어 둔 입구. 보통 키가 필요하지만, 지금은 키조차 필요 없는 경우.

import requests
from urllib.parse import quote

prompt = "a single factory worker in a white safety helmet " \
         "leaning over a stainless steel inspection line"
url = f"https://image.pollinations.ai/prompt/{quote(prompt)}"
r = requests.get(url, params={"width":768,"height":512,"nologo":"true"}, timeout=60)
open("worker.jpg","wb").write(r.content)      # → 57,015 바이트 저장
자동화의 한 칸으로 넣기 쉽다 — "상품 설명 목록을 읽어 각각 썸네일 만들고 상품 코드로 저장" = 에이전트가 이 세 줄을 목록 수만큼 감싸면 끝.
한계도 분명 — 익명은 대략 15초에 한 번, 같은 교실 IP로 묶여 막힐 수 있고, 무료 서비스는 가동 보장이 없습니다. 데모·학습엔 훌륭하지만 업무 자동화의 심장으로 쓸 것은 아닙니다.

🖥️ 무료 GPU에서 직접 — VRAM부터 확인

  • Colab 메뉴에서 런타임 유형을 GPU로 바꿔야 그래픽카드가 붙는다(기본값은 없음 → 안 바꾸면 코드가 멈춤)
  • 붙었으면 무엇이 붙었는지 확인하는 습관 — 특히 VRAM(그래픽카드 전용 메모리). 모델 파라미터가 통째로 여기 올라가야 계산된다
  • 무료 티어는 대개 Tesla T4 · VRAM 14.6GB 남짓(구글이 보장하진 않음)
import torch
p = torch.cuda.get_device_properties(0)
print(f"{p.name} / VRAM {p.total_memory/1024**3:.1f}GB")   # 예: Tesla T4 / 14.6GB
이 14.6GB가 잣대 — 이보다 큰 모델은 아예 안 돌거나, 일부를 본체 메모리로 밀어내며 아주 느려진다. (뒤 "무엇으로 만들까"에서 다시 등장)
모델 실행은 diffusers 라이브러리로 합니다 — 허깅페이스가 만든 것으로, 확산 모델을 이름만 대면 내려받아 실행해 줍니다. import가 안 되면 !pip install -U diffusers transformers accelerate.

🔍 코드에서 눈여겨볼 두 곳

guidance_scale=0.0

오타 아님. 프롬프트를 얼마나 세게 밀지의 배율인데, 증류 모델은 그 과정이 이미 안에 구워져 있다 → 밖에서 또 밀면 상함. 증류 안 된 기본 모델은 3~7.

torch_dtype=float16

숫자를 몇 비트로 담을지. 공식 예제는 대개 bfloat16(같은 16비트, 범위 넓음)인데 오래된 GPU엔 float16이 낫다. 단 결과가 통째로 검게 나올 수 있어 눈으로 확인.

모델을 바꿀 때 이 값을 함께 안 바꿔 결과가 망가지는 일이 흔하다. 이름만 갈아 끼우면 안 된다.
float16으로 낮추면 계산 도중 값이 범위를 벗어나 검게 나올 수 있으니, 바꿔 올렸다면 결과가 정상인지 확인하세요.

🤖 에이전트에게 통째로 시키기

"이미지 생성 스크립트 만들어 줘"라고만 하면 에이전트가 알아서 모델·값을 정해 앞에서 배운 걸 하나도 못 쓴다. 내가 정할 것을 명시하고 나머지를 맡긴다.

아래 조건으로 배치 이미지 생성 스크립트를 만들어 주세요.
- 입력 scenes.csv (열: id, subject, action, camera, lighting, environment, style)
  각 행의 여섯 열을 한 영어 문장형 프롬프트로 조립 → out/{id}.png 저장
- 모델 stabilityai/sdxl-turbo, 스텝 4, 가이던스 0.0, dtype float16 고정
- 시드는 id를 정해진 규칙으로 숫자화(같은 id면 언제 돌려도 같은 값)
- 이미지마다 프롬프트·시드·모델명을 out/{id}.json에 함께 저장
- 파이프라인은 한 번만 GPU에 올리고 행을 순회, 실패 행은 건너뛰고 목록 출력
내가 정한 것 = 입력 형식 · 모델과 값 · 재현 기록 · 실패 처리. 이 넷은 품질과 재현성을 좌우하니 맡기지 않는다. 반복문·파일쓰기는 맡겨도 된다.
SDXL-Turbo도 증류판이라 스텝 4·가이던스 0. 모델을 바꾸면 이 값도 그 모델 공식 예제에 맞춰야 합니다.

✅ 받은 코드에서 확인할 네 곳

1파이프라인을 반복문 밖에서 한 번만 올렸나 — 안에서 올리면 행마다 재적재해 백 배쯤 느려진다(흔한 실수)
2시드가 정말 재현 가능한가 — 파이썬 기본 해시는 실행마다 값이 달라지게 돼 있다(보안상). 그걸로 시드를 만들면 오늘 그림을 내일 못 뽑는다
3가이던스·스텝이 지시대로 들어갔나 — 에이전트가 자기 기본값으로 되돌려 놓기도 한다(증류 모델에 가이던스 넣으면 상함)
4기록 파일에 무엇이 들어갔나 — 프롬프트만 저장하고 시드를 빼먹으면 재현 불가
이건 이미지 생성만의 이야기가 아니라 에이전트에게 코드를 받을 때 늘 하는 일입니다.
재현이 목적이면 실행과 무관하게 늘 같은 값을 주는 해시 방식을 쓰라고 지시해야 합니다.

⚖️ 그런데 — 모델마다 라이선스가 다르다

  • 실습의 FLUX.2-klein 4B = 아파치 2.0 — 상업 포함 자유, 산출물 권리도 사용자에게. 그래서 실습 모델로 선택
  • SDXL-Turbo = Stability 커뮤니티(연매출 100만$ 기준), FLUX.2-klein 9B = 비상업 전용
  • 모델을 바꿀 땐 라이선스는 물론 스텝 수·가이던스도 그 모델 공식 예제에 맞춰야 한다
이름만 갈아 끼우고 나머지를 그대로 두면 결과가 이상해진다. 이 구분이 다음 덱("무엇으로 만들 것인가")의 주제.
같은 FLUX.2-klein이라도 4B는 아파치, 9B는 비상업입니다. 이름만 보고 내려받으면 알 수 없습니다.

📌 이것만은 꼭 — 핵심 5문장

1API는 코드가 부르는 입구 — 세 줄이면 한 장, 자동화 한 칸으로 넣기 쉽다(단 무료는 제한·가동 보장 없음).
2직접 돌릴 땐 런타임을 GPU로 + VRAM 확인(무료 T4 ≈ 14.6GB, 이게 모델 크기의 잣대).
3한 장 1초는 증류 덕분 — 그래서 프롬프트를 고쳐 가며 반복할 수 있다.
4코드의 두 곳 — guidance_scale=0.0(증류) · dtype. 모델 바꾸면 함께 바꾼다.
5에이전트엔 모델·값·기록·실패처리를 명시하고, 받은 코드는 파이프라인 1회·재현 시드를 확인.
5번이 실무의 핵심 — 자동화는 재현 가능해야 쓸 수 있습니다.

✅ 정답 & 해설

A1. 세 줄로 자동화에 넣기 쉽다. 단 익명 15초 제한·같은 IP 차단·가동 보장 없음이라 업무 심장으로는 부적절.
A2. 모델 파라미터가 통째로 VRAM에 올라가야 계산되므로. 넘치면 안 돌거나 본체 메모리로 밀어내며 아주 느려진다(무료 T4 ≈ 14.6GB).
A3. 프롬프트를 고쳐 가며 반복 비교할 수 있어서. 증류로 50스텝을 4스텝으로 줄인 덕분.
A4. 증류 모델은 가이던스가 이미 안에 구워져 있어, 밖에서 또 밀면 그림이 상하므로 0으로 끈다(기본 모델은 3~7).
A5. 맡기면 안 되는 넷 = 입력 형식·모델과 값·재현 기록·실패 처리. 확인 = 파이프라인 1회 로드·재현 가능한 시드·가이던스/스텝·기록.
A5는 이미지뿐 아니라 에이전트에게 코드를 받을 때 늘 적용됩니다.

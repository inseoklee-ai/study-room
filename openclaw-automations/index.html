Gateway가 켜져 있어야 예약한 시간에 일이 시작됩니다

모니터링 절에서 지금 상태를 보는 눈을 얻었습니다. 이번에는 스스로 움직이는 시간표를 만듭니다.

automations는 Gateway의 스케줄러입니다

  • 모델 안에서 실행되는 기능이 아닙니다 — Gateway 프로세스가 실행 중이어야 예약한 시간에 일이 시작됩니다
  • 일정·실행 상태·실행 기록은 OpenClaw의 공유 SQLite 데이터베이스에 저장됩니다 — Gateway를 다시 시작해도 예약 자체가 사라지지 않습니다
  • 실행 결과는 채팅 채널 · 웹훅 · 기록으로 보낼 수 있습니다
출처: docs.openclaw.ai/automation/cron-jobs
1

비어 있는 시간표부터

권한은 실행 조건과 별개로 먼저

⑨ 자동화
처음 사용하는 환경이면 목록은 비어 있습니다.

목록을 먼저 봅니다

openclaw automations list
  • openclaw automations는 작업을 만들고, 목록과 상세 정보, 실행 기록을 보고, 지우는 명령입니다
  • 짧게 openclaw cron이라고 써도 같은 명령으로 동작합니다
🔑 작업을 만들거나 지우거나 즉시 실행하는 변경 명령에는 operator.admin 권한이 필요합니다 — 권한은 예약이 실행되는 조건과 별개로 먼저 확인합니다
출처: docs.openclaw.ai/automation/cron-jobs
2

일회성과 반복을 만들어 봅니다

3분 뒤 알림 · 5분 시보

⑨ 자동화
작업을 만들 때는 일정이 먼저이고 프롬프트가 그 다음입니다.

3분 뒤의 알림

date -u +%FT%TZ

출력된 UTC 현재 시각에서 3분 뒤의 ISO 시각을 계산해 아래 자리에 넣습니다.

openclaw automations create "<ISO시각>" --name "첫 알림" \
  --session main \
  --system-event "3분 전에 예약한 알림이 도착했습니다"
  • --session main은 앞에서 연 WebChat의 main 세션으로 시스템 이벤트를 보냅니다
  • 한 번만 실행하는 작업은 성공적으로 끝나면 자동으로 지워집니다
  • 이름은 목록에서 작업을 알아보기 쉽게 붙입니다. 위 명령은 프롬프트 대신 시스템 이벤트를 넣은 형태
WebChat을 열어 그 메시지가 나타나는지 봅니다.

5분마다 울리는 시보

📖 cron 표기식(분 시 일 월 요일) — 반복 시간을 다섯 칸으로 적는 방식. */5 * * * *에서 첫 칸 */5는 5분마다를 뜻하고, 나머지 네 칸의 *는 모든 시, 모든 날, 모든 달, 모든 요일
openclaw automations create "*/5 * * * *" \
  "지금 시각과 대기 중인 알림이 있으면 한 줄로 알려 줘" \
  --name "5분 시보"
  • 몇 분 기다리며 WebChat에 시보가 두 번 도착하는지 봅니다
  • 이 작업은 반복 일정이므로 한 번 실행되어도 목록에 남고 다음 5분을 기다립니다
일회성과 반복의 차이가 목록에 남는지로 드러납니다.

실행된 기록을 봅니다

openclaw automations runs --id <job-id>
  • automations list에서 시보의 작업 ID를 확인한 뒤 그 작업의 실행 기록을 봅니다
  • 시보가 두 번 울렸다면 기록에도 두 번의 실행이 생깁니다
  • 일회성 작업은 실행 뒤 목록에서 사라지지만, 반복 작업은 다음 실행 시간을 가진 채 목록에 남습니다 — 목록과 실행 기록을 나란히 보면 이 차이가 그대로 나타납니다
⚠️ Gateway를 끄면 스케줄러도 함께 멈춥니다. 그동안에는 예약 시간이 되어도 작업이 실행되지 않습니다 — 다만 다시 켠 뒤에도 SQLite에 저장한 일정과 이전 실행 기록은 남아 있습니다
출처: docs.openclaw.ai/automation/cron-jobs
3

같은 일을 대화로 시킵니다

다섯 칸을 외우지 않아도 됩니다

⑨ 자동화
대화로 시키는 길이 두 가지 있습니다.

반복 감지와 /loop

길내용
반복을 알아채는 길같은 부탁을 여러 번 하면 에이전트가 먼저 예약으로 바꿀지 제안합니다. 만들기 전에 일정과 할 일을 사람의 말로 한 문장 확인 — 예: "매주 평일 오전 7시에 어제 밤 업데이트를 요약해 이 방에 올립니다". cron 표기식이 아니라 사람의 문장으로 확인하게 하는 설계
/loopWebChat에서 /loop 5m 지금 시각을 한 줄로 알려 줘 → 이 대화에 묶인 5분 반복 작업. 소유자만 쓸 수 있는 명령. 간격을 빼면 1분에서 1시간 사이에서 스스로 다음 실행을 정합니다. /loop status로 보고 /loop stop으로 끕니다
🔎 /loop로 시보를 하나 만든 뒤 openclaw automations list를 다시 실행해 — CLI로 만든 시보와 /loop로 만든 시보가 한 목록에 나타나는지 확인합니다. 만드는 입구가 달라도 스케줄러는 하나입니다
출처: docs.openclaw.ai/automation/cron-jobs

실습이 끝나면 시간표를 비웁니다

openclaw automations remove <job-id>
  • list에서 5분 시보의 작업 ID를 찾아 넣습니다
  • /loop로 만든 시보는 대화창에서 /loop stop으로도 지울 수 있습니다
반복 작업을 남겨 두면
Gateway가 켜져 있는 동안 계속 실행됩니다
실습이 끝난 작업은 지우는 습관이 필요합니다
출처: docs.openclaw.ai/automation/cron-jobs

❓ 이해도 확인

Q1. automations는 어디에서 실행되나?
A1. 모델 안이 아니라 Gateway에 들어 있는 스케줄러. Gateway가 실행 중이어야 예약이 시작된다.
Q2. 일회성과 반복 작업의 차이는?
A2. 일회성은 성공하면 자동으로 지워지고, 반복은 다음 실행 시간을 가진 채 목록에 남는다.
Q3. CLI와 /loop로 만든 작업의 관계는?
A3. 만드는 입구가 달라도 스케줄러는 하나여서 같은 목록에 나타난다.
Q1을 모르면 "예약했는데 안 울린다"는 문제의 원인을 찾지 못합니다.

설치하고 내 작업대 상태 확인

두 길 · 버전으로 검증 · 오류 설명법

② 설치
필요한 도구 — Claude Code(메인)·Node.js와 npm(웹 실행)·Git(변경 기록). Claude Code는 Claude Desktop 안에서 바로 실행할 수 있습니다.

🛤️ 두 길, 그리고 확인 브릿지

🅰️ 빠른 길 (AI 네이티브)

Claude Desktop 안 Claude Code에 자연어로 맡긴다 — "Node·npm·Git이 깔려 있는지 확인하고, 없으면 공식 방법으로 설치하고, 각 버전을 출력해 줘"

🅱️ 손으로 (기본기)

공식 문서 방법으로 하나씩 — 버전이 바뀌어도 가장 믿을 수 있는 출처. "어디서부터 왔는지" 아는 힘

"버전을 보여줘"를 덧붙이는 이유AI가 "설치했습니다"라고 답해도, 버전 출력이 그 주장을 내가 검증하는 가장 단순한 방법
어떤 길로 깔았든 마지막은 직접 터미널을 열어 버전을 확인하는 단계로 이어진다 — 이 습관이 앞으로 모든 바이브 코딩의 기본.
공식 문서 한 줄씩 치는 게 귀찮아도, 나중에 문제가 생겼을 때 어디서부터 왔는지 아는 힘이 됩니다.

🔧 손으로 설치 — 권한 충돌을 피하며

# Node.js·npm은 nvm으로 관리 (macOS/Linux/WSL)
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.5/install.sh | bash
nvm install --lts       # 현재 LTS 설치
nvm use --lts           # 이 터미널에서 그 LTS 사용
node --version
npm --version

# Claude Code (macOS/Linux/WSL)
curl -fsSL https://claude.ai/install.sh | bash
# Windows PowerShell:  irm https://claude.ai/install.ps1 | iex
# 또는 Node 22+:       npm install -g @anthropic-ai/claude-code
claude --version
왜 nvm인가 — Node를 시스템 위치에 직접 깔면 전역 패키지 설치 때 EACCES 권한 오류로 sudo를 붙여야 하는 경우가 많다. nvm은 홈 디렉터리 ~/.nvm 아래를 써서 sudo 없이 설치할 수 있다(sudo npm install -g는 쓰지 않는다).
Windows는 nvm-windows(별개)에서 nvm-setup.exe를 받아 nvm install <LTS-버전>·nvm use <LTS-버전>로(--lts 별칭 없음). uv는 curl -LsSf https://astral.sh/uv/install.sh | sh. Claude Code는 파이썬 패키지가 아니라 uv로 설치하지 않습니다. 설치 명령 복사 전 링크의 태그·릴리스를 함께 확인하세요.

출력판단
v20.11.1처럼 버전 번호실행된다(숫자는 컴퓨터마다 다름)
command not found·not recognized설치나 경로 문제일 수 있음
설치가 안 되어 있거나 명령이 동작하지 않으면 그 결과 자체가 오늘의 학습 자료 — 실패 화면을 숨기지 말고 그대로 기록한다. 오류를 만나면 무작정 여러 명령을 치기보다 지금 나온 출력 한 줄을 복사해 AI에게 설명.
설치 확인은 통과 의식이 아니라, 앞으로 AI에게 문제를 설명할 때 쓰는 증거 수집입니다. 상태표를 자기 노트에 채우고, 빈칸은 본인 컴퓨터 결과로 채웁니다.

🔍 AI에게 오류를 설명하는 방식

나는 macOS/Windows 환경에서 웹 개발 작업대를 설정하고 있어.
터미널에서 아래 명령을 실행했어.

명령:
node --version

출력:
[여기에 실제 오류 메시지 붙여넣기]

내 목표는 실습을 진행할 수 있게 Node.js와 npm 버전을 확인하는 거야.
원인을 추정하지 말고, 내가 먼저 확인할 순서 3가지만 알려줘.
핵심은 환경·실행한 명령·실제 출력을 분리해서 주는 것. "안 돼요"라고 하면 AI도 추측한다. 반대로 "node --version을 쳤더니 command not found가 나왔다"고 하면 AI는 다음 행동을 좁힐 수 있다.
"원인을 추정하지 말고 확인할 순서 3가지만"이라는 제약이 AI가 성급히 명령을 던지는 것을 막습니다.

첫 파일과 바이브 코딩 루프

폴더·파일 · index.html · 지시→생성→판단→수정

③ 첫 파일 · ④ 루프
작업대 위에 첫 산출물을 올립니다. my-first-web 폴더와 index.html — 뒤 실습에서 첫 화면 제작의 출발점이 됩니다.

📁 첫 폴더와 파일 만들기

# 프로젝트를 모아둘 위치에서 (예: cd ~/Documents)
mkdir my-first-web
cd my-first-web
pwd                     # 현재 위치 확인
touch index.html        # Windows PowerShell: ni index.html
pwd는 현재 위치를 보여준다 — 이 출력은 나중에 AI에게 "내가 어느 폴더에서 작업 중인지" 설명할 때 단서가 된다.
  • 다음은 백지에서 HTML을 외워 쓰지 않고, 먼저 AI에게 만들 것을 말하고 나온 결과를 읽고 판단한다
프로젝트 폴더에서 Claude Code를 실행한 뒤 요청을 입력하면 Claude Code가 index.html을 직접 만들어 줍니다.

🔧 AI에게 첫 파일을 맡긴다

index.html에 브라우저에서 바로 열 수 있는 첫 화면을 만들어줘.
조건:
- 한국어 문서로 설정해줘.
- 큰 제목에는 [내 이름 또는 역할]을 넣어줘.
- 본문에는 [내 도메인]에서 AI를 활용해 보고 싶은 일을 한 문장으로.
<!-- AI가 생성한 결과 예시 — 외워 쓰는 코드가 아니라 검토 대상 -->
<!DOCTYPE html>
<html lang="ko">
<head><meta charset="UTF-8"><title>나의 첫 웹페이지</title></head>
<body>
  <h1>교육 운영 전문가 김아이펠</h1>
  <p>교육 현장의 반복 안내 업무에 AI를 활용해 보고 싶습니다.</p>
</body>
</html>
코드를 대신 써 달라는 요청이지만 책임까지 넘기는 요청은 아니다 — "돌아간다"에서 멈추지 않고 내 목표에 맞는지 확인. lang="ko"·charset="UTF-8"이 있으면 한국어 표시 문제를 줄이고, 제목·문장은 내 도메인으로 바뀌어야 산출물 증거가 된다.
브라우저에서 index.html을 열어(더블클릭 또는 주소창에 경로) 제목·본문이 보이는지, 내 도메인 문장으로 바꿨는지 확인합니다.

🔄 바이브 코딩 루프는 네 단계

1만들 것을 자연어로 또렷이 말한다
2AI가 코드를 생성한다
3여러분이 결과를 읽고 판단한다
4다시 지시해 수정한다
목표는 화려한 화면이 아니라AI 출력에 대해 근거 있는 재요청을 하는 것
이 섹션이 오늘의 중심 — 설치와 파일 생성은 준비이고, 바이브 코딩은 여기서 시작된다. 작은 수정 하나로 이 루프를 경험한다.
지시 → 생성 → 판단 → 수정 지시가 한 번 돌았다면, 개발 환경은 더 이상 설치 목록이 아니라 작업대가 됩니다.

➕ 두 번째 요청 — 추가할 것 + 지킬 것

방금 만든 index.html을 수정해줘.
추가할 것:
- 내 도메인에서 AI로 개선하고 싶은 반복 업무 3개를 목록으로.
- 각 항목은 한 줄 설명을 붙여줘.

지킬 것:
- 기존 제목과 첫 문장은 유지해줘.
- HTML 구조가 읽기 좋게 들여쓰기되어야 해.
첫 요청과 다른 점 — "무엇을 추가할지"와 "무엇은 건드리지 말지"를 함께 말한다.

🤔 예측 — AI가 실수할 만한 지점은? 기존 문장을 바꾸거나, 시키지 않은 CSS를 추가하거나, 업무 3개가 도메인과 안 맞을 수 있다. 그래서 다음에 판단표로 검토한다

AI가 <section>에 <h2>와 <ul> 목록을 붙이되 기존 제목·문장은 그대로 두었는지가 첫 검토 지점입니다.

🔍 판단하고 재요청하기

AI 출력이 나왔으면 곧바로 적용하지 말고 아래로 판단한다.

판단 항목본다
기존 제목·첫 문장이 유지되었나지킬 것을 어겼는지
업무 3개가 내 도메인에 맞나추상적이거나 남의 예시인지
목록 설명이 현장에서 쓰는 말인가내 언어로 바뀌었는지
좋아. 다만 목록 3개가 내 실제 업무와 조금 달라. 아래처럼 바꿔줘.
1. [내 업무 1]
2. [내 업무 2]
3. [내 업무 3]
이 한 번의 왕복이 오늘의 핵심 루프 — 지시 → 생성 → 판단 → 수정 지시가 돌았다면 개발 환경은 작업대가 된다.
재요청은 근거와 함께 구체적으로 — 무엇이 왜 안 맞는지, 무엇으로 바꿀지를 짚어 줍니다.

🎯 이 덱의 핵심 정리

개념한 문장
버전으로 검증"설치했습니다"를 믿지 말고 버전 출력으로 내가 확인
nvm홈 디렉터리를 써 권한 충돌(EACCES)을 피한다. sudo -g 금지
오류 설명환경·명령·실제 출력을 분리해 주고, 추정 말고 확인 순서를 요청
첫 파일외워 쓰지 않고 말하고 읽고 판단 — lang·charset·내 도메인 확인
루프 4단계지시 → 생성 → 판단 → 수정. 추가할 것 + 지킬 것을 함께
재요청"돌아간다"에서 멈추지 않고 근거 있는 재요청
다음 덱에서 터미널·셸·커널·프롬프트가 실제로 어떻게 다른지(command not found가 왜 나오는지)를 지도로 봅니다.

✅ 정답 & 해설

A1. AI가 "설치했습니다"라고 해도 내 컴퓨터에서 진짜 되는지는 모른다 — 버전 출력이 그 주장을 내가 검증하는 가장 단순한 방법.
A2. 시스템 위치에 직접 깔 때 나는 EACCES 권한 오류(sudo 필요). nvm은 홈 디렉터리 ~/.nvm를 써 sudo 없이 설치할 수 있다.
A3. 환경·실행한 명령·실제 출력을 분리해 주고 "원인을 추정하지 말고 확인 순서 3가지만" 요청 — AI가 다음 행동을 좁힌다.
A4. ①자연어로 또렷이 말한다 ②AI가 생성 ③내가 읽고 판단 ④다시 지시해 수정.
A5. AI가 기존 문장을 바꾸거나 시키지 않은 것을 추가할 수 있어 — 무엇을 건드리지 말지를 함께 말하면 그 실수를 막는다.
A4의 루프가 이 강의 전체의 뼈대입니다.

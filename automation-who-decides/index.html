반복하는 일, AI에게
맡기면 안 될까

먼저 정할 것은 AI를 쓸지 말지가 아닙니다

아침에 메일함을 열면 비슷한 문의가 쌓여 있습니다. 이 강의는 도구 이름보다 그 판단의 기준을 살펴봅니다.

아침 메일함의 같은 하루

1배송은 언제 도착하는지, 결제는 왜 실패했는지, 반품은 어디로 보내는지 확인합니다
2내용을 읽고 담당 팀에 전달합니다
3같은 내용을 표에 다시 옮깁니다
4점심이 가까워져도 메일은 줄지 않습니다
💭 이때 AI가 이 일을 맡아 준다면 좋겠다는 생각이 자연스럽게 듭니다
이 장면에서 출발합니다. 문제는 "맡길 수 있느냐"가 아니라 "무엇을 어디까지 맡기느냐"입니다.

⚠️ 뜻밖의 예외

잘못 분류된 문의가 여러 팀으로 전달될 수 있습니다. 멈춰야 할 작업이 계속 실행될 수도 있습니다

나중에 결과만 남고
왜 그런 선택이 이어졌는지는 찾기 어려울 수 있습니다
세 번째 문장이 이 대단원 전체의 문제의식입니다 — 결과는 남는데 경로가 남지 않는 상태.

다음 행동을 누가 정하는가

결과가 같아 보여도 살펴볼 곳은 달라집니다

① 자동화와 에이전트
이 질문이 자동화·워크플로·에이전트를 가르는 축입니다.

화면에는 최종 수정안만 보입니다

opencode, Claude Code, Antigravity에 저장소를 살펴보고 수정안을 만들어 달라고 맡긴 장면을 떠올려 봅니다.

  • 도구는 파일을 읽고, 명령을 실행하고, 테스트 결과를 확인한 뒤 다음 행동을 고를 수 있습니다
  • 그러나 어떤 파일을 먼저 열었는지, 어느 명령을 택했는지, 실패 뒤에 왜 다시 시도했는지는 빠르게 지나갑니다
📌 이 불편함은 도구를 잘못 사용했다는 뜻이 아닙니다 — 같은 "에이전트"라는 이름 아래에 서로 다른 통제 방식이 있기 때문입니다
도구를 탓하기 전에 통제 방식을 구분하는 것이 이 절의 목표입니다.

  • 결과가 같아 보여도 — 문제가 생겼을 때 살펴볼 곳은 달라집니다
왼쪽에서 오른쪽으로 갈수록 사람이 직접 정하던 다음 행동이 고정 그래프를 거쳐 모델의 판단으로 옮겨갑니다.

같은 업무 — 고객 문의 분류

누가 정하는가장면
사람사람이 메일을 읽고 기준을 적용해 알림을 보냅니다
고정 그래프수신 → 분류 → 담당 팀 찾기 → 알림 발송을 연결하고 조건을 정해 두었습니다
모델내용이 모호한 문의에서 조회 도구를 쓸지, 추가 정보를 요청할지, 후보를 다시 찾을지 모델이 고릅니다
세 경우 모두 화면에는
"담당 팀에 알림을 보냈다"는 결과만 남을 수 있습니다
결과가 같기 때문에 화면만 보고는 세 경우를 구별할 수 없습니다.

원인을 찾는 방식이 다릅니다

누가 골랐나되짚을 것
사람입력과 판단 기준을 되짚습니다
고정 그래프어느 조건에서 다른 경로로 갔는지 확인합니다
모델제공한 도구 · 관측한 결과 · 반복 한도 · 승인 규칙을 함께 확인합니다
🚗 선택권이 이동하는 모습은 운전대가 손에서 자동 조향 장치로, 다시 상황을 해석하는 조수에게 넘어가는 모습과 닮았습니다 — 목적지는 같아도 브레이크를 확인할 곳은 달라집니다
모델이 골랐을 때 확인 대상이 가장 많다는 점에 주목하세요.

국면마다 확인할 질문이 다릅니다

제품 이름이 아니라 확인 지점으로

① 자동화와 에이전트
세 국면 각각에서 무엇을 확인해야 하는지 봅니다.

국면별 확인 질문

국면다루는 것확인할 질문
사람이 대화창에서
하나씩 요청		조사·파일·코드·연결 도구입력한 내용이 어떤 연결 도구와 외부 서비스에 전달되는지, 실행 기록을 어디까지 볼 수 있는지
고정 그래프가
순서를 정함		트리거 · 노드 · 분기 · 실행 이력그래프 가운데 모델을 넣어도 전체가 곧바로 모델 주도가 되지 않으므로 — 모델이 판단하는 범위와 그 앞뒤의 연결, 실행 권한을 나누어
모델이 다음
도구를 고름		저장소 · 터미널 · 테스트어느 경로가 읽기만 가능한지, 변경과 외부 통신은 어디에서 승인하는지, 테스트 결과가 다음 선택에 다시 반영되는지
제품마다 제공 범위는 다를 수 있지만 확인할 질문은 같습니다.

세 국면은 등을 돌린 제품 목록이 아닙니다

  • 하나의 도구 안에서도 국면마다 선택 주체가 달라질 수 있습니다
  • 대화창에 연결 기능이 붙을 수 있습니다
  • 고정 그래프 한가운데 모델 판단이 들어갈 수도 있습니다
  • 코딩 에이전트에도 사람이 승인하는 절차가 함께 있을 수 있습니다
📌 그래서 "이 제품은 에이전트, 저 제품은 워크플로"라는 분류보다 — 이 국면에서 다음 행동을 누가 정하는가를 묻습니다
제품 단위가 아니라 국면 단위로 묻는 습관을 들이는 슬라이드입니다.

고정 경로동적 선택
검토와 재현에 유리예외가 많은 업무에 도움 — 대신 비용과 오류가 쌓일 가능성도 커집니다
⚠️ 이 구분은 어느 쪽이 더 낫다는 뜻이 아닙니다 — 모델에 선택을 더 맡길수록 도구 권한, 반복 한도, 사람이 멈추는 지점을 더 분명히 정해야 합니다

❓ 이해도 확인

Q1. AI에 반복 업무를 맡길 때 먼저 정해야 하는 것은?
A1. 쓸지 말지가 아니라 — 무엇을 맡기고, 어디에서 멈추게 하며, 문제가 생기면 무엇을 확인할지.
Q2. 결과가 같은데도 세 국면을 구분해야 하는 이유는?
A2. 원인을 찾는 방식이 다르기 때문. 사람이면 판단 기준, 그래프면 조건과 경로, 모델이면 도구·관측·반복 한도·승인 규칙을 본다.
Q3. 고정 경로와 동적 선택의 장단은?
A3. 고정 경로는 검토와 재현에 유리하고, 동적 선택은 예외가 많은 업무에 도움이 되지만 비용과 오류가 쌓일 가능성이 커진다.
Q2가 이 소단원의 핵심입니다.

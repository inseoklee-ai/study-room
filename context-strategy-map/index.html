선택과 상태 — 이번 판단의 조립

1

전략은 보관이 아니라 조립

두 축으로 나눈다 — 선택 연산과 상태 정책

선택(가로 축) · 상태(세로 축)
문서가 저장돼 있다고 매 호출 전문을 넣어야 하는 건 아니며, 창에서 제외했다고 그 정보를 버린 것도 아닙니다. 보관·검색·압축·조회는 서로 다른 일이며, 이 파트는 그 결정을 두 축으로 분리합니다.

🧭 결정을 두 축으로 나눈다

선택 연산 (가로 축)

이번 호출에 무엇을 넣을지 정한다.

전체 투입 · RAG · 압축 · 폐기

상태 정책 (세로 축)

여러 턴 이력을 어떻게 유지하고 다음 호출에 다시 구성할지 정한다.

누적 · 슬라이딩 윈도 · 요약 · 러닝 서머리

선택이 근거의 범위를 정하고, 상태가 그 근거가 시간 속에서 사라지거나 되살아나는 방식을 정한다.
선택 연산은 이번 한 번의 입력을 조립하는 결정이고, 상태 정책은 그 입력을 여러 턴에 걸쳐 다시 만드는 결정입니다. 도구 실행 결과(검색·파일 읽기·명령 출력)도 빠르게 창을 채우는 상태이므로, 원시 출력·참조·요약·삭제 중 무엇으로 남길지 같은 방식으로 결정합니다.

🔲 두 축의 교차 지도

상태 ＼ 선택전체 투입RAG압축폐기
누적기록·정책 전문 모두 보존매 턴 검색 결과가 계속 붙음안 하면 팽창철회 가정도 명시 안 하면 누적
슬라이딩최근 턴 전문만최근 질문에 맞는 조각만 재검색창 밖 사실 남길지 결정장기 조건이 함께 사라질 수 있음
요약원문 주소를 필요 시 전문으로미결정을 질의로 재검색요약문이 압축 결과임을 검증폐기 가정·이유를 요약에 남김
러닝 서머리고정 정책은 원문 참조로 연결새 사실마다 필요한 조각만 회수목표·확정·가정·미결정을 정한 칸에갱신 때 철회·폐기 사유 함께
한 칸을 정답으로 고르는 게 아니다 — 장면에 따라 여러 칸을 조합한다.
법적 예외 많은 반품 상담은 정책 전문을 전체 투입하고, 대화는 최근 턴+원문 주소를 가진 러닝 서머리로 잇습니다. 짧은 내부 질의는 최근 몇 턴만 남기고 관련 조각을 검색합니다. 도구 결과의 시각·출처·실행 식별자와 답에 쓴 필드를 연결해 두면 재현·감사가 가능합니다.

⚖️ 압축 ≠ 요약 — 두 결정을 분리

압축 = 선택 연산

이번 입력의 길이를 줄인다. 원문 일부를 축약·구조화. 한 문서 전문을 두 문단으로 줄여 이번 답에 넣는 것.

요약 = 상태 정책

과거 대화·작업의 상태를 다음 턴으로 넘긴다. 지난 열두 턴의 확정 사실·미결정을 갱신해 다음 상담에 넘기는 것.

실제 시스템은 압축한 상태 요약을 선택해 넣을 수 있으나, 두 결정의 책임은 분리해 기록한다.
둘을 뭉뚱그리면 무엇이 잘못됐는지 짚을 수 없습니다. 길이를 줄인 결정(압축)과 이력을 이어간 결정(요약)을 따로 기록해야, 실패가 나왔을 때 어느 결정에서 예외·출처가 빠졌는지 추적할 수 있습니다.
2

네 선택 연산의 실패와 복구

각 선택은 서로 다른 실패를 만든다

전체 투입 · RAG · 압축 · 폐기
선택 연산은 이번 호출의 근거 범위를 정합니다. 네 선택지는 저마다 강점이 있는 만큼 저마다 다른 방식으로 실패하므로, 실패의 모양을 알면 무엇을 확인하고 어떻게 복구할지 미리 정할 수 있습니다.

📚 전체 투입 — 한 호출에 직접

  • 짧은 정책·강하게 연결된 계약서·매번 거의 같은 근거를 참조하는 업무에 좋다 — 대조 쉽고 검색 단계 없음
  • 예외 조항이 얽혀 있어도 함께 읽으므로 빠뜨릴 걱정이 줄어든다
  • 단, 길고 이질적 자료를 다 올리면 무관한 토큰이 핵심 조항과 경쟁하는 context rot과 입력 비용 증가
실패 — 전문 안에 답이 있는데 무관한 보상 규정·오래된 예시를 더 크게 따른다. "모두 넣었으니 안전"은 위치·관련성을 안 봤다는 뜻일 수 있다.
context rot은 창을 채운다고 성능이 오르지 않는다는 신호입니다. 복구는 무관 문서를 분리하고, 직접 답하는 절의 위치를 바꾸고, 선택 경로를 시험해 어떤 조각이 실제로 답에 쓰였는지 확인하는 것입니다.

🔎 RAG — 이번 질문에 맞는 조각만

1청크 — 문서를 읽기 좋은 작은 단위(문단·조항)로 저장
2retriever — 질문이 오면 비슷한 청크를 찾아 순위 매겨 후보 선택
3생성 — 선택된 조각만 창에 넣고 답을 만든다
🗂️ 인덱스카드 비유 — 상자 전체=저장소, 카드 한 장=청크, 탭·알파벳=메타데이터. retriever가 "반품" 칸에서 두세 장만 창에 넣는 게 선택 단계.
핵심은 모델이 문서 전체를 기억하는 게 아니라, 이번 질문에 맞아 보이는 조각을 읽고 답하는 순서입니다. 전문 투입의 입력 비용과 긴 창의 context rot을 피하고, 정책 개정 시 문서 교체·재청킹으로 반영할 수 있습니다(모델 재학습 불필요).

⚠️ RAG의 실패 — 상위 결과 ≠ 완전성

  • 사서가 잘못된 페이지를 가져오면 답변자도 근거를 못 읽는다
  • top-1(가장 높은 순위 한 개)만 쓰면 수령일 조항은 찾고 택 제거 예외·배송비 조항은 놓칠 수 있다
  • 조항이 청크 경계에서 잘리면 조건과 예외가 분리된다
  • 오래된 버전 청크가 검색되면 그럴듯하지만 현재와 다른 답
복구 — 후보에 기한·예외·비용 조항과 현재 버전이 함께 있는지 확인, 부족하면 질의를 넓혀 재검색하거나 전문으로.
검색 상위 결과가 완전성을 보장하지 않는다는 것이 이 선택의 핵심 위험입니다. 좋은 조각을 한 번 찾았다는 사실을 답의 경계로 삼지 말고, 누락 신호가 보이면 질의를 재작성해 다시 검색하거나 전문 경로로 전환합니다.

🗜️ 압축 & 🗑️ 폐기 — 줄이되 지우지 않기

압축

사실·긴 문서·탐색 결과를 더 짧게. 입력 예산·중복에 유용하나 축약문은 원문 증거를 대신하지 않는다.

부정문·예외·조건부 결정·출처가 빠지면 짧아진 문장이 사실처럼 보인다. → 원문 식별자와 확정·가정·미해결 상태를 남긴다.

폐기

끝난 로그·철회 해석·효력 끝난 버전을 현재 입력에서 제외. 삭제 ≠ 망각.

뺀 재료는 저장소에 남겨 재조회 가능하게, 왜 제외했는지·어느 원문인지 기록. 안 그러면 폐기 이유까지 사라져 같은 오류를 되살린다.

압축은 판단 경로를 바꿀 수 있으므로 무엇이 빠졌는지 남기는 것이 검증의 토대입니다. 폐기는 잊는 게 아니라 이번 입력에서 빼는 것이며, 제외 목록에 이유와 원문 주소를 남겨야 되살릴 수 있습니다.

📋 네 선택 — 실패와 복구 한눈에

전략대표 실패실행 전 확인실패 뒤 복구
전체 투입무관 규정이 핵심 조항을 밀어냄문서 버전·직접 답하는 절의 위치무관 문서 분리·위치 변경·선택 경로 시험
RAG예외 미검색으로 그럴듯한 불완전 답후보에 기한·예외·비용 조항·인용 위치질의 재작성·재검색·재정렬, 부족하면 전문
압축요약이 예외·폐기 가정을 사실처럼 남김원문 주소·확정·가정·미해결 상태원문 재개봉·불확실 항목은 확인 행동으로
폐기필요한 근거·폐기 이유까지 사라짐제외 목록에 이유·원문 주소저장소에서 원문 재조회·필요분 재투입
고르는 기준은 이름이 아니라 판정 사슬 — 무엇을 넣을지(선택)·어느 조각이 근거일지(신뢰)·반복할 가치가 있는지(비용).
RAG를 코드로 직접 만들지 않아도 됩니다. LangChain, LlamaIndex, Qdrant 같은 도구가 모델·임베딩·벡터 저장소·retriever를 공통 인터페이스로 제공합니다. 다만 도구 이름이 아니라 판정 사슬을 문서에서 확인하고 하나만 골라 작게 시작합니다.

상태 정책과 압축 손실 검증

상태는 쌓이는 기록이 아니라 다시 구성하는 이력

누적 · 슬라이딩 · 요약 · 러닝 서머리
대화가 길어진다는 것은 모델 안에 기억이 축적되는 게 아니라, 다음 호출에 어떤 기록을 다시 넣을지 결정해야 한다는 뜻입니다. 대화 상태는 목표·확정 사실·결정 이유·미해결 질문·다음 행동처럼 다음 판단에 필요한 정보를 보존한 입력 묶음입니다.

🔄 상태를 다시 구성하는 네 방식

누누적 — 첫 메시지부터 순서대로. 경위·예외 형성이 중요할 때 좋으나 철회 가정·실패 도구 결과도 남아 충실성이 현재 관련성을 보장하지 않음
슬슬라이딩 윈도(최근 N턴) — 입력 크기 예측 쉽고 최신 협업에 가까우나 최근 언급 안 된 장기 사실(계약 조건·금지 사항·파일 경로)을 잃을 수 있음
요요약 — 오래된 이력을 짧은 상태로. 단 원문 연결 없는 요약은 또 하나의 불투명한 문서
러러닝 서머리 — 정해진 틀(목표·확정·가정·미해결·다음 행동)을 반복 갱신. 갱신 전후 비교+폐기 사유까지 남긴다
러닝 서머리의 이유 — 12턴에 철회한 '불량 반품' 가정이 29턴에 되살아나는 일을 막는다.
러닝 서머리는 단발 요약과 다릅니다. 목표=고객 질문, 확정=수령일·정책 조항, 가정=택 제거 해석, 미해결=실제 착용 확인, 다음 행동=물을 질문처럼 정해진 칸을 계속 갱신합니다. 원문 로그는 상태를 만들 수 있는 저장소일 뿐, 모든 로그를 매번 올리는 게 상태 전략은 아닙니다.

🔬 압축 손실은 원문과 한 줄씩 대조

대조 항목원문에서 찾을 질문압축본에 남길 표현누락 시 위험
사실누가·언제·무엇을 확정했나수령일·정책 버전·확정 조항오래된 사실을 현재처럼
부정하지 말라·해당 안 되는 경우'즉시 불가로 단정하지 않음'금지된 결론을 사실로
예외기본 규칙을 뒤집는 단서택 제거 뒤 착용 여부 확인일반 규칙만 남아 경계 사례 소멸
미결정아직 확인 못한 사실실제 착용 여부 미확인가정을 확정 사실로 승격
출처어느 문서 어느 절[반품 정책 v2.1 §3]원문 재확인 길 없음
예 — "14일 이내 반품 가능, 배송비 고객 부담"으로 줄이면 택 제거 뒤 즉시 반품 불가로 단정할 수 없다는 예외·미결정이 사라진다. 문장 하나 누락이 행동 권한과 고객의 선택을 바꾼다.
검증은 그럴듯한지 판단이 아니라 답을 바꿀 항목을 원문과 대조하는 일입니다. 원문에서 사실·부정·예외·미결정·출처를 표시하고, 압축본의 각 판단 문장에 원문 주소를 붙이며, 빠진 항목은 '없음'으로 명시한 뒤 그것이 답의 가능 범위·다음 확인 행동을 바꾸는지 검토합니다.

📌 이것만은 꼭 — 핵심 4문장

1질문은 "무엇을 기억시킬까"가 아니라 "무엇을 이번 호출에 넣고, 무엇을 저장소에 둘까."
2선택 연산(전체 투입·RAG·압축·폐기)과 상태 정책(누적·슬라이딩·요약·러닝 서머리)을 나눈다.
3압축 ≠ 요약 · 삭제 ≠ 망각 — 줄이거나 빼되 원문 주소와 이유를 남긴다.
4틀렸다는 신호가 보이면 더 요약하는 대신 원문을 다시 읽어 복구한다.
상태 전략은 하나를 영구히 고르는 문제가 아닙니다. 다음 답이 원문 문장을 다시 읽어야 하나, 최근 협업 순서만 알면 되나, 확정 사실·미결정만 유지하면 되나를 구분한 뒤 선택 연산으로 무엇을 올릴지 정합니다. 이 순서를 거꾸로 하면 줄인 뒤에야 예외·출처가 빠졌음을 발견합니다.

Q4. Self-Route 비교에서 top-1 RAG와 전체 문맥의 집계 성능 수치는?
Q5. 압축 손실을 검증할 때 원문과 대조할 다섯 항목은?
답이 바로 떠오르지 않으면 앞 장으로 돌아가 확인해 보세요. Q2와 Q5가 오늘의 핵심을 가장 잘 가립니다.

✅ 정답 & 해설

A1. 선택 연산=이번 호출에 무엇을 넣을지, 상태 정책=여러 턴 이력을 어떻게 유지·재구성할지.
A2. 압축=선택 연산(이번 입력 길이 줄이기), 요약=상태 정책(과거 상태를 다음 턴으로). 책임은 분리해 기록.
A3. 수령일 조항은 찾아도 택 제거 예외·배송비 조항을 놓친다 — 검색 상위 결과가 완전성을 보장하지 않는다.
A4. top-1 RAG 20.24 vs 전체 문맥 45.53(특정 모델·retriever·벤치마크 구성 결과).
A5. 사실 · 부정 · 예외 · 미결정 · 출처 — 각 판단 문장에 원문 주소를 붙이고 빠진 항목은 '없음'으로.
A2와 A5를 자기 말로 설명할 수 있으면 오늘 목표는 달성입니다. 특히 압축 손실 검증은 그럴듯함이 아니라 답을 바꿀 항목의 대조라는 점을 기억하세요.

선택된 문장이 답에 들어왔다는 이유만으로

맥락 전략의 지도 — 여기까지 · 다음: 같은 질문·다른 맥락

선택과 상태가 근거를 바꾼다는 사실은 같은 질문의 통제 실행으로 확인합니다. 선택된 문장이 답에 들어왔다는 이유만으로 믿어도 되는지 — 출처와 신뢰를 판정하는 일이 다음 소단원들의 주제입니다.

Ollama · 크기 사다리 · 양자화 · KV 캐시 실측 · 기기 사양서

여기까지는 계산이었습니다. 이제 모델 하나를 내려받아 내 컴퓨터에서 직접 돌리고, 무엇이 좋고 무엇이 답답한지 손으로 기록합니다.

계산이 알려주지 못하는 것 — 답이 한 글자씩 끊기는지, 4비트가 얼마나 멍청해지는지 — 을 직접 만져 봅니다.

🔌 왜 직접 돌려봐야 할까

  • 숫자는 거짓말을 안 하지만 전부를 말하지도 않습니다 — 속도 체감·품질 저하는 손으로 만져봐야 압니다
  • 이번엔 인터넷을 끊어도 돌아가고, 청구서도 없고, 입력 문장이 어느 회사 서버에도 닿지 않는 상태를 만듭니다
🤝 실습 방식: 코드를 통째로 받아 실행하는 게 아니라, 목적·조건이 적힌 프롬프트를 코딩 에이전트에게 건네고 에이전트가 내 환경에 맞춰 명령을 만들게 합니다. (OS·GPU·메모리가 다 달라 정답 스크립트가 없음)
그 기록이 다음 섹션에서 "이 워크로드는 어디서 돌려야 하는가"를 판단하는 근거가 됩니다. 단순한 명령은 그냥 직접 보여줍니다.
1

설치는 십 분이면 끝납니다

Ollama — 로컬 실행을 한 줄로

설치 · 명령어
로컬 실행 도구는 여럿이지만 우리는 Ollama를 씁니다.

🛠️ Ollama가 한 줄 뒤로 숨긴 것

모델 가중치를 내려받고 · 하드웨어에 맞는 추론 엔진을 붙이고 · 채팅 인터페이스와 HTTP API까지 한 번에. 원래는 CUDA 버전 맞추기 · GGUF 경로 지정 · 컴파일 옵션이던 일을 명령어 뒤로 숨겼습니다.

ollama pull <모델>   # 모델 가중치를 내려받기
ollama run  <모델>   # 대화 시작 (없으면 알아서 받음)
ollama list          # 받아둔 모델 목록 (ls)
ollama ps            # 지금 메모리에 올라간 모델과 크기
ollama stop <모델>   # 메모리에서 내리기
ollama show <모델>   # 구조와 최대 컨텍스트 보기
ollama rm   <모델>   # 모델 삭제
🔑 ollama ps는 나중에 아주 중요해집니다 — 모델이 GPU에 온전히 올라갔는지, 일부가 CPU로 밀려났는지를 알려주는 유일한 창구입니다.
설치는 공식 다운로드 페이지(ollama.com/download)에서 macOS/Windows/Linux 설치 파일을 받아 실행하면 됩니다.

💬 대화 중 슬래시 명령 (전체는 /?)

/set system <문장>           이 세션의 시스템 메시지
/set parameter num_ctx <수>   컨텍스트 크기 변경
/set think | /set nothink     생각 과정 켜기/끄기
/set verbose | /set quiet      응답마다 속도 통계 표시
/set format json              JSON으로만 답하기
/show info                    모델 정보
/clear                        대화 맥락 비우기
/bye                          나가기
  • 여러 줄 입력은 """로 감싸기 · 프롬프트에 파일 경로를 적으면 이미지(.jpg/.png)·오디오(.wav) 첨부
  • 답변 멈춤 Ctrl+c · 편집기에서 긴 프롬프트 작성 Ctrl+g
슬래시 명령은 대화 세션 안에서만 동작합니다. /set think로 다시 켜서 생각 과정을 비교해볼 수도 있습니다.

🤖 [코딩 에이전트 프롬프트] 설치

설치에서 막히는 지점은 거의 항상 환경 문제(드라이버·권한·디스크·보안 정책)입니다. 이 부분은 에이전트에게 맡기는 게 정확합니다.

▼ 그대로 복사해 붙여 넣으세요
목표: 이 컴퓨터에 Ollama를 설치하고, 정상 동작하는지까지 확인한다.

조건:
- 먼저 이 머신의 OS, CPU, GPU 모델과 VRAM 용량, 전체 RAM, 디스크
  여유 공간을 조사해 표로 보여줄 것.
- 공식 배포 경로(https://ollama.com/download 또는 각 OS의 공식
  패키지 매니저)만 사용할 것.
- 설치 후 `ollama --version`과 `ollama ls`가 정상 실행되는 것까지 확인할 것.
- GPU 가속이 실제로 활성화되는 환경인지 판정하고, 아니라면 그 이유를 알려줄 것.
- 각 명령을 실행하기 전에 무엇을 왜 하는지 한 줄로 먼저 설명할 것.
에이전트가 내 환경을 먼저 조사하게 하고, 공식 경로만 쓰게 하고, 실행 전 설명을 요구하는 것이 안전한 프롬프트의 뼈대입니다.

가장 작은 모델부터 올려봅니다

크기 사다리와 속도 읽는 법

--verbose · eval rate
처음부터 큰 모델을 받으면 안 됩니다. 수십 GB를 받는 동안 아무것도 못 배우고, 메모리가 모자라 실패하면 그 시간이 통째로 날아갑니다.

🪜 공개 모델 라이브러리와 Qwen 사다리

ollama.com 라이브러리엔 Gemma·Qwen·Llama·gpt-oss·DeepSeek 등 가중치가 공개된 모델만 크기별 태그로 올라와 있습니다. (태그 이름은 몇 달마다 바뀌니 실습 당일 라이브러리에서 확인)

태그용량성격
qwen3.5:0.8b1.0 GB어떤 노트북에서도. 품질 기대는 낮게
qwen3.5:2b2.7 GB요약·분류 같은 단순 작업의 하한선
qwen3.5:4b3.4 GB8GB 메모리 기기의 현실적 상한
qwen3.5:9b6.6 GB12GB VRAM 카드에서 쾌적
qwen3.5:27b17 GB24GB 카드 또는 통합 메모리 넉넉한 Mac
크기 사다리가 촘촘해 모델 크기만 바꿔 비교하는 오늘 실험에 알맞습니다. 첫 상대는 아래쪽이되 맨 밑은 아닌 4b(3.4GB).
우리가 받아둘 수 있는 건 이렇게 공개된 모델뿐입니다. 아래 태그가 없으면 1GB 안팎의 가장 작은 태그로 바꿔도 실험은 동일합니다.

📥 받고 → 이름 확인 → 실행

Apple Silicon 맥에서는 같은 태그라도 그 기기에 맞는 변종(mlx)으로 저장될 수 있습니다. 실제로 4b가 4b-mlx(4.0GB)로 받아지기도 하니, 받아진 실제 이름으로 실행해야 합니다.

ollama pull qwen3.5:4b
ollama list          # 여기 찍힌 이름을 그대로 쓴다 (mlx 꼬리표가 붙을 수 있음)
ollama run <확인한 이름> --verbose --think=false
⚠️ 맨 아래 0.8b로 시작하지 않는 이유: 1GB 모델은 지시를 자주 흘리고 형식을 못 지켜 "로컬 모델은 못 쓰겠구나"로 첫 경험이 끝납니다. (0.8b는 뒤 비교 실험의 대조군으로 다시 만남)
순서: 받고 → 실제 무슨 이름으로 받아졌는지 확인하고 → 그 이름으로 실행. 없는 이름으로 run하면 처음부터 다시 받기 시작합니다.

🚩 두 플래그와 --verbose 출력

--think=false

등호를 꼭 붙이세요. 값 생략이 가능한 형태라 --think false처럼 띄우면 false가 프롬프트로 넘어가 버립니다. (생각 과정을 끔)

--verbose

응답이 끝날 때마다 소요 시간 통계를 함께 출력합니다.

total duration:     ...            전체 소요 시간
load duration:      ...            모델을 메모리에 올린 시간
prompt eval rate:   ... tokens/s   입력을 읽는 속도 (프리필)
eval count:         N token(s)
eval rate:          ... tokens/s   답변을 생성하는 속도  ← 핵심
계산은 그대로 두고 화면에만 안 보이게 하려면 --hidethinking. 대화 중 /set think로 다시 켤 수 있습니다.

⏱️ 프리필 vs eval rate — 무엇을 볼까

prompt eval (프리필)입력 전체를 한 번 훑어
K·V를 만드는 준비
→
eval (생성)답을 한 토큰씩
이어 쓰는 시간
  • 프리필은 입력을 병렬 처리해 대체로 빠름 · 체감 속도는 eval rate가 정함
  • 사람 읽는 속도 ≈ 초당 5~10토큰 → eval rate 15↑면 쾌적, 5↓면 답답
  • load duration은 첫 실행에서만 큼(디스크→메모리) → 첫 응답은 버리고 두 번째부터 기록
🔑 앞으로 계속 들여다볼 숫자는 마지막 줄의 eval rate (tokens/s) 하나입니다.
prompt eval 구간은 답을 한 글자 쓰기 전 치러야 하는 준비 작업이라 '프리필'이라 부릅니다.

실험 ① 크기 사다리를 올라가며

같은 질문, 크기만 바꿔 관찰

변수는 하나만
하나의 프롬프트를 고정하고 모델 크기만 바꿔 무엇이 달라지는지 봅니다. 변수를 하나만 움직이는 것이 실험의 기본입니다.

🧪 네 종류의 질문

①
사실 확인형
짧고 정답 분명. 작은 모델도 맞혀 크기 효과 안 보임
②
다단계 추론형
조건 3개 동시 만족. 여기서 크기가 갈림
③
지시 준수형
출력 형식 엄격. 작은 모델은 형식을 흘림 — 에이전트에 가장 중요
④
지구력형
긴 입력+긴 출력. 프리필 시간·후반 품질
③ 지시 준수형이 에이전트를 만들 사람에게 가장 중요합니다 — JSON 한 글자가 어긋나면 파이프라인 전체가 멈추기 때문.
사실확인은 작은 모델도 잘하고, 크기의 값어치는 다단계 추론에서 나옵니다. 형식 준수는 실무 파이프라인이 가장 먼저 무너지는 지점입니다.

🤖 [프롬프트] 크기 비교 실험

목표: 같은 프롬프트를 크기가 다른 로컬 모델 여러 개에 넣고, 속도와 품질이
어떻게 달라지는지 측정해 하나의 비교표로 만든다.

조건:
- Ollama 공식 라이브러리에서 지금 실제로 존재하는 태그만 고를 것. 같은 계열
  안에서 크기가 다른 3~4개를 사다리처럼 고를 것.
- 사다리 맨 아래 칸(1GB 안팎)을 반드시 포함. 잘하는 모습이 아니라
  "어디서부터 무너지는지"를 보려는 대조군이다.
- 고르기 전 이 기기의 VRAM/RAM을 확인하고, 다 올라가지 못할 크기는 뺄 것.
- 테스트 프롬프트 4개(그대로 사용):
  (1) 사실 확인: HTTP 429의 뜻과 클라이언트의 올바른 대응을 두 문장으로.
  (2) 다단계 추론: 5명 회의 가능 요일 문제(A 월/수, B 화/수/목, C 수/금,
      D 월/화/수, E 수/목) — 가능한 요일과 근거를 단계별로.
  (3) 지시 준수: 문장에서 person/org/amount를 JSON 객체 하나로만 출력.
      코드블록·설명 금지.
  (4) 지구력: 앞 교안 서너 문단을 붙이고 "핵심 주장·근거 3·반론 1을
      소제목 붙여 800자 이상으로".
- 각 모델×4프롬프트, 매번 두 번 돌려 두 번째 수치만 기록(첫 실행 버림).
- `--verbose`의 eval rate와 eval count를 기록.
- 결과 표: 모델 / 용량 / eval rate / (1)정답 / (2)정답 /
  (3)순수 JSON 여부 / (4)prompt eval rate·후반 품질.
- (3)은 눈이 아니라 실제 JSON 파서로 판정할 것.
- 끝에 "이 기기에서 형식을 안정적으로 지키는 가장 작은 모델"을 한 줄 결론.
변수는 모델 크기 하나. 두 번째 수치만 기록하고, JSON은 파서로 판정하게 하는 것이 핵심 조건입니다.

👀 표가 나오면 무엇을 볼까

관찰 항목대체로 이렇게 나옵니다
크기와 속도커질수록 토큰당 읽을 가중치↑ → 메모리 대역폭에 비례해 느려짐 (MoE는 덜 느림)
크기와 정답률(1)은 작은 모델도 맞힘. 값어치는 (2)에서
형식 준수작은 모델은 설명·백틱을 덧붙임 → 파이프라인이 먼저 무너지는 곳
첫 토큰까지입력이 길수록 프리필↑ → "말 시작"까지 오래
지구력작은 모델은 길어질수록 같은 말 반복·앞 조건 망각
이 관찰이 뒤에 채울 기기 사양서의 재료입니다.

🪤 오해 — "큰 모델은 무조건 느리다"

항상 맞지는 않습니다. MoE(Mixture-of-Experts)는 전체 파라미터가 수백억 개여도 토큰 하나를 만들 때 일부 전문가만 깨웁니다.

gpt-oss:120b — 내려받는 용량은 65GB지만, 토큰당 깨어나는 파라미터는 전체의 1/20에도 못 미침 → 메모리에만 올릴 수 있다면 용량이 짐작하는 것보다 훨씬 빠름

메모리에 들어가느냐 = 전체 파라미터
얼마나 빠르냐 = 활성 파라미터
그래서 로컬 모델을 고를 땐 두 숫자를 따로 봐야 합니다 — 총 파라미터(메모리)와 활성 파라미터(속도).

실험 ② 같은 모델을 다른 정밀도로

양자화를 눈으로 확인

4비트 vs 8비트 vs 16비트

🔑 4비트 칸이 6GB가 아니라 7.6GB인 건 계산 오류가 아닙니다. q4_K_M은 민감한 두 자리를 6비트로 남겨 실효 ~4.8비트, 여기에 블록 스케일 값이 더해집니다. 정수 비트로 어림한 값은 하한, 실제 파일은 늘 그보다 조금 위.
16비트=2바이트니 24GB, 8비트는 절반이라 12GB 언저리(실제 13GB), 4비트는 더 벌어져 7.6GB. gpt-oss처럼 처음부터 MXFP4(4.25비트)로 배포돼 변환 없이 그대로 실행되는 모델도 있습니다.

🔧 컨텍스트를 박아 넣은 파생 모델

컨텍스트를 바꾸는 길은 여럿이고 실행 방식에 따라 먹히기도 안 먹히기도 합니다. 그래서 어디서든 똑같이 적용되는 하나만 씁니다 — 원하는 길이를 박은 파생 모델 만들기.

# 이 모델의 최대 길이부터 확인
ollama show qwen3.5:4b-mlx

# 그 길이를 박은 파생 모델 만들기
printf 'FROM qwen3.5:4b-mlx\nPARAMETER num_ctx 262144\n' > Modelfile
ollama create qwen3.5-256k:4b -f Modelfile
ollama run qwen3.5-256k:4b --verbose --think=false
Modelfile은 두 줄짜리 텍스트 파일입니다. Windows·PowerShell에 printf가 없으면 메모장에 두 줄을 적어 확장자 없이 Modelfile로 저장 후 ollama create만 실행. 원본과 레이어를 공유해 디스크는 거의 안 늘어남.
한 번 만들어 두면 터미널에서든 앱에서든 긴 컨텍스트가 그대로 적용됩니다.

📟 ollama ps의 PROCESSOR 열 = 답안지

100% GPU

전부 GPU에 올라감 ✅

48%/52% CPU/GPU

계산의 48%가 CPU로 밀려남

🔑 우리가 찾는 건 이 값이 절반을 넘는 순간이 아니라 처음으로 0을 벗어나는 순간입니다. 1%만 밀려나도 그 층은 매 토큰마다 시스템 메모리를 왕복해 속도가 이미 꺾입니다. → 손으로 계산한 KV 캐시 값이 맞았는지 검증해 주는 답안지.
ollama ps는 모델이 메모리에 올라가 있는 동안만 의미가 있으니, 터미널 창을 하나 더 열어 두고 응답 직후에 칩니다. 몇 분 놀면 모델이 내려가 목록이 비어버립니다.

🤖 [프롬프트] 컨텍스트 · 한계선 찾기

긴 입력은 파일로: ollama run <모델> --verbose < long.txt · ollama ps는 창을 하나 더 열어 응답 직후에

목표: 실제로 밀어 넣는 입력 길이를 늘려 가며 메모리 점유량과 속도가 어떻게
변하는지 측정하고, 이 기기의 실제 한계선을 찾는다.

조건:
- 모델은 이 기기에서 GPU에 온전히 올라가는 것 중 가장 큰 것으로 하나 고정.
- num_ctx는 먼저 값만 바꿔 `ollama ps` SIZE가 변하는지 확인. 변하면 SIZE가
  GPU 메모리에 들어오는 가장 큰 값으로, 안 변하면 모델 최대값으로 열고 고정.
- 변수는 실제 입력 토큰 수. 500 → 5000 → 20000 → 70000 순으로. 매 단계 전
  `ollama stop`으로 내렸다 다시 올릴 것.
- 각 단계: (a) ps의 SIZE와 PROCESSOR 열 (b) prompt eval count·rate, eval rate.
- PROCESSOR가 100% GPU에서 벗어나는 첫 지점을 명시. 그 전후 eval rate가
  몇 배 차이 나는지 계산. 끝까지 안 벗어나면 그렇다고 쓸 것.
- 측정값에서 "토큰 1개당 KV 캐시 바이트"를 역산하고, 레이어 수·헤드 구성으로
  이론값을 계산해 둘을 비교(`ollama show`로 구조 확인).
- 이론값과 실측값이 어긋나면 가능한 이유를 제시.
- 결과를 표 하나와 세 줄 요약으로.
실측값이 이론값보다 작으면 GQA 때문일 가능성이 큽니다 — K·V 헤드를 여러 쿼리 헤드가 나눠 써 캐시가 헤드 수만큼 늘지 않습니다. 이 맞춰보기 경험이 "이건 들어가겠는데" 감각의 출처입니다.

✅ 정답 & 해설 (1/2)

A1. 속도 체감·양자화 품질 저하는 만져봐야 알기 때문. 이점: ①오프라인 동작 ②청구서 없음 ③데이터가 외부 서버에 안 감.
A2. 답을 한 토큰씩 생성하는 속도(tokens/s). 15↑ 쾌적, 5↓ 답답. 첫 응답엔 디스크→메모리 로딩 시간(load duration)이 섞이므로 버린다.
A3. 값 생략이 가능한 플래그라 띄어 쓰면 false가 프롬프트로 넘어가기 때문. --think=false로 붙여야 함.

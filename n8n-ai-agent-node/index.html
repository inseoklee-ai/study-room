두 번째 질문 — 재형식화

방금 받은 제목과 설명을 한 문장으로 정리해 줘

  • 새 사실을 찾을 이유가 없으므로 — 같은 대화 맥락에서 답했다면 새 도구 호출이 생기지 않습니다

흐름을 판정하는 기준

업무를 한 문장으로 좁힙니다

⑤ 워크플로 속 에이전트
화면·CLI·에이전트에서 같은 흐름의 실행 기록을 봤습니다. 그 관찰을 내 업무 판정에 쓰려면 무엇을 물어야 하는지 정리합니다.

업무를 한 문장으로 좁힙니다

❌ 넓은 문장

"고객 지원 자동화" — 입력과 확인 범위가 넓어집니다

✅ 좁힌 문장

"매일 오전 새로 들어온 공개 문의를 읽고 담당자가 확인할 세 줄 요약을 만듭니다" — 읽는 대상 · 결과를 받는 사람 · 사람이 확인하는 지점이 드러납니다

  • 이 강의의 예시 업무 — "매일 공개 API에서 정보를 읽어 짧은 요약을 만듭니다"
  • 판정 흐름 — 반복 업무 한 문장 → 입력·산출물 → 허용 권한 → 검증 신호 → 도입 · 보류 · 거절
📌 화면의 노드와 CLI의 응답이 같아 보여도 — 업무에 허용할 범위는 실행의 흔적과 권한 경계를 함께 읽어야 드러납니다
판정의 세 결론은 소단원 ⑥에서 판정문 양식으로 다시 다룹니다.

IF 노드로 분기 만들기

같은 입력에는 언제나 같은 결과

⑤ 워크플로 속 에이전트
지금까지의 워크플로는 입력이 들어오면 같은 순서로 노드를 실행했습니다.

조건을 검사해 경로를 나눕니다

n8n의 IF 노드는 정해진 조건을 검사하고 실행 경로를 true와 false로 나눕니다. HTTP Request와 AI Agent 사이에 추가할 수 있습니다.

HTTP Request
    ↓
IF: title과 description이 모두 있는가?
    ├─ true  → AI Agent → 한 문장 요약
    └─ false → 확인 필요 기록 또는 담당자 검토
  • title이 비어 있지 않은지 확인하고, 두 번째 조건으로 description이 비어 있지 않은지 확인합니다. 두 조건을 모두 만족해야 true 경로로 보냅니다
값이 정상적으로 들어오면 AI Agent가 요약을 만들고, 하나라도 비어 있으면 false 경로에서 처리를 멈추거나 확인이 필요하다는 결과를 남깁니다.

이 분기는 AI의 판단이 아닙니다

같은 입력에는 언제나 같은 결과를 내는
명시적인 규칙입니다
  • IF 노드가 알맞은 조건 — 필드가 비어 있는지, 상태코드가 200인지, 점수가 기준 이상인지처럼 조건을 정확히 표현할 수 있을 때
  • 실행 기록에서도 어떤 조건이 참이었고 어느 경로가 실행되었는지를 확인할 수 있습니다
"AI를 넣었으니 지능적"이라는 오해를 끊는 슬라이드입니다. IF는 규칙이고, 규칙의 장점은 재현성입니다.

false 경로를 비워 두지 않습니다

🔁 통과시키는 장치

정상 값을 다음 단계로 자동 통과

🛑 통제 지점

잘못된 입력이 다음 단계로 넘어가지 않도록 막는 자리

  • 그래서 false 경로는 오류 기록 · 재시도 · 사람의 확인 단계와 연결하는 편이 좋습니다
  • 정상 경로뿐 아니라 예외 경로가 무엇을 하는지도 워크플로의 일부입니다
예외 경로를 비워 두면 "조용한 실패"가 생깁니다 — 소단원 ①에서 본 "멈춰야 할 작업이 계속 실행"되는 문제입니다.
4

에이전트가 다음 행동을 선택하게 하기

모든 조건을 미리 나열할 수는 없습니다

⑤ 워크플로 속 에이전트
입력 문장의 의도를 해석하거나, 현재 정보만으로 답할 수 있는지 판단하고, 필요한 도구를 선택해야 하는 경우입니다.

목표와 현재 상태로 다음 행동을 고릅니다

사용자 요청
    ↓
AI Agent
    ├─ 새 사실이 필요함 → 읽기 도구 호출 → 결과 확인 → 답변
    ├─ 받은 정보로 충분함 → 도구 호출 없이 재형식화
    └─ 근거가 부족함     → 부족한 정보 표시 또는 사람에게 확인 요청
  • 앞 실습에서 AI Agent는 질문을 읽고 공개 API 도구를 호출할지 판단했습니다
  • 에이전트는 고정된 한 경로를 실행하는 대신 — 목표와 현재 상태를 바탕으로 다음 행동을 선택합니다
세 갈래 가운데 마지막(근거 부족 → 사람에게 확인)이 실무에서 가장 자주 빠지는 갈래입니다.

여러 읽기 도구를 붙이면 범용적인 흐름이 됩니다

  • 예 — 문서 정보를 읽는 도구와 서비스 상태를 확인하는 도구를 함께 연결하면, 에이전트는 질문에 필요한 도구를 골라 호출할 수 있습니다
  • 한 번의 호출로 정보가 충분하지 않다면 — 결과를 확인한 뒤 다른 도구를 호출하거나 질문을 좁힐 수도 있습니다
🎯 범용성은 에이전트에게 모든 권한을 주는 데서 생기지 않습니다 — 허용된 도구 안에서 다음 행동을 선택할 수 있게 하는 데서 생깁니다
이 문장이 이 소단원의 결론에 가장 가깝습니다.

IF 노드와 AI Agent는 서로를 대신하지 않습니다

구분IF 노드AI Agent 노드
판단 기준미리 작성한 조건입력의 의미와 현재 맥락
같은 입력의 결과같은 경로로 분기모델과 도구 결과에 따라 달라질 수 있음
알맞은 업무값 · 상태 · 수치 검사의도 해석 · 도구 선택 · 요약
확인할 기록조건 결과와 실행 경로도구 호출 · 도구 결과 · 최종 답변
주요 통제조건식과 예외 경로도구 권한 · 지시문 · 호출 범위 · 사람의 승인
📌 분명한 규칙은 IF 노드에, 해석이 필요한 부분은 제한된 도구를 가진 AI Agent에 맡깁니다 — 실제 흐름에서는 두 노드를 함께 씁니다
실행 기록에서 분기 조건과 도구 호출을 함께 확인할 수 있다면, 무엇이 규칙에 따른 결과이고 무엇이 AI의 판단에 따른 결과인지 구별할 수 있습니다.

❓ 이해도 확인

Q1. 두 질문을 던져 확인하려는 것은?
A1. 새 사실을 찾은 답변과 이미 받은 사실을 재형식화한 답변을 구별하는 것. 실행 기록의 도구 호출 유무로 확인한다.
Q2. IF 노드의 두 얼굴은?
A2. 결과를 자동 통과시키는 장치이면서, 동시에 잘못된 입력을 막는 통제 지점. 그래서 false 경로를 비워 두지 않는다.
Q3. 에이전트의 범용성은 어디서 생기나?
A3. 모든 권한을 주는 데서가 아니라 — 허용된 도구 안에서 다음 행동을 선택할 수 있게 하는 데서.
Q3이 이 소단원의 결론입니다.

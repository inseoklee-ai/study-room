OpenClaw는 한 덩어리 명령이 아니라 여러 부품으로 이루어져 있습니다. 그중 첫 번째가 게이트웨이입니다.

게이트웨이는 오래 유지되는 실행 과정입니다

  • 게이트웨이는 채널 연결을 오래 유지하는 실행 과정입니다
  • 기본적으로 내 컴퓨터의 127.0.0.1:18789에서 연결을 받습니다 — 127.0.0.1은 이 컴퓨터 안에서만 접속한다는 뜻
🎯 오늘의 목표 — 연습용 환경에 설치하고, onboard(온보딩)로 첫 설정을 마친 뒤 WebChat에서 한 문장을 보냅니다. 설치 결과는 버전·진단·응답 화면에 남습니다
온보딩은 처음 실행에 필요한 선택을 대화형으로 받는 과정입니다.

시작 위치와 버전을 먼저

격리는 폴더 이름만으로 완성되지 않습니다

② 설치
이 실습은 오늘 처음 만드는 연습 폴더에서만 진행합니다.

연습 폴더에서만 진행합니다

mkdir -p ~/openclaw-lab && cd ~/openclaw-lab
pwd
node --version
  • 실제 업무 저장소, 홈 디렉터리의 설정 폴더, 개인 파일이 있는 위치에서는 진행하지 않습니다
  • -p는 이미 있어도 오류를 내지 않는 옵션입니다
  • 공식 설치 문서가 요구하는 Node — 22.22.3+ · 24.15+ · 25.9+, Node 26 권장
  • 범위에 맞지 않으면 Node를 억지로 바꾸지 말고 실패 경로로 이동합니다
화면의 버전과 수업 자료에 적힌 권장 버전을 대조합니다.

2

설치와 온보딩을 한 번씩

노트북 환경이 섞인 수업에서는 npm 경로

② 설치
공식 README는 macOS·Linux·WSL2에는 install.sh, Windows에는 install.ps1을 안내합니다. npm은 운영 체제와 관계없이 같은 명령으로 설치할 수 있습니다.

npm으로 설치합니다

npm install -g openclaw@latest --allow-scripts=openclaw
openclaw --version
  • --allow-scripts=openclaw는 npm의 lifecycle script 허용 옵션입니다
  • latest는 설치 시점의 최신 버전을 받아 오므로 — 화면에 보이는 숫자는 설치한 날짜에 따라 다를 수 있습니다
openclaw onboard --install-daemon
📌 데몬은 터미널 창을 계속 열어 두지 않아도 백그라운드에서 실행되는 관리 서비스입니다. 이 옵션은 대화형 설정과 데몬 설치를 함께 수행 — macOS에서는 LaunchAgent, Linux/WSL2에서는 systemd 사용자 서비스로
설치할 버전을 지정할 수도 있습니다.

두 인증 경로의 차이

경로동작과금
ANTHROPIC_API_KEYOpenClaw가 직접 키를 들고 호출종량 과금
claude-cli같은 호스트에서 로그인한 Claude Code를 재사용 — 내부적으로 Claude CLI를 실행해 로그인해 둔 세션을 대신 사용구독에서 차감되지만 실제 호출은 CLI를 거칩니다
⚠️ 코딩 에이전트 구독 계정을 연결해도 Claude가 구독으로 완벽하게 동작하는 것은 아닙니다. 그리고 API 키 값을 메모나 화면 캡처에 남기지 않습니다
  • 온보딩 화면에서는 수업용 인증 경로만 고릅니다
이 두 경로의 차이가 소단원 ⑧ 사용량 화면에서 "돈"과 "남은 양"의 차이로 다시 나타납니다.

실행 상태를 세 곳에서 확인

마지막 줄만 보고 성공으로 판단하지 않습니다

② 설치
온보딩을 마쳤다고 바로 채널을 연결하지 않습니다.

진단은 화면 그대로 읽습니다

openclaw doctor
openclaw gateway status
  • doctor는 구성 진단 명령입니다. 경고와 오류가 있으면 마지막 줄만 보고 성공으로 판단하지 않습니다
  • 통과한 항목과 남은 항목을 화면 그대로 읽는 것이 진단의 목적입니다
  • gateway status에서는 게이트웨이의 실행 상태를 봅니다
  • 둘 중 하나라도 실패하면 그 시점에서 멈춥니다
"OK"라는 마지막 줄이 모든 항목의 통과를 뜻하지 않습니다.

WebChat에서 첫 문장

WebChat은 OpenClaw가 자체적으로 제공하는 대화 화면입니다. 실행 중인 게이트웨이가 이 화면을 http://127.0.0.1:18789에서 내어 놓고, 브라우저가 게이트웨이와 WebSocket 연결을 유지한 채 이력과 메시지를 주고받습니다.

openclaw dashboard
  • 화면은 저절로 열리지 않습니다 — 이 명령이 기본 브라우저에서 그 주소를 엽니다
  • 게이트웨이가 멈춰 있으면 화면이 열려도 새 메시지를 보낼 수 없습니다
이 메시지를 받았다면 `연결 확인`이라고만 답해 주세요.
⚠️ 주소를 추측해 입력하거나 외부 네트워크에 포트를 열지 않습니다 — 기본 주소의 외부 접속은 공식 문서에서 권장하지 않으며 원격 접속에는 별도의 승인 절차가 필요합니다
WebSocket은 브라우저와 서버가 연결을 끊지 않고 메시지를 계속 주고받는 통신 방식입니다.

원격 접속의 길 — Tailscale

Tailscale은 내 기기들을 하나로 묶어 사설망처럼 쓰게 해 주는 도구입니다.

기능하는 일
Serve게이트웨이를 127.0.0.1에 둔 채 사설망 안에서만 쓰는 HTTPS 주소를 붙임
Funnel공개 주소를 만들 수도 있음
📌 텔레그램 연결과는 다른 길입니다 — 텔레그램은 에이전트가 메시지를 받을 새 창구를 여는 것이고, 이쪽은 이미 떠 있는 WebChat 화면을 다른 기기에서도 쓰게 하는 길입니다
출처: docs.openclaw.ai/gateway/tailscale

생긴 상태를 열고, 끝나면 멈춥니다

화면에 표시된 경로만 따라갑니다

② 설치
설치와 온보딩 뒤에는 상태가 남습니다.

남은 흔적을 엽니다

ls -la ~/.openclaw
  • 온보딩 완료 화면, doctor 출력, gateway status 출력에서 이 경로가 표시되는지 확인하고 직접 엽니다
  • 폴더 이름과 보이는 파일·하위 폴더 이름이 설치가 남긴 흔적입니다
  • 파일 내용에 토큰, 키, 개인 대화가 보이면 내용을 복사하거나 공유하지 않습니다
⚠️ 화면에 표시된 경로만 따라갑니다 — 화면에 없는 경로를 검색하거나 추측으로 만들어 열지 않습니다
추측 탐색은 관측이 아니라 소음을 만듭니다.

첫 응답
  • 설치·온보딩·진단이 실패했다면 openclaw --version으로 설치 여부부터 다시 확인합니다
  • WebChat에서 응답을 받지 못했다면 게이트웨이 상태와 오류 문구를 함께 봅니다
각 결과에서 화면에 나타난 버전, 상태, 응답이 설치가 끝났다는 증거입니다.

수업이 끝날 때 멈추는 법

openclaw daemon stop
openclaw gateway status
openclaw config file
  • 게이트웨이를 터미널에서 직접 실행했다면 그 터미널에서 Ctrl-C
  • 이어서 gateway status로 멈췄는지 확인합니다
  • 프로그램을 멈춰도 상태 디렉터리와 설정 파일은 지우지 않는 한 남습니다. 기본 설정 파일은 ~/.openclaw/openclaw.json
🔐 마무리에서는 프로그램을 끄고 — 수업용 토큰과 인증 경로의 보관 위치와 접근 가능 범위를 다시 살핍니다
끄는 것과 지우는 것은 다른 일입니다.

❓ 이해도 확인

Q1. 연습 폴더를 만들어도 격리가 완성되지 않는 이유는?
A1. 설정·상태·자격 증명이 홈 폴더의 ~/.openclaw/에 모이기 때문. 그래서 수업용 계정·키만 쓴다.
Q2. 두 인증 경로의 차이는?
A2. API 키는 OpenClaw가 직접 키를 들고 호출(종량), claude-cli는 로그인해 둔 Claude Code 세션을 CLI로 대신 사용(구독 차감).
Q3. doctor를 읽는 법은?
A3. 마지막 줄만 보지 않고 통과한 항목과 남은 항목을 화면 그대로 읽는다. 하나라도 실패하면 그 시점에서 멈춘다.
Q1이 이 절의 안전 규율입니다.

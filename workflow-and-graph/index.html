자동화에 맡길 일을 고를 때는 먼저 규칙을 확인합니다.

무조건 · 항상 · 매번을 쓸 수 있는가

일을 설명하면서 이 세 낱말을 쓸 수 있다면 규칙이 비교적 선명합니다. 조건과 결과를 이어 적을 수 있는 일입니다.

1새 문의에 접수 번호를 붙이는 규칙
2매일 아침 전날 매출을 표에 옮기는 규칙
3첨부가 없는 신청서에는 안내를 보내도록 정합니다
"무조건/항상/매번"은 규칙성을 가리는 아주 실용적인 리트머스입니다.

정해 둔 경로 · 분기 · 검토할 수 있는 기록

② 자동화와 워크플로
그래프가 순서를 정하는 워크플로에서는 사람이 경로를 미리 정합니다.

워크플로의 정의

📖 Anthropic은 워크플로를 "미리 정의된 코드 경로로 LLM과 도구가 조율되는 시스템"으로 정의합니다
  • 예 — 새 문의를 분류합니다. 환불 관련 문의는 담당 부서로 보냅니다. 나머지는 일반 답변 흐름으로 보냅니다
  • 따라서 워크플로의 핵심은 모델이 자유롭게 움직이는 데 있지 않습니다 — 정해 둔 경로와 분기, 그리고 검토할 수 있는 기록에 있습니다
출처: Anthropic, Building effective agents, https://www.anthropic.com/research/building-effective-agents

같은 요약 업무라도 책임의 경계가 다릅니다

비교의 다섯 질문

질문확인하는 것
통제누가 시작 · 중지 · 승인 · 쓰기 권한을 정하는지
관측입력 · 도구 호출 · 응답 · 실패 지점을 기록으로 되짚을 수 있는지
이식성프롬프트 · 연결 규칙 · 코드 · 비밀값을 다른 환경으로 옮길 때 무엇을 다시 준비해야 하는지
비용구독 · 모델 처리량 · 실행 횟수처럼 어떤 단위로 요금이 계산되는지
데이터 경로입력 · 로그 · 모델 · 결과 · 비밀값이 어느 서비스와 저장 위치를 지나는지
이 다섯 질문이 이 중단원의 나머지 실습 전체를 관통합니다.

예시 업무를 하나 정합니다

매일 아침 공개 데이터에서 정보를 읽고
세 문장으로 요약을 받습니다
  • 전제 — 공개 데이터는 개인 정보가 없는 공개 API라고 가정합니다
  • 같은 업무라도 세 국면에 놓으면 확인할 내용이 달라집니다
이 업무가 다음 두 표의 행을 채웁니다. 실습에서 실제로 만들어 볼 흐름과도 같습니다.

같은 업무 · 세 국면 ① — 통제 · 관측

국면통제 — 시작·수정·전송의 승인 주체관측 — 원문 응답·요약·실패 기록의 위치
사람이 하나씩 시킴매일 대화에서 요청. 예약과 연결 기능이 있다면 켜고 끄는 권한을 확인요약과 별도로 공개 데이터의 원문 응답을 저장하거나 다시 열 수 있는지
그래프가 순서를 정함정해 둔 시각의 실행과 요약 전송을 수정·중지하는 권한. 발송은 별도 승인을 거치게 설정각 실행의 요청 · 응답 · 분기 · 오류를 실행 기록에서
모델이 다음을 고름일정 설정 · 코드 변경 · 파일 저장 · 메시지 발송에 필요한 승인 경로를 각각실행 명령 · 코드 변경 · 표준 출력 · 오류를 사람이 재현할 수 있는지
모델 국면에서 승인 경로를 "각각" 확인해야 한다는 점이 핵심입니다.

같은 업무 · 세 국면 ② — 이식성 · 비용 · 데이터 경로

국면이식성비용데이터 경로
사람이 하나씩대화 지시와 연결 설정을 다른 계정·도구로 옮길 수 있는지플랜의 사용량 한도와 연결 도구 사용량이 같은 한도인지공개 데이터·대화 내용·연결 도구 입력이 각각 어느 제공자에게
그래프내보낸 뒤에도 비밀값을 다시 넣어야 하는지와 버전 차이하루 한 번의 전체 워크플로 실행이 어떤 단위로 계산되는지호스팅 위치 · 실행 로그 · 외부 모델 · 공개 API 사이의 이동
모델저장소의 코드와 환경 변수 중 다른 컴퓨터에서 다시 준비할 내용계정 사용량 · 모델 처리량 · 실행 환경 비용을 각각공개 데이터 요청·로컬 파일·환경 변수·모델 입력·저장소의 연결 경로
코드가 저장소에 있어도 실행 환경과 비밀값을 재현하지 못하면 업무 전체를 옮길 수 없습니다.

표는 승자를 가리는 도구가 아닙니다

🎯 확인하지 않은 전제를 드러내는 도구로 사용합니다
  • 대화 도구·흐름 도구·개발 도구를 비교할 때 제품 이름을 행에 더할 수 있습니다
  • 다만 공식 문서에서 확인하지 못한 가격 · 연결 수 · 기능 차이는 "미확인"으로 남겨 둡니다

Q1. 어떤 일이 "아직 규칙이 아닌지" 어떻게 시험하나?
A1. 낯선 동료에게 가르친다고 상상해, "이 경우에는 어떻게 하나요"에 "알아서 해주세요"라고 답하게 되면 그 부분은 규칙이 아니다.
Q2. 워크플로의 핵심은?
A2. 모델의 자유로움이 아니라 정해 둔 경로와 분기, 검토할 수 있는 기록.
Q3. 비교의 다섯 질문은?
A3. 통제 · 관측 · 이식성 · 비용 · 데이터 경로. 확인 못 한 항목은 "미확인"으로 남긴다.

대단원 4 · 컨텍스트 엔지니어링 · ②

같은 창에서
경쟁하는 다섯 종류

하나의 입력 예산을 나눠 쓴다 — 지시·문서·메모리·도구·이력

맥락이라 하면 대화 이력을 먼저 떠올리지만, 창을 나눠 쓰는 것은 이력만이 아닙니다. 시스템 지시, 도구 정의와 실행 결과, 검색으로 가져온 근거, 답의 출력 스키마까지 매 호출의 창에 함께 들어옵니다. 컨텍스트를 다룬다는 것은 대화창 관리가 아니라 구성요소 전체가 벌이는 자리 다툼을 설계하는 일입니다.

🎯 오늘의 한 문장 — 컨텍스트는 대화창이 아니라 자리 다툼이다.
세 파트를 지나면 컨텍스트를 '대화 이력'과 같은 말로 쓰던 습관에서 벗어나, 하나의 입력 예산을 어느 재료에 얼마나 배정할지 설계하는 관점으로 옮겨 갑니다.
1

한 칸을 나누는 재료들

매 호출의 창에는 대화 이력만 들어오지 않는다

구성요소 카드 · 같은 입력 예산
컨텍스트를 '대화 이력'과 같은 말로 쓰면 실제로 무엇이 자리를 차지하는지 놓칩니다. 매 호출 창에는 대화 이력뿐 아니라 시스템 지시, 도구 정의와 실행 결과, 검색 근거, 출력 스키마가 함께 들어옵니다.

🪟 맥락 = 대화 이력? 아니다

  • 맥락이라 하면 대화 이력을 먼저 떠올리지만, 창을 나눠 쓰는 것은 이력만이 아니다
  • 매 호출 창엔 시스템 지시 · 도구 정의와 실행 결과 · 검색 근거 · 출력 스키마가 함께 들어온다
컨텍스트를 다룬다 = 대화창 관리가 아니라 구성요소 전체가 벌이는 자리 다툼을 설계하는 일.
화면에서는 서로 다른 영역처럼 보이지만, 호출 때는 하나의 입력 예산 안에 모두 놓입니다. 그래서 '무엇을 넣을까'는 언제나 '무엇을 뺄까'와 함께 판단해야 합니다.

🃏 구성요소 카드로 보자

출처어디서 왔나
역할무엇을 하나
길이얼마나 크나
신뢰얼마나 믿나
  • 매 호출 창에 들어오는 각 재료를 카드로 본다 — 카드마다 출처·역할·길이·신뢰 수준이 다르다
  • 한 카드를 늘리면 다른 카드가 쓸 공간이 준다
지시·요청·이력·검색·도구·구조화 출력까지 넓게 보는 관점이다. (Philipp Schmid, Context Engineering)
구성요소 카드로 보면, 컨텍스트 설계가 단순히 '길이를 줄이는 일'이 아니라 출처·역할·신뢰가 다른 재료들의 비중을 정하는 일임이 드러납니다. Philipp Schmid의 Context Engineering은 지시·요청·이력·검색·도구·구조화 출력까지 넓게 다루는 실무 안내입니다.
2

하나의 창에서 경쟁하는 다섯

같은 막대를 나눠 쓴다 — 늘리면 어딘가 줄어든다

지시 · 문서 · 메모리 · 도구 목록 · 대화 이력
다섯 재료는 화면에선 서로 다른 영역처럼 보여도 호출 때는 같은 입력 예산 안에 놓입니다. 다섯이 하나의 막대를 나눠 쓰므로, 어느 하나를 늘릴 땐 출력 영역과 다른 재료의 자리를 함께 확인해야 합니다.

🍱 하나의 창에서 경쟁하는 다섯 재료

1지시 — 모델의 역할·금지 사항
2문서 — 질문에 답할 근거
3메모리 — 이전 작업의 요약·결정 기록·사용자 선호
4도구 목록 — 모델이 쓸 수 있는 도구의 이름·매개변수·설명
5대화 이력 — 사용자와 assistant가 주고받은 기록
다섯 재료는 뒤 파트에서 다시 역할별로 나눕니다. 지금은 '이 다섯이 같은 창에 함께 들어온다'는 사실 자체가 핵심입니다.

📏 화면은 나뉘어 보여도 — 같은 예산

지시—
문서—
메모리—
도구 목록—
대화 이력—
다섯 재료가 하나의 막대를 나눠 쓴다
어느 하나를 늘릴 땐
출력 영역과 다른 재료의 자리를 함께 확인화면에선 서로 다른 영역처럼 보여도 호출 때는 같은 입력 예산 안에 놓인다
같은 입력 예산이라는 사실이 이 소단원의 뼈대입니다. 다섯 재료를 각자 독립적으로 최적화하려 하면 서로의 자리를 빼앗는다는 것을 놓치게 됩니다.

⚖️ 하나를 늘리면 다른 하나가 준다

지긴 시스템 지시 + 도구 정의를 넣으면 안전 동작 바탕은 늘지만 정책 문서·대화 이력 자리가 준다
이과거 대화를 모두 유지하면 선호·합의 결정은 보존되나 지금 질문에 직접 답하는 조항이 묻힐 수 있다
문새 문서를 넓게 넣으면 근거 범위는 커지나 오래된 메모리와 충돌 가능성↑
어느 하나가 본질적으로 불필요한 게 아니라, 현재 과제에 필요한 비중을 정해야 한다.
세 예시 모두 '무엇을 빼야 하는가'라는 단일한 답이 없습니다. 지시도 이력도 문서도 각자 값어치가 있고, 다만 이번 과제에서 어느 것이 얼마만큼 필요한지가 다릅니다.
3

다섯은 같은 역할을 하지 않는다

서로 대신할 수 없기에, 충돌하면 무엇을 다시 볼지 판단

역할 구분 · 대체 불가 · 예산표
다섯 재료가 같은 막대를 나눠 쓴다고 해서 서로 바꿔 넣을 수 있는 건 아닙니다. 각 재료의 역할이 다르기 때문에, 충돌이 생겼을 때 무엇을 다시 확인할지 판단하려면 종류를 구분해야 합니다.

🧭 다섯 재료의 서로 다른 역할

재료맡는 역할
지시누구를 위해 어떤 형식으로 무엇을 하지 말지 정하는 규칙 — 역할·안전·출력 형식·예외 처리
문서현재 질문의 사실·규칙을 제공
메모리이전에 확정한 결정·선호를 짧게
도구 목록무엇을 조회·실행할 수 있는지
대화 이력질문 경위와 최근 정정
지시는 모든 답의 울타리라 함부로 못 줄이지만, 같은 규칙 반복·무관한 예시는 근거 문서 자리를 줄인다. 지시에 출처·적용 범위를 붙여 정책인지 예시인지 구분.
지시는 역할·안전·출력 형식·예외 처리가 쌓이면 상당한 크기가 됩니다. 그렇다고 통째로 줄일 수는 없으니, 정책과 예시를 표시해 두면 무엇이 반복이고 무엇이 필수인지 가려낼 수 있습니다.

🚫 서로를 대신할 수 없다

1메모리가 원문을 대신할 수 없다 — 요약은 결정·선호를 짧게 담을 뿐 근거 문서 자체가 아니다
2도구 설명이 실제 결과를 대신할 수 없다 — 무엇을 할 수 있는지와 무엇이 실제 나왔는지는 다르다
3과거 대화가 최신 주문 상태를 대신할 수 없다 — 경위는 지금의 사실이 아니다
재료의 종류를 구분해야 충돌할 때 무엇을 다시 확인할지 판단할 수 있다.
대체 불가의 원칙은 실전에서 디버깅의 지침이 됩니다. 답이 틀렸을 때, 메모리가 원문을 대신하려 했는지, 도구 설명을 결과로 오인했는지, 과거 대화를 최신 상태로 착각했는지를 나눠 보면 무엇을 다시 넣어야 할지 보입니다.

📋 예산표는 줄일 대상을 찾는 도구

입력 항목실제 토큰 수고정/가변출처제거 시 위험확보할 출력량
지시—고정———
도구 정의—가변———
대화 이력—가변———
간단한 예산표 항목: 입력 항목 · 실제 토큰 수 · 고정/가변 · 출처 · 제거 시 위험 · 확보할 출력량.
예산표는 무엇이 얼마나 자리를 차지하는지 눈에 보이게 만듭니다. 각 행에 출처와 제거 시 위험을 함께 적어야, 자리를 줄일 후보를 감이 아니라 근거로 고를 수 있습니다.

✂️ 예산표로 자리를 확보한다

지고정 지시 8k는 매번 유지하되 중복 예시 2k 절감 가능
도도구 정의 12k는 현재 노출 안 하는 도구를 빼 절감
이대화 이력은 최근 원문 + 결정 메모로 분리
목적 = 무조건 짧게가 아니라
문서 근거와 설명할 출력의 자리를
어디서 확보할지 투명하게 결정
절감의 목표는 토큰을 아끼는 게 아니라, 근거 문서와 설명할 출력이 놓일 자리를 만드는 것입니다. 8k, 12k, 2k 같은 수치는 소스의 예시로, 실제 값은 시스템마다 다릅니다.

🔁 넣을지는 곧 뺄지의 판단

  • 오래된 메모리를 남길 이유
  • 전문을 넣어야 하는 예외
  • 이번에 안 쓸 도구
  • 원문으로 되돌아갈 주소
이 넷을 함께 적어야 선택이 검토 가능해진다 — 무엇을 넣을지는 곧 무엇을 뺄지의 판단.
같은 예산을 나눠 쓰는 이상, 무언가를 넣는 결정에는 언제나 무언가를 빼는 결정이 붙습니다. 남길 이유·예외·안 쓸 도구·되돌아갈 주소를 적어 두면, 나중에 왜 그렇게 배치했는지 되짚어 검토할 수 있습니다.

📌 이것만은 꼭 — 핵심 4문장

1컨텍스트는 대화창 관리가 아니라 구성요소 전체의 자리 다툼이다.
2지시·문서·메모리·도구 목록·대화 이력이 하나의 입력 예산을 나눠 쓴다.
3다섯은 같은 역할을 하지 않고 서로 대신할 수 없다 — 충돌하면 종류를 나눠 다시 본다.
4예산표로 무엇을 넣고 뺄지 투명하게 정한다 — 목적은 짧게가 아니라 자리 확보.
4번이 이 소단원의 실천 태도입니다. 컨텍스트를 줄이는 것 자체가 목표가 아니라, 근거와 출력이 놓일 자리를 확보하기 위한 수단으로 예산표를 씁니다.

✅ 정답 & 해설

A1. 대화창 관리가 아니라 구성요소 전체가 벌이는 자리 다툼을 설계하는 일 — 시스템 지시·도구·검색 근거·출력 스키마까지 함께 다룬다.
A2. 지시(역할·금지) · 문서(근거) · 메모리(결정·선호) · 도구 목록(이름·매개변수·설명) · 대화 이력(주고받은 기록).
A3. 같은 입력 예산 — 하나의 막대를 나눠 쓰므로 하나를 늘리면 출력 영역과 다른 재료의 자리가 준다.
A4. 메모리가 원문을, 도구 설명이 실제 결과를, 과거 대화가 최신 주문 상태를 대신할 수 없다.
A5. 목적은 문서 근거와 출력의 자리를 투명하게 확보하는 것. 항목: 입력 항목·토큰 수·고정/가변·출처·제거 시 위험·확보할 출력량.
A4와 A5를 자기 말로 설명할 수 있으면 오늘 목표는 달성입니다. 특히 예산표는 '짧게 만들기'가 아니라 '자리를 어디서 확보할지 정하기'임을 기억하세요.

순서의 벽 — word2vec에서 attention까지

이미지가 깊이의 벽에 부딪혔던 이야기를 봤습니다. 언어는 결이 다른 벽 — 순서의 벽에 부딪혔습니다. 단어를 벡터로 바꾸는 word2vec에서 시작해, RNN·LSTM·seq2seq를 거쳐 attention에 이르는 흐름을 따라갑니다.

🗺️ 오늘의 여정

PART 1단어를 벡터로
(word2vec)
→
PART 2순서의 벽
(RNN·LSTM)
→
PART 3병목과 되돌아보기
(seq2seq·attention)
  • 신경망은 글자를 못 먹는다 — 단어를 벡터로 바꾸는 word2vec
  • 순서대로 읽는 RNN이 만난 순서의 벽, 그리고 LSTM
  • 번역을 위한 seq2seq의 고정벡터 병목과, 그것을 깬 attention
  • 마지막에 다음 벽을 향한 질문 — 트랜스포머로 가는 문
🎯 오늘의 한 줄 — 이미지의 깊이의 벽과 언어의 순서의 벽은 한 뿌리이고, 둘 다 지름길(통로)로 넘는다.
오늘은 손으로 돌려보는 유사도 게임 실습도 포함됩니다. 개념 → 코드 → 관찰 순으로 갑니다.

⏪ 30초 복습 — 이미지의 깊이의 벽

  • 층을 깊게 쌓다가 학습 신호가 희미해지는 vanishing gradient 문제에 부딪혔다
  • 신경망은 skip connection(지름길)으로 그 벽을 넘었다
  • 사진은 한 장이 통째로 주어지지만, 문장은 단어가 하나씩 순서대로 흐르는 시간의 데이터
"나는 어제 도서관에서 책을 빌렸다" — '빌렸다'는 저 앞의 '나는'·'책을'을 기억해야 뜻이 통한다. 언어의 벽은 순서의 벽이다.
이미지가 깊이의 벽이었다면 언어는 순서의 벽입니다. 이 둘이 어떻게 같은 뿌리인지가 오늘의 숨은 주제입니다.
1

단어를 숫자로 바꾸는 첫 관문

뜻의 관계를 방향과 거리로 남기다

word2vec · 임베딩
신경망은 글자를 그대로 먹지 못합니다. 모든 입력은 결국 숫자 벡터여야 합니다. 그런데 번호만 매기면 단어 사이의 의미 관계가 통째로 사라집니다.

🔤 이웃으로 뜻을 배우는 word2vec (2013)

  • '왕'=1번, '여왕'=2번처럼 번호만 매기면 의미 관계가 통째로 사라진다
  • 발상: 단어의 뜻은 어떤 이웃과 함께 등장하는지에 이미 담겨 있다
  • "커피를 ___ 마셨다"의 빈칸 맞히기를 수억 번 → 비슷한 자리 단어는 비슷한 벡터
왕 − 남자 + 여자 ≈ 여왕뜻의 관계가 벡터 공간의 방향과 거리로 남는다
누가 뜻을 알려 준 적이 없는데도, 빈칸 채우기 연습만으로 왕−남자+여자를 계산하면 여왕 근처에 도착합니다. (Efficient Estimation of Word Representations, arXiv:1301.3781)

🧱 임베딩 = 언어 신경망의 표준 입력

문장단어들의 나열
→
각 단어한 개의 벡터
(임베딩)
→
신경망벡터들의 흐름을
받아 처리
word2vec이 언어를 신경망이 먹을 수 있는 재료로 손질해 준 셈입니다. 재료는 준비됐고, 문제는 이 흐름을 어떻게 소화하느냐였습니다.
임베딩(embedding)은 이후 모든 언어 신경망의 표준 입력이 됩니다. "표현"도 같은 것을 가리키는 말입니다.

🎮 만져 보기 — 꼬맨틀

  • 매일 정답 단어 하나. 아무 단어나 던지면 정답과의 가까운 정도를 −100~100 숫자로 돌려준다
  • 사전 뜻풀이 비교가 아니라, 학습된 단어 벡터 사이의 거리를 재는 것 (FastText)
  • '바다' → '해변'·'파도'는 예상대로인데, 뜻은 상관없어 보이는데 점수가 튀는 단어가 꼭 있다
벡터 공간이 배운 것은 사전적 정의가 아니라 쓰임의 이웃 관계 — 설명 열 줄보다 한 판이 더 잘 보여 줍니다.
꼬맨틀(semantle-ko.newsjel.ly)은 word2vec의 후속 격인 FastText로 위키·웹 문서를 학습한 벡터를 씁니다. "이게 왜 높지?" 하는 순간이 핵심 체험입니다.

🧪 손으로 돌려보기 (1) — 에이전트에게 시키기

꼬맨틀을 직접 만들 차례입니다. 단어를 벡터로 바꾸고, 두 벡터의 각도(코사인 유사도)로 가까운 정도를 재면 끝. 코딩 에이전트에게 이렇게 시켜 보세요.

파이썬으로 단어 유사도 게임을 만들어 줘.

- sentence-transformers의 paraphrase-multilingual-MiniLM-L12-v2 모델로
  단어를 벡터로 바꾼다
- 정답 단어 하나를 정하고, 후보 단어 목록과 정답 사이의
  코사인 유사도를 계산한다
- 가까운 순으로 순위를 매겨 점수와 함께 출력한다
- 모델은 CPU에서 돌리고, GPU가 없어도 되게 해 줘
원리는 방금 본 그대로입니다. 단어를 벡터로, 두 벡터의 각도로 가까운 정도를 재는 것. 에이전트가 만들어 준 것이 다음 장 코드와 크게 다르지 않다면 잘 나온 것입니다.

🧪 손으로 돌려보기 (2) — 코드

# 처음 한 번만 설치합니다. 이미 깔려 있으면 건너뛰어도 됩니다.
!pip install sentence-transformers

from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer(
    "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2")

VOCAB = ["바다","해변","파도","모래","갈매기","항구","등대",
         "산","숲","나무","계곡","등산","커피","카페","우유","아침",
         "컴퓨터","키보드","코드","버그","고양이","강아지","산책",
         "회사","회의","보고서","월급"]
ANSWER = "바다"

emb = model.encode(VOCAB, normalize_embeddings=True)
ans = model.encode([ANSWER], normalize_embeddings=True)[0]
sims = emb @ ans        # 길이를 1로 맞췄으니 내적이 곧 코사인 유사도

for rank, i in enumerate(np.argsort(-sims), 1):
    print(f"  {rank}위  {VOCAB[i]}  {sims[i]*100:.1f}점")
normalize_embeddings=True로 길이를 1로 맞추면 내적(emb @ ans)이 그대로 코사인 유사도가 됩니다. 후보 단어를 여러분 관심사로 바꿔 돌려 보세요.

👀 여기서 볼 것 세 가지

1아무도 바다와 해변이 비슷하다 알려 준 적 없다 — 비슷한 자리에 등장한 문장을 읽었을 뿐인데 76.7점
2버그가 8위(55.2점) — 벡터가 배운 건 사전적 정의가 아니라 쓰임의 이웃 관계. "이게 왜 높지?"의 정체
3후보를 내 도메인 단어로 바꿔 보라 — 업무 용어끼리 뭉치는지 보면 이 모델을 내 일에 쓸 수 있을지 감이 잡힌다
재료(임베딩)는 준비됐습니다. 이제 이 벡터들의 흐름을 신경망이 어떻게 소화하느냐가 문제입니다.
세 번째가 실무 포인트입니다. 예제 단어를 자기 도메인으로 바꿔 보면 이 임베딩 모델의 쓸모를 바로 가늠할 수 있습니다.
2

앞 단어를 기억하며 읽다 만난 순서의 벽

시간 축을 따라 다시 나타난 vanishing gradient

RNN · LSTM
사람이 문장을 읽는 방식을 흉내 낸 것이 순환 신경망(RNN)입니다. 앞에서 뒤로 한 단어씩 읽되, 지금까지 읽은 내용을 요약한 기억을 함께 들고 다음 단어로 넘깁니다.

🔁 RNN — 기억을 들고 한 단어씩

단어 1읽기 → 은닉 상태
→
단어 2은닉 상태 + 단어 2
→ 새 은닉 상태
→
…끝까지계속 갱신
  • 같은 신경망을 문장의 단어 수만큼 반복해서 돌리는 구조
  • 은닉 상태(hidden state) = 문장을 따라 흐르며 갱신되는 작업 기억
첫 단어로 은닉 상태를 만들고, 그 은닉 상태와 두 번째 단어를 합쳐 새 은닉 상태를 만들고… 문장 끝까지 잇습니다.

🧱 발상은 우아했지만 — 순서의 벽

  • 문장이 길어지면 앞쪽 단어 정보가 은닉 상태를 여러 번 거치며 흐려져, 뒤엔 거의 안 남는다
  • '나는'이라는 주어가 스무 단어 뒤 동사까지 살아 도달하지 못한다
  • 은닉 상태를 한 단계씩 넘기는 건 신경망 층을 하나씩 쌓는 것과 수학적으로 같다
이미지의 vanishing gradient가 이번엔 깊이가 아니라
시간 축을 따라 나타난 것순서의 벽 = 깊이의 벽과 한 뿌리
학습 신호가 시간을 거슬러 앞 단어로 전달될 때 이미지에서와 똑같이 희미해집니다. 두 벽은 이름만 다를 뿐 같은 문제였습니다.

🚪 LSTM — 장기 기억 통로와 게이트

  • 은닉 상태 옆에 셀 상태(cell state)라는 별도의 장기 기억 통로를 하나 더 둔다
  • 이 통로에 정보가 들고·나고·지워지는 것을 게이트로 조절 — 입력·망각·출력 게이트를 스스로 학습
입력 게이트무엇을 새로 기억?
망각 게이트무엇을 잊을까?
출력 게이트무엇을 내보낼까?
셀 상태 통로엔 곱셈으로 뒤섞는 변형이 거의 없다 → 신호가 멀리까지 온전히 흐른다. 이미지의 skip connection과 발상이 놀랍도록 닮았다(통로를 터 준다).
게이트가 열려 있으면 정보가 거의 그대로 통과합니다. 지름길을 터 신호가 흐려지지 않게 한다는 아이디어가 skip connection과 같습니다. (LSTM, Neural Computation 1997)

⛓️ 그래도 남은 순차성

  • LSTM으로 벽이 낮아졌지만 완전히 사라진 건 아니다
  • 순서대로 한 단어씩 처리한다는 RNN의 본질은 그대로
  • 앞 단어를 끝내야 뒤 단어를 시작 → 문장 전체를 한꺼번에 병렬 계산할 수 없다
이 순차성은 두고두고 발목을 잡습니다 — 나중에 트랜스포머가 정면으로 겨냥할 지점입니다.
병렬 계산을 막는 순차성은 속도와 확장성의 걸림돌로 남습니다. 이 걸림돌이 다음 이야기의 씨앗입니다.
3

병목을 만들고, 되돌아보기로 깨다

문장을 벡터 하나에 욱여넣기 → 원문을 다시 보기

seq2seq · attention
RNN·LSTM으로 문장을 읽게 되자 사람들은 번역을 시켰습니다. 한 언어를 읽고 다른 언어로 뱉는 인코더-디코더, 곧 seq2seq입니다.

🗜️ seq2seq — 압축했다 푸는 통역사

인코더 RNN원문을 끝까지 읽어
→
문맥 벡터 1개문장 전체 뜻을
압축해 담음
→
디코더 RNN이 벡터로 번역문을
한 단어씩 풀어냄
원문을 압축했다가 다시 푸는 통역사 구조. 통계 기반 번역을 넘어서는 성능을 처음 보여 주며 큰 반향을 일으켰습니다.
인코더의 마지막 은닉 상태 하나에 문장 전체 뜻을 담은 것이 문맥 벡터(context vector)입니다. (Sequence to Sequence Learning, arXiv:1409.3215)

🍾 고정벡터 병목

  • 열 단어든 쉰 단어든, 원문의 모든 정보가 크기가 고정된 벡터 하나를 반드시 통과해야 한다
  • 문장이 길어질수록 다 욱여넣을 수 없어 앞부분이 뭉개진다
  • 실제로 seq2seq 번역 품질은 문장이 길어지면 눈에 띄게 무너졌다

🎧 통역 부스 비유 — 통역사가 3분짜리 연설을 다 듣고 나서 단 한 문장으로 요약해 전달하라는 요구를 받은 셈입니다. 애초에 무리였던 것이죠.

국제회의 통역 부스처럼, 연설이 끝날 때까지 기다렸다가 한 문장으로 압축해 넘기라는 건 무리입니다. (사진: G7 통역 부스, Wikimedia, CC BY-SA 2.0 — 여기선 CSS/비유로 대체)

🔎 attention — 되돌아보기로 병목을 깨다

  • 질문을 바꿨다: 왜 원문 전체를 벡터 하나로 압축해야만 할까?
  • 인코더가 만든 단어별 은닉 상태를 뭉개지 않고 전부 남겨 둔다
  • 디코더는 번역 단어를 만들 때마다 원문의 모든 단어를 되돌아보며 가중치를 매긴다
  • '학교'를 번역할 차례면 원문 'school'에 큰 가중치, 나머진 작게
원문 전체가 매 순간 다시 열람 가능한 참고 자료가 된다 → 고정벡터 병목이 깨지고, 긴 문장에서 무너지던 번역 품질이 되살아났다.
정보가 더는 벡터 하나의 좁은 문을 억지로 통과할 필요가 없어졌습니다. (Neural Machine Translation by Jointly Learning to Align and Translate, arXiv:1409.0473)

왼쪽은 원문 전체가 벡터 하나로 좁아졌다 펼쳐지는 병목, 오른쪽은 매 단어가 원문 전체를 되돌아보며 필요한 곳에 가중치를 준다.
왼쪽 seq2seq는 모든 원문이 벡터 1개를 통과합니다. 오른쪽 attention은 번역 단어마다 원문 세 개를 직접 되돌아보며, 굵은 연결선일수록 큰 가중치입니다.

🚪 다음 벽을 향한 질문

  • attention은 원래 순차적으로 도는 RNN을 거드는 보조 장치였다
  • 그런데 번역 품질을 끌어올린 주역은 attention이었고, RNN의 순차 처리는 병렬을 막는 걸림돌로 남았다

이미지가 skip connection으로 깊이의 벽을 넘었듯, 언어는 이 질문 하나로 트랜스포머(Transformer)로 건너갑니다.
이 대담한 질문이 다음 이야기의 문을 엽니다. 다음 소단원에서 attention만으로 세운 구조, 트랜스포머로 들어갑니다.

📌 이것만은 꼭 — 핵심 5문장

1word2vec — 이웃 단어로 뜻을 배워, 임베딩이 언어 신경망의 표준 입력이 됐다.
2RNN은 은닉 상태로 기억을 넘기지만, 긴 문장에서 순서의 벽(시간 축 vanishing gradient)에 부딪혔다.
3LSTM은 셀 상태 통로+게이트로 신호를 멀리 날랐다 — skip connection과 한 뿌리.
4seq2seq는 문맥 벡터 하나로 압축 → 고정벡터 병목. attention이 원문을 되돌아보며 그 병목을 깼다.
5남은 순차성을 걷어내자는 질문이 트랜스포머로 가는 문을 연다.
깊이의 벽과 순서의 벽은 한 뿌리이고, 둘 다 "통로를 터 주는" 아이디어로 넘었습니다. 그리고 남은 걸림돌이 다음 구조를 부릅니다.

Q1. word2vec은 뜻을 어떻게 배우나? '왕−남자+여자≈여왕'이 가능한 이유는?
Q2. 꼬맨틀에서 뜻이 먼 단어가 높게 나오는 건 벡터가 무엇을 배웠기 때문인가?
Q3. RNN의 순서의 벽은 무엇이며, 이미지의 어떤 문제와 한 뿌리인가?
Q4. LSTM의 셀 상태가 skip connection과 닮은 점은?
Q5. seq2seq의 고정벡터 병목을 attention은 어떻게 깼나?
Q3와 Q5가 오늘의 핵심입니다. 순서의 벽=깊이의 벽, 병목=되돌아보기로 해소.

✅ 정답 & 해설

A1. 주변 단어(이웃) 맞히기를 반복해 비슷한 자리에 오는 단어는 비슷한 벡터가 되게 학습. 뜻의 관계가 방향·거리로 남아 왕−남자+여자≈여왕이 성립.
A2. 벡터가 배운 건 사전적 정의가 아니라 쓰임의 이웃 관계 — 같은 문맥에 자주 함께 쓰인 단어라 점수가 높게 튄다.
A3. 긴 문장에서 앞 단어 정보가 은닉 상태를 거치며 흐려지는 것. 은닉 상태 넘김 = 층 쌓기와 같아, 시간 축의 vanishing gradient(=깊이의 벽)와 한 뿌리.
A4. 셀 상태 통로엔 곱셈 변형이 거의 없어 신호가 온전히 멀리 흐른다 — 지름길(통로)을 터 준다는 발상이 같다.
A5. 원문 단어별 은닉 상태를 전부 남기고, 디코더가 매 단어마다 원문 전체를 되돌아보며 가중치를 줘 벡터 하나의 좁은 문을 없앴다.
A3·A5를 자기 말로 설명할 수 있으면 오늘 목표 달성입니다.

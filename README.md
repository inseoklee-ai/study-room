## 🛠️ 정리 방식 — 강의 하나가 웹 덱 + PPT 가 되기까지

이 저장소의 작업 절차는 **스킬 파일로 고정돼 있습니다** → [`.claude/skills/lesson-deck/SKILL.md`](.claude/skills/lesson-deck/SKILL.md)
study-room 폴더에서 Claude Code 를 열면 `/lesson-deck` 으로 뜨고, 강의 본문을 붙이면 아래 절차대로 진행됩니다.

| 파일 | 역할 |
|---|---|
| [`SKILL.md`](.claude/skills/lesson-deck/SKILL.md) | 작업 절차·덱 분할 기준·금지 목록·커밋 전 체크리스트 |
| [`references/deck-template.html`](.claude/skills/lesson-deck/references/deck-template.html) | 검증된 덱의 CSS·조작 스크립트 + 표지/파트/본문/확인/마무리 본보기 5장 |
| [`references/block-vocabulary.md`](.claude/skills/lesson-deck/references/block-vocabulary.md) | `build_ppts.js` 가 아는 마크업 목록 |

### 산출물 구성

강의 하나(또는 소단원 하나)마다 **폴더 하나**를 만들고 그 안에 두 파일을 둡니다.

```
<폴더명>/index.html          # 웹 슬라이드 — 의존성 없는 단일 HTML
<폴더명>/<폴더명>.pptx        # 같은 HTML 에서 자동 변환한 PPT
```

폴더명은 **영어 kebab-case**로 내용을 말해주는 이름 (`why-server` `network-basics` `context-rot`).

### 작업 순서

1. **자리 확인** — `index.html` 지도와 이 README 에서 이번 강의의 위치를 찾는다. `예정 (0/N)` 자리가 다음 차례
2. **덱 분할** — 최근 관행은 **소단원 1개 = 덱 1개, 17~20 슬라이드**. 옛 강의는 소단원 2개를 한 덱으로 묶었다(12~18장). 묶으면 뒤 소단원은 `#N` 앵커로 링크하고 `✓ 포함` 으로 표시
3. **덱 HTML 작성** — `references/deck-template.html` 을 복사해 `<title>` 과 본문만 채운다. 표지 → 지도 → PART 구분면 → 본문 → 이해도 확인 → 마무리 순서. **모든 슬라이드에 `<aside>` 학습노트**(= `S` 키로 뜨는 발표 대본)를 단다
4. **PPT 생성**
   ```bash
   npm i pptxgenjs node-html-parser     # package.json 이 gitignore 대상이라 새 클론에선 먼저 설치
   node build_ppts.js <폴더명>           # 인자 없이 실행하면 덱 110개를 전부 다시 뽑는다
   ```
   새 폴더 이름은 `build_ppts.js` 의 `LESSONS` 기본 목록 끝에도 추가해 둔다
5. **커리큘럼 지도(`index.html`) 반영** — 강의 줄 상태 배지, 소단원 줄의 웹·PPT 링크, **상단 칩 숫자**(대단원 · 완료한 강의 · 웹 슬라이드 · PPT 수)
6. **이 README 두 곳 반영** — 위 커리큘럼 체크리스트 + 그 아래 **라이브 주소 목록**. 후자를 빼먹으면 GitHub 저장소 화면에서 링크를 누른 사람이 슬라이드가 아니라 소스 폴더로 갑니다
7. **확인 후 배포**
   ```bash
   python -m http.server 8000    # 새 덱을 실제로 열어 이동·진행바·S 노트·콘솔 오류 확인
   git add <폴더들> index.html README.md
   git commit -m "대단원N 중단원x 강y 완결: 강의명 ①~⑨ N개 덱"
   git push origin master        # 이 저장소의 기본 브랜치는 master (study-room-2 는 main)
   ```
   푸시 후 GitHub Pages 재빌드를 기다려 **배포된 URL 로 다시 확인**

### 쓸 수 있는 마크업

덱 HTML 은 사람이 보는 웹 슬라이드이면서 `build_ppts.js` 가 읽어 PPT 로 옮기는 **원본**입니다.
그래서 **변환기가 모르는 마크업을 쓰면 PPT 에서 조용히 뭉개집니다.**

| 마크업 | PPT 렌더 |
|---|---|
| `.cover` + `h1` | 진한 초록 표지면 |
| `.part` + `.pno` | 번호 카드 파트 구분면 |
| `<p>` · `<ul class="pts">` | 본문 문단 · `›` 초록 불릿 |
| `.steps` > `.st` | 번호 단계 카드 |
| `.qa` > `.q` / `.q.a` | 질문(초록) · 정답(금색) 카드 |
| `.hl` · `.big` | 강조 띠 · 진한 초록 큰 문장 |
| `.chain` > `.cell` + `.ar` | 흐름 사슬 카드 + 화살표 |
| `.grid2` > `.box` · `.box` | 2열 카드 · 단독 카드 |
| `<table class="t">` | 표 (`class="t"` 를 빼면 웹에서 스타일이 안 먹는다) |
| `<pre>` | 코드 카드 |

`<aside>` 는 **웹 `S` 키 전용**이고 PPT 에는 들어가지 않습니다. 자세한 목록은 [`block-vocabulary.md`](.claude/skills/lesson-deck/references/block-vocabulary.md).

### 정리 원칙

- **본문 없이 소단원 제목만 보고 내용을 만들지 않는다** — 학습 정리가 아니라 창작이 된다
- 코드·명령어·실측 수치·사례는 **원문 그대로** 살린다
- 강사가 "아직 안 된다 / 주의하라"고 못 박은 대목을 지우지 않는다 — 과장은 학습을 망친다
- 원문 순서를 그대로 옮기지 않고 **강의 흐름으로 재배열**해도 된다. 그게 이 저장소의 값이다
- 한국어로 쓴다. 원어는 처음 등장할 때만 병기
- 덱마다 CSS·팔레트를 새로 만들지 않는다. 외부 프레임워크·CDN 도 쓰지 않는다 — **단일 HTML 원칙**
- `.pptx` 만 고치지 않는다. 원본은 HTML 이므로 HTML 을 고치고 다시 뽑는다

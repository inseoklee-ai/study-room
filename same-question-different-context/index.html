같은 질문·다른 맥락

네 조건 통제 실험 — 답이 근거에 닿는 방식을 비교

같은 반품 정책, 같은 질문인데 맥락을 어떻게 주느냐에 따라 모델의 답이 달라질 수 있습니다. 이 실습은 맥락 변수 하나만 바꾸고 나머지는 고정한 통제 실험으로, 답의 내용뿐 아니라 답이 근거에 닿는 방식까지 비교합니다.

네 파트를 지나면, 같은 질문에 맥락만 달리 넣었을 때 답이 어떻게·왜 달라지는지를 인상 비평이 아니라 통제된 비교로 설명할 수 있게 됩니다.
1

고정할 것과 바꿀 것을 나눈다

통제 실험 = 알고 싶은 변수 하나만 바꾸고 나머지 고정

none · full · selected · selected_cited
통제 실험이란 원인을 알고 싶은 변수 하나만 바꾸고 나머지를 고정하는 것입니다. 여기서 바꾸는 변수는 입력 맥락의 범위와 출처 표식뿐입니다.

🔒 무엇을 고정하고 무엇을 바꾸나

고정하는 것

질문 · 모델 · 모델 버전 · 생성 파라미터 · 출력 형식 · 실행 장비 · (가능하면) 실행 시각 기록 방식.

바꾸는 것

입력 맥락의 범위(얼마나 넣나)와 출처 표식(문서명·버전·절 번호를 붙이나)뿐.

같은 반품 정책인데도 답은 맥락을 어떻게 주느냐에 따라 달라질 수 있다 — 그 차이를 답이 근거에 닿는 방식으로 비교한다.
고정 목록에서 하나라도 함께 바뀌면, 관찰된 차이가 맥락 때문인지 다른 변수 때문인지 구분할 수 없게 됩니다. 그래서 바꾸는 변수를 맥락의 범위와 표식으로만 좁힙니다.

🧭 네 조건 — 무엇을 분리하나

조건입력 맥락분리하는 변수주의
none정책 없음외부 근거 없이 답할 때의 기준선정책과 같은 답도 우연한 일치일 수 있음
full정책 전문예외·연결 조항을 함께 볼 때의 변화긴 문서의 잡음·배치 효과가 함께 들어감
selected관련 조각선택한 최소 근거 집합의 변화빠진 조항 때문에 답이 달라질 수 있음
selected_cited같은 조각+출처 표식출처를 되찾을 수 있게 한 효과표식이 사실성·권위를 자동 보장하지 않음
selected_cited는 정보를 더 넣어 정답을 만드는 장치가 아니라, 동일 조각을 근거로 되찾고 인용하게 하는 표식의 효과를 본다.
selected와 selected_cited는 문장 내용이 같고 표식만 다릅니다. 두 조건의 답이 다르면 표식이 인용 위치·근거 표현에 관여했을 가능성을 살핍니다. 단 문서 제목·절 번호는 권위의 증명서가 아닙니다.

❓ 고정 질문과 세 판단 지점

"고객이 상품을 수령한 뒤 12일이 지났고 택을 제거했습니다. 단순 변심으로 반품하려 하며 배송비가 누구에게 있는지 묻습니다. 확인된 정책만 근거로 답하고, 정책이 말하지 않는 사실은 단정하지 마세요."

①수령일(12일)
·
②택 제거
·
③단순 변심 배송비
정책에 착용 여부·택 제거의 의미가 없으면, 모델이 빈자리를 일반 관행으로 채우지 않고 확인 질문·조건부 표현으로 남기는지 본다.
이 세 지점이 판단이 갈리는 곳입니다. 각 조건은 두 번 실행합니다. 같은 파라미터에서도 생성엔 변동이 있으므로, 두 답이 다르면 조건의 효과와 실행 간 변동을 분리할 단서가 생깁니다. 두 번이 통계 검정은 아니지만, 한 번의 인상적 답을 조건의 일반 성질로 선언하는 일을 줄여줍니다.
2

앞서 만든 자를 그대로 쓴다

새 평가 이론을 만들지 않는다 — 이진·형식 기준을 고정 통제로 회수

이진 판정 · 형식 준수 · 근거 일치
지시 설계에서 만든 이진·형식 기준을 그대로 고정 통제로 가져옵니다. 이진 판정은 조건을 지키면 1 아니면 0이며, 형식 준수는 내용의 사실성과 별도로 검사합니다. 친절한 말투·긴 설명은 이 기준을 통과시키지 않습니다.

📋 고정 채점 항목 — 이진/기록 기준

항목이진/기록 기준확인 방법
형식reply·evidence·question 세 필드, 근거 없을 때 evidence는 nullJSON 파싱·필드 검사
정답성수령 12일 사실과 정책 기한·배송비 조항에 안 어긋남질문과 원문 대조
근거 일치핵심 판단마다 실제 입력 조항·표식 위치가 대응답 문장 옆에 원문 위치
무근거 주장입력 밖 주문·착용·환불 사실을 단정 안 함입력 밖 문장 표시
충돌 처리예외가 있으면 반영하거나 적용에 필요한 사실을 물음기본 규칙·예외 함께 대조
기권근거 부족 시 null+확인 질문으로 멈춤근거 없는 완료형 단정 찾기
답이 요구한 필드를 가졌는지, 근거가 있을 때 어느 조항인지 적었는지, 근거가 없을 때 null과 확인 질문을 남겼는지를 먼저 고정 기준으로 삼습니다.

⚖️ 정답성과 근거 일치를 합치지 않는다

우연한 정답

none이 "14일 이내 반품 가능"이라 우연히 정책과 같아도, 회사 정책의 출처가 없으므로 근거 일치는 통과가 아니다.

표식은 맞지만 어긋남

selected_cited가 [반품 정책 v2.1 §3]을 정확히 적어도, 그 절이 배송비가 아닌 기한만 말하면 배송비 판단의 근거 일치는 실패.

형식이 맞는 JSON도 내용의 참을 대신하지 않는다. 정답성·근거 일치는 서로 다른 것을 잰다.
정답성은 답이 사실·정책과 어긋나지 않는가를, 근거 일치는 그 판단이 실제 입력 조항에 대응하는가를 잽니다. 둘을 합치면 우연히 맞은 답과 근거를 보존한 답을 구분할 수 없게 됩니다.
3

정책과 출처 표식을 준비해 실행한다

예시 정책은 실습용 가상 문서

langchain-ollama · qwen3.5:2b
예시 정책은 실습용 가상 문서입니다. 전문엔 무관해 보이는 배송 지연 보상 조항도 넣어 관련성·문서량을 함께 관찰합니다. 관련 조각엔 기한·택 제거 뒤 확인·단순 변심 배송비를 함께 포함합니다 — 하나라도 빠지면 다른 근거 집합이 되기 때문입니다.

📄 정책 전문과 관련 조각·표식

POLICY_FULL = """
[반품 정책 v2.1 §1] 상품은 수령 후 14일 이내에 반품을 신청할 수 있습니다.
[반품 정책 v2.1 §2] 단순 변심 반품의 왕복 배송비는 고객 부담입니다.
[반품 정책 v2.1 §3] 택 제거 상품은 착용 여부 확인 뒤 처리합니다.
[반품 정책 v2.1 §4] 불량·오배송은 회사가 배송비를 부담합니다.
"""
POLICY_SELECTED = """
[반품 정책 v2.1 §1] 상품은 수령 후 14일 이내에 반품을 신청할 수 있습니다.
[반품 정책 v2.1 §3] 택 제거 상품은 착용 여부 확인 뒤 처리합니다.
"""
CONTEXTS = {"none": "", "full": POLICY_FULL, "selected": POLICY_SELECTED,
    "selected_cited": "[반품 정책 v2.1, §1·§3]\n\n" + POLICY_SELECTED}
selected와 selected_cited는 문장 내용이 같고 표식만 다르다 — 앞머리에 [반품 정책 v2.1, §1·§3]이 붙었을 뿐.
selected에는 §1·§3만 담고, selected_cited는 같은 두 조각 앞에 출처 표식 한 줄을 더합니다. §2(단순 변심 배송비)를 selected에서 뺐다면 그것이 다른 근거 집합이 된다는 점과 제외 이유를 함께 기록해야 합니다.

🐍 네 조건 × 두 번 실행 루프

MODEL, TEMPERATURE, REPEATS = "qwen3.5:2b", 0, 2

llm = ChatOllama(model=MODEL, temperature=TEMPERATURE,
                 reasoning=False)   # think:false에 해당
OUT.mkdir(exist_ok=True)
for name, ctx in CONTEXTS.items():
    for rep in range(1, REPEATS + 1):
        user = (ctx + "\n\n" + QUESTION) if ctx else QUESTION
        resp = llm.invoke(user)
        (OUT / f"{name}-run{rep}.txt").write_text(
            resp.content, encoding="utf-8")
각 조건을 두 번 실행해 파일로 남긴다 — {조건}-run{반복}.txt. 실행 전 ast.parse로 구문을 먼저 검증해 복사 오류와 API·모델 오류를 구분한다.
실행 전 python -c "import ast, pathlib; ast.parse(...)"로 구문을 먼저 검증하면 복사 과정의 구문 오류와 API·모델 오류를 구분할 수 있습니다. 오류가 나면 줄 번호와 메시지를 기록합니다.

🧵 reasoning=False — 추론 토큰 예산의 단서

  • qwen3.5처럼 추론 토큰을 따로 내는 모델은 대체로 추론을 켠 쪽이 어려운 질문에서 더 좋은 답을 낸다
  • 단 langchain-ollama에서 추론 끄기는 think가 아니라 reasoning=False
  • 반복 실행 관찰에선 추론 토큰이 출력 예산을 소진해 본문이 비는 현상이 실제로 관찰됨
  • → 관찰 안정성을 위해 추론을 끄고 조건 비교에 맞췄다
⚠️ 어떤 설정이 나은지는 과업마다 측정할 일이지, 기본값에 대한 믿음으로 정할 일이 아니다.
추론을 끈 것은 이 조건 비교 실습에서 본문이 비는 현상을 피해 관찰을 안정시키기 위한 선택입니다. 다른 과업에서는 추론을 켠 쪽이 나을 수 있으므로, 기본값을 신뢰하지 말고 측정해야 합니다.
4

원출력과 메타데이터를 함께 남긴다

재현성 = 같은 답의 보장이 아니라, 추적할 수 있게 남기는 실천

모델·버전·날짜·파라미터·로그
재현성은 다른 사람이 같은 답을 반드시 얻는다는 약속이 아니라, 무엇을 실행했고 무엇이 달랐는지 추적할 수 있게 남기는 실천입니다. 모델명만 적으면 같은 이름 아래 배포 버전·서버 구현·날짜·파라미터가 달라졌는지 모릅니다.

🗂️ 기록표에 함께 남길 열

1실행 식별 — 조건 · 반복 · 모델·버전 · 날짜 · 파라미터 · 원출력 로그 파일명
2비용·응답성 — 토큰(입력·출력) · 입력 토큰 · 지연
3실패 유형 — poisoning · distraction · confusion · clash · 없음
4필수 결정 회수율 — 세 판단 지점 중 회수 수 / 3
정확한 버전 문자열을 모르면 추정 대신 '제공되지 않음'. API가 토큰 수를 안 주면 추정값 대신 제공되지 않음.
각 출력 옆에 모델·버전·날짜·반복 수·파라미터·원출력 로그 파일명을 기록합니다. 로그 파일을 남겨야 집계된 숫자에서 원문으로 되돌아가 사람이 재대조할 수 있습니다.

📉 토큰·지연은 품질 점수가 아니다

  • 입력 토큰이 적어 더 빠르고 저렴해도, 필요한 예외를 누락했다면 그 절약은 근거를 줄인 결과
  • 전문 조건의 지연이 길어도 실제로 더 정확·근거에 맞았는지는 채점표가 따로 말한다
  • 같은 정답이라도 실패 유형은 다른 처방을 요구 — poisoning=상태 정정, distraction=선택 축소, confusion=근거 경계 분리, clash=우선순위 판정
압축·선택 뒤에도 수령일·택 제거·배송비라는 필수 결정 요소가 답에 남았는지 필수 결정 회수율로 기록해야, 우연히 맞은 답과 근거를 보존한 답을 구분한다.
정답 여부만으로는 운영 판단을 할 수 없습니다. 같은 정답이라도 입력 토큰·지연에 따라 비용·응답성 선택이 달라지고, 네 실패 유형은 각각 다른 처방을 요구하기 때문입니다.

📌 이것만은 꼭 — 핵심 4문장

1통제 실험은 맥락의 범위와 출처 표식만 바꾸고 질문·모델·파라미터·형식을 고정한다.
2네 조건(none·full·selected·selected_cited)은 각각 다른 변수를 분리하며, 표식은 사실성을 자동 보장하지 않는다.
3정답성과 근거 일치는 별개 — 형식 맞는 JSON도 내용의 참을 대신하지 않는다.
4원출력·메타데이터를 남기고 필수 결정 회수율로 우연한 정답과 근거를 보존한 답을 가른다.
토큰·지연은 품질 점수가 아니며, 정답 여부만으로는 운영 판단을 할 수 없습니다. 무엇을 실행했고 무엇이 달랐는지 추적할 수 있게 남기는 것이 이 실습의 태도입니다.

Q1. 이 통제 실험에서 바꾸는 변수와 고정하는 것은 각각 무엇인가?

✅ 정답 & 해설

A1. 바꾸는 것: 입력 맥락의 범위와 출처 표식뿐. 고정: 질문·모델·모델 버전·생성 파라미터·출력 형식·실행 장비·실행 시각 기록 방식.
A2. 문장 내용은 같고 출처 표식(문서명·버전·절 번호)만 다르다. 표식은 사실성·권위를 자동 보장하지 않는다 — 원문이 실제로 그 판단을 뒷받침하는지는 사람이 재대조.
A3. none이 우연히 정책과 같은 답을 내도 출처가 없어 근거 일치는 실패이고, selected_cited가 표식을 정확히 적어도 그 절이 다른 사안이면 근거 일치는 실패다.
A4. think가 아니라 reasoning=False. 추론 토큰이 출력 예산을 소진해 본문이 비는 현상을 피하고 조건 비교의 관찰을 안정시키려 껐다.
A5. 수령일·택 제거·배송비 세 판단 지점 중 답에 남은 수 / 3. 압축·선택 뒤에도 근거가 보존됐는지 봐야 우연히 맞은 답과 근거를 보존한 답을 구분하기 때문.
A3와 A5를 자기 말로 설명할 수 있으면 오늘 목표는 달성입니다. 더 읽기: 실습 코드는 day29_context_test.py, 로그는 context-lab-logs 디렉터리에 남습니다.

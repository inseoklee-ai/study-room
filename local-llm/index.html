2

학습과 추론은 애초에 다른 일

GPU 메모리에 무엇을 올려야 하는가

핵심 개념 · 메모리 해부
여기가 오늘의 심장입니다. 학습이 메모리에 무엇을 얹는지, 추론은 그중 무엇만 필요한지를 숫자로 확인합니다.

🏗️ 학습 = 모델을 만드는 일

학습에서 GPU 메모리에 올라가야 하는 건 파라미터만이 아닙니다.

  • 순전파 — 입력을 층층이 통과시켜 답을 내는 앞 방향 계산
  • 활성값 — 오차를 되짚으려면 순전파 중 각 층의 중간 결과값을 전부 붙들고 있어야 함
  • 그래디언트(기울기) — "이 값을 바꾸면 오차가 얼마나 변하나"를 파라미터마다 기록
  • 옵티마이저(Adam) — 파라미터마다 '어느 방향으로 밀려왔나 + 얼마나 들쭉날쭉했나' 2개 기록을 보관
  • 혼합 정밀도 — 속도를 위해 FP16으로 계산하되, 반올림에 갱신이 사라지는 걸 막으려 FP32 사본을 따로 보관
💡 FP16 = 16비트(2바이트), FP32 = 32비트(4바이트). 자릿수가 많을수록 정확하지만 자리를 더 차지합니다.
혼합 정밀도(mixed precision): 계산 대부분은 빠른 FP16으로, 미세한 갱신이 반올림에 먹혀 사라지지 않게 FP32 마스터 사본을 하나 더 둡니다.

💻 추론 = 만든 모델을 쓰는 일

학습이 하던 일들…

오차 측정 · 역전파 · 그래디언트 · 옵티마이저 상태 · 활성값 보관

추론이 하는 일

정해진 숫자로
행렬곱 한 번 → 다음 토큰

  • 파라미터는 이미 정해졌고, 우리는 그걸 조정하지 않습니다
  • 오차를 잴 일도, 거슬러 올라갈 일도, 옵티마이저 상태를 들 일도 없습니다
🔑 추론은 학습 메모리 항목 중 딱 '첫 줄'(가중치)만 필요합니다.
남이 수백만 달러를 들여 정해 놓은 숫자 뭉치를 받아서, 우리는 그걸 '읽기만' 하면 됩니다.

🧮 파라미터 1개를 감당하는 데 드는 바이트

구분구성파라미터당7B 모델 기준
학습FP16 2B + FP32 마스터 4B + Adam 8B + 그래디언트 4B (+활성값 별도)18바이트+126GB↑
추론FP16 가중치 2B (+ KV cache)2바이트대14GB 남짓
학습 126GB↑
약 9배
추론 14GB
🔑 같은 모델인데 메모리 요구가 아홉 배 가까이 차이 — 그래서 학습은 데이터센터, 추론은 노트북의 일이 됩니다.
허깅페이스가 정리한 학습 메모리 해부 기준입니다. 가중치 6B(FP16 2 + FP32 4) + Adam 8B + 그래디언트 4B = 18B, 여기에 배치·시퀀스 길이에 따라 부풀어 오르는 활성값이 얹힙니다.

✅ 단원 2 정리

학습가중치 + 활성값 + 그래디언트 + 옵티마이저 상태까지 메모리에 → 파라미터당 18바이트+
추론정해진 파라미터로 행렬곱만 → 파라미터당 2바이트대 ('첫 줄'만 필요)
결론7B 기준 126GB vs 14GB, 약 9배 차이 — 추론이 노트북의 일이 될 수 있는 이유
여기까지가 모순의 해소입니다. 다음은 "그래도 추론이 공짜는 아니다"라는 이야기.
3

그래도 벽은 하나 남는다

추론이 싸다고 공짜라는 뜻은 아니다

한계 · 메모리 벽
추론의 비용은 학습보다 훨씬 작지만, 넘어야 할 벽이 딱 하나 남습니다.

🧱 넘어야 할 벽 — 파라미터를 전부 메모리에

  • 토큰 하나를 만들려면 모든 층을 처음부터 끝까지 통과해야 함
  • 각 층의 가중치 행렬이 그때마다 필요합니다
  • 일부만 올리고 나머지를 디스크에서 읽어오면? 토큰마다 수 GB를 긁어와야 해 실용적인 속도가 안 납니다
7,000,000,000개 × 2바이트(FP16) ≈ 14GB
그래서 계산은 아주 단순해집니다 — 모델을 통째로 올릴 메모리가 있느냐 없느냐.
타협이 어려운 조건입니다. 원리적으로는 일부만 올릴 수 있지만, 토큰 하나 만들 때마다 디스크에서 수 GB를 읽으면 속도가 실용적이지 않습니다.

📏 그래서 숫자가 전부를 결정합니다

모델FP16 메모리노트북에서?
7B약 14GB16GB 카드에 겨우
Llama 3.1 8B14.96GB (측정값)다른 것 올릴 자리 없음
70B140GB아예 다른 세계
노트북 GPU8 ~ 16GB 뿐—
⚠️ 14.96GB 파일은 16GB 카드에도 겨우 들어갑니다. 이 벽을 어떻게 넘었는지가 다음 이야기.
라마(Llama)는 메타가 가중치를 공개한 계열이라 파일 크기가 그대로 알려져 있어 기준으로 삼기 좋습니다. Llama 3.1 8B의 FP16 파일은 14.96GB로 측정됩니다.

오늘 우리가 갈 길

양자화에서 시작해 '판단 기준'으로 끝난다

로드맵
오늘 강의는 하나의 흐름으로 이어집니다. 벽을 넘는 기술에서 출발해, 마지막엔 스스로 판단하는 감각으로 바뀝니다.

🧭 오늘의 흐름 — 4단계

1양자화 — 14GB를 4GB대로 줄이는 기술. 왜 줄여도 멀쩡한지, 얼마나 줄일 수 있는지, 무엇을 잃는지를 숫자로 확인
2직접 실행 — 도구를 설치하고 모델을 받아, 내 기계에서 토큰이 나오는 것을 눈으로 확인
3한계 체험 — 속도는 어떤지, 품질이 어디서 무너지는지, 컨텍스트를 늘리면 무슨 일이 벌어지는지 몸으로
4판단 기준 — 로컬 vs API를 3축으로: ① 데이터가 어디까지 나가도 되나 ② 비용 역전점 ③ 인프라 의존도
🔑 마지막엔 "내 에이전트의 이 부분은 로컬에서, 저 부분은 API로"를 스스로 결정하게 됩니다.
양자화 → 실행 → 한계 → 판단. 감각을 판단 기준으로 바꾸는 것이 이 강의의 최종 목표입니다.

📌 이것만은 꼭 — 핵심 6문장

1모델을 만드는 일(학습)과 쓰는 일(추론)은 비용 구조가 완전히 다르다
2학습은 파라미터당 18바이트+ (가중치·그래디언트·옵티마이저·활성값)
3추론은 파라미터당 2바이트대 — 정해진 숫자로 행렬곱만 하면 되니까
47B 기준 126GB vs 14GB, 약 9배 — 그래서 추론은 노트북의 일이 될 수 있다
5단, 추론에도 벽 하나: 전체 파라미터를 메모리에 (7B≈14GB, 70B≈140GB)
6노트북 GPU는 8~16GB뿐 → 이 벽을 넘는 기술이 양자화, 그것이 출발점
이 6문장이 오늘 내용의 전부입니다. 캡처해두고 복습하세요.

✅ 정답 & 해설

A1. 학습과 추론의 비용 구조가 다르기 때문. 학습은 파라미터를 조정하려고 활성값·그래디언트·옵티마이저 상태까지 메모리에 얹지만, 추론은 정해진 파라미터로 행렬곱만 한다.
A2. 총 18바이트+ = FP16 2B + FP32 마스터 4B(가중치 6B) + Adam 8B + 그래디언트 4B. 여기에 활성값이 별도로 얹힌다.
A3. 2바이트대(FP16 가중치). 7B × 2B ≈ 14GB (Llama 3.1 8B은 14.96GB로 측정).
A4. 전체 파라미터를 메모리에 올려야 한다는 것. 토큰마다 모든 층의 가중치가 필요한데, 디스크에서 매번 수 GB를 읽으면 실용 속도가 안 나오기 때문.
A5. ① 데이터가 어디까지 나가도 되나 ② 비용이 어느 지점에서 역전되나 ③ 남의 인프라에 얼마나 의존해도 되나.
A2·A3의 숫자를 정확히 말할 수 있으면 오늘 핵심은 잡은 것입니다.

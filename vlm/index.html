단원 4 · AI는 문서와 사진에서 무엇을 꺼낼까 (4)

이미지와 언어를
함께 보는 모델

VLM · 열린 질문, 고정된 출력 · 형식과 내용은 다르다

"갑이 누구인가"에 문서엔 "발주자"라고만 적혀 있을 수 있습니다. 글자를 읽는 것만으로는 부족하고 문맥을 해석해야 합니다.

🗺️ 오늘의 흐름

  • VLM이란 — 이미지 단서와 언어 요구를 함께 해석하는 모델
  • 그림을 언어 모델이 다룰 표현으로 — 패치·비전 인코더·연결 모듈
  • 문서 전용 VLM은 무엇을 더 보나 (PaddleOCR-VL)
  • 말로 답한다 = 틀려도 말이 될 수 있다 → 외부 정거장을 만든다
🎯 한 줄: 질문의 의미 범위는 열려 있어도 답은 문장·Markdown·JSON으로 고정할 수 있습니다. 단 형식을 지켰다 ≠ 내용이 맞다.
앞 강의들은 받을 답의 모양이 정해져 있었습니다(문자열·박스·픽셀). VLM은 열린 질문을 다루되 출력 형식은 고정합니다.

🤔 두 질문에 공통으로 필요한 것

"갑이 누구입니까"

문서엔 "갑" 대신 "발주자". 글자 인식만으론 부족, 계약 문맥 해석 필요

"위험해 보이는 곳?"

적재물·열린 배전반·물기… 후보 목록을 질문 전에 못 정함

필요한 건 출력 형식의 자유가 아니라
이미지 단서 + 언어 요구를 함께 해석하는 능력
이런 모델이 VLM(Vision-Language Model, 시각-언어 모델). 답은 문장·Markdown·JSON으로 요구 가능 — 단 형식 준수와 내용 정확은 별개.
출력 형식을 자유롭게 두는 게 핵심이 아닙니다. 시각과 언어를 함께 해석하는 능력이 핵심입니다.
1

그림을 언어 모델이 다룰 표현으로

패치 · 비전 인코더 · 연결 모듈

시각을 언어 옆에 놓기
언어 모델은 입력을 토큰과 숫자 벡터로 바꿔 처리합니다. VLM은 이미지도 작은 영역의 특징 벡터로 바꿔 연결합니다.

🔗 이미지 특징을 언어에 연결하는 세 방식

이미지의 작은 영역 = 패치, 패치에서 특징을 만드는 신경망 = 비전 인코더. 연결 방식은 한 가지가 아닙니다.

방식시각 정보가 언어와 만나는 법
Projector·concat이미지 특징을 언어 토큰 크기로 바꿔 같은 입력 줄에 붙임 (단순·널리 쓰임)
Cross-attention언어 토큰이 별도 이미지 특징을 필요한 순간에 참고 (두 흐름 분리)
Q-Former 다리소수의 학습된 질의가 이미지에서 필요한 특징만 뽑아 전달 (압축 다리)
⚠️ "모든 VLM이 한 줄에 넣어 동일한 self-attention으로 처리한다"는 지나친 일반화. 공통점은 시각 특징과 언어 요구가 모델 내부에서 정보를 주고받는다는 것뿐.
연결 방식은 구현마다 다릅니다. 목적만 같습니다 — 시각 단서와 언어 요구를 함께 사용하는 것.

🧩 이미지를 언어 모델이 쓸 수 있는 정보로

문서·사진픽셀
→
비전 인코더시각 특징
→
연결 모듈projector · cross-attention · Q-Former 등
→
언어 모델질문과 함께 해석
🔑 구현마다 연결 방식은 달라도 시각 단서와 언어 요구를 함께 사용한다는 목적은 같습니다.
픽셀 → 시각 특징 → 연결 → 언어 모델이 질문과 함께 해석. 이 네 정거장이 VLM의 뼈대입니다.
2

문서 전용 VLM은 무엇을 더 보려 하는가

읽는 순서 · 표 셀 · 수식 · 차트

PaddleOCR-VL
범용 VLM은 사진·도표·화면·문서를 폭넓게 다룹니다. 문서 전용 VLM은 문서에 반복되는 구조에 학습과 출력을 집중합니다.

📑 범용 vs 문서 전용

범용 VLM

사진·도표·화면·문서를 폭넓게

문서 전용 VLM

읽는 순서·제목/본문·표 셀·수식·차트에 학습·출력 집중

  • PaddleOCR-VL — 문서 파싱용 VLM 계열. 초기 0.9B는 NaViT 동적 해상도 비전 인코더 + ERNIE 언어 모델 → 텍스트·표·수식·차트를 Markdown/구조화로 복원. 실제론 레이아웃 분석 + VLM 인식을 함께
🔑 "기존 OCR보다 무조건 우수한 하나의 모델"이 아님 — 좌표 대량 문자 인식엔 전용 OCR이 더 단순·빠르고, 복잡한 표·수식 읽기 순서 보존엔 문서 VLM이 유리. 그래서 같은 페이지를 두 방식으로 돌려 차이를 직접 봐야.
도구 선택은 우열이 아니라 작업 성격에 달렸습니다. 좌표가 필요하면 OCR, 구조·순서가 중요하면 문서 VLM.
3

말로 답한다 = 틀려도 말이 될 수 있다

환각 · 좌표 대조 · 재현성 ≠ 정확성

생성형의 특성
생성형 VLM은 앞 토큰과 입력을 바탕으로 다음 토큰 분포를 계산해 답을 이어 갑니다.

🌀 환각 · 좌표 · 재현성 ≠ 정확성

  • 환각 — 잘 안 보이는 자리에서 멈추지 않고 문맥상 그럴듯한 값을 채움 → 원문에 없는 내용이 자연스럽게 섞임(따로 확인)
  • 좌표 — OCR은 검출 영역·인식 문자열에 묶여 오류 위치를 되짚기 쉬움. VLM도 상자 출력은 되지만 필드마다 일관된 근거 좌표가 기본 보장은 아님 → 좌표 받았다고 믿지 말고 원문과 대조
  • 재현성 ≠ 정확성 — 같은 오답을 두 번 낼 수 있음. 반복 실행 비교는 흔들리는 필드를 찾는 도구일 뿐 정답 검증을 대신하지 않음
🔑 "형식을 지켰다"와 "내용이 맞다"가 다르듯, "같은 답이 나온다"와 "맞는 답이다"도 다릅니다.
재현성은 안정성이지 정확성이 아닙니다. 두 번 같아도 둘 다 틀릴 수 있습니다.
4

내부 정거장이 밖에서 안 보일 때

그래서 외부에 새 정거장을 만든다

검증 절차
전통 OCR은 중간 산출물을 꺼내 보기 쉽지만, VLM은 API 결과만으론 "못 읽음/표 오해/질문 오해"를 분리하기 어렵습니다.

🛠️ 외부에 만드는 다섯 정거장

1원본 페이지와 해시를 보존
2요약·추정·보정을 금지, 판독 불가는 [UNCLEAR]로 표시
3페이지별 원시 결과와 정규화 결과를 둘 다 저장
4사람이 미리 적은 확인점과 대조
5실행일·모델·버전·프롬프트·데이터 전송 위치를 기록
🔑 뒤 실습은 모델 순위를 정하는 대회가 아니라, 서로 다른 도구에 이 외부 정거장을 붙여 보는 과정입니다.
VLM은 내부 단계(비전 인코더·연결 모듈)가 보이지 않으니, 검증을 밖에서 만들어 붙입니다.

📌 이것만은 꼭 — 핵심 6문장

1VLM = 이미지 단서와 언어 요구를 함께 해석. 열린 질문도 다룸
2답은 문장·Markdown·JSON으로 고정 가능 — 단 형식 준수 ≠ 내용 정확
3구조: 픽셀 → 비전 인코더 → 연결 모듈(projector/cross-attn/Q-Former) → 언어 모델
4문서 전용 VLM(PaddleOCR-VL)은 구조·읽기 순서에 강점 — OCR과 우열이 아니라 용도 차이
5생성형은 환각·좌표 근거 불확실·재현성 ≠ 정확성 → 원문 대조 필수
6내부가 안 보이니 외부 정거장 5단계(원본 보존·[UNCLEAR]·원시+정규화·확인점·기록)를 붙인다
VLM의 힘은 열린 질문 해석이고, 그 대가는 검증을 밖에서 설계해야 한다는 것입니다.

🎯 이해도 확인 질문

Q1. VLM이 하는 일을 한 문장으로? "출력 형식의 자유"가 핵심이 아닌 이유는?
Q2. 이미지를 언어 모델에 연결하는 세 방식과 그 공통점은?
Q3. 문서 전용 VLM은 무엇에 집중하나? OCR과 우열 관계인가?
Q4. "말로 답한다 = 틀려도 말이 된다"는 무슨 뜻? 재현성과 정확성은 어떻게 다른가?
Q5. VLM에 외부 정거장이 필요한 이유와, 그 다섯 단계는?
Q4가 이 강의에서 가장 실무적인 함정입니다.

✅ 정답 & 해설

A1. 이미지 단서와 언어로 표현된 요구를 함께 해석하는 것. 형식은 JSON 등으로 고정할 수 있으니, 핵심은 형식 자유가 아니라 시각+언어 공동 해석이다.
A2. Projector·concat / Cross-attention / Q-Former 다리. 공통점 = 시각 특징과 언어 요구가 모델 내부에서 정보를 주고받는다.
A3. 읽는 순서·제목/본문·표 셀·수식·차트에 집중. 우열이 아니라 용도 차이 — 좌표 대량 인식은 OCR, 복잡한 표·순서는 문서 VLM.
A4. 생성형은 안 보이는 자리도 그럴듯하게 채워 환각이 섞임. 재현성(같은 답이 나옴)은 안정성일 뿐, 정확성(원문에 맞음)과 별개 — 같은 오답도 두 번 나온다.
A5. 내부 단계가 API 결과만으론 안 보여 오류 종류를 분리 못 하므로. ①원본+해시 ②[UNCLEAR]·보정 금지 ③원시+정규화 ④확인점 대조 ⑤실행 기록.
A4가 VLM 도입에서 가장 자주 놓치는 지점입니다 — 그럴듯함과 맞음은 다릅니다.

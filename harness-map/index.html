빈칸이 적은 도구가 아니라, 내 병목 칸에 근거 있는 도구를 고릅니다

도구 이름을 한꺼번에 외우려는 표가 아닙니다.

표를 읽는 순서가 있습니다

1먼저 내 과업에서 확인할 병목을 하나 정합니다
2표에서는 그 병목에 닿는 열을 읽습니다
3행동 포맷에서 시작해 문맥·경험·반성·미니멀·권한을 지나, 마지막 평가 열에서 무엇이 이미 확인됐고 무엇이 남았는지 확인합니다
🎯 앞 절에서 결과와 궤적을 따로 읽었다면 — 이제 그 질문을 도구 카드에도 적용합니다
소단원 ⑨의 결과/궤적 분리를 도구 비교에 그대로 옮기는 절입니다.

이 표는 우열표도 안전 판정표도 아닙니다

  • 클로즈드 도구의 내부 구현은 확인할 수 없습니다
  • 공개 코드가 있는 도구도 — 설치 버전, 로컬 설정, 실행 기록 없이 안전하다고 증명할 수 없습니다
표는 앞 절에서 읽은 카드와
다시 확인할 근거를 한자리에 모은 것입니다
이 경고를 빼고 표만 옮기면 제품 비교표가 되어 버립니다.

기능 지도 ② — 반성 · 미니멀 · 권한 · 평가

도구반성미니멀권한평가
Claude Code실행 결과를 다음 대화에 반영필요한 도구 구성을 확인승인과 권한 설정을 확인gather–act–verify 흐름 확인
opencode실행 결과를 다음 단계에 반영필요한 모드만 선택역할별 허가를 확인실행 기록과 검증 단계 확인

OpenClaw실행 결과를 다음 세션에 기록필요한 채널만 연결채널과 도구의 설정을 확인공식 문서의 기록 위치 확인
Hermes관측을 다음 호출에 반영활성 skills만 조립채널·세션·권한 설정 확인공식 문서와 실행 기록 확인
SWE-agent피드백 뒤 다음 행동을 선택과업 전용 인터페이스 사용실행 도구의 범위를 확인SWE-bench와 ablation으로 측정
평가 열만 학술 근거가 붙은 도구가 있고, 나머지는 '확인한다'로 끝난다는 점 자체가 정보입니다.

내 병목을 기준으로 후보를 둘로 줄입니다

소단원 ①의 세 질문을 다시 씁니다

⑩ 기능 지도
표를 다 읽은 뒤에도 모든 열을 같은 무게로 비교하지 않습니다.

세 질문으로 후보를 고릅니다

1내 과업의 병목 기능을 하나 적습니다
2그 기능을 확인할 근거가 카드의 1차 근거에 있는지 확인합니다
3미확인 경계가 현재 과업에서 허용되는지 판단합니다
📌 필요한 경계가 미확인이라면 — 탈락이라고 단정하지 않고 다음 확인 대상으로 적습니다
이 과정을 거쳐 후보를 두 종으로 줄입니다.

병목별 고르는 법

📄 문맥이 병목이면

세션 · 관측 요약 · repo map 가운데 내 작업에서 실제로 볼 수 있는 기록을 가진 도구를 남깁니다

🔐 권한이 병목이면

문서의 기능 설명만으로 남기지 않고 — 현재 설정과 승인 기록을 확인할 수 있는 도구를 남깁니다

비교표는 후보를 줄여 줄 뿐입니다
마지막 판정에는 자기 환경에서 만든 실행 기록이 필요합니다
이 문장이 다음 소단원 ⑪의 과제 전체를 여는 전제입니다.

❓ 이해도 확인

Q1. 이 표를 어떻게 읽어야 하나?
A1. 빈칸이 적은 도구가 아니라 내 병목 칸에 근거 있는 도구를 고른다. 제품 우열이나 안전 판정으로 해석하지 않는다.
Q2. 필요한 경계가 "미확인"이면?
A2. 바로 탈락시키지 않고 다음 확인 대상으로 적는다.
Q3. 비교표로 결론을 낼 수 없는 이유는?
A3. 표는 후보를 줄여 줄 뿐이고, 마지막 판정에는 자기 환경에서 만든 실행 기록이 필요하기 때문.
Q3이 ⑪로 넘어가는 다리입니다.

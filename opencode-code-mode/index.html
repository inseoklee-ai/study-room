OpenCode의 Code Mode

바뀐 것은 모델이 도구를 호출하는 방식입니다

여전히 주간 기록을 읽어 달라고 요청했는데, 화면에는 execute라는 코드 실행이 보입니다.

모델이 만든 짧은 코드

  • Code Mode에서는 모델이 도구 호출을 담은 짧은 JavaScript 코드를 만들고, OpenCode가 정해진 범위 안에서 그 코드를 실행합니다
  • 이곳에서 JavaScript는 여러 도구를 순서대로 부르거나, 반환된 자료에서 필요한 항목을 고르는 데 사용합니다
  • 학생이 새 언어로 서버를 다시 작성하는 활동은 아닙니다 — 우리가 만든 Python 서버와 JSON 자료는 계속 사용합니다
내 OpenCode 버전에서 Code Mode를 사용할 수 있는지 확인해 줘.
가능하면 켜고 week-one 기록을 MCP로 읽어 줘.
📌 읽어 볼 것 — 설치 버전, 바꾸는 설정, 다시 시작할 필요가 있는지. 기능 이름이 같아도 설치한 버전에 따라 설정 위치가 다를 수 있습니다
Claude Code를 사용한다면 앞 절의 경로로 실습하고 여기서는 두 방식의 차이를 살펴보면 됩니다.
1

V1과 V2의 설정 위치

두 방식이 합쳐지지는 않습니다

⑦ Code Mode
V1 안내는 v1.18.29 고정 소스, V2 안내는 별도의 V2 공식 문서를 기준으로 합니다.

V1 — 환경 변수

opencode --version                                  # 설치 버전 확인

OPENCODE_EXPERIMENTAL_CODE_MODE=true opencode        # macOS · Linux

$env:OPENCODE_EXPERIMENTAL_CODE_MODE = "true"        # PowerShell
opencode
Remove-Item Env:OPENCODE_EXPERIMENTAL_CODE_MODE      # 되돌리기
opencode
  • 환경 변수는 프로그램을 시작할 때 전달하는 이름과 값 — Python 서버의 데이터 파일을 바꾸는 설정이 아니라 OpenCode의 동작을 선택하는 설정
  • 이미 열려 있는 다른 OpenCode 창에 소급 적용되지는 않습니다 — 설정을 바꿨는데 이전 방식이 보이면 방금 실행한 프로세스의 새 대화인지 확인
  • 실험 기능 전체를 활성화한 환경에서는 개별 변수 제거만으로 꺼지지 않을 수 있습니다 — 확실히 끄려면 false를 명시하여 새로 시작
macOS·Linux에서 한 줄 실행만 사용했다면 다음에는 보통 opencode로 시작하면 됩니다. 셸 설정 파일에 변수를 저장했다면 그 설정도 확인하세요.

V2 — 서버별 codemode

mcp.servers.weekly-records.codemode

"codemode": true
  • V2 공식 문서는 서버를 mcp.servers 아래에 등록하며 서버별 codemode의 기본값을 true로 설명합니다
  • 명시적으로 false를 넣었던 경우에는 true로 바꾸거나 그 항목을 제거해 기본값을 사용합니다
  • disabled와 codemode는 다른 설정입니다 — disabled: true는 서버 연결 자체를 막고, codemode: false는 연결된 서버의 도구를 Code Mode 대신 직접 노출
📌 서버가 연결되지 않았다면 먼저 연결 설정을 확인하고, 연결된 도구를 어떻게 호출할지는 그다음입니다. V1 설정 파일에 V2 예시를 덧붙이는 것으로 두 방식이 합쳐지지는 않습니다
아직 서버를 연결하지 않았다면 소단원 ④의 V2 등록을 먼저 따라갑니다. 조각만으로 전체 설정 파일을 덮어쓰지 말고 실행 명령과 데이터 위치를 유지합니다.
2

목록과 검색의 역할

먼저 검색을 거치는 것이 항상 필요한 것은 아닙니다

⑦ Code Mode
우리 서버에는 주간 기록을 읽는 도구가 하나 있습니다.

두 경로 모두 자연스럽습니다

처음 주어진 안내모델이 진행할 수 있는 경로
필요한 도구와 입력 규칙이 이미 보임안내를 읽고 해당 도구 호출
목록이 일부만 보이고 필요한 도구가 빠져 있음도구 검색 → 반환된 경로·입력 확인 → 호출
  • V1 v1.18.29의 Code Mode는 처음 제공할 도구 안내에 분량을 정해 두고 그 안에 들어가는 정의를 보여 줍니다. 안내에는 서버별 도구 묶음도 표시됩니다
  • 이 검색은 이미 연결된 도구 가운데 쓸 것을 찾는 과정 — 인터넷에서 새 MCP 서버를 찾아 설치하는 과정과 구별합니다
  • 서버별로 도구를 묶은 이름 공간을 네임스페이스라 합니다. 실습에서는 weekly-records 아래에 get_weekly_records — 화면 이름은 호스트의 이름 처리 규칙을 거치므로 호출할 때는 실제 목록·검색 결과의 경로를 사용
return await tools.$codemode.search({ query: "get_weekly_records" });
⚠️ 이 코드가 반환하는 것은 업무 기록이 아니라 도구 안내입니다 — 발견 다음에는 week를 전달하는 실제 호출이 필요합니다
v1.18.29에서 내부 검색의 경로는 tools.$codemode.search입니다. 위는 문법을 읽기 위한 예시이며 학생이 입력해야 할 설정 명령은 아닙니다. 다른 계열이나 버전의 검색 함수 이름을 그대로 섞어 쓰지 않습니다.
3

실행 기록 따라가기

바깥은 execute, 안쪽은 MCP 호출

⑦ Code Mode
설정을 적용한 OpenCode에서 "weekly-records MCP에서 week-one 기록을 읽어 줘"라고 요청합니다.

안쪽 호출까지

학생: week-one 기록을 읽어 줘
  ↓
모델: execute에 도구 호출 코드를 전달
  ↓
OpenCode: 내부 호출을 MCP 요청으로 전달
  ↓
weekly-records: get_weekly_records가 자료를 읽어 반환
  ↓
OpenCode: 코드 실행 결과를 모델에게 전달
const result = await tools["weekly-records"].get_weekly_records({ week: "week-one" });
return result;
  • tools는 실행 환경에 제공된 도구 모음, ["weekly-records"]는 서버 묶음 — 이름에 -가 있어 대괄호 안에 문자열로 접근
  • await는 결과가 도착할 때까지 기다린다는 뜻. Python 함수를 호출하는 것처럼 보이지만 이 코드는 OpenCode 쪽에서 실행되고 실제 Python 함수는 MCP 서버에서 실행됩니다
🎯 나누어 읽기 — 모델이 생성한 호출 코드 · 서버의 Python 코드 · 반환된 업무 자료. 그러면 새로운 이름이 나타나도 경로를 놓치지 않습니다
V1 소스에서 바깥쪽 도구 이름은 execute이며 내부 호출은 MCP 클라이언트를 통해 원래 서버로 전달됩니다. 위 코드는 소스와 실습 이름을 바탕으로 구성한 설명용 예시이며 실제 캡처가 아닙니다.

내 실행에서 맞춰 볼 것

  • get_weekly_records에 전달된 주차와 결과의 week를 맞춰 봅니다
  • 원본 data/week-one.json의 업무 ID 네 개가 반환 자료에도 있는지 확인
  • AI가 "성공했습니다"라고 적은 문장보다 — 이 입력과 결과의 대응이 실제 조회를 확인하는 근거
  • 내부 호출이 접혀 있다면 상세 기록을 펼치고, 사용할 수 있는 로그에서도 확인되지 않는 부분은 확인한 것으로 기록하지 않습니다
화면 표현은 설치 환경에 따라 달라질 수 있으므로 표시된 호출 상세를 기준으로 읽습니다.
4

읽어 온 자료와 돌려줄 자료

고르는 위치가 결과의 양을 바꿉니다

⑦ Code Mode
blocker는 업무 진행을 막는 사유를 담는 필드입니다. 값이 null이면 사유가 기록되어 있지 않은 것입니다.

필요한 부분만 반환하기

week-one 기록에서 blocker가 적힌 항목의 ID와 막힌 이유만 보여 줘.
  • Code Mode에서는 도구로 받은 결과를 코드 안에서 살펴보고 필요한 부분을 반환할 수 있습니다 — 전체를 받았더라도 모델에게 전달하는 최종 값은 선택한 ID와 사유만일 수 있습니다
  • 다만 이번 도구의 실제 반환 자료형을 먼저 확인해야 합니다. V1 v1.18.29 호스트 소스는 MCP의 구조화된 결과가 있으면 이를 사용하고, 없으면 텍스트 내용을 전달하는 경로를 갖습니다 — 텍스트를 객체처럼 취급하면 필드를 찾지 못합니다
  • 읽을 것 — 어떤 자료를 받고, 어떤 조건으로 골랐고, 무엇을 반환했는지. 코드가 아닌 답변 단계에서 골랐다면 그 경로 역시 구분해서 기록
📌 두 위치의 차이는 자료가 커졌을 때 드러납니다 — 전체 기록을 모델에 전달한 뒤 답변만 짧게 만들면 이미 긴 자료를 읽은 상태입니다. 어느 경로를 택했는지는 결과 문장의 길이만으로 알 수 없으므로 실행 기록을 함께 봅니다
AI가 생성한 코드를 전부 직접 작성할 필요는 없습니다. 이번 요청은 원본의 blocker 필드만으로 대조할 수 있습니다.

사용 결과의 해석

  • 남길 것 — OpenCode 버전, 사용한 모델, 실행된 도구, 입력 주차, 원자료와 대조한 항목
  • OpenCode는 여러 제공자의 모델을 사용할 수 있고 모델별로 코드 생성과 도구 호출 능력이 다릅니다 — 설정 예시를 확인한 것과 자기 모델 조합에서 호출에 성공한 것은 각각 확인
  • 이번 한 도구 실습으로 성능 우열이나 토큰 절감률까지 판정하지는 않습니다
  • 더 비교한다면 — 같은 모델·서버·요청의 새 대화 두 개에서 설정을 달리하고 처음 주어진 문맥과 호출 뒤 추가된 결과를 나누어 관찰. 검색이 한 번 더 필요했던 시간과 최종 결과 크기도 함께
🔗 우리는 이제 기록을 가져오고 원하는 필드를 고를 수 있습니다. 그런데 개발 완료라고 적힌 업무를 팀 주간보고의 '완료'에 넣어도 되는지는 아직 정하지 않았습니다

❓ 이해도 확인

Q1. Code Mode에서 바뀐 것은?
A1. 모델이 도구를 호출하는 방식. Python 서버와 JSON 자료는 계속 사용한다.
Q2. tools.$codemode.search가 반환하는 것은?
A2. 도구 안내이지 업무 기록이 아니다. 발견 뒤 week를 전달하는 실제 호출이 필요하다.
Q3. 결과에서 필드를 고를 때 먼저 확인할 것은?
A3. 반환 자료형. 구조화된 결과가 없으면 텍스트가 전달될 수 있고, 텍스트를 객체처럼 취급하면 필드를 찾지 못한다.
Q3은 Code Mode에서 자주 만나는 실패 형태입니다.

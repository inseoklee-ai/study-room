프롬프트의 문장 하나가 모델의 행동 경계입니다

검색 결과를 답변의 근거로 바꾸는 경계가 프롬프트입니다.

배포해도 서버가 답을 대신 만들지 않습니다

정적 Pages에 배포한 챗봇의 주소에서 질문을 보낼 때, 화면은 공개되어도 Ollama 호출이 막힐 수 있습니다.

배포된 앱은 사용자 컴퓨터의 브라우저에서 실행되고
브라우저는 여전히 그 컴퓨터의 로컬 엔진을 직접 호출합니다
  • "정적 파일을 배포하면 서버가 로컬 모델 호출을 대신할 것"이라는 해석은 틀립니다
  • 이 실행 경계를 먼저 확인한 뒤에는, 연결 문제와 별개로 모델이 어떤 근거에서 답해야 하는지도 프롬프트에 명시해야 합니다
🧭 배포 환경의 연결 조건과 답변 근거의 조건은 서로 다른 층에서 검증합니다
이 구분을 먼저 해 두면 뒤의 CORS 문제와 근거 문제를 섞지 않고 진단할 수 있습니다.
1

프롬프트는 검색 결과를 근거로 바꾸는 경계

buildPrompt()의 순서

⑥ 프롬프트와 스트리밍
검색된 청크를 단순히 이어 붙이는 것만으로는 자료 밖의 내용을 보태지 않도록 제한할 수 없습니다.

순서가 계약입니다

1자료가 모두의연구소 컨퍼런스 모두콘의 공개 문서 청크라는 소개
2근거 원칙을 명시
3답 안에 근거 청크의 [ID]를 표시하도록 요구
4상대 시각 해석을 위한 KST 현재 시각
5그 뒤에만 [자료]와 [질문]을 배치
  • 이 순서는 모델의 능력을 높이는 주문이 아니라 — 모델이 어떤 범위에서 답하고 무엇을 인용해야 하는지를 문장으로 고정하는 계약
  • 청크마다 MC-xxx 형식의 ID와 section을 보존하면 사용자는 답변의 문장을 원문 청크까지 되짚을 수 있고, 모델도 막연한 "자료에 따르면" 대신 검토 가능한 근거를 남깁니다
ID 보존이 소단원 ③의 스키마 설계와 이어집니다.

약한 근거일 때의 문장은 그대로 보존합니다

다음 자료는 모두의연구소의 컨퍼런스 '모두콘'에 대한 공개 문서에서 뽑은 조각입니다.
주의: 검색된 조각의 유사도가 낮습니다. 질문과 완전히 맞는 근거가 아닐 수 있으니,
근거에 있는 내용만 짧게 답하고 자료에 없는 부분은 없다고 말합니다.
근거가 된 조각의 [ID]를 답 안에서 표시합니다.
현재 시각은 [KST 시각]입니다. '지금', '올해', '다음 주' 같은 상대 표현은
이 시각을 기준으로 해석합니다.

[자료]
[MC-... | 섹션] 청크 텍스트

[질문]
사용자 질문
🎯 "짧게 답하고 자료에 없는 부분은 없다고 말합니다"는 답변을 거부하기 위한 장치가 아니라 — 불확실한 검색에서 사실성을 지키기 위한 장치
KST 시간 컨텍스트 역시 장식이 아니며, 지금·올해·다음 주 같은 상대 표현을 질문 입력 시점의 서울 시간으로 해석할 기준을 제공합니다. 구조는 그대로 조립하되 [KST 시각], 청크 목록, 사용자 질문만 실행 시점의 값으로 바꿉니다.
2

Ollama 응답은 조각으로 읽습니다

스트리밍과 취소

⑥ 프롬프트와 스트리밍
스트리밍은 속도 과시가 아니라 상태와 권리를 드러내는 인터페이스입니다.

줄바꿈으로 구분된 JSON 조각

로컬 엔진은 POST http://localhost:11434/api/chat으로 qwen3.5:2b에 요청하며, 본문에는 stream:true와 think:false를 포함합니다.

await fetch("http://localhost:11434/api/chat", {
  method: "POST",
  signal: controller.signal,
  body: JSON.stringify({
    model: "qwen3.5:2b", stream: true, think: false, messages,
  }),
});
  • 응답은 한 개의 완성 JSON이 아니라 줄바꿈으로 구분된 조각이므로, ReadableStream을 읽어 남은 문자열을 보관하고 줄 단위로 파싱한 뒤 각 조각의 텍스트를 화면 답변에 이어 붙입니다
  • 이 구조에서는 토큰당 약 50ms라는 실측 경로의 응답 감각을 사용자가 빈 화면이 아닌 자라나는 문장으로 경험합니다
  • 네트워크 오류와 JSON 파싱 실패는 답변 상태와 분리해 표시하고, 취소할 때에는 AbortSignal로 이미 시작한 스트림을 멈춥니다
스트리밍은 생성 중이라는 상태와 취소할 권리를 사용자에게 드러내는 인터페이스입니다.

연결 상태와 CORS를 배포 환경까지 확인합니다

채팅 전에 GET /api/tags로 Ollama 상태를 확인하면, 모델이 꺼진 상황을 생성 실패처럼 보이지 않게 안내 배너와 재시도 동작으로 분리할 수 있습니다.

# macOS
launchctl setenv OLLAMA_ORIGINS "https://YOUR_ID.github.io"

# Windows
setx OLLAMA_ORIGINS "https://YOUR_ID.github.io"

# systemd 환경
systemctl set-environment OLLAMA_ORIGINS="https://YOUR_ID.github.io"
  • 로컬 개발 서버에서 되는 요청도 GitHub Pages 배포 뒤에는 자동으로 해결되지 않습니다 — 정적 페이지가 서버를 대신해 호출하는 것이 아니라 사용자 브라우저가 계속 자신의 localhost:11434로 요청하기 때문
  • 운영체제별 설정 뒤에는 앱을 재시작해야 하며, 실제 Pages 주소에서 상태 확인과 스트리밍을 함께 점검해야 합니다
  • Chrome과 Edge를 권장하고 Safari에서는 Ollama 연결과 임베딩 WASM이 불안정할 수 있음을 시작 화면에 명시하는 편이 좋습니다
배포 주소와 로컬 엔진 사이의 경계를 화면에 드러내는 일은, 사용자가 자신의 환경에서 점검할 조건을 알게 하는 제품의 책임입니다. 연결 배너와 재시도를 남겨 두면 로컬 엔진이 꺼져 있거나 출처 허용이 빠졌을 때 이를 검색·프롬프트 실패로 오해하지 않게 합니다.
3

실습 5 — 챗봇 UI의 상태를 명세합니다

예쁜 대화창이 아니라 상태 전이

⑥ 프롬프트와 스트리밍
입력창과 답변 말풍선만으로는 완성되지 않습니다.

사용자가 지금 어느 단계인지 읽을 수 있어야 합니다

Vite, React, TypeScript로 모두콘 RAG 챗봇 UI 골격을 만듭니다.
로컬 qwen3.5:2b 엔진 선택, GET /api/tags 연결 상태 배너와 재시도,
임베딩·하이브리드 검색·생성 단계 표시, 스트리밍 답변과 AbortSignal 중지 버튼을 구현합니다.
각 답변에는 출처 칩을 표시하고 칩에는 MC ID, section, vector 또는 bm25 방법, 점수를 보입니다.
최고 유사도가 0.55보다 낮으면 약한 근거 경고를 보이며, 스트리밍 오류가 나도
이미 받은 답변과 출처는 유지합니다. Chrome과 Edge 권장, Safari 불안정 안내도 포함합니다.
  • 특히 스트리밍이 중단되어도 이미 받은 답변 청크를 지우지 않고, 출처 칩은 ID·section·검색 방법·점수를 보여 주며 원문으로 연결되게 요구합니다
  • 이 구조는 답변의 신뢰를 배지 하나에 맡기지 않고, 사용자가 근거와 과정을 직접 확인할 수 있게 만듭니다
상태 전이와 실패 시 유지할 내용을 구체적으로 쓰는 것이 이 요청의 핵심입니다.

더 깊이 갈 사람을 위한 길

1더 큰 로컬 모델로 바꿔 보기 — ollama로 다른 모델을 받아 모델명만 바꾸면 같은 파이프라인에서 답변 리듬이 어떻게 달라지는지, 컴퓨터 사양에 따른 응답 속도의 한계도 함께 기록됩니다
2시스템 프롬프트 문구를 하나씩 바꿔 같은 질문 세트로 답변을 비교하는 A/B 실험
3temperature 값을 바꿔 답변의 일관성 변화를 살피는 실험
프롬프트의 문장 하나가 모델의 행동 경계입니다
세 실험 모두 소단원 ⑧에서 루브릭과 함께 기록하면 비교 가능한 자료가 됩니다.

❓ 이해도 확인

Q1. Pages에 배포하면 Ollama 호출 문제가 해결되나?
A1. 아니다. 배포된 앱은 사용자 브라우저에서 실행되고 여전히 그 컴퓨터의 localhost:11434를 호출한다. 로컬 Ollama에서 OLLAMA_ORIGINS로 Pages 출처를 허용해야 한다.
Q2. 프롬프트에서 [ID] 표시를 요구하는 이유는?
A2. 사용자가 답변의 문장을 원문 청크까지 되짚을 수 있고, 모델도 막연한 "자료에 따르면" 대신 검토 가능한 근거를 남기게 하기 위해.
Q3. Ollama 스트리밍 응답을 어떻게 읽나?
A3. 한 개의 완성 JSON이 아니라 줄바꿈으로 구분된 JSON 조각. ReadableStream을 읽어 남은 문자열을 보관하고 줄 단위로 파싱해 이어 붙인다. 취소는 AbortSignal.
Q4. 스트리밍 오류가 났을 때 UI는?
A4. 이미 받은 답변 청크와 출처를 지우지 않는다. 네트워크·파싱 실패는 답변 상태와 분리해 표시한다.
Q1이 이 소단원에서 가장 자주 막히는 실무 지점입니다.

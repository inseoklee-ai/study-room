닿는 곳을 늘리는 기능들

브라우저 · 카메라 · 위치 · 음성

⑩ 확장
입구와 권한이 함께 늘어나는 기능들입니다.

브라우저를 움직입니다

통합 브라우저 조작 기능은 페이지 열기 · 탭 다루기 · 스크린샷 · 클릭 · 입력 · PDF 저장까지를 하나의 서비스로 묶어 둡니다. 에이전트가 눈으로 화면을 보고 손으로 누르는 일을 대신합니다.

⚠️ 입구의 관점에서 보면 웹이 통째로 새 접촉면이 됩니다 — 에이전트가 방문하는 페이지에는 사람을 향한 문장이 얼마든지 있습니다. 앞 절에서 읽은 "읽은 내용과 실행 요청의 분리" 원칙이 브라우저에서는 더 자주 적용되는 셈입니다

말로 이어서 대화합니다

Talk mode는 로컬 글소리 인식과 합성을 함께 쓰는 연속 음성 대화로, 화면을 보지 않고 대화가 이어집니다.

⚠️ 음성은 승인의 문제를 다시 만듭니다 — 소리로 듣는 승인은 눈으로 읽는 승인보다 흘러가기 쉽습니다. 문서는 위험도가 큰 작업은 발화로 정확하게 다시 승인하도록 요구합니다
손을 늘리는 기능마다
승인의 형태도 함께 설계 대상이 됩니다

처음 닿는 것분리되고 제한된
읽기 전용 reader agent
  • IMAP 감시 기능은 메일함을 지켜보다가 인증된 받은 메일을 별도의 읽기 전용 역할로 넘깁니다
  • 공식 문서는 이 구조를 "임의의 메일을 주 에이전트에 바로 넣는 기능이 아니다"라고 분명히 못 박습니다
🎯 메일함은 검증할 수 없는 입력이 들어오는 입구이고 — 그 입구에 처음 닿는 것을 권한이 가장 작은 별도의 역할로 격리합니다. 문 같은 곳에는 문지기가 따로 서 있는 구조
출처: docs/automation/imap

모델에 문제가 생기면 다음 모델로

모델 페일오버는 지금 쓰는 모델에 문제가 생겼을 때 같은 제공자 안에서 인증 프로필을 바꿔 본 뒤 설정해 둔 다음 모델로 넘어가는 기능입니다.

📌 페일오버는 실패를 없애는 장치가 아니라 — 실패 뒤에 시도할 순서를 정해 두는 장치입니다
  • 다음 모델을 정해 두지 않으면 넘어갈 곳이 없고, 인증 프로필이 여러 개여야 회전이 가능합니다
  • 앞 절의 인증 정리와 이어지는 설정입니다
출처: docs/concepts/model-failover

ClawHub — 스킬 배포처

openclaw skills search
openclaw skills install
⚠️ 설치할 수 있다는 것과 안전하다는 것은 다른 말입니다. ClawHub는 악성으로 표시된 배포판은 거부하지만 — 감사 내용을 함께 보여 주고 설치를 이어 가는 형태의 배포판도 있습니다
  • 무엇을 설치하는지 그 문서를 읽는 습관이 마켓을 쓰는 조건입니다
  • 휴대폰 앱은 입구를 주머니까지 가져옵니다 — iOS·Android 앱이 노드로 연결되어 있으면 폰의 감각과 알림이 에이전트와 이어집니다. 앞 절의 텔레그램 연결과 같은 원리가 앱이라는 다른 옷을 입은 것

❓ 이해도 확인

Q1. 확장 기능을 읽는 세 기준은?
A1. 입구(닿는 곳) · 상태(남기는 기록) · 권한(허락해야 하는 것).
Q2. IMAP 감시가 보여 주는 설계 원칙은?
A2. 검증할 수 없는 입력에 처음 닿는 것을 권한이 가장 작은 읽기 전용 역할로 격리한다. 임의의 메일을 주 에이전트에 바로 넣는 기능이 아니다.
Q3. 모델 페일오버가 하는 일과 하지 않는 일은?
A3. 실패를 없애지 않고, 실패 뒤 시도할 순서를 정한다. 다음 모델과 여러 인증 프로필이 있어야 작동한다.
Q1이 앞으로 어떤 확장을 만나도 쓸 수 있는 잣대입니다.

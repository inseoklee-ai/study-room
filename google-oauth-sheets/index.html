Google Workspace 자료를
읽는 인증과 연결

브라우저에 로그인한 사실이 새 프로그램으로 자동 전달되지는 않습니다

금요일마다 동료가 업데이트한 Google Sheets를 내려받아 복사한다면, 복사한 뒤 바뀐 기록은 보고서에 반영되지 않습니다.

프로그램이 알려야 하는 세 가지

로컬 프로그램 → Google 로그인·동의 화면 → 학생의 계정 선택·동의
             ← 인증 결과를 받아 토큰 저장 ←
로컬 프로그램 → 토큰을 첨부해 Sheets API 호출 → 표 데이터 반환
  • 프로그램은 어떤 앱이, 어느 사용자의 동의를 받아, 어떤 작업을 하려는지 Google에 알려야 합니다
  • Google 계정의 비밀번호는 Google 로그인 화면에 입력합니다. 로컬 프로그램은 동의 결과를 바탕으로 API를 요청할 수 있는 토큰을 받습니다
  • Skill 문서를 작성하는 것 자체에는 credential이 필요하지 않습니다 — 그 Skill이 사용하는 MCP·CLI·스크립트가 Google API를 호출할 때 인증이 필요합니다
📌 이 실습의 순서 — 프로젝트와 앱 준비 → 최초 로그인 → 프로그램의 API 읽기 → MCP 등록 → 에이전트의 실제 호출. Colab MCP와는 별개의 인증 경로이며 앞의 노트북 연결 승인이 이 동의를 대신하지는 않습니다
화면 메뉴가 작게 보이면 각 캡처를 확대해 확인합니다. 실제 콘솔은 언어와 업데이트 시점에 따라 메뉴 위치가 조금 다를 수 있습니다.

1

프로젝트와 API 준비

개인 Gmail 계정도 이 API를 쓸 수 있습니다

⑬ Google 인증
이번 캡처는 개인 Google 계정, 별도 실습 프로젝트, Google Sheets API, Desktop app, spreadsheets.readonly 조합으로 진행했습니다.

Cloud 프로젝트

  • Google Cloud Console 오른쪽 위 계정에서 이번 실습에 사용할 개인 계정인지 먼저 확인. 회사 계정으로 열려 있다면 전환한 뒤 진행
  • Cloud 프로젝트는 API 설정과 앱 인증 정보를 묶어 관리하는 단위입니다 — 내 컴퓨터의 실습 폴더나 Drive 폴더와는 다른 곳. 실습 폴더에는 Python 파일, Cloud 프로젝트에는 '프로그램이 사용할 Google 기능과 앱 설정'. Google 표 자체를 이 프로젝트로 옮기지는 않습니다
  • New Project로 만들고 Project name에 목적을 나타내는 이름(예: Workspace OAuth Practice). 프로젝트 ID는 전역에서 고유해야 하므로 화면 예제와 달라도 됩니다
  • 생성 뒤 상단 프로젝트 선택기에 방금 만든 이름이 표시되는지 확인 — 엉뚱한 프로젝트에서 API를 켠 뒤 다른 프로젝트의 인증 JSON을 받으면 설정은 각각 존재해도 함께 작동하지 않습니다
이름이 아닌 자신의 계정으로 만드는 작업입니다.

API 사용 설정

  • 선택한 프로젝트에서 APIs & Services → Library를 열고 Google Sheets API를 찾아 Enable
  • 이 작업은 '우리 프로그램에서 표 API를 사용할 준비'이고 — 어느 사용자의 어느 표를 읽을지는 아직 정하지 않았습니다
하려는 작업확인할 API
표의 셀 읽기Google Sheets API
문서 본문 읽기Google Docs API
파일 이름 검색·목록 조회Google Drive API
메일 읽기Gmail API
일정 읽기Google Calendar API
⚠️ API 사용 설정은 이 프로젝트에서 API를 쓸 준비이며, 내 문서 접근에 대한 사용자 동의와는 별개입니다. Docs/Sheets 도구가 파일을 찾기 위해 Drive API도 사용할 수 있으므로 도구 문서의 요구 사항을 함께 봅니다
서비스 이름에 Workspace가 들어간다고 유료 회사 계정이 필수인 것은 아닙니다.

동의 화면과 테스트 사용자

  • Google Auth platform → Branding에서 App name(예: Sheets Practice), 지원 이메일(동의 화면을 본 사용자가 문의할 연락처), 연락 이메일(앱 설정 관련 안내)
  • Audience는 이 앱을 누가 이용할지 — 개인 계정 실습은 External. External은 곧바로 공개 게시한다는 뜻이 아닙니다 — Testing 상태로 두고 Test users에 등록한 계정으로 시험
  • Internal은 Workspace 또는 Cloud Identity 조직 내부 대상이며 조건을 충족할 때 사용 — 개인 계정 실습에서는 회사용 Internal 안내를 그대로 따라가지 않습니다
  • Test users에는 나중에 브라우저 로그인에서 선택할 개인 이메일을 추가 — Cloud 프로젝트를 편집할 사람이나 표를 공유받을 사람 목록과는 다릅니다. 프로젝트를 편집할 수 있어도 다른 계정으로 로그인하면 테스트 사용자 제한에 걸릴 수 있습니다
📌 공개 배포를 위해 임의의 홈페이지나 개인정보처리방침 주소를 넣지 않습니다 — 이 실습에서는 Testing을 유지한 채 이후 실제 인증과 읽기에 성공했습니다
위쪽에 Branding 미완료 안내가 보이면 Branding에서 누락 정보를 확인합니다. 프로젝트 설정 마지막에는 Google API 사용자 데이터 정책을 읽고 동의하는 단계가 있습니다.

Scope와 파일 공유 권한

SCOPES = ["https://www.googleapis.com/auth/spreadsheets.readonly"]
  • 끝의 readonly는 읽기 전용. 이 문자열은 Google이 구별하는 권한 식별자이므로 정확한 값을 사용합니다
  • Scope와 파일 공유 권한은 서로 다른 조건입니다 — '표 읽기'를 동의했어도 공유받지 않은 다른 사람의 비공개 표까지 읽을 수는 없고, 편집 권한이 있는 표라도 읽기 전용 토큰으로 수정 API를 호출할 수는 없습니다
  • 이어서 봐야 하는 셋 — 콘솔 Data Access의 선언, Python의 SCOPES, 실제 로그인 동의 화면. 콘솔에서 범위를 저장했다는 사실만으로 프로그램의 요청이나 기존 토큰의 권한이 자동으로 바뀌지는 않습니다
  • 목록에서 찾기 어렵다면 Manually add scopes에 전체 문자열을 입력하고 Add to table → Update → Save
⚠️ See all your Google Sheets spreadsheets는 접근 가능한 표 전체에 대한 읽기 권한이며 예제 표 하나만 허용하는 범위가 아닙니다
표에 내용을 쓰는 기능이 필요해지면 코드의 기능뿐 아니라 요청할 권한도 다시 검토해야 합니다.

이름이 비슷한 두 파일

파일만들어지는 순간역할
credentials.jsonCloud 콘솔에서 앱 클라이언트를 만들고 다운로드어떤 앱이 로그인을 요청하는지 식별하는 설정
token.json프로그램 실행 후 사용자가 로그인하고 동의동의한 사용자로 API를 요청하고 인증을 갱신하는 정보
  • Google Auth platform → Clients → Create client → Desktop app을 선택하고 JSON을 다운로드 — Web application을 요구하는 도구라면 그 안내의 redirect URI를 정확히 등록해야 합니다. 앱 종류를 추측하지 않습니다
  • 촬영 당시 콘솔은 창을 닫으면 client secret을 다시 보거나 다운로드할 수 없다고 안내했습니다
  • 예제 보관 위치는 ~/.config/google-workspace/credentials.json이며 인증 프로그램이 같은 폴더에 token.json을 생성 — 둘 다 실습 ZIP이나 Git 저장소에 넣지 않습니다
  • 다운로드한 내용이나 토큰을 에이전트 대화에 붙여 넣지 않습니다 — 도구에는 파일을 읽을 경로를 설정하고, 과제에는 '어느 설정 항목에 경로를 지정했는가'만 적습니다
  • 저장소 안에 둘 수밖에 없다면 .gitignore로 제외하고 이미 추적되고 있지 않은지도 확인 — .gitignore는 이미 올라간 비밀값을 지워 주지 않습니다
📌 Credential은 인증에 쓰는 정보를 넓게 부르는 말입니다 — 모든 도구에서 credentials.json이라는 파일 하나를 의미하는 것은 아닙니다. 다른 위치를 쓰면 CREDENTIALS_PATH(앱 JSON)와 TOKEN_PATH(로그인 결과)로 지정하며 이 두 이름은 첨부 코드의 약속이고 공통 이름은 아닙니다
Desktop app을 선택한 이유는 로컬 프로그램이 브라우저 로그인 결과를 돌려받는 실습이기 때문입니다. Web application용 redirect URI 입력란을 찾아 임의로 채우지 않습니다.

최초 로그인과 API 읽기

MCP를 먼저 등록하지 않는 이유

⑬ Google 인증
실습 ZIP에는 GOOGLE_AUTH_README.md, 최초 인증용 google_auth_check.py, 읽기 MCP 서버 google_sheet_reader.py가 있습니다.

준비와 실행

uv sync --locked --extra google
uv run --locked --extra google python google_auth_check.py
  • Extra(선택 의존성 묶음)는 특정 기능을 쓸 때 기본 의존성에 더할 라이브러리 묶음 — google extra는 기본 MCP 환경에 Google API와 인증용 라이브러리를 추가합니다. 새 Google 프로젝트나 가상환경을 만드는 옵션이 아닙니다
  • 실행 명령에도 --extra google을 명시하면 필요한 라이브러리를 실행 전에 확인하고 준비할 수 있습니다
  • 첨부 requirements.txt·requirements-google.txt는 기존 방식과의 호환 참고이며 기준은 pyproject.toml과 uv.lock
  • 이 명령은 인증 JSON을 읽고 기본 브라우저를 엽니다 — 아직 로그인한 적이 없으므로 지금 이 순간에 사용자 동의를 요청. 계정이 여러 개면 Test users에 등록한 개인 계정을 고릅니다
  • 프로그램은 결과를 받기 위해 localhost에서 잠시 기다립니다 — 지금 프로그램을 실행하는 자기 컴퓨터를 가리키며 그 컴퓨터 안에서만 결과를 받고 사용하지 않는 포트를 잠시 엽니다. 별도의 로그인 웹사이트를 인터넷에 배포하는 작업은 아닙니다
🎯 로그인 후 이 프로그램이 Google 공식 예제 표를 직접 읽습니다 — MCP를 먼저 등록하지 않는 이유: 이 단계의 결과로 Google 인증과 API가 동작하는지 확인할 수 있고, 이후 호스트 연결에 문제가 생겨도 어느 단계까지 성공했는지 구분할 수 있습니다
새 프로젝트를 만드는 uv init은 실행하지 않습니다. 다른 실습의 가상환경이 활성화되어 있다면 현재 폴더의 환경에 맞춘 뒤 진행합니다.

동의 화면과 반환값

  • 계정 선택 — 콘솔에서 정한 앱 이름과 사용할 계정을 확인
  • 미검증 안내 — 직접 만든 Testing 앱의 안내입니다. 앱 이름·개발자·계정을 확인한 이 실습에서는 Continue. 출처를 모르는 다른 앱의 경고를 무조건 넘기는 절차가 아닙니다
  • 권한 동의 — 권한 설명이 표 읽기인지 확인한 뒤. 콘솔에 범위를 저장했더라도 실제 실행 프로그램이 다른 권한을 요청할 수 있으므로 이 화면을 다시 확인
{
  "title": "Example Spreadsheet",
  "sheet": "Class Data",
  "range": "'Class Data'!A1:C3",
  "values": [
    ["Student Name", "Gender", "Class Level"],
    ["Alexandra", "Female", "4. Senior"],
    ["Andrew", "Male", "1. Freshman"]
  ]
}
✅ 완료 판단 — 이번 환경에서는 동의 후 localhost 완료 페이지가 Chrome에서 ERR_BLOCKED_BY_CLIENT로 보였지만 로컬 프로그램은 인증 결과를 받아 위 응답을 출력하고 정상 종료했습니다. 이 메시지 하나로 성공·실패를 단정하지 않습니다 — 먼저 터미널의 종료 상태와 실제 읽기 결과를 확인. token 파일의 내용은 출력하지 않습니다
사용자 개인 자료를 읽은 예제가 아닙니다. 표에서 A·B·C는 열 이름, 1·2·3은 행 번호이며 A1:C3은 헤더를 포함합니다.

토큰을 받아 다시 사용하는 코드

두 함수가 읽는 파일이 다릅니다

⑬ Google 인증
핵심 흐름은 인증 파일 경로 확인 → 기존 토큰 읽기 또는 최초 로그인 → 표 읽기입니다.

최초 로그인과 재사용

creds = (load_token(token_path) if token_path.exists() and not args.reauth
         else authenticate(credential_path, token_path, ...))
flow = PrivateURLFlow.from_client_secrets_file(str(credentials_path), SCOPES)
creds = flow.run_local_server(
    host="localhost", bind_addr="127.0.0.1", port=0,
    open_browser=not no_browser,
    success_message="Authentication complete. You can close this tab.",
    timeout_seconds=timeout, prompt="consent")
check_scopes(creds)
save_private(token_path, creds.to_json())
  • from_client_secrets_file()이 앱 설정 JSON과 요청할 SCOPES를 읽습니다 — 이 줄에서 로그인이 끝나는 것은 아닙니다. run_local_server()가 브라우저 흐름을 시작하고 그 결과로 creds를 만듭니다
  • port=0은 사용할 수 있는 포트를 시스템이 고르도록, prompt="consent"는 동의 화면을 요청
  • save_private()는 임시 파일을 만든 뒤 교체하며 토큰을 다른 사용자에게 공개하지 않도록 저장 — 토큰 자체를 보고서나 답변에 출력할 이유는 없습니다
  • PrivateURLFlow는 InstalledAppFlow의 확장 — 표준 OAuth 절차를 새로 구현한 것이 아니라 자동으로 브라우저를 열지 않는 실행에서도 로그인 URL을 파일로 전달하도록 보조 동작을 더한 것
파일이 있다는 사실과 그 인증이 유효하다는 사실은 다르므로 실제 유효성 확인은 load_token() 안에서 계속합니다.

    if not path.is_file():
        raise ValueError("인증 토큰이 없습니다. google_auth_check.py를 먼저 실행하세요.")
    creds = Credentials.from_authorized_user_file(str(path))
    check_scopes(creds)
    if not creds.valid:
        if not creds.refresh_token:
            raise ValueError("재인증이 필요합니다. --reauth를 실행하세요.")
        creds.refresh(Request())
        check_scopes(creds)
        save_private(path, creds.to_json())
    return creds
  • from_authorized_user_file()은 사용자 동의 뒤 만들어진 토큰 JSON을 읽습니다 — 앞의 from_client_secrets_file()이 읽는 앱 JSON과 대상이 다릅니다
  • 접근 토큰에는 유효 기간이 있습니다. 갱신 토큰이 유효하면 creds.refresh(Request())가 새 접근 토큰을 요청하므로 매번 로그인할 필요가 줄어듭니다. 갱신 토큰이 없거나 만료·철회된 경우에는 재로그인
  • load_token() 자체는 브라우저를 열지 않으므로 실패하면 인증 프로그램에서 재인증
  • check_scopes()의 역할 — 다른 도구에서 받은 넓은 권한의 토큰을 파일명만 바꿔 가져와 놓고 '읽기 전용 실습'이라고 생각하는 상황을 발견하려고 저장된 범위를 실습 범위와 대조합니다. 파일을 읽을 때 scopes를 새 값으로 덮어쓰지 않고 원래 저장된 범위를 확인
이 함수가 처음과 갱신 뒤 모두 check_scopes()를 호출하는 이유입니다.

                                      └ 문서 ID: /d/ 뒤부터 /edit 앞까지
if not re.fullmatch(r"[A-Za-z0-9_-]+", spreadsheet_id):
    raise ValueError("표 URL 전체가 아닌 spreadsheet_id를 입력하세요.")
service = build("sheets", "v4", credentials=creds, cache_discovery=False)
metadata = service.spreadsheets().get(

    fields="properties(title),sheets(properties(title))").execute()

  • build("sheets","v4", ...)의 클라이언트는 앞서 배운 MCP 클라이언트와 별개의 Google API 호출용 Python 객체
  • 첫 get()은 문서 제목과 시트 제목. fields로 필요한 항목만 지정하므로 모든 메타데이터를 가져오지 않아도 됩니다 — 메타데이터는 셀의 실제 기록이 아니라 자료를 설명하는 정보
  • 작은따옴표와 replace()는 시트 이름에 공백이나 작은따옴표가 있어도 올바른 범위 문자열이 되도록

  • 반환 딕셔너리는 title·sheet·range·values. values의 안쪽 목록 하나가 한 행이며 뒤쪽의 빈 행·열은 생략될 수 있으므로 항상 같은 크기로 반환된다고 가정하지 않습니다

읽기 함수를 MCP로 공개

호출 도중 첫 로그인을 기다리게 하지 않습니다

⑬ Google 인증
지금까지는 학생이 인증 프로그램을 실행했습니다. 이제 AI가 필요할 때 같은 기능을 요청할 수 있도록 공개합니다.

도구 등록과 오류 처리

@mcp.tool()
def read_sheet_header(spreadsheet_id: str) -> dict:
    """지정한 Google 표의 제목과 첫 시트 A1:C3을 읽습니다. 생성·수정하지 않습니다.

    spreadsheet_id는 표 URL의 /d/와 /edit 사이 ID입니다.
    인증이 안 되어 있으면 터미널에서 google_auth_check.py를 먼저 실행하세요.
    """
    try:
        token = load_token(configured_path("TOKEN_PATH", "token.json"))
        return read_header(token, spreadsheet_id)
    except Exception as error:
        raise ToolError(
            "Google 읽기 실패. 인증 확인 스크립트와 지정 표의 접근 권한을 확인하세요 "
            f"({type(error).__name__}).") from None
  • @mcp.tool()이 앞서 만든 read_header()를 그대로 이용하되 이름과 입력을 호스트가 발견·호출할 수 있게 등록. 함수 설명은 어떤 표를 얼마나 읽는지 알려 주고 URL이 아니라 ID가 필요하다는 안내도 담습니다
  • 먼저 TOKEN_PATH에서 토큰을 읽어 전달 — MCP 호출 도중 브라우저에서 첫 로그인을 기다리게 하지 않고 준비된 인증으로 바로 읽는 구조. 필요한 재로그인은 인증 프로그램이 맡습니다
  • 예외 시 ToolError로 Google API의 긴 응답 원문을 그대로 대화에 흘리는 대신 인증 확인 프로그램과 접근 권한을 확인할 단서를 남깁니다
📌 등록 명령은 uv --directory "/내/실습폴더" run --locked --extra google mcp run google_sheet_reader.py --transport stdio — 세 설정(Claude Code / OpenCode V1 / V2) 모두 실행 명령은 같고 호스트가 설정을 읽는 위치와 켜기·끄기 항목만 다릅니다. 이 로컬 MCP 설정에 원격 MCP용 OAuth 항목을 추가하는 단계는 아닙니다
위치를 바꿨다면 인증 프로그램에는 CREDENTIALS_PATH와 TOKEN_PATH를, MCP 서버에는 TOKEN_PATH를 지정합니다. Claude Code는 env, OpenCode는 environment에 넣습니다. 인증 파일 내용을 설정에 복사하지 않습니다.

호스트의 호출과 원본 대조

  • 연결 목록에 google-sheets-reader가 보이면 서버와 연결된 것. 이어 read_sheet_header가 선택되었는지, spreadsheet_id에 URL 속 ID가 전달되었는지, 반환된 제목과 행이 원본과 같은지
  • 연결 표시 · 실제 도구 호출 · 원본 대조가 각각 다른 관찰입니다
  • 공개 예제를 호출했다면 title은 Example Spreadsheet, sheet는 Class Data. values의 첫 목록은 헤더
  • 요청에 '처음 세 줄'을 썼다고 헤더 다음 세 명의 데이터가 오는 것은 아닙니다 — 이 도구는 헤더를 포함한 1–3행을 읽도록 작성했습니다
  • 읽기 전용 scope라도 접근 가능한 파일이 한 개로 제한된다는 뜻은 아니므로 도구가 허용받은 실제 범위를 별도로 확인
📌 표를 읽는 기능을 연결한 것이므로 이 순서만 적었다고 별도의 Skill이 필요한 것은 아닙니다 — 앞에서 만든 Skill이 Google 자료를 필요로 한다면 이 MCP를 자료를 읽는 수단으로 사용할 수 있습니다. 인증 JSON이나 토큰은 Skill 본문에 넣지 않습니다
같은 인증으로 SDK 클라이언트에서 read_sheet_header를 호출해 표 제목·범위·내용을 다시 확인한 기록이 있습니다. 이 기록은 Claude Code·OpenCode 모델의 도구 선택까지 검증한 것은 아닙니다.

팀 자료로 확장과 멈춘 단계

  • 공개 예제 표는 인증과 읽기 경로를 확인하기 위한 자료입니다 — 반환된 학생 명단을 주간 보고서 데이터로 사용하는 것은 아닙니다
  • 연결하려면 week-one·week-two의 기록을 연습용 Google 표에 옮기고 열 이름과 값의 의미를 정하는 단계가 더 필요합니다 — 업무 ID·주차·진행 기록·배포 상태·운영 확인이 각각 어디에. 현재의 A1:C3만으로 모든 업무를 가져올 수 있는지 학생이 판단
  • 데이터 위치를 Google 표로 바꿨다고 팀 규칙까지 새로 만들어야 하는 것은 아닙니다. 반대로 데이터 연결 설명만 적은 문서를 억지로 별도 Skill로 만들 필요도 없습니다

❓ 이해도 확인

Q1. credentials.json과 token.json의 차이는?
A1. 앞은 어떤 앱이 로그인을 요청하는지 식별하는 설정(콘솔에서 다운로드), 뒤는 동의한 사용자로 API를 요청하는 정보(로그인 뒤 생성).
Q2. scope와 파일 공유 권한의 관계는?
A2. 서로 다른 조건. 표 읽기를 동의해도 공유받지 않은 표는 못 읽고, 편집 권한이 있어도 읽기 전용 토큰으로 수정할 수 없다.
Q3. MCP를 먼저 등록하지 않는 이유는?
A3. 인증 프로그램의 결과로 Google 인증과 API가 동작하는지 먼저 확인하면, 이후 호스트 연결에 문제가 생겨도 어느 단계까지 성공했는지 구분할 수 있다.
Q3이 이 절의 실습 설계 의도입니다.

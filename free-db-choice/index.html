무료로 쓸 수 있는
DB 고르기

공짜로 시작하기 — 한도·백업·정책을 알고 고른다

비전공자도 무료로 진짜 데이터베이스를 쓸 수 있습니다. 다만 시작 전에 하나만 기억하세요 — 무료 티어는 배우기·MVP용이지 큰 규모의 운영용은 아닙니다.

발표 직전에 앱이 멈추는 이유

프로젝트를 막 시작한 학생이 "무료로 시작하고 싶은데 뭘 골라야 하지?"라며 서비스마다 다른 제한을 비교하고 있습니다. 가입은 쉬워도 저장 용량이나 사용량 제한을 놓치면, 발표 직전에 앱이 멈출 수 있습니다.

🎯 그래서 목적과 제한을 함께 보고 고르는 기준이 필요합니다
  • 표를 보기 전에 먼저 적어 보세요 — 내 서비스가 SQL 표와 로그인·파일저장을 한 번에 원하는지, 아니면 DB만 필요한지
  • 무료 한도는 가입 직전에 공식 가격 페이지에서 다시 확인합니다
기능을 만들기 전부터 표가 부담스러울 수 있습니다. 내 필요를 한 줄로 적고 나서 표를 보면 훨씬 쉽습니다.

2

클라우드 말고, 내 컴퓨터에 직접 설치해서 무료로

SQLite · PostgreSQL · MySQL · Docker

⑥ 무료 DB 고르기
지금까지는 '남의 컴퓨터(클라우드)'를 빌리는 무료 티어를 봤습니다. DB는 내 컴퓨터에 직접 설치해서도 무료로 쓸 수 있습니다 — 대부분 오픈소스라 설치도 사용도 공짜입니다.

내 컴퓨터에서 무료로 — 세 가지 길

1SQLite — 설치도 서버도 없다. DB 전체가 파일 하나. 서버를 따로 켤 필요 없이 그 파일을 앱이 직접 읽고 쓴다. 작은 앱·프로토타입·모바일 앱이 즐겨 쓴다 (파이썬 등에 기본 내장돼 사실상 '설치 없이' 쓰기도)
2PostgreSQL · MySQL — 진짜 DB를 내 컴퓨터에. 회사들이 실제로 쓰는 그 오픈소스 DB를 무료로 설치할 수 있다. 클라우드에서 빌리던 것과 같은 것을 내 손안에서
3Docker — 명령 한 줄로 띄우기. 설치가 번거로우면 DB를 '컨테이너'로 띄운다. 내 컴퓨터를 어지럽히지 않고 켜고, 필요 없으면 통째로 지운다
SQLite가 실습(소단원 ⑦)의 기본값이 되는 이유가 1번입니다. 파일 하나라서 설치·계정·네트워크 문제가 아예 없습니다.

로컬 vs 클라우드 — 언제 뭘

💻 로컬 (내 컴퓨터)

완전 무료, 오프라인에서도 되고 내 데이터가 내 손안에. 개발·학습·실험에 최고. 단, 남에게 열려면 배포나 터널이 필요하고(지난 시간의 '집 서버'), 내 컴퓨터가 꺼지면 멈춘다

☁️ 클라우드

24시간 켜져 있고 남에게 안정적으로 열린다. 실제 서비스엔 이쪽

만들 때내 컴퓨터
(로컬 SQLite)
→
세상에 낼 때클라우드 DB
🗣️ AI에게 — "개발용으로는 가벼운 로컬 SQLite로 시작하고, 배포할 때 클라우드 DB로 바꿀 수 있게 해줘."
이 흐름이 소단원 ⑦ 실습의 길 A → 길 B 구조와 정확히 같습니다.
3

무료 티어, 시작 전에 확인할 것

용량 · 일시정지 · 백업 · 정책 · 요금

⑥ 무료 DB 고르기
발표 직전에 멈추는 사고를 막는 다섯 가지 점검입니다.

다섯 가지 점검

1용량 한도 — 예: 500MB. 이미지 같은 큰 파일을 많이 넣으면 금방 찹니다
2미사용 시 일시정지 — 예: Supabase는 1주일 안 쓰면 프로젝트가 잠깐 멈춥니다(다시 켜면 됨)
3백업 방법 — 앞에서 본 참사를 피하려면 자동 백업이 되는 요금제인지(무료면 직접 백업이 필요한지) 꼭 확인
4정책 변경 — PlanetScale처럼 무료가 사라질 수 있습니다
5트래픽이 늘면 유료 — 서비스가 커지면 자연스럽게 넘어갑니다. 요금·용량 알림을 켜 두세요
3번이 소단원 ⑤의 백업 참사와 직접 연결됩니다. "무료라서 자동 백업이 없다"는 사실을 모르고 쓰는 경우가 가장 위험합니다.
4

AI에게 데이터베이스를 붙여 달라고 하기

문법 대신 '무엇을 + 조건'

⑥ 무료 DB 고르기
이 프롬프트가 이 강의의 실질적 산출물입니다.

이 네 줄이면 충분합니다

내 서비스에 데이터를 저장하려고 해. 나는 비전공자고 무료로 시작하고 싶어.
1. 내가 저장할 것은 [예: 상품, 주문]인데, 어떤 표(테이블)와 항목(열)이
   필요할지 스키마를 제안해줘.
2. 무료 SQL 데이터베이스(예: Supabase, PostgreSQL) 기준으로
   이 스키마를 만드는 방법을 알려줘.
3. 접속 정보(비밀번호·키)는 코드에 넣지 말고 환경변수로 빼줘.
4. DB에 값을 넣을 때는 파라미터화 쿼리로 처리하고,
   비밀번호는 해시로 저장해줘.
🔗 3·4번은 지난 시간의 환경변수·보안, 그리고 오늘 배운 SQL 주입 방어와 그대로 이어집니다
문법을 몰라도 '무엇을 저장할지 + 조건'만 주면 AI가 스키마 설계부터 연결·보안까지 도와줍니다. 조건 문장을 빠뜨리면 AI는 가장 흔한(그래서 때로 안전하지 않은) 방식으로 만듭니다.

❓ 이해도 확인

Q1. 무료 티어는 무엇을 위한 것인가?
A1. 배우기·MVP(초기 버전)용. 큰 규모의 운영용이 아니다.
Q2. Supabase 무료 요금제에서 특히 주의할 두 가지는?
A2. ① 자동 백업이 포함되지 않는다(직접 백업 필요) ② 1주 미사용 시 일시정지될 수 있다. 용량은 프로젝트당 DB 500MB.
Q3. 로컬과 클라우드의 흔한 사용 흐름은?
A3. 내 컴퓨터(로컬)에서 만들고 → 세상에 낼 때 클라우드로. 개발·학습은 로컬, 24시간 열려야 하면 클라우드.
Q2의 수치는 2026-02 확인값입니다. 학습자에게 "가입 직전에 공식 페이지를 다시 보라"는 습관을 함께 심어 주세요.

범주 · AI 친화도 · 인기≠정답 · 판단 축

③ 판단
"최고"가 하나가 아니라 "조건에 맞는 최선"이 여럿입니다.

🗂️ 이름을 범주로 잡는다

범주예시큰 그림
UI 라이브러리·프레임워크React·Vue·Svelte·Angular·Solid·Qwik화면 조각·상태·렌더링 규칙
메타프레임워크Next.js·Nuxt·SvelteKit라우팅·서버 렌더링·빌드·배포까지 묶음
주변 생태계라우터·상태관리·UI·테스트실제 프로젝트에서 함께 선택
React(UI 라이브러리) → Next.js(React 기반 메타프레임워크)Vite는 이들의 대안이 아니라 개발·빌드 도구
  • 각 문서가 스스로를 어떻게 부르나 — React "UI를 렌더링하는 라이브러리", Vue "점진적으로 도입", Angular "라우팅·폼 묶음이 강함", Svelte "컴파일러로 브라우저 부담 줄임", Solid "반응형 성능", Qwik "서버 상태 이어받기". 이름마다 푸는 관점이 다르다
React만 쓸 때는 라우팅·데이터·배포를 더 직접 조합하고, Next.js는 그 선택 일부를 기본 흐름으로 묶어 줍니다.

🤖 문법은 AI가 짠다 — 그래서 '무엇을 고르냐'가 더 중요

"상품 목록 컴포넌트 만들어 줘"면 AI가 그 프레임워크 문법으로 써 준다 — 문법은 외울 필요 없다. 그런데 "아무거나 골라도 되겠네?"는 오해 — AI가 프레임워크마다 코드를 짜는 정확도가 실제로 다르다.

근거내용
① 자료 많은 것을 더 정확히DesignBench에서 React·Vue는 컴파일 성공률 0.83+, Angular는 0.69~0.76. AI 벤치마크가 React를 기준으로 자주 고르는 것도 "학습 데이터에 많아서"
② 규칙이 일관될수록 일관되게"정석"이 강한 프레임워크는 매번 비슷한 구조. 자유도가 아주 높으면 부를 때마다 달라져 검토·수정이 는다
🔬 직접 확인 — 후보가 정해졌으면 AI에게 같은 요청을 세 번 시켜 보라. 세 번 다 비슷하면 궁합이 좋은 것, 매번 딴판이면 나중에 고치기 어렵다.
공개 자료가 많은 프레임워크일수록 AI의 첫 코드가 정확합니다. 📚 DesignBench, arXiv:2506.06251, 2025.

📊 "가장 많이 쓴다 ≠ 가장 좋다"

지표값
프론트엔드 사용률 (Stack Overflow 2025, 4.9만 명)React 44.7% (Angular 18.2·Vue 17.6), 메타 Next.js 21.5%
개발자 만족도 (State of JS 2024)Svelte ~74%, React 62%로 내려가는 중
많이 쓰는 것 ≠ 내 조건에 맞는 것사용자가 많다 = 자료·예제·AI 학습 데이터가 많다는 뜻이기도
정리 — 자료·AI 지원을 최우선이면 React 계열이 무난한 출발점, 코드 간결함·개발 경험을 중시하면 Svelte 같은 선택도 합리적. 정답 하나는 없고, 판단 축으로 내 조건에 맞춰 고른다.
어제 배운 그대로입니다 — 많이 쓰는 것과 내 조건에 맞는 것은 다릅니다.

실무 부서에서 오래 쓸 내부 도구면 장기 유지보수·생태계가 앞서고, 2주 안에 데모면 러닝커브·배포 자료가 앞섭니다.

"뭐가 좋아요?" 대신 AI와 PRD

인터뷰 → 추천 → PRD

④ 대화
좋은 개발은 "○○ 만들어 줘" 한 방으로 시작하지 않습니다. 무엇을 만들지 AI와 주고받으며 정하는 편이 훨씬 좋은 결과를 냅니다.

🗣️ 대화 세 단계

1AI에게 나를 인터뷰하게 — 한 번에 다 설명 말고, "정해야 할 것들을 한 번에 하나씩 물어봐 줘". 모르는 건 "네가 제안해 줘"라고 답해도
2프레임워크를 추천받기 — "이 서비스에 어떤 프레임워크가 좋을지 3개 이상 장단점과 함께". 나온 답은 '왜 이걸?', '내 조건에도 맞나?'로 되묻기
3PRD로 정리받기 — "지금까지 정한 내용을 PRD로. 추후 백엔드(로그인·저장·결제) 추가도 고려해서"
내가 만들고 싶은 건 [수제 디저트 온라인 가게]인데,
[선물 사는 사람이 편하게 고르도록] 하고 싶어.
구체적 PRD를 짜기 위해 정해야 할 것들을, 한 번에 하나씩 물어봐 줘.
되묻는 동안 흐릿하던 아이디어가 정리된다. 이 PRD가 오늘 과제의 뼈대이자, 나중에 백엔드를 붙일 때 길잡이.
AI가 "주 사용자는? 상품은 어떻게 분류? 결제까지 필요?"처럼 되묻습니다.

📚 지금 단계의 더 나은 공부법

문법을 파는 것보다
PRD와 개발 계획을 꼼꼼히 읽는 것
  • 코드가 무엇을, 왜 하려는지 위에서 내려다보는 눈이 생긴다
  • 그 눈이 있어야 AI가 만든 결과도 판단할 수 있다
나침반은 방향을 알려주지만 걸을지는 결정하지 않는다 — 후보·근거는 AI가, 최종 선택은 조건을 아는 사람이. PRD를 읽는 힘이 프레임워크 문법보다 오래 쓸모 있다.
다음 덱에서 이 PRD로 실제 화면을 만들 때, 백엔드 없이 시작하는 법(목업 데이터)을 봅니다.

✅ 정답 & 해설

A1. React(UI 라이브러리) → Next.js(React 기반 메타프레임워크, 라우팅·배포까지 묶음). Vite는 이들의 대안이 아니라 개발·빌드 도구.
A2. AI가 프레임워크마다 코드 정확도가 다르다 — 자료 많고 규칙 일관한 것을 더 정확·일관되게 짠다(DesignBench에서 Angular가 낮음).
A3. 사용률은 React 1위(44.7%)인데 만족도는 Svelte(~74%)가 위, React 62%로 하락 중.
A4. AI가 나를 인터뷰하게 — "정해야 할 것들을 한 번에 하나씩 물어봐 줘". 되묻는 동안 아이디어가 정리된다.
A5. AI와 함께 만든 PRD·개발 계획을 꼼꼼히 읽기 — 코드가 무엇을 왜 하는지 내려다보는 눈이 생겨 결과를 판단할 수 있다.
A2를 기억하면 "인기"만이 아니라 "AI 친화도"도 판단 축에 넣게 됩니다.

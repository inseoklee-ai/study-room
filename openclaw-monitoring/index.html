같은 화면의 숫자라도 하나는 돈이고 하나는 남은 양입니다

맡긴 일이 많아질수록 얼마나 쓰고 있는지를 보는 일이 중요해집니다. 새로 설치하는 것은 없습니다.

측정의 단위부터

  • 토큰은 모델이 글을 주고받는 양을 세는 단위입니다. 입력과 출력이 각각 세고, 비용은 이 양에서 계산됩니다
  • 세션 단위 숫자와 모아 둔 전체 요약은 다른 질문에 답합니다

/status — 상태 카드

/status
  • 상태 카드가 답으로 옵니다 — 세션 토큰과 추정 비용이 적히고
  • 인증 방식에 따라 현재 모델 제공사의 사용량 창 요약이 함께 보입니다
출처: docs/concepts/usage-tracking

/usage — 토글로 순환합니다

/usage
/usage tokens
/usage full
/usage cost
자리보여 주는 것
tokens입력과 출력을 한 줄로
full모델 · 추론 수준 · 빠른 처리와 느린 처리 · 컨텍스트 창 · 비용을 보여 줄 수 있는 만큼
cost세션 기록을 모아 계산한 로컬 비용 정리
  • 인수 없이 입력할 때마다 끄기 → 토큰 → 자세히의 순서로 순환합니다
  • 입력 토큰과 출력 토큰 중 어느 쪽이 큰지, 대화가 길어지면서 어느 쪽이 빨리 불어나는지가 다음 대화를 얼마나 이어 붙일지 판단하는 재료가 됩니다
컨텍스트 창에서 현재 세션이 쓴 분량과 최근 실행 사용량을 확인합니다. 출처: docs/concepts/usage-tracking

구독 창과 API 비용은 같은 숫자가 아닙니다

접속 경로와 숫자의 뜻은 함께 읽습니다

⑧ 모니터링
사용량 화면을 읽을 때 인증 경로에 따라 숫자의 뜻이 달라지는 것을 정리해 둡니다.

하나는 돈이고 하나는 남은 양입니다

인증 경로화면의 숫자누가 계산하나
API 키호출마다 계산한 추정 비용OpenClaw가 키를 갖고 있으므로 OpenClaw가 계산
구독 로그인남은 한도 비율 (제공사의 사용량 창 형태)제공사가 계산해 알려 줌
⚠️ 어느 경로로 접속했는지 모른 채 숫자만 보면 남은 비율을 남은 돈으로 잘못 읽을 수 있습니다 — 접속 경로와 숫자의 뜻은 함께 읽어야 합니다
  • 온보딩에서 두 경로를 고르며 열쇠를 누가 갖고 있느냐가 차이라는 점을 보았습니다 — 그 차이는 사용량 화면에도 그대로 나타납니다
출처: docs/concepts/usage-tracking

목적과 개인정보 경계가 다른 세 가지

구분내용주의
내 사용량 관찰/status · /usage · CLI 표—
문제 분석 자료진단 번들 — 로컬에서 압축 파일 하나로 상태와 로그를 모아 줌개인정보를 가려 주더라도 로그 요약이 들어 있으므로 함부로 나누지 않고 비밀 자료처럼
제품 개선 통계제품이 스스로 보내는 것은 하루 한 번 버전 확인이 전부기능 사용 통계는 동의하기 전까지 꺼져 있습니다
출처: docs/gateway/diagnostics, docs/gateway/telemetry

❓ 이해도 확인

Q1. 같은 사용량 화면의 숫자가 인증 경로에 따라 어떻게 달라지나?
A1. API 키는 추정 비용(돈), 구독 로그인은 남은 한도 비율(남은 양). 남은 비율을 남은 돈으로 읽으면 안 된다.
Q2. /usage full이 보여 주는 것은?
A2. 모델 · 추론 수준 · 빠른/느린 처리 · 컨텍스트 창 · 비용을 보여 줄 수 있는 만큼.
Q3. 진단 번들을 다룰 때 주의점은?
A3. 개인정보를 가려 주더라도 로그 요약이 들어 있으므로 비밀 자료처럼 다룬다.
Q1이 이 소단원의 핵심 구분입니다.

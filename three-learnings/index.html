1

회귀 · 가장 작은 학습

weight 하나, bias 하나로 규칙을 스스로 찾게

카페 매출 예측 · torch
작은 카페의 30일치 (방문객, 매출) 기록만 있고 정확한 식은 모릅니다. 이 관계식을 데이터만 보고 모델이 찾게 합니다.

🔧 torch, 두 개념만

텐서 (tensor)

앞서 본 그 숫자 배열. 같은 코드가 CPU·GPU 어디서든 도는 게 장점 — 데이터를 어느 장치에 올리느냐만 바꾸면 된다.

autograd (자동 미분)

loss.backward() 한 줄이면 "각 파라미터가 오차에 얼마나 기여했나"(기울기)를 알아서 계산 — 역전파를 torch가 대신 밟아 준다.

할 일은 넷 — ① 숨은 직선 규칙의 데이터를 만든다 → ② 눈으로 본다 → ③ 규칙을 안 알려 준 채 스스로 찾게(예측·오차·조정) → ④ 찾은 규칙과 줄어든 오차를 그래프로 확인.
숨은 규칙은 매출 = 2×방문객 + 1 (+ 날마다 다른 잡음). 모델은 이 '2'와 '1'을 모른 채 출발해 데이터만으로 찾아냅니다.

💻 학습 루프 — 예측·오차·조정

w = torch.zeros(1, 1, requires_grad=True)   # 엉뚱한 값(0)에서 출발
b = torch.zeros(1,    requires_grad=True)

def model(x): return x @ w + b              # 예측 매출 = w*방문객 + b

lr = 0.03
for step in range(600):
    pred = model(x)                          # ① 예측
    loss = ((pred - y) ** 2).mean()          # ② 오차 (평균제곱오차 MSE)
    loss.backward()                          # autograd가 기울기 계산 (역전파)
    with torch.no_grad():                    # ③ 조정 (경사하강)
        w -= lr * w.grad;  b -= lr * b.grad  #   기울기 반대 방향으로 한 걸음
        w.grad.zero_();    b.grad.zero_()

# 학습된 규칙:  매출 = 2.07 * 방문객 + 0.79   (숨은 정답: 2.00, 1.00)
아무도 규칙을 안 알려 줬는데 30일치 데이터만으로 2.07·0.79를 찾아냈다 — 숨은 정답(2,1)에 가깝다. 이것이 "데이터로 학습한다"의 전부.
lr(학습률)은 한 걸음의 크기입니다. 실무에선 이 루프를 torch.nn.Linear·optim.SGD로 짧게 줄이지만, 경사하강이 실제로 뭘 하는지 보려 손으로 폈습니다.

📉 결과 — 직선이 점 한가운데로

왼쪽 그래프빨간 학습 직선이
흩어진 점 한가운데를 통과
오른쪽 그래프오차(loss)가 급락했다가
평평해진다
  • 기울기 ≈ 2.07 = "방문객 100명 늘면 매출 약 207만원 증가"
  • 절편 ≈ 0.8 = 방문객 0명에도 잡히는 기본 매출(배달·포장 등). 절편이 더 흔들리는 건 데이터 중심에서 먼 지점이라 잡음에 민감해서
거대 언어 모델도 방식은 똑같다다른 건 규모뿐 — 파라미터가 2개가 아니라 수십억~수천억, 예측이 숫자 하나가 아니라 다음 토큰의 확률분포
이 작은 학습을 웹 전체 규모로 돌린 것이 모델의 사전학습(pretraining)입니다.
2

분류 · softmax와 MNIST

"어느 쪽인가"를 확률로 고른다

손글씨 0~9 · 후보별 확률
카페는 연속된 숫자(매출)를 맞히는 회귀였습니다. 세상 많은 문제는 "어느 쪽인가"를 고르는 분류 — 손글씨가 0~9 중 무엇인지, 메일이 스팸인지.

🎲 분류의 출력 = 후보별 확률

분류에서 모델은 "정답 하나"가 아니라 후보마다 확률을 낸다 — "3일 확률 88%, 8일 9%…". 여러 점수를 모두 0~1이고 합이 1인 확률로 바꾸는 장치가 softmax.

로짓(raw 점수):     [2.0,  1.0,  0.1]
① exp 적용:         [7.39, 2.72, 1.11]   # 모두 양수로, 차이는 더 벌려
② 합(11.2)으로 나눔: [0.66, 0.24, 0.10]   # 합 = 1
가장 큰 로짓이 가장 큰 확률(0.66)이 되고 작은 점수에도 확률이 남는다. 이 값이 곧 "얼마나 확신하는가" → "확률 낮으면 사람에게 넘긴다" 같은 판단 기준을 세울 수 있다. (soft+max: 나머지에도 확률을 조금 남겨 부드럽게 고름)
흥미롭게도 언어모델이 "다음 토큰"을 고를 때 쓰는 것과 똑같은 장치입니다 — 후보 수만 개에 확률을 매겨 고를 뿐 원리는 같습니다.

🧑‍💻 코딩 에이전트에게 시켜 보기 — MNIST

이번엔 코드를 외우지 않고 에이전트에게 프롬프트로 시키고 결과를 관찰합니다. MNIST = 손글씨 0~9 7만 장, 기계학습의 "Hello World".

PyTorch로 MNIST 손글씨 숫자(0~9) 분류기를 만들어 주세요.
1. 데이터를 학습용/시험용으로 나눕니다.
2. 간단한 신경망 학습. 손실은 CrossEntropyLoss, softmax는
   예측을 보여줄 때만 적용(출력층 softmax + CrossEntropy 이중적용 금지).
3. 시험 정확도 + 이미지 1장의 10개 클래스 softmax 확률을 보여 주세요.
4. 그런 다음, 학습 데이터를 10%만 써서 다시 학습해 정확도를 비교해 주세요.
CPU에서도 몇 분 안에 끝나도록 가볍게.
관찰 체크리스트 — softmax 10개 합이 1인가? 정답 확률이 최고인가? 전체 정확도는? 데이터를 10%로 줄이면?
여러분의 역할은 코드를 외우는 게 아니라 "무엇을 시키고 무엇을 확인할지" 아는 것입니다.

📊 결과 — 데이터가 가른다

[예측 예시]  실제 정답 7 · 모델 예측 7
  숫자 7:  99.91%  ###################   (나머지는 거의 0%)

[정확도 비교]
  전체 데이터(60,000장) : 97.06%
  10% 데이터(6,000장)   : 91.51%
  차이                  : 5.55%p
10%로 줄이니 정확도가 떨어졌다모델이 나빠서가 아니라 볼 예시가 줄었기 때문 — 오늘의 핵심
softmax 확률 10개를 더하면 1이 되고, 정답(7)에 99.91%가 몰렸다 — 이 확률이 곧 "확신 정도".
손실 함수는 CrossEntropyLoss가 내부에서 log-softmax를 처리하므로 출력층엔 softmax를 얹지 않고 로짓을 그대로 넣습니다. softmax는 예측을 보여줄 때만.
3

파인튜닝 · 남이 배운 것을 물려받기

앞쪽 '보는 눈'은 그대로, 마지막 판단만 새로

전이학습 · ResNet18
MNIST는 밑바닥부터 배워도 금방이지만, 개/고양이는 "귀·털·눈·질감" 같은 복잡한 시각 특징이 필요해 밑바닥 학습엔 엄청난 사진·계산이 듭니다. 우리에겐 몇백 장뿐일 수도.

← 물려받는 부분(보편적, 얼려 둠) ────────────── 새로 배움 →
  • 수백만 장으로 미리 학습된 ResNet18(층 18개)은 이미 "선·모서리·질감·형태"를 보는 눈을 가졌다
  • 그 눈은 그대로 두고 마지막 판단 부분만 내 문제(개/고양이)에 맞게 조금 더 학습 = 파인튜닝(전이학습)
  • '선·모서리 보는 눈'은 개든 고양이든 자동차든 똑같이 쓸모 → 앞쪽 층을 얼려(freeze) 데이터·계산을 아낀다
적은 데이터로도 잘 되는 이유 = 사전학습된 특징을 재사용하기 때문. 카페의 "예측→오차→조정"을 이미 똑똑한 모델 위 마지막 부분만 다시 도는 셈.
신경망은 층을 지날수록 점점 복잡한 것을 봅니다 — 앞쪽은 보편 패턴, 뒤쪽은 구체적 형태.

🐕 코딩 에이전트에게 시켜 보기 — 파인튜닝

torchvision 사전학습 ResNet18을 개 vs 고양이로 파인튜닝해 주세요.
1. 인증 없이 받아지는 소규모 공개 데이터(예: OxfordIIITPet 고양이/개 라벨).
2. 사전학습 가중치 로드 후, 마지막 분류 층만 2개(개/고양이)로 바꿔 학습.
3. 시험 정확도 출력.
4. 비교로, 사전학습 없이(랜덤) 밑바닥부터 학습한 정확도도 함께.
GPU 있으면 쓰고, 데이터는 일부만 써서 빨리.
관찰 — 사전학습 vs 밑바닥, 정확도 차이가 얼마나? (특히 데이터가 적을수록 사전학습 쪽이 크게 앞선다) · 학습 시간이 카페·MNIST보다 얼마나 길어졌나?
같은 데이터·에폭에서도 사전학습 쪽이 크게 앞선다 = 전이학습의 효과이 실습은 GPU 없이 노트북이면 매우 느리거나 멈춘다 — 왜인지는 다음 덱에서
앞쪽 층의 '보는 눈'을 공짜로 물려받으니, 마지막 판단 층만 적은 데이터로 맞춰도 잘 됩니다.

📌 이것만은 꼭 — 핵심 5문장

1회귀는 연속값(매출)을 예측 — weight·bias 2개도 데이터만으로 숨은 규칙을 찾는다.
2분류는 "어느 쪽인가"를 softmax 확률(합=1)로 고르고, 그 값이 곧 확신 정도.
3파인튜닝은 사전학습된 '보는 눈'을 물려받아 마지막 판단만 새로 — 적은 데이터로도 잘 된다.
4셋 다 방식은 같은 예측→오차→조정. 다른 건 무엇을 예측하느냐와 규모뿐(LLM도 마찬가지).
5MNIST 10%↓ 정확도↓, 사전학습↑ 정확도↑ — 모델보다 데이터가 결과를 가른다.
5번이 강의 1 전체의 결론이고, 다음 덱에서 규모·비용의 현실로 이어집니다.

🎯 이해도 확인 질문

Q1. 카페 회귀에서 모델이 찾은 2.07·0.79는 각각 무슨 뜻인가?
Q2. 회귀와 분류의 차이는? 분류의 출력은 무엇인가?
Q3. softmax는 무슨 일을 하며, 그 확률값을 어떻게 판단에 쓰나?
Q4. MNIST 데이터를 10%로 줄이니 정확도가 떨어진 이유는?
Q5. 파인튜닝이 적은 데이터로도 잘 되는 이유는? 무엇을 물려받나?
Q4·Q5가 오늘의 핵심입니다 — 데이터 양의 효과와 전이의 원리.

✅ 정답 & 해설

A1. 기울기 2.07 = 방문객 100명↑당 매출 약 207만원↑, 절편 0.79 = 방문객 0명에도 잡히는 기본 매출(배달·포장 등).
A2. 회귀는 연속된 값(매출)을, 분류는 어느 범주인지를 예측. 분류의 출력은 정답 하나가 아니라 후보별 확률.
A3. 여러 점수를 합이 1인 확률로 바꾼다. 확률값이 확신 정도라, "낮으면 사람에게 넘긴다" 같은 기준을 세울 수 있다.
A4. 모델이 나빠서가 아니라 볼 예시(데이터)가 줄어서. 97.06% → 91.51%로 5.55%p 하락.
A5. 수백만 장으로 학습된 '선·모서리·질감을 보는 눈'(앞쪽 층)을 물려받고 마지막 판단 층만 새로 배우기 때문. = 전이학습.
A4·A5를 자기 업무 데이터로 상상해 보면 "데이터가 전부"라는 결론이 손에 잡힙니다.

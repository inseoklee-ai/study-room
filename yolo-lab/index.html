Ultralytics YOLO — 무엇을 가져다 쓰나

세 작업, 세 head, 세 자료형

사전학습 추론
Ultralytics 패키지는 입력·가중치 다운로드·추론·결과 객체·시각화·내보내기를 하나의 인터페이스로 묶습니다. YOLO("...pt")로 불러와 predict를 실행합니다.

🧩 같은 패키지, 다른 head

작업head가 내는 결과화면어울리는 질문
Detection클래스·박스·점수사각형무엇이 어디에 몇 개인가
Instance seg박스 + 개체별 마스크대상 윤곽각 대상이 어디까지인가
Pose사람 박스 + 관절 keypoint점·연결선신체 부위가 어떤 자세인가
세 모델은 COCO 같은 공개 데이터의 범용 클래스·사람 관절을 미리 학습한 가중치 — 공장 결함·특수 부품·회사만의 자세 기준을 자동으로 알지는 못함.
같은 YOLO 패키지를 호출해도 가중치·head·학습 라벨·출력 자료형이 다릅니다.

⚖️ 라이선스와 고정된 입력 조건

Ultralytics는 AGPL-3.0 + Enterprise 이중 라이선스. 수업용 로컬 체험을 넘어 조직의 비공개 제품·서비스에 포함하려면 배포 형태와 라이선스 조건을 먼저 검토.

입력

input/bus.jpg — 사람 여러 명 + 버스처럼 큰 윤곽. Ultralytics 공개 예제의 수업용 사본(출처·해시 기록)

공통 조건

같은 bus.jpg · imgsz 640 · conf 0.25 · device CPU · 학습·미세조정·내보내기 안 함

🔑 공통 조건을 맞춰도 작업별 head와 학습 목표가 달라 출력은 달라집니다.
도구를 가져다 쓰는 편리함과 사용 권리는 별개 문제입니다.

세 작업을 한 번에 실행하고 읽기

정규화 JSON + 시각화, 둘 다 저장

자료형으로 읽기
한 작업이 실패해도 나머지는 실행합니다. 시각화와 원시 결과를 모두 저장합니다.

🤖 세 작업을 한 번에 맡기기

input/bus.jpg에 준비된 사전학습 모델 세 개를 실행.
환경은 uv만(pip·conda·전역 금지), 없으면 다운로드 말고 오류 기록.
모델: yolo26n.pt(detect) · yolo26n-seg.pt(segment) · yolo26n-pose.pt(pose)
공통: device=cpu, imgsz=640, conf=0.25 · train/fine-tune/export 안 함 · ultralytics 버전 기록

정규화 JSON:
{ "task":"detect|segment|pose", "model":"...", "image_size":640,
  "confidence_threshold":0.25,
  "items":[{ "class_id":0, "class_name":"person", "confidence":0.91,
    "bbox_xyxy_pixels":[x1,y1,x2,y2],
    "polygon_xy_pixels":null, "keypoints_xyc_pixels":null }] }
segment는 polygon을, pose는 keypoints를 채우고 나머지는 null.

저장: outputs/yolo/{detect,segment,pose}/result.jpg + raw.json
     summary.json(작업별 검출 수·클래스별 수·평균 신뢰도)
     run_manifest.json(입력·가중치 SHA-256, 모델명, 버전, imgsz·conf·device, 시간, 네트워크 여부)
한 작업이 실패해도 나머지는 실행. 실패는 failure_log.md에.
🔑 채팅의 "완료"가 통과선이 아님 — raw.json과 시각화 이미지를 직접 열어 확인.
정규화 JSON 스키마를 미리 정해 두면 세 작업의 결과를 같은 형식으로 비교하고 다음 코드에 바로 넘길 수 있습니다.

📦 결과 객체를 자료형으로 읽기

Detection
class + confidence + [x1,y1,x2,y2]
Segmentation
박스 + 다각형/마스크 정보
Pose
사람별 박스 + 관절점 x,y (+가시성·점수)
🔑 시각화가 그럴듯해도 원시 결과가 없으면 다음 코드에서 쓸 수 없고, 원시 배열만 있고 그림이 없으면 사람이 빠르게 검수하기 어렵습니다. 그래서 둘 다 저장합니다.
자료형이 다르면 다음 단계 코드도 다릅니다 — 좌표 4개, 다각형, 관절점 배열은 각각 다르게 다뤄야 합니다.

앱과 임계값, 서로 대신 못 하는 세 작업

임계값 민감도 관찰(교차검증 아님)

Gradio
세 실행 함수를 재사용해 Gradio 앱을 만들고, 같은 사진에서 임계값을 바꿔 결과 수 변화를 관찰합니다.

🎚️ 임계값 손잡이를 붙인 작은 앱

세 YOLO 실행 함수를 재사용해 Gradio 앱. models/yolo 세 파일만, 없으면 다운로드 X.
- 이미지 업로드 · Detect/Segment/Pose 탭 · confidence 슬라이더 0.05~0.90 · 실행 버튼
- 결과 이미지·객체 수 · 원시 JSON 다운로드 · 모델명·버전·imgsz·conf 표시
- 오류 시 빈 성공 화면 대신 오류 메시지
apps/yolo/app.py, .venv-day15-yolo/bin/python apps/yolo/app.py로 실행.
임계값 0.15·0.25·0.60으로 바꿔 결과 수 변화를 기록 — 정답 라벨 없이 어느 값이 더 정확하다고 단정하지 않음. 교차 검증이 아니라 임계값 민감도 관찰.
실패로 대체 결과를 쓰면 fallback/outputs/yolo/thresholds의 0.15·0.25·0.60 폴더를 읽는 읽기 전용 모드(업로드·임의 임계값 비활성, fallback_used=true 표시).
Gradio는 입력·출력 컴포넌트를 미리 갖춘 오픈소스 UI 도구로, 화면을 처음부터 만들지 않고 결과 연결에 집중하게 해 줍니다.

🚫 세 작업은 서로 대신할 수 없습니다

관찰이유
Detection 박스가 몸 주변 배경까지 포함박스 좌표를 맞히도록 학습했기 때문
Segmentation이 사람·버스 윤곽을 각각 칠함개체별 마스크 손실과 head가 있기 때문
Pose가 버스에는 관절점을 안 만듦기본 pose 가중치의 keypoint 정의가 사람 몸 대상이기 때문
🔑 "YOLO가 이미지를 이해한다"는 한 문장으로 세 결과를 뭉치지 마세요. 같은 패키지를 호출했어도 가중치·head·학습 라벨·출력 자료형이 다릅니다.
박스로는 넓이를, 마스크로는 개수 세기를, 포즈로는 자세를 각각의 방식대로만 답할 수 있습니다.

학습·실패·사용 책임

가져다 쓴 모델의 책임도 결과로 남긴다

사전학습 추론의 경계
오늘 사용한 것은 사전학습 추론입니다. 이미 COCO로 학습된 가중치를 새 사진에 적용했습니다.

🎓 학습은 어디에 끼어드나

방식언제 생각하나필요한 것
사전학습 추론기존 클래스·출력이 업무에 맞음입력과 실행 환경
Fine-tuning같은 실패 반복 + 회사 고유 대상권리 확인 이미지·일관 라벨·train/val 분리
From scratch기존 시각 특징까지 안 맞는 특수 영역매우 많은 데이터·연산·전문성
YOLO 학습엔 이미지·라벨뿐 아니라 data.yaml(학습·검증 경로, 클래스 이름)이 필요. Detection=박스, segment=다각형, pose=keypoint 라벨이라 작업을 바꾸면 라벨 비용도 바뀜. 이번 실습에선 학습을 실행하지 않고 판단 기준만 소개.
사전학습 클래스에 없는 대상을 계속 놓치면 권리가 확인된 이미지·라벨을 모아 fine-tuning을 검토할 수 있습니다.

🧯 실패를 결과로 남깁니다

  • 로컬 가중치 없음 → 다운로드·모델 전환 없이 오류 기록 · CUDA·MPS 오류 → CPU 고정
  • Pose 0건 → 모델을 조용히 바꾸지 말고 입력·임계값 기록 · 마스크 이상 → 탐지 박스와 나란히 저장해 어느 head 차이인지
  • 세 모델 실행 불가/앱 안 열림 → fallback/outputs/yolo/thresholds 읽기 전용 모드로 전환
🔑 모든 실패는 failure_log.md에, 대체 사용 시 fallback_used=true. 통과 = 직접 추론 모드와 읽기 전용 fallback 모드 중 하나가 실행되면 됨. 설치 성공보다 중요한 건 실패 지점을 재현 가능하게 남기는 것.
대체 결과 사용은 실패가 아닙니다. 숨기거나 조용히 다른 모델로 바꾸는 것이 문제입니다.

🪪 가져다 쓴 모델의 사용 책임도 결과

학교 출입 안전 · 체육 자세 분석 · 분리수거 품목 탐지 · 과학실 안전 장비 중 하나를 고르고, 답은 사람이 정합니다.

▼ 빈 양식 프롬프트 (use_case_card.md)
아래 항목의 빈 양식만 만들어 줘. 내 답을 추정하거나 대신 채우지 않는다.

- 사람이 검토하고 이의를 제기할 통로
실험으로 판단할 수 없는 항목은 미확인으로 남긴다.
🔑 버스 예제의 결과가 잘 나온 것과, 실제 사람을 촬영·판정해도 된다는 것은 전혀 다른 결론. 이 카드는 Joseph Redmon의 문제 제기를 실습의 선택 기준으로 되돌리는 장치.
도구를 잘 실행하는 것과 그 도구를 사람에게 써도 되는지는 분리해서 판단해야 합니다.

📤 사진 실습 제출물

  • detection·segmentation·pose 결과 이미지 각 1장 + 작업별 원시 JSON + summary.json
  • 모델명·버전·입력 해시·실행시간이 든 manifest · 임계값 3개에서 관찰한 변화
  • 직접 추론 또는 읽기 전용 fallback으로 실행되는 apps/yolo/app.py · use_case_card.md
  • 세 작업 중 업무 하나를 골라 "왜 이 자료형이 필요한가"를 두 문장으로
필수 제출 뒤 시간이 남으면 옆 사람 앱에 처음 보는 사진 한 장을 넣고 — 보기 좋은 결과보다 처음 드러난 실패 하나를 발표.
이 실습으로 단원 4(AI는 문서와 사진에서 무엇을 꺼낼까)의 문서·사진 두 실습이 모두 끝납니다.

📌 이것만은 꼭 — 핵심 6문장

1같은 사진·같은 패키지라도 세 head(det·seg·pose)는 세 자료형을 낸다
2공통 조건(사진·imgsz·conf·CPU)을 맞춰도 head·학습 목표가 달라 출력이 다름
3시각화 + 원시 JSON 둘 다 저장 — 그림은 검수용, 원시는 다음 코드용
4임계값 0.15·0.25·0.60은 민감도 관찰(정답 없이 교차검증 아님)
5세 작업은 서로 대신 못 함 — "YOLO가 이해한다"로 뭉치지 말 것
6가져다 쓴 모델의 사용 책임(use_case_card)도 결과 — 잘 돈다 ≠ 사람에게 써도 된다
사전학습 추론의 편리함과, 그것을 실제 사람에게 적용할 책임은 분리해서 남깁니다.

✅ 정답 & 해설

A1. 같은 사진에서 세 자료형을 만들어 차이를 확인. Detection=클래스·박스·점수, Segmentation=개체별 마스크(윤곽), Pose=사람 관절 keypoint.
A2. 작업별 head와 학습 목표가 다르기 때문. 같은 입력이라도 박스·마스크·관절점은 서로 다른 손실로 학습됐다.
A3. 시각화는 사람 검수용, 원시 JSON은 다음 코드용. 그림만 있으면 파이프라인에 못 쓰고, 배열만 있으면 빠른 검수가 어렵다.

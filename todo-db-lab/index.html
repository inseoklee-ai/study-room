에이전트로 '내 Todo 앱'을
내 컴퓨터에 만들기

따라 하기 — 목표(PRD)를 주면 에이전트가 만들고, 나는 검토·판단·수정한다

이제 배운 걸 모아 직접 만들어 봅니다. 만들 것은 내 컴퓨터에서 도는 작은 Todo(할 일) 앱입니다. 할 일을 추가·확인·완료·삭제하고, 그 데이터가 내 컴퓨터의 무료 DB에 저장돼 껐다 켜도 남습니다.

왜 Todo 앱인가 — CRUD의 교과서

C추가
→
R목록 보기
→
U완료 표시
→
D삭제
  • Todo 앱은 저장·조회·수정·삭제(CRUD)의 교과서라 DB를 손에 익히기에 딱입니다
  • 방식은 에이전틱 — 목표(PRD)를 주면 에이전트가 계획·설치·구현을 하고, 우리는 검토·판단·수정합니다

길 A — 내 컴퓨터(로컬)

무료 로컬 DB(예: SQLite)에 저장. 인터넷 없이 내 PC에서 완결

길 B — 클라우드(Supabase)

같은 앱을 클라우드 DB로. 남에게 링크로 보여줄 때

두 가지 길을 다 해 봅니다(원하는 쪽부터). 도구는 Claude Code나 Cursor의 에이전트 모드처럼 명령 실행·파일 생성·설치를 스스로 하는 것을 씁니다. AI가 짠 코드는 한 번씩 훑어보세요.
1

PRD로 시작하고, DB 구조를 설계받기

만들 것 한 장 → 구조도

⑦ 실습
앞서 배운 대로 PRD부터 씁니다. 코드보다 먼저 '무엇을'입니다.

PRD — 기본 기능 + 내가 넣고 싶은 기능

[무엇] 내 컴퓨터에서 도는 Todo(할 일) 앱.
[기본 기능(CRUD)] 할 일 추가 / 목록 보기 / 완료 표시 / 삭제
[저장] 데이터는 내 컴퓨터의 무료 DB에 저장(껐다 켜도 남기)
[내가 넣고 싶은 기능]   <- 여기에 1~2개 직접 적기
   예: 마감일 표시 / 카테고리(태그) / 오늘 할 일만 보기 / 검색
[규칙] 무료 도구만. 비밀값은 .env로.
       (로그인 같은 걸 넣는다면 직접 만들지 말고 검증된 라이브러리로.)
✍️ '내가 넣고 싶은 기능' 한두 개를 꼭 적으세요 — 그게 남의 튜토리얼과 내 프로젝트를 가릅니다
규칙 줄의 "로그인은 직접 만들지 말고"는 소단원 ④의 결론이 그대로 실습 규칙이 된 것입니다.

코드보다 DB 구조부터 받습니다

"위 PRD로 만들 Todo 앱의 DB 구조(어떤 표·열·관계)를 먼저 설계해서
 구조도로 그려 보여 줘. 내 커스텀 기능(마감일·태그 등)도 반영해서.
 로컬 무료 DB(예: SQLite)를 쓸 거야."
✔확인 — AI가 표(예: todos, 태그를 넣었다면 tags와 연결표)와 열(제목·완료여부·마감일…)을 구조도로 보여 준다
✔앞서 배운 표 사이 관계대로 잡혔는지 눈으로 확인한다
  • 예시 — 할 일(todos)과 태그(tags)는 연결표(todo_tags)로 이어집니다(다대다)
  • 소단원 ③에서 배운 N:M → 연결 표가 여기서 실제로 나옵니다
학생 ↔ 수업 예시로 배운 N:M이 태그에서 그대로 반복됩니다. 구조도를 받았을 때 "왜 표가 세 개인가"를 스스로 설명할 수 있으면 소단원 ③을 이해한 것입니다.
2

길 A — 내 컴퓨터에 만들어 돌리기 (로컬)

SQLite 파일 하나 · localhost

⑦ 실습
DB 구조에 합의했으면 실제 구현을 맡깁니다.

작업 지시서 — 이대로 붙여 넣으세요

"이 PRD와 방금 합의한 DB 구조로 Todo 앱을 만들어 줘.
 데이터는 로컬 SQLite 파일 하나(todo.db)에 저장하고,
 브라우저에서 localhost로 열리게 해 줘.
 .env · todo.db 는 .gitignore 에 넣어.
 먼저 전체 계획을 보여주고, 각 단계 끝에 뭘 확인하면 되는지 알려 줘."
1계획 한 번 읽기 — PRD와 맞는지
2위험한 명령은 승인 — 이 프로젝트 폴더 안인지 확인
3잘 되던 순간마다 Git 커밋 — 되돌릴 지점을 남긴다
에이전트가 계획→설치→파일 생성→DB 만들기까지 스스로 합니다. 우리가 할 일은 이 셋뿐입니다.

통과 기준 — 새로고침해도 남는가

✅ 브라우저에서 할 일을 추가하면 목록에 뜨고, 새로고침·앱 재시작 후에도 남는다
  • DB 뷰어로 todo.db를 열어 todos 표에 행이 실제로 쌓였는지 확인
  • 확인 툴은 AI에게 추천받기 — SQLite는 'DB Browser for SQLite'나 VS Code의 SQLite 확장

화면에서 보이는 것

제목 My Todo, 입력창과 추가 버튼, 마감일이 붙은 할 일 목록

실제로 남는 곳

내 컴퓨터의 todo.db 파일 — 껐다 켜도 남는다

소단원 ①의 판단 한 줄("새로고침해도 남아야 하는 데이터인가")이 여기서 통과 기준이 됩니다. 화면만 보고 넘어가지 말고 DB 뷰어로 행을 직접 보는 게 중요합니다.

자주 막히는 곳 — 증상과 확인

증상확인 / 해결
npm install에서 better-sqlite3 빌드 에러(node-gyp)네이티브 모듈이라 빌드 도구가 필요. 에러를 그대로 에이전트에 주고 "내 OS(맥/윈도우) 기준 빌드 도구를 설치·확인해 줘" (맥: Xcode Command Line Tools, 윈도우: 빌드 툴·Python). Node는 LTS 권장
포트가 already in use(EADDRINUSE)이전 서버가 아직 떠 있음. 그 창을 끄거나 다른 포트로
추가했는데 새로고침하면 사라짐화면에만 있고 DB엔 안 들어감. "추가한 할 일을 DB에 저장하고 다시 읽어오게 해 줘"
코드 고쳤는데 반영 안 됨개발 서버를 껐다 켜기 (특히 .env 수정 후)
todo.db를 GitHub에 올려버림.gitignore에 추가. 이미 커밋했다면 에이전트에게 'git 이력에서도 빼 줘'까지
세 번째 증상이 이 강의의 핵심 오해입니다 — 화면에 보이는 것과 저장된 것은 다릅니다.

안 되면 — 에러를 그대로 붙여넣기

1에러 메시지를 그대로 에이전트에게 붙여넣어 고치게 한다 (관찰 → 수정 반복)
2같은 걸 계속 못 고치면 마지막으로 되던 지점으로 되돌리고(그래서 커밋을 남겼습니다)
3문제를 잘게 쪼개 다시 시킨다
🧭 에이전트와 일할 때의 규율 — 되돌릴 지점을 남기고, 한 번에 한 가지만 고친다
바이브 코딩 루프에서 배운 관찰→수정 반복이 그대로 적용됩니다. 에러를 요약하지 말고 원문 그대로 주는 게 요령입니다.
3

길 B — 클라우드(Supabase)로도

그리고 RLS 꼭 켜기

⑦ 실습
같은 앱을 클라우드 DB로도 만들어 두면 나중에 남에게 링크로 보여줄 수 있습니다(로컬은 내 PC에서만 열리니까요).

같은 앱을 클라우드 Postgres로

"같은 Todo 앱을, 로컬 SQLite 대신 Supabase(무료 클라우드 Postgres)에
 저장하도록 바꿔 줘. 접속 키는 .env로 빼고,
 RLS(행 수준 보안)를 켜서 허용된 접근만 되게 해 줘."
  • 확인 — Supabase 대시보드의 Table Editor에서 todos 표에 행이 쌓이는지 눈으로
⚠️ RLS 꼭 켜기 — 안 켜면 공개 키로 누구나 데이터에 접근할 수 있습니다
RLS는 소단원 ⑤의 '접근을 제한하는 보안'이 클라우드 DB에서 구체화된 형태입니다. 무료 실습에서 가장 흔히 빠뜨리는 설정이라 반드시 짚어 주세요.

소단원 ⑥에서 예고한 흐름을 실습으로 완성했습니다.

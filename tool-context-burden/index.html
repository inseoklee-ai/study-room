모델 입력에 들어갈 수 있는 것

내용이번 실습의 예늘어나는 계기
시스템·프로젝트 지시에이전트의 작업 방식, 프로젝트 규칙지침이나 설정 추가
요청·대화 이력첫 주 기록 요청, 이전 질문과 답변대화를 이어 감
도구 정의get_weekly_records의 이름·설명·입력 규칙도구 추가 또는 상세 정의 로드
실행 결과조회된 주차 정보와 업무 기록 목록더 많은 자료를 가져옴
읽은 자료팀 보고 기준, 필요한 프로젝트 파일새 파일과 참조 자료를 읽음
📌 호스트가 이 모든 것을 항상 원문 그대로 전송하는 것은 아닙니다 — 필요한 항목을 고르거나, 오래된 내용을 요약하거나, 읽는 시점을 조절할 수 있습니다
학생의 요청은 한 문장이지만, 모델이 적절한 도구를 고르려면 기능이 있다는 사실과 사용법도 알아야 합니다. 호출이 끝난 뒤에는 실제 기록도 읽어야 합니다.

토큰과 문맥 창

  • 토큰은 모델이 문자열을 나눈 조각입니다 — 단어나 글자와 정확히 일치하지 않고, 한국어·영어·코드 기호가 어떻게 나뉘는지도 모델에 따라 다릅니다
  • 따라서 "한국어 한 글자는 한 토큰"처럼 바꾸어 계산하기보다 — 호스트가 표시하는 사용량을 읽는 편이 낫습니다
  • 문맥 창은 모델이 한 번에 다룰 수 있는 정보의 범위 — 화면의 69% used는 해당 환경이 표시한 사용 비율
⚠️ 이 수치가 AI의 지식 중 69%를 썼다거나 계정의 월간 이용량을 69% 사용했다는 뜻은 아닙니다
보고서를 작성할 때는
실제 업무 기록과 판단 기준을 충분히 읽을 공간이 필요합니다
그 공간을 아직 사용하지 않을 도구의 상세 설명이 많이 차지한다면, 어떤 정보를 먼저 제공할지 조정할 이유가 생깁니다.

같은 도구, 세 가지 정보

구분내용쓰이는 순간
도구 정의이름 get_weekly_records, 업무 기록을 읽음, week 문자열 입력모델이 기능을 선택하고 입력을 만들 때
호출 입력{"week":"week-one"}실행을 요청할 때
실행 결과첫 주의 팀 정보·보고 기준일·업무 기록 목록실제 기록을 받아 내용을 이해할 때
  • 도구 정의를 읽었다고 첫 주 업무를 읽은 것은 아닙니다. 반대로 첫 주 기록을 받았다면 그 내용은 더 이상 사용 안내가 아니라 보고서의 원자료입니다
  • MCP에서도 tools/list와 tools/call은 구분됩니다. 호스트가 목록을 받아 보관하는 단계와 그 상세 내용을 모델 문맥에 넣는 단계도 구분 — MCP가 모든 정의를 매번 한꺼번에 읽히도록 강제하는 것은 아닙니다
🎯 별개의 단계로 보기 — 서버 연결 → 도구 정의 발견·로드 → 도구 호출 → 결과 읽기. 연결할 기능을 유지하면서 모델이 읽는 상세 설명의 양은 줄일 수 있는 이유
스키마는 데이터가 어떤 모양이어야 하는지를 적은 규칙입니다. week: str는 자료형을 설명하고, 실제 Python 함수가 허용 주차인지 실행 중에 검사합니다.

실행 전 · 실행 후

⑤ 문맥 부담
아래 숫자는 원리를 설명하기 위한 가상 수치입니다. 캡처를 분석해 얻은 측정값은 아닙니다.

가상 수치로 보기

100개 도구 × 정의당 평균 500토큰 = 약 50,000토큰

검색을 위한 안내 1,000토큰 + 두 도구의 정의 1,000토큰
= 약 2,000토큰
  • 실제로 필요한 도구가 두 개라면 나머지 98개의 상세 사용법은 이번 작업에서 사용하지 않을 수 있습니다
  • 실제로는 설명의 길이, 검색에 쓰는 안내, 발견한 도구 수가 모두 달라집니다. 또 이 숫자에는 대화 이력이나 업무 기록의 실행 결과가 들어 있지 않습니다
⚠️ 다른 상황 — 찾은 도구의 설명은 아주 짧지만 실행하자 1년치 업무 기록이 수천 줄 반환됩니다. 상세 정의를 나중에 읽는 기능을 켜더라도 커진 실행 결과 자체가 작아지지는 않습니다
지금 필요한 것은 첫 주 기록인데 나머지 자료까지 모두 읽게 된 것입니다.

생기는 위치가 다릅니다

⏳ 실행 전의 부담

사용하지 않을 도구의 상세 설명이 많음 → 관련 정의만 필요한 시점에 읽는 방식

📦 실행 후의 부담

실제로 가져온 데이터가 너무 많음 → 조회 기간과 항목을 좁히거나 필요한 결과를 추려 전달

  • 우리 서버가 week를 받아 해당 주의 파일만 반환하는 것도 이 구분과 연결됩니다 — 현재 서버에 1년치 조회 기능이 있다는 뜻은 아닙니다
  • 실무 데이터로 확장할 때 "일단 전부 가져오자"보다 "이번 판단에 어떤 범위가 필요한가"를 먼저 정하면 읽어야 할 결과를 줄일 수 있습니다
📌 문맥 사용량이 줄어드는 것과 전체 작업의 비용·시간이 줄어드는 것도 따로 확인해야 합니다 — 검색 단계가 추가되면 모델을 한 번 더 호출할 수 있고, 재사용할 때는 캐시나 요금 방식이 영향을 줍니다
문맥 사용량은 한 시점에 다루는 정보량이고, 누적 사용 토큰은 여러 요청에서 사용한 양이 더해진 값입니다. 캡처의 시간이나 비용까지 문맥 숫자 하나로 설명하지 않습니다.

필요한 설명을 찾은 뒤 읽기

지연 로딩

⑤ 문맥 부담
지연 로딩(deferred loading)은 사용할 때까지 상세 내용을 불러오는 시점을 미루는 것입니다.

두 흐름

모든 상세 정의를 먼저 제공필요한 정의를 찾아 읽음
여러 도구의 상세 사용법을 모델에게 제공도구를 발견하는 데 필요한 안내를 제공
요청에 맞는 도구를 선택요청에 관련된 도구를 검색·발견
이미 읽은 사용법으로 호출 입력 작성필요한 도구의 상세 사용법을 확인
도구를 호출하고 결과를 읽음호출 입력을 작성하고 실행 결과를 읽음
🎯 이 도구 검색은 현재 사용할 수 있도록 연결된 기능 중에서 관련 도구를 찾는 과정입니다 — 인터넷에서 새 MCP 서버 저장소를 찾고 설치하는 검색과는 대상이 다릅니다
  • Anthropic의 Tool Search 설명도 검색 단계가 추가되므로 도구 수가 적을 때와 많을 때의 이점이 다를 수 있다고 설명합니다
  • 학생이 관찰할 것 — 발견한 기능 · 실제 호출 입력 · 반환된 기록. 검색 결과에 이름만 나타난 것을 기록 조회 성공으로 읽지 않습니다
도구는 연결되어 있고, 필요한 기능을 발견하면 그때 사용법을 자세히 읽습니다. 모든 기능을 없애거나 서버를 끄는 방식과는 다릅니다.

내 환경에서 확인할 단서

지금 연결된 MCP 도구가 어떻게 AI에게 알려지는지 확인해 줘.
실제로 확인한 내용과 추정은 구분해 줘.
  • 서로 다른 관찰 — "연결된 도구의 목록을 볼 수 있다", "이번 작업에서 검색 도구가 호출되었다", "업무 기록이 반환되었다"
  • AI가 정확한 토큰 수를 제시한다면 어디에서 확인한 값인지도 읽어 보세요 — 전체 모델 입력이나 서버별 사용량을 보여 주지 않는 환경에서는 직접 확인하기 어렵습니다
  • 검색 호출이 매 요청마다 보여야만 정상인 것은 아닙니다. 도구가 적으면 처음부터 제공될 수도 있고, 한 대화에서 이미 발견한 정의를 다시 쓸 수도 있습니다
  • 절감 효과를 보려고 필요 없는 서버를 잔뜩 설치할 필요도 없습니다
제공된 화면에서 다수 연결의 상황을 이해하고, 자신의 환경에서는 업무 기록 읽기가 어떤 경로를 거치는지 관찰합니다.

같은 "문맥이 크다" 뒤의 다른 원인

관찰한 상황먼저 살펴볼 곳
대화를 거의 하지 않았는데 많은 도구 설명이 제공됨필요한 도구 정의만 불러오는 기능
한 번의 조회에서 수천 줄의 원자료가 반환됨조회 범위와 반환할 항목
같은 대화에서 여러 작업을 오래 이어 감남아 있는 대화·파일·결과와 호스트의 문맥 관리
도구는 발견했는데 인증 만료 오류가 반환됨해당 서비스의 인증 상태와 서버 오류
비슷한 이름의 다른 기능을 호출함발견한 도구 설명과 실제 호출 입력
🎯 기록이 지나치게 많이 반환됐다면 검색 설정부터 바꾸기보다 요청한 기간과 반환된 기간이 맞는지 확인하는 편이 원인에 가깝습니다. 인증이 만료됐다면 도구 설명을 덜 읽게 해도 접근 권한은 복구되지 않습니다
어느 단계에서 문제가 생겼는지에 맞춰 방법을 고르는 것이 도구를 많이 연결한 환경을 다루는 출발점입니다.

Q1. 두 부담은 어디에서 생기나?
A1. 실행 전은 사용하지 않을 도구의 상세 설명, 실행 후는 가져온 데이터의 양. 지연 로딩은 앞의 문제만 다룬다.
Q2. 이 절의 도구 검색은 무엇을 찾는 것인가?
A2. 이미 연결된 기능 중에서 관련 도구를 찾는 것. 인터넷에서 새 서버를 찾아 설치하는 검색이 아니다.
Q3. 69% used가 뜻하지 않는 것은?
A3. AI 지식의 69%나 계정 월간 이용량의 69%가 아니다. 해당 환경이 표시한 문맥 창 사용 비율이다.

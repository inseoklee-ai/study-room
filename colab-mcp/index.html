Colab MCP 연결과 실행

문서에 적힌 코드와 실행 중인 상태를 구분합니다

"앞으로는 학습 시간 같은 기록도 모아서 평균을 보고 싶어요. 어떤 값을 계산했는지 다시 확인할 수 있게 남기면 좋겠어요."

한 문서에 네 가지를 남깁니다

①입력 데이터
②계산 코드
③실행 결과
④설명
  • 이 일을 할 수 있는 문서가 노트북(notebook). Colab은 브라우저에서 노트북을 작성하고 Python을 실행하는 환경
  • 셀(cell)은 한 칸 — 코드 셀과 텍스트 셀이 있고, 코드 셀을 실행하면 그 아래에 출력이 나타납니다. 따라서 "어떤 코드를 실행해서 이 숫자가 나왔는가"를 같은 자리에서 읽을 수 있습니다
  • 앞의 보고서 Skill은 팀의 판단 기준을 재사용하는 데, Colab은 계산을 실행하고 그 과정을 남기는 데 씁니다 — 보고서에 계산이 필요하면 둘을 함께
대화에 답만 남겨 두면 며칠 뒤 같은 계산을 확인하기가 번거롭습니다. 입력값을 찾고, 다시 요청하고, 처음과 같은 방식으로 계산했는지도 맞춰야 합니다.

문서와 실행 중인 상태

  • 브라우저에서 코드를 작성했다고 Python이 실행되고 있는 것은 아닙니다 — 런타임(runtime)이 필요합니다. 런타임은 Python을 실제로 실행하고, 실행 중 만든 변수와 설치한 라이브러리를 보관하는 환경
  • 예 — minutes = [20, 30, 40]이라 적으면 문서에 코드가 저장됩니다. 이 셀을 실행해야 런타임 안에 minutes라는 변수가 만들어집니다
  • 런타임이 새로 시작되면 노트북에 코드는 그대로 보여도 변수는 아직 없을 수 있습니다
문서에 적힌 코드와 실행 중인 상태를 구분하는 것이
노트북 사용의 출발점입니다
이 수업에서는 Colab이 제공하는 원격 실행 환경을 사용합니다. 오른쪽 Gemini 패널은 Colab에 포함된 별도의 AI 대화 화면이며, 이번 실습의 요청은 평소 사용하는 Claude Code·OpenCode에 입력합니다.

역할을 나누어 봅니다

서버는 내 컴퓨터, 계산은 Colab 런타임

⑫ Colab MCP
요청이 거치는 프로그램을 작업 위치에 따라 나타냅니다.

네 층

내 컴퓨터의 Claude Code 또는 OpenCode
          ↓ 도구 호출 요청
내 컴퓨터에서 실행하는 Colab MCP 서버
          ↓ 연결된 노트북 조작
Chrome의 Colab 노트북
          ↓ 코드 셀 실행
Colab 런타임의 Python
  • Colab MCP 서버는 내 컴퓨터에서 실행됩니다. 반면 노트북 셀의 Python 계산은 Colab 런타임에서 실행됩니다
  • 앞에서 만든 weekly_records_server.py를 Colab 셀에 붙여 넣는 실습이 아닙니다 — 새 MCP 서버를 로컬 호스트에 등록하고, 그 서버를 통해 브라우저의 노트북을 조작하는 실습
📌 "셀을 하나 추가해 줘"는 노트북 문서를 바꿉니다. "그 셀을 실행해 줘"는 런타임에 계산을 시킵니다 — 셀은 생겼는데 결과가 나오지 않았다면 두 동작 중 첫 번째까지만 된 것일 수 있습니다
이 차이를 실제 화면에서 확인하게 됩니다.

Chrome과 로컬 실행 도구

  • 이 수업에서는 Google Chrome을 권장합니다 — 기존 실습에서 Chrome으로 승인 창과 셀 실행까지 확인했습니다. 공식 저장소가 Chrome만 지원한다고 안내하는 것은 아니며 수업에서 확인한 환경을 맞추기 위한 권장
  • 내 컴퓨터의 Chrome에서 실습에 사용할 Google 계정으로 로그인. 일반 Colab 페이지를 열어 둔 것만으로 MCP 연결이 끝난 것은 아닙니다
  • Colab MCP 프로그램은 Python 3.13 이상을 요구합니다 — 이것은 내 컴퓨터에서 MCP 서버를 실행하는 Python의 조건이며, Colab 노트북 셀의 Python을 바꾸라는 뜻이 아닙니다
  • uvx는 uv에 포함된 명령으로 도구가 필요한 패키지를 별도 환경에 설치하고 실행하게 해 줍니다. 공식 저장소에서 프로그램을 가져오려면 Git도 필요
📌 앞에서는 uv sync·uv run으로 우리 프로젝트를 다뤘습니다. 이번에는 공개된 Colab MCP를 별도 도구로 실행하므로 uvx — Colab MCP의 패키지를 업무 기록 프로젝트에 섞어 설치할 필요는 없습니다
여러 계정을 쓰고 있다면 이후 저장할 노트북이 어느 계정에 들어갈지도 확인해 두세요.

서버 등록

claude mcp add --transport stdio --scope project colab-mcp \
  -- uvx --python 3.13 git+https://github.com/googlecolab/colab-mcp
// OpenCode V1
"colab-mcp": {
  "type": "local",
  "command": ["uvx","--python","3.13","git+https://github.com/googlecolab/colab-mcp"],
  "enabled": true,
  "timeout": 120000
}

// OpenCode V2 — mcp.servers 아래
"colab-mcp": {
  "type": "local",
  "command": ["uvx","--python","3.13","git+https://github.com/googlecolab/colab-mcp"],
  "timeout": { "execution": 120000 }
}
  • --python 3.13은 그 로컬 도구를 실행할 Python을 지정 — 없으면 uv가 내려받을 수 있습니다
  • V1의 timeout: 120000은 밀리초이므로 호스트 측 120초. V2의 timeout은 세부 대기 시간을 담는 객체이고 execution은 도구 호출 대기를 지정 — V1의 숫자형과 형태가 다릅니다
  • 브라우저 승인 단계에도 별도의 기다리는 시간이 있으므로 이 숫자를 늘리면 모든 제한 시간이 함께 늘어나는 것은 아닙니다
⚠️ V1과 V2 두 JSON을 함께 추가하지 않고 현재 설치 계열의 설정을 사용합니다. 같은 로컬 프로그램을 실행하지만 호스트가 설정을 읽는 위치가 다릅니다
학생이 볼 것은 명령을 얼마나 길게 생성했는지가 아니라 어느 호스트 설정을 바꿨고 서버가 실행될 준비가 됐는지입니다.

브라우저의 MCP 연결 승인

글자는 같지만 연결하는 대상이 다릅니다

⑫ Colab MCP
처음에는 open_colab_browser_connection이라는 연결 도구가 보일 수 있습니다. 이름을 외울 필요는 없습니다.

두 개의 Connect

위치연결하는 대상연결 뒤 확인할 변화
Colab 화면 오른쪽 위의 Connect노트북에서 코드를 실행할 런타임코드 셀을 실행할 수 있는 상태
가운데 승인 창의 Connect현재 노트북과 로컬 Colab MCP 서버에이전트가 연결된 노트북을 읽고 조작할 수 있는 상태
  • 승인 창의 제목은 Connect to a local Colab MCP server — 자신이 방금 요청한 연결인지 확인하고 누릅니다. 브라우저가 로컬 네트워크 접근 허용을 묻는 경우에도 지금 요청한 로컬 연결인지 확인
  • 안내에는 한 로컬 MCP 서버에 한 노트북 세션을 연결한다는 내용이 있습니다 — 여기서 세션은 현재 서버와 이어져 있는 노트북 연결. 탭을 여러 개 열었다고 같은 서버가 그 모두를 동시에 조작할 준비가 된 것은 아닙니다
⚠️ MCP 연결을 승인했어도 런타임이 준비되지 않았다면 계산은 아직 실행되지 않을 수 있습니다. 반대로 손으로 코드를 실행할 수 있어도 에이전트가 그 노트북을 조작할 연결은 없을 수 있습니다
다른 선택지인 Cancel이나 Connect separate tabs로 경로를 나눌 필요는 없습니다.

연결 뒤 달라지는 도구 목록

  • 연결 전후에는 서버가 제공하는 도구 목록 자체가 달라질 수 있습니다 — 연결 전에는 편집할 노트북이 아직 정해지지 않았고, 연결되면 그 노트북의 내용을 읽거나 셀을 추가·실행하는 기능을 쓸 수 있게 됩니다
  • 실행 중에 목록이 바뀌는 것을 동적 도구 목록이라 합니다 — 서버가 "도구 목록이 바뀌었다"는 알림을 보내고 호스트가 이를 받아 목록을 갱신해야 새 기능을 쓸 수 있습니다
  • 공식 안내는 로컬 클라이언트와 도구 목록 변경 알림 지원을 요구하며 지원 예시에 Claude Code가 포함됩니다. OpenCode에서는 현재 버전에서 연결 후 편집·실행 기능을 쓸 수 있게 되는지 확인
🔍 Tool Search와 구분 — 여기서는 연결 상태에 따라 서버가 제공하는 기능이 바뀝니다. Tool Search는 제공 가능한 많은 기능 중 지금 필요한 설명을 찾는 방식이었습니다
연결된 노트북 이름과 지금 들어 있는 셀을 확인해 줘.
답변의 노트북 이름이 Chrome 탭의 이름과 맞는지, 셀 내용도 맞는지 비교합니다. 연결 도구만 계속 사용할 수 있다면 셀 실행을 여러 번 요구하기보다 승인과 도구 목록 갱신부터 살펴봅니다.

계산 셀과 42 출력

세 가지를 따로 확인합니다

⑫ Colab MCP
첫 실행은 학생도 바로 결과를 판단할 수 있는 작은 계산으로 시작합니다.

세 가지를 따로 확인

print(37 + 5)

42
1요청한 코드가 셀에 생겼는지
2그 셀이 실행되었는지
3셀 아래 출력이 예상값과 맞는지
  • 기존 기록에서는 add_code_cell로 코드를 담은 셀을 추가하고 run_code_cell로 실행했습니다 — 첫 호출은 노트북에 내용을 쓰는 단계, 두 번째는 Python 계산을 요청하는 단계
  • AI 답변에 "42입니다"만 쓰여 있고 노트북에 변화가 없다면 — 'Colab에서 계산하기'는 아직 확인하지 못한 것
📌 기존 캡처는 당시 연결에서의 실행 증거입니다 — 자신의 환경에서도 실제 호출 결과와 노트북을 맞춰 보아야 현재 연결을 확인할 수 있습니다
2026-09-06 실제 MCP 호출로 이 셀을 추가·실행했고, 새 연결에서도 승인 창의 Connect를 누른 뒤 같은 셀 추가·실행과 42 출력을 다시 확인했습니다. 화면만 보고 추측하기보다 호스트의 도구 호출 기록과 셀의 변화를 함께 읽는 습관을 들이세요.

입력을 바꾸며 계산 근거 읽기

minutes = [20, 30, 40]
average = sum(minutes) / len(minutes)
print(average)
  • 대괄호 안에 여러 값을 담은 자료를 리스트(list)라 합니다. 이번 원소는 한 번 기록한 학습 시간이며 단위는 분
  • sum(minutes)는 90, len(minutes)는 3, 나누면 30. Python에서는 결과가 소수로 표시되어 30.0이 나올 수 있습니다
  • 마지막 입력 40을 70으로 바꾸면 — 합계 90→120, 기록 수는 여전히 3이므로 평균은 40.0. 세 관측값 중 하나가 30분 늘어났으므로 전체 평균은 10분 늘어난 것으로도 설명할 수 있습니다
  • 이전의 30.0이 그대로라면 — 값을 바꾼 셀과 계산 셀을 올바른 순서로 실행했는지 살펴봅니다. 코드를 고친 상태, 실행한 상태, 새 출력을 보고 있는 상태가 서로 일치하는지
⚠️ 계산 코드가 맞는 것과 숫자의 의미가 맞는 것은 별개입니다 — 이 30분은 기록이 있는 세 번의 평균. 기록이 없는 나머지 날도 0분으로 보아 나누면 다른 숫자가 나옵니다. Colab은 선택한 계산을 실행해 주지만 "기록이 없는 날을 어떻게 다룬다"는 기준까지 정해 주지는 않습니다
기록이 아예 없는 주라면 빈 리스트의 길이는 0이므로 0으로 나누게 됩니다. 먼저 결정할 것은 예외 처리의 길이가 아니라 자료가 없음을 보고서에서 어떻게 표현할지입니다.

노트북 보관과 다시 실행

  • 실행 결과 화면 상단에는 Cannot save changes와 Copy to Drive가 보입니다 — 열린 scratchpad는 임시 노트북. 계산이 성공했다는 사실과 노트북을 내 계정에 보관했다는 사실은 구분
  • 보관할 결과가 있으면 Copy to Drive로 복사하고 알아볼 수 있는 제목을. "결과는 30"이라고만 적기보다 입력의 단위와 평균의 뜻도 텍스트 셀에
  • 다시 열었을 때도 셀은 위에서부터 실행하는 편이 이해하기 쉽습니다 — 첫 셀에서 minutes를 만들고 두 번째에서 계산했다면 새 런타임에서 두 번째만 실행하면 minutes를 찾지 못할 수 있습니다
  • 셀 아래에 과거 출력이 보이더라도 지금 런타임에서 방금 계산한 결과와는 구분합니다
  • 노트북을 복사해 다른 탭으로 옮겼다면 에이전트가 조작 중인 노트북도 다시 확인 — 저장·복사가 기존 MCP 세션의 대상을 자동으로 바꿨다고 생각하지 않습니다
연결 중에는 대상 탭과 로컬 MCP 프로세스를 유지하고, 실습을 마칠 때 필요한 결과를 보관한 뒤 연결을 종료합니다.

멈춘 위치와 다음 확인

관찰한 현상멈췄을 위치다음 확인
서버 등록부터 실패실행 환경·호스트 설정uvx와 Git 실행 가능 여부, Python 요구 사항, 설치 로그
Colab 탭은 열렸지만 연결 대기브라우저 로그인·로컬 연결 승인같은 컴퓨터의 Chrome인지, 도구가 연 탭인지, 승인 창의 Connect를 눌렀는지

셀은 생겼지만 출력이 없음런타임 준비 또는 Python 실행오른쪽 위 런타임 상태와 셀 오류. 변수가 없다면 앞 셀을 실행
작업하다 연결이 끊김탭·로컬 프로세스·노트북 세션대상 탭과 MCP 프로세스 유지 여부. 새로 연결했다면 노트북 제목과 셀을 읽어 올바른 대상인지
📌 로그인 화면까지 열렸는데 시간이 지나 실패했다면 — Python 코드를 고칠 단계가 아닙니다. Colab MCP 연결 구현에는 UI_CONNECTION_TIMEOUT = 60.0이라는 브라우저 연결 대기 제한이 별도로 있어, 호스트를 120초로 설정해도 서버 내부의 약 60초 대기가 함께 늘어나지는 않습니다
먼저 로그인 상태를 준비한 뒤 다시 연결을 요청합니다. 설정 값을 반복해서 키우기 전에 어느 쪽이 실패를 반환했는지 로그를 읽어 보세요.

남길 것과 남기지 않을 것

  • 연결 도구는 연결용 임시 값을 담은 URL을 만듭니다 — 그 전체 주소를 과제·채팅·공개 캡처에 붙이지 않습니다
  • 결과로 남길 것 — 사용한 호스트와 Chrome, 연결 뒤 실제로 호출한 기능 하나, 계산 셀과 출력. 노트북에 숫자가 나온 근거를 보여 주는 데 연결용 임시 주소는 필요하지 않습니다
  • 정리할 때는 "Colab이 연결됐다"에서 한 걸음 더 — 로컬 MCP 서버가 어느 노트북을 조작했고, Python은 어디에서 실행되었으며, 어떤 입력으로 어떤 결과가 나왔는지
⚠️ Colab MCP 연결을 위해 다음 절의 Google Workspace용 credential JSON을 새로 만들 필요는 없습니다 — 여기서는 Colab 로그인과 브라우저의 MCP 연결 승인을 사용했습니다. Colab에 로그인한 상태가 그 앱의 접근 동의까지 대신해 주는 것은 아닙니다

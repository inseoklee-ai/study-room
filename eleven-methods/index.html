1

실험을 설계한다

같은 질문을 눈으로 비교할 수 있게 호출을 짠다

qwen3.5:2b · Ollama · Claude SDK
프롬프트는 입력 문장이고, 모델은 그 문장의 역할·형식·길이·금지 조건을 함께 해석합니다. 그래서 주제가 같아도 응답은 같지 않습니다. 이 파트에서는 그 차이를 관측 가능하게 만드는 실험 구조를 세웁니다.

🔬 무엇을, 어떻게 관측하나

  • 같은 모델·같은 질문이라도 프롬프트가 다르면 답의 모양·내용이 크게 달라진다
  • 두 관점 — Claude SDK(query()로 호출 구성) · Ollama/LangChain(로컬 서버·메시지 추상화)
  • 이 교안이 실제 실행·기록한 경로 = 로컬 Ollama
  • 가능한 일·불가능한 일을 함께 남기는 이유 — 결과는 모델만의 성질이 아니라 호출 도구의 성질도 포함하니까
판단 분리 — "지시를 따랐는가"와 "말한 내용이 사실인가"를 하나로 합쳐 판단하지 않는다.
실험 결과가 순수한 모델 능력의 지표가 아니라는 점이 핵심입니다. 같은 모델이라도 어떤 하네스로 부르느냐에 따라 조절 가능한 변수가 달라지므로, 실측치는 늘 도구 조건과 함께 읽어야 합니다.

💻 짧은 호출 루프 (축약본)

PROMPTS = {
  "basic":    "다음을 계산하세요: 25 × 14 - 87 ÷ 3",
  "role_cot": "당신은 꼼꼼한 수학 교사입니다 …\n다음을 계산하세요: 25 × 14 - 87 ÷ 3",
  "few_shot": "예: 18 × 5 - 12 ÷ 3은 90 - 4 = 86입니다 …",
}
for name, prompt in PROMPTS.items():
    payload = {"model": "qwen3.5:2b",
               "messages": [{"role": "user", "content": prompt}],
               "stream": False, "think": False}  # think:false 없으면 추론이 content를 비움
    # POST http://localhost:11434/api/chat → message.content 저장
한 질문을 여러 프롬프트로 돌려 결과 텍스트를 파일로 남긴다. 비교의 출발점은 재현 가능한 호출.
같은 질문을 basic, role_cot, few_shot 세 프롬프트로 보내고 각 응답을 파일로 저장합니다. 읽기 전 파일명·프롬프트·모델·설정을 나란히 적어 두어야, 나중에 어떤 조건에서 나온 답인지 되짚을 수 있습니다.

🧠 thinking 모델과 think:false

1thinking 모델 = 최종 답 전에 내부 추론을 생성한다. 기본 호출에선 추론 토큰이 컨텍스트를 다 써 content가 비는 현상이 난다
2think:false로 이를 억제 — 이건 정확도 장치가 아니라 비교할 최종 텍스트를 확보하는 호출 조건
3설정을 바꾸면 파일명·조건 열에 반드시 남긴다. 길거나 그럴듯해도 통과 근거로 쓰지 않는다
temperature = 다음 토큰의 무작위성. 낮을수록 같은 선택 가능성↑ — 그러나 낮은 값은 외부 사실을 검증하지 않는다.
think:false는 성능을 올리는 옵션이 아니라 비교 대상이 되는 최종 텍스트를 확보하기 위한 조건일 뿐입니다. 계산은 계산값을, JSON은 파싱과 항목을, 길이는 문자 수를, 금지어는 실제 포함 여부를 각각 확인해야 합니다.

📐 형식 준수 ≠ 사실 정확

관찰 대상조건실측 결과

JSON "물류강" 사례는 형식과 내용의 분리를 가장 선명하게 보여 줍니다. 파싱 성공은 형식 통과, 계산값 321은 계산 기준 통과, 금지어 미사용은 문자열 기준 통과 — 각 기준은 다른 실패를 잡고, 한 기준의 통과를 전체 품질로 부르면 안 됩니다.

🔍 판정 표가 드러낸 것

부부정 지시는 답만 못 지킨 게 아니라 해석을 바꿨다 — "소수점 쓰지 마라" → 9/11 분수. 금지어는 개념 공간에서 개념을 비활성화하는 부작용이 있어, 금지 문장 하나를 안전장치로 볼 수 없다
비think on/off는 비용 조건 — think:false(0자)와 think:true(10,249자) 모두 정답. 후자의 thinking이 약 5배. 이미 풀린 문제에서 thinking은 정확도 없이 비용만↑
온temperature는 추론 오류 교정 노브가 아님 — temp 0은 같은 오답 재현, temp 1.5는 일관성을 잃어 무효
Claude SDK의 경계 — query()는 temperature·top_k를 노출하지 않는다. 노출 안 된 옵션은 기본값으로 채우지 말고 "조절 불가"로 적는다.
어떤 하네스를 고르느냐가 조절 가능한 변수를 결정합니다. 비교할 때는 "모델이 다르다"만 적지 말고 모델명·프롬프트·메시지 위치·시스템 지시·temperature·top_k·thinking·반복 횟수·노출 옵션을 함께 기록해야 합니다.

🔢 토큰 선택 두 단계

① logit정렬 안 된 날(raw) 점수
"서울" 높고 "바나나" 낮음
확률 아님 · 음수 가능 · 합≠1
→
② softmax지수값을 전체 합으로 나눠
0~1 정규화, 합=1
"서울" 0.92 · "평양" 0.04
모델의 답 = 이 분포 위의 표본 추출(sample)logit은 각 후보의 날 점수, softmax는 그것을 확률로 바꾼 분포 — 디코딩 노브는 이 분포를 손댄다
확률화 이전의 logit 순서가 곧 모델이 무엇을 더 그럴듯하게 보는가이다.
logit은 정규화되지 않은 날 점수라 그 자체로는 확률이 아닙니다. softmax가 각 logit의 지수값을 전체 합으로 나눠 0에서 1 사이 확률로 만들고, 모델의 최종 답은 이 분포에서 하나를 뽑는 표본 추출입니다.

🎛️ 세 노브가 분포를 비트는 법

Ttemperature — logit을 temp로 나눈 뒤 확률화. temp<1이면 분포가 뾰족(강한 후보 더 강), temp→0이면 최고 후보가 1로 수렴해 매번 같은 토큰(세 응답 동일의 원인), temp>1이면 약한 후보도 상당한 확률(1.5에서 세 응답 다름)
Ktop_k — 뽑기 전 후보 수를 자른다. 상위 k개만 남기고 나머지 0, 재정규화. top_k=1이면 최고 후보 하나만 → temp 무관 같은 토큰
Ptop_p — 누적 확률이 p가 될 때까지 상위 후보를 남김. 후보 수 고정 대신 분포 모양에 따라 유동
한계 — 노브가 바꾸는 건 분포의 모양이지 logit 순서가 아니다. "9월 11일"에 높은 logit을 준 모델에게 낮은 온도는 그 오답을 더 충실히 반복할 뿐 — 실험 관찰과 정확히 일치.
이 한계가 PART 2의 함정 결과를 설명합니다. 모델이 오답에 높은 logit을 매겼다면 어떤 샘플링 노브도 순서를 뒤집지 못하므로, 낮은 온도는 오답을 안정적으로 재현하고 높은 온도는 일관성만 잃습니다. 함정 교정은 디코딩이 아니라 지시·맥락 쪽의 일입니다.

2형식 준수 ≠ 사실 정확 — 파싱된 63자 JSON이 틀린 "물류강"을 담았다. 기준마다 따로 검사한다.

Q1. 계산 실험에서 세 프롬프트가 모두 맞힌 값과, 그런데도 갈린 것은 각각 무엇인가?
Q2. JSON "물류강" 사례가 보여 준 핵심 구분은 무엇인가?
Q3. 함정 질문에서 temp 0과 temp 1.5의 결과는 각각 무엇을 뜻하나?
Q4. logit과 softmax는 각각 무엇이며, 모델의 답은 어떻게 결정되나?
Q5. 디코딩 노브가 바꾸지 못하는 것은 무엇이고, 그것이 함정 결과와 어떻게 이어지나?
답이 바로 떠오르지 않으면 앞 장으로 돌아가 확인해 보세요. Q4와 Q5가 오늘의 핵심 원리를 가장 잘 가립니다.

✅ 정답 & 해설

A1. 맞힌 값은 계산 정답 321. 갈린 것은 설명량(297자 / 952자 / 153자) — 프롬프트가 답의 모양을 바꾼다.
A2. 형식 준수 ≠ 사실 정확 — 파싱은 성공(형식 통과)했지만 "물류강"은 틀렸다. 파서만으로는 사실을 판정 못 한다.
A3. temp 0 = 세 번 동일 오답, 재현성일 뿐 정답 아님. temp 1.5 = 1/3만 정답, 우연한 탈출이지 해결이 아님.
A4. logit = 정규화 안 된 날 점수(확률 아님). softmax = 그것을 합 1의 확률로 정규화. 답은 이 분포의 표본 추출.
A5. 바꾸지 못하는 것은 logit 순서. 오답에 높은 logit을 준 모델에겐 낮은 온도가 오답을 더 충실히 반복할 뿐이다.
A4와 A5를 자기 말로 설명할 수 있으면 오늘 목표는 달성입니다. 노브는 분포의 모양을 다룰 뿐, 무엇이 더 그럴듯한가라는 순서 자체는 지시·맥락으로 바꿔야 합니다.

보관과 자산은 다릅니다

작업 전체를 보관하는 일과 다음 과업에서 쓸 판단을 남기는 일은 다릅니다. 실패한 명령, 우연히 통과한 설정, 현재 과업에만 맞는 해결책까지 다시 불러오면 기록은 오히려 판단을 흐릴 수 있습니다.

조건 1원문 기록에서
근거를 확인할 수 있다
조건 2필요한 때
검색할 수 있다
조건 3다음 행동으로
바꿔 적용할 수 있다
🎯 이 셋을 만족할 때 경험이 자산이 됩니다

ExpeL · Voyager · AWM · WikiSkill

⑤ 경험·스킬 축적
점점 진화하는 계보로 읽으면 각 연구가 남긴 문제가 다음 연구의 출발점이 됩니다.

ExpeL — 반복 판단을 insight로

ExpeL은 한 번의 실행에서 나온 관측과 성공·실패 경험을 바로 다음 프롬프트에 쌓아 두지 않습니다. 여러 경험에서 반복해 쓸 판단을 insight로 추출해 저장합니다.

  • 새 과업이 오면 FAISS와 kNN으로 가까운 예시를 찾아 최대 6개까지 실행에 제공합니다
  • 추출에 GPT-4, 실행에 GPT-3.5를 쓴 WebShop 조건에서 보상은 0.701, ReAct는 0.665
  • 남긴 문제 — 잘못된 insight가 저장됐을 때 무엇을 근거로 고치거나 폐기할지는 이 방식만으로 해결되지 않습니다
출처: Zhao et al., ICLR 2024, arXiv:2308.10144. GPT-4로 insight를 추출하고 GPT-3.5가 실행한 WebShop 조건이며, 잘못된 insight의 갱신·폐기 기준은 제시하지 않습니다.

Voyager — 코드 스킬 · AWM — workflow

연구남기는 형태결과붙은 조건
Voyager자연어 메모 대신 실행 가능한 코드 스킬 라이브러리. 새 과업에서 검색·조합아이템 3.3배, 이동 거리 2.3배, milestone 최대 15.3배, 스킬 검색 top-1 80.2%Minecraft 환경의 결과 — 다른 업무의 재사용 효과를 보장하지 않음
AWM
Agent Workflow Memory		과거 궤적에서 재사용할 workflow를 유도해 메모리로. 다음 과업에서 후보를 골라 제공Mind2Web 24.6%, WebArena 51.1% 상대 개선. 교차 평가 8.9~14.0점 상승웹 탐색 환경의 결과 — 웹 밖 일반화는 이 결과만으로 판단하지 않음
🏗️ 커뮤니티에서는 이 흐름을 컴파운드 엔지니어링이라 부르기도 합니다 — 한 번의 실행 결과를 다음 실행의 입력으로 남기고 검색·조합·검토를 거치며 능력을 쌓는다는 뜻. 그러나 저장한 내용이 오래되거나 틀렸다면 다음 실행에도 같은 오류를 넘길 수 있습니다
출처: Wang et al., arXiv:2305.16291(Minecraft 코드 스킬 검색·조합); Agent Workflow Memory, arXiv:2409.07429(웹 탐색 궤적에서 유도한 workflow를 현재 사이트·과업에 맞춰 사용).

insight여러 실행에서 반복된 판단을 검색해 적용반례와 갱신 날짜가 있습니까?오염
코드 스킬검증한 절차를 실행 가능한 단위로 재사용입력 조건과 되돌리는 방법이 있습니까?오래된 절차 반복
⚖️ 원문은 검토하기 좋지만 길고, 요약은 빠르지만 누락될 수 있으며, insight는 검색하기 좋지만 오염될 수 있고, 스킬은 바로 실행할 수 있지만 오래된 절차를 그대로 반복할 수 있습니다
이 구분이 실제 도구에서 어떻게 이어지는지 보려면, 저장한 세션을 다시 찾아 현재 판단에 넣는 경로를 먼저 확인해야 합니다.

경험 기능의 핵심 반론

⑤ 경험·스킬 축적
ExpeL이 남긴 갱신·폐기 문제가 여기서 실험이 됩니다.

운영 조건이 뒤집힙니다

그럴듯하지만 틀린 insight 하나가 검색을 통해 여러 과업에 반복 주입될 수 있고, 실행 스킬은 그 판단을 더 빠르게 행동으로 옮길 수 있습니다.

스킬을 많이 모았는지가 아니라
틀린 지식을 찾아 고치고 되돌릴 수 있는지가 운영 조건입니다
1같은 과업·모델·예산을 고정합니다
2한 조건에는 검증한 insight 또는 스킬을, 다른 조건에는 고의로 틀린 insight 또는 스킬을 넣습니다
3출처 기록 · 만료 기한 · 반대 증거 · 되돌리기 정책을 하나씩 바꾸며 성공률 · 토큰 · 오염 전파를 함께 기록합니다
출처: 학생 실험 설계, topic-harness-paper-evidence.md §8-6. 고의로 틀린 memory·skill을 주입해 출처 기록·되돌리기·만료 기한·반대 증거 정책을 비교합니다.

❓ 이해도 확인

Q1. 로그가 '경험'이 되는 세 조건은?
A1. ① 원문에서 근거 확인 가능 ② 필요할 때 검색 가능 ③ 다음 행동으로 변환 가능.
Q2. ExpeL이 남긴 문제는?
A2. 잘못된 insight가 저장됐을 때 무엇을 근거로 고치거나 폐기할지의 기준이 없다. 이것이 이 기능의 핵심 반론이 된다.
Q3. WikiSkill의 Table 1 수치를 인용하지 않는 이유는?
A3. 아직 확인하지 않았기 때문. Figure 1 캡션에서 확인한 경향만 적고 미확인 수치는 쓰지 않는다.
Q4. 경험 기능의 운영 조건은 무엇으로 바뀌나?
A4. 얼마나 많이 모았는가 → 틀린 지식을 찾아 고치고 되돌릴 수 있는가.

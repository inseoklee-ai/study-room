result.json · changes.diff · 세션 JSONL

⑦ 관측과 판정

마지막 문장이 이 강의 전체의 관측 규율입니다.

판정 — 두 층으로 나눕니다

결정론적 채점 · LLM judge

⑦ 관측과 판정
관측한 기록을 모았다면, 이제 실행 결과와 그 결과에 이른 행동을 함께 판정합니다.

1층 — 종료 코드를 직접 받습니다

common.py는 수정 뒤 테스트 패치를 적용하고 pytest를 실행해 종료 코드를 직접 받습니다.

⚠️ pytest | tail처럼 파이프로 연결하면 pytest 실패가 tail의 종료 코드 0으로 가려질 수 있습니다. 이 실험은 그 방식으로 판정하지 않습니다

2층 — 전사를 읽어 구조화 출력으로

첫 층만으로는 통과하지 못한 실행이 어떤 방식으로 실패했는지 알기 어렵습니다. judge.py는 세션 전사와 결과를 판정 모델에 보냅니다.

판정에 들어가는 것
근거 추적 · 편집 최소성 · 검증 성실성의 0·1·2 점수
실패 분류 enum
실행 기록에서 가져온 evidence_quote
한 줄 사유
🎯 인용 필드를 필수로 둔 까닭은 — 추측으로 점수를 매기지 않기 위해서입니다
소단원 ③에서 본 스키마 요구가 여기서 실행됩니다.

판정 명령

.venv/bin/python judge.py
  • 판정 결과를 각 실행의 judgment.json에 쓰고 — 전체 행을 grading.jsonl과 results-table.md로 모읍니다
  • results-table.md의 A·B·C는 각각 기준선 실행(A) · 워크플로 실행(B) · 오케스트레이션 실행(C)
.venv/bin/python judge.py --aggregate
cat runs/A-sympy__sympy-24909/judgment.json
📌 --aggregate는 판정만 다시 모을 때 씁니다
판정을 다시 돌리지 않고 집계만 갱신할 수 있습니다.

집계표 판정
  • LLM 판정의 점수는 테스트 통과를 대체하지 않습니다 — 테스트는 수정의 결과를, 판정 기록은 그 결과에 이르는 행동의 근거를 읽습니다
  • evidence_quote가 실제 전사에 없는 문장이라면 점수도 신뢰할 수 없으므로 — 원래 기록으로 돌아가 확인합니다
네 단계를 차례로 연결해 한 실행의 흐름으로 읽습니다.

❓ 이해도 확인

Q1. pytest | tail로 판정하면 안 되는 이유는?
A1. pytest 실패가 tail의 종료 코드 0으로 가려질 수 있기 때문. 출력 처리와 종료 코드 처리를 분리한다.
Q2. 두 층이 각각 답하는 질문은?
A2. 1층(테스트)은 수정의 결과, 2층(판정)은 그 결과에 이르는 행동의 근거. 점수가 통과를 대체하지 않는다.
Q3. evidence_quote가 전사에 없으면?
A3. 점수도 신뢰할 수 없다. 원래 기록으로 돌아가 확인한다.
Q1은 실험 인프라의 버그가 결과를 조용히 왜곡하는 대표 사례입니다.

1

"학습에 안 씀" ≠ "남지 않음"

한 문장이 답하는 것은 절반뿐

두 개의 다른 통제 장치
많은 조직이 "학습에 쓰지 않습니다" 한 줄을 근거로 도입을 승인합니다. 그런데 그 문장은 궁금한 것의 절반만 답합니다.

🔐 다른 통제 장치, 따로 설정됩니다

"학습에 쓰지 않는다"

내 문장이 다음 모델의 재료가 되지 않는다

"남지 않는다"

내 문장이 어딘가에 저장되어 있지 않다

🔑 이 둘은 다른 통제 장치이고 실제로 따로 설정됩니다. "학습에 안 쓴다"는 문장은 사실이지만, "저장되지 않는다"는 전혀 별개의 질문입니다.
API 문서를 열면 거의 항상 "입력·출력은 기본적으로 학습에 사용하지 않습니다"가 먼저 눈에 들어옵니다. 사실이고 중요하지만, 보관은 별도입니다.

📄 공식 문서에 적힌 것 (2026년 7월 확인)

확인한 것문서에 적힌 내용
학습 사용OpenAI: 2023-03-01 이후 API 데이터를 학습에 안 씀, 쓰려면 명시적 동의
로그 보관같은 문서 — 남용 모니터링 로그 최대 30일, 법이 더 긴 보관을 요구하면 예외
다른 사업자Anthropic: API 입출력을 수신·생성 후 30일 이내 자동 삭제, 상업용은 기본 학습 안 씀
예외안전 시스템이 위반 표시한 대화 최대 2년, 신뢰·안전 분류 점수 최대 7년
⚠️ "학습에 안 씀"과 "보관"이 표 안에서 이미 갈라져 있습니다. 그리고 예외 항목을 보면 어떤 것은 몇 년씩 남습니다.
학습 사용 한 줄만 보고 보관·예외를 넘겨짚으면 안 된다는 것이 표에 그대로 드러납니다.

📅 숫자는 바뀝니다 — 실무 규칙

  • 검색하면 보관 기간을 7일이라 적은 글, 30일이라 적은 글이 뒤섞여 나옵니다
  • 둘 다 어느 시점엔 맞았을 수 있습니다 — 정책이 바뀌기 때문
요약 글이 아니라 공급자의 공식 문서를 열고
확인한 날짜를 함께 적어두세요
이 노트북에 적힌 숫자도 마찬가지입니다. 여러분이 실제로 결정하는 날에는 다시 확인해야 합니다.
블로그 요약은 시점이 불명확합니다. 공식 문서 + 확인 날짜가 감사에서 통하는 근거입니다.
2

ZDR은 문자 그대로 0이 아닙니다

제로 데이터 보관, 이름과 실제는 다르다

신청 · 범위 · 예외
ZDR(Zero Data Retention). 이름만 들으면 콘솔 토글 같지만 실제로는 그렇지 않습니다.

🚪 ZDR의 세 가지 진실

1신청해서 승인받아야 한다 — OpenAI는 사전 승인+추가 요건+영업팀 문의. Anthropic은 조직 단위 계약이라 새 조직엔 자동으로 안 따라옴. 종량제 카드 결제만으론 못 얻음
2적용 범위에 구멍 — 파일 API·배치 처리·코드 실행처럼 상태를 저장하는 기능은 ZDR 대상 아님. 콘솔·워크벤치도 빠짐. 특정 모델 자체가 30일 보관을 요구해 ZDR이 적용 안 되기도
3제로에도 예외 — 법적 요구·안전 시스템 판단 시 남을 수 있음. OpenAI: CSAM 분류기에 탐지되면 ZDR에서도 수동 검토용 보관. Anthropic: ZDR·HIPAA 계약이 있어도 플래그된 입출력 최대 2년
계약이 있어도 어떤 모델·기능을 고르면 보관이 되살아납니다.
ZDR은 콘솔의 토글이 아니라 협상된 계약이고, 그 계약에도 기능·모델·법·안전이라는 구멍이 있습니다.

🧾 감사 자리에서 설명해야 할 것

이건 사업자가 약속을 어긴다는 이야기가 아닙니다. 안전 의무와 법적 의무가 계약보다 위에 있다는 이야기입니다.

"ZDR을 켰습니다"가 아니라
"이런 조건에서 이만큼 남고,
이런 경우엔 이렇게 남습니다"
⚠️ 소비자용 챗 인터페이스(웹·앱)는 API와 정책이 다릅니다. 학습 동의·보관·삭제가 별도 설계이고 ZDR 대상도 아님. 팀원이 "회사가 승인한 AI"라 여기며 개인 계정 챗창에 고객 문서를 붙여 넣는 것은 계약과 무관한 완전히 다른 경로.
API 계약과 소비자용 챗은 완전히 별개입니다. 이 혼동이 실무에서 가장 위험한 데이터 유출 경로 중 하나입니다.

그래서 무엇을 확인해야 하는가

데이터 판단 = 여섯 개의 분리된 질문

6가지 확인 항목
하나의 질문이 아닙니다. 하나만 확인하고 나머지를 넘겨짚는 것이 가장 흔한 실수입니다.

🧭 여섯 개의 분리된 질문

확인 항목구체적으로 물어야 할 것
학습 사용기본으로 훈련에 쓰이나, 아니면 명시적 동의가 있어야 쓰이나
로그 보관남용·보안·장애 대응용으로 무엇이 며칠 남나, 예외 조건은
처리 리전어느 나라·리전에서 처리되나, 리전을 지정할 수 있나
하위 처리자사업자가 다시 쓰는 클라우드·외부 서비스는 어디, 목록 공개되나
계약 형태표준 약관인가, DPA가 붙나, 협상된 기업 계약인가
삭제와 감사삭제 요청 가능한가, 감사 제출 자료 있나, 키·접근 권한은 누가
🔑 이 여섯을 따로따로 확인해야 합니다. 하나로 나머지를 덮으면 반드시 구멍이 생깁니다.
로컬 실행은 이 목록의 상당 부분(리전·하위 처리자·보관 협상)을 없애줍니다. 하지만 전부는 아닙니다.
4

로컬도 자동으로 안전하지 않습니다

통제 지점이 밖에서 안으로 들어왔을 뿐

안쪽을 관리할 사람은 이제 나
문장이 사업자 경계를 안 넘으니 리전·하위 처리자·보관 협상은 사라집니다. 여기까지는 분명한 이점입니다.

🏠 로컬에서 실제 사고가 나는 곳

이점: 리전·하위 처리자·보관 협상이 사라짐. 그러나 통제 지점이 밖→안으로 들어왔을 뿐, 관리할 사람은 이제 여러분.

  • 노트북 분실 — 모델 파일과 프롬프트 기록이 함께 유출. 디스크 암호화가 꺼져 있었다면 잠금화면은 무의미
  • 인증 없이 포트 개방 — 사내 서버가 사내망 누구에게나 열린 창구가 됨
  • 클라우드 백업 폴더에 로그 — 로컬로 옮긴 이유가 조용히 무효가 됨
  • 화면 공유·녹화 — 회의 중 민감한 프롬프트가 그대로 녹화
로컬은 통제 지점을 없앤 게 아니라 안으로 옮긴 것입니다. 그 안쪽을 이제 내가 지켜야 합니다.

📋 로컬을 고를 때도 문서로 남길 것

2로그는 어디에 얼마나 쌓이는가
3백업은 어디로 가는가
4장비를 폐기할 때 디스크는 어떻게 처리하는가
밖에 묻던 질문을
이제 안에다 묻는 것입니다
로컬이라고 문서 작업이 사라지지 않습니다. 질문의 대상이 사업자에서 내 조직으로 바뀔 뿐입니다.

🔍 위험한 문장 찾기

코딩 에이전트가 사내 AI 사용 지침 초안으로 이런 문장을 냈다고 해봅시다.

"개인정보가 포함된 문서라도 API 회사가 학습에 사용하지 않는다고 명시하고 있으므로, 그대로 전송해도 문제없습니다."

문법이 매끄럽고 근거도 인용했습니다. 그래서 더 위험합니다. 이 한 문장에서 문제되는 지점 세 곳을 찾아보세요. (다음 장에 해설)
매끄러운 문장일수록 검토 없이 통과되기 쉽습니다. 근거 인용이 곧 올바른 결론을 뜻하지 않습니다.

💡 문제되는 세 곳

① "학습에 안 쓴다고 명시하므로" — 근거 부족. 학습 사용은 여섯 항목 중 하나일 뿐(로그·리전·하위 처리자·계약·삭제가 남음). 근거 하나로 결론을 덮음
② "그대로 전송해도" — 가장 위험. 식별자 제거·최소 범위·문서 분리 같은 선행 조치를 건너뜀. 판단은 이지선다가 아니라 "무엇을 얼마나 깎아 보내나"
③ "문제없습니다" — 단정도 문제. 규정·정책은 다르고 바뀜. 단정 대신 확인 절차와 확인 날짜
목적: 아래 사내 AI 사용 지침 초안에서 근거가 부족한 단정을 찾는다.
조건: 문장마다 어떤 확인 항목이 빠졌는지 지적한다.
      확인 항목은 학습 사용, 로그 보관, 처리 리전, 하위 처리자,
      계약 형태, 삭제와 감사다.
      대안 문장을 제시할 때는 확인 주체와 확인 시점을 포함한다.
매끄러운 근거 인용이 검토를 대신하지 않습니다. 에이전트에게 이 검토 자체를 시킬 수도 있습니다.

워크북의 마지막 열이 다음(비용·주권)을 거쳐 최종 결정문으로 이어집니다.

🎯 이해도 확인 질문

Q1. "학습에 쓰지 않는다"와 "남지 않는다"는 어떻게 다른가?
Q2. 보관 기간 같은 정책 숫자를 다룰 때의 실무 규칙은?
Q3. ZDR이 "문자 그대로 0"이 아닌 이유 3가지는?
Q4. 데이터 판단의 6개 확인 항목은?
Q5. 로컬이 자동으로 안전하지 않은 이유와 대표적인 사고 지점은?
Q6. "그대로 전송해도 문제없습니다"에서 문제되는 세 곳은?
Q3와 Q6이 이 강의에서 가장 실무적인 지점입니다.

✅ 정답 & 해설

A1. 학습=내 문장이 다음 모델의 재료가 되느냐, 보관=내 문장이 어딘가 저장되느냐. 다른 통제 장치이고 따로 설정된다.
A2. 요약 글 말고 공급자 공식 문서를 열어 확인한 날짜를 함께 기록. 실제 결정하는 날 다시 확인(정책이 바뀌므로).
A3. ①신청·승인 필요(카드 결제론 안 됨) ②기능·모델에 적용 구멍(파일·배치·코드 실행·특정 모델) ③법·안전 예외(플래그 시 최대 2년 등).
A4. 학습 사용 · 로그 보관 · 처리 리전 · 하위 처리자 · 계약 형태 · 삭제와 감사. 여섯을 따로 확인.
A5. 통제 지점이 안으로 옮겨왔을 뿐 관리는 내 몫. 노트북 분실·인증 없는 포트·클라우드 백업 폴더·화면 공유 녹화.
A6. ①"학습 안 씀"만으로 결론(6항목 중 하나) ②"그대로 전송"(깎는 선행 조치 생략) ③"문제없습니다" 단정(확인 절차·날짜로 대체).
A6의 "무엇을 얼마나 깎아 보내는가"가 데이터 축의 핵심 사고방식입니다.

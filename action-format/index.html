어렵게 만드는 문법

행동 포맷 — 무엇을 고칠지 알아도 어떻게 적느냐에서 갈립니다

모델이 수정할 내용을 알고 있어도 변경 위치와 형식을 잘못 표현하면 작업은 실패합니다. 행동 포맷은 이 실패를 줄이는 기능입니다.

"이 함수를 고쳐 달라"의 빈칸

❌ 자유 문장

대상 경계 · 기존 내용 · 교체 내용을 모델이 다시 추정해야 합니다

✅ 구조화된 문법

찾을 내용과 바꿀 내용을 묶은 편집 블록, 또는 실행 가능한 코드 — 다음 행동의 형태를 좁힙니다

🎯 행동 포맷은 모델이 바꿀 대상을 찾고, 바꿀 내용과 실행 결과를 서로 확인 가능한 단위로 표현하게 합니다
  • Claude Code와 opencode에서도 파일 변경과 명령 실행이 어떤 표시로 남는지 살피는 이유가 여기 있습니다
  • 권한과 문맥의 경계 자체는 뒤 절에서 따로 다룹니다
이 소단원은 '무엇을 할 수 있나'가 아니라 '어떻게 적어야 덜 실패하나'를 봅니다.

근거 셋 — 조건을 붙여 읽습니다

SWE-agent · CodeAct · Aider

③ 행동 포맷
모든 수치에 조건이 붙어 있습니다. 조건 없이 옮기면 인용이 아니라 오독입니다.

SWE-agent — 18.0% vs 10.3%

SWE-agent는 프린스턴 연구진이 만든 연구용 코딩 에이전트로, 언어 모델을 위한 전용 인터페이스인 ACI가 일반 셸보다 적합할 수 있다는 가설을 검토했습니다.

조건해결률
기준(ACI 포함)18.0%
편집 기능을 제거10.3%
⚠️ 이 차이는 같은 벤치마크와 해당 구현의 ablation 조건에서 나온 결과입니다 — 모든 모델과 모든 편집 도구에서 같은 크기의 차이가 난다는 의미로 해석해서는 안 됩니다
  • 여기까지 말할 수 있는 것 — 인터페이스 설계가 해결률을 바꿀 수 있다
출처: Yang et al., NeurIPS 2024, arXiv:2405.15793. SWE-bench Lite ablation의 해당 구현 조건이며 다른 모델·과업으로 일반화하지 않습니다.

CodeAct — 행동을 코드 한 덩어리로

CodeAct는 행동을 JSON 형태의 도구 호출 대신 실행 가능한 Python 코드 한 덩어리로 쓰게 합니다.

도구 호출 방식

여러 파일의 줄 수를 셀 때 — 파일 열기 호출 → 결과 → 줄 세기 호출 식으로 여러 번 왕복

코드 방식

for 루프와 함수 호출이 든 코드 한 덩어리로 쓰고 실행 결과만 받음. 관측이 돌아오면 코드 자체를 고쳐 다시 제출할 수도 있음

  • 가설 — 흩어진 도구 호출을 하나의 표현으로 묶으면 모델이 계획을 온전히 드러낼 수 있다
  • 17개 LLM에서 기존 형식 대비 최대 +20%p를 보고 — 단, 지속 세션을 복원하는 기능의 효과까지 측정한 결과는 아닙니다
출처: Wang et al., ICML 2024, arXiv:2402.01030. 실행 Python 코드 action space 조건이며 지속 세션 복원 효과는 측정하지 않았습니다.

Aider — whole 46% vs diff 30% (GPT-3.5)

Aider는 터미널 안에서 파일을 편집하는 오픈소스 도구로, 변경을 자동으로 git 커밋해 줍니다. 두 가지 편집 포맷을 제공합니다.

포맷모델이 출력하는 것
whole파일 전체를 새 내용으로 다시 씀 — 바뀌지 않은 줄까지 모두 출력
diff바꿀 부분만 search-replace 블록으로 — 바꾸기 전 줄과 바꾼 뒤 줄만 짝으로
  • 측정 조건 — 133개 Exercism Python 과업, 실패하면 실제 개발자가 보는 것과 같은 피드백(테스트 오류의 앞 50줄)을 다시 넣어 재시도, 성공 기준은 전체 테스트 통과
  • 이 방식은 SWE-agent가 문제와 테스트로 측정하는 길과 같은 방향이지만 과업 난이도와 채점 세부가 달라 두 벤치마크 수치를 나란히 놓지 않습니다
⚠️ Aider 수치는 독립 비교가 아닌 벤더의 자체 벤치마크입니다 — 다른 과업·모델에서도 항상 whole이 낫다는 뜻이 아닙니다
출처: Aider 벤더 자체 벤치마크. 다만 설계는 실제 개발 흐름을 그대로 옮긴 것이어서 주목할 만합니다 — "작성한 코드가 실제로 동작하는가"를 재는 방식.

소단원 ①의 여섯 칸 형식으로 정리합니다.

Aider 최소 카드

칸내용
입구터미널 대화에서 파일과 요청을 함께 받아 편집 대화를 시작합니다
상태대화, 지정 파일, 테스트 결과가 다음 응답의 재료로 이어집니다
대표 행동search와 replace를 한 블록에 써서 기존 문자열과 교체 문자열을 함께 나타냅니다
권한 경계파일 변경과 명령 실행의 허용 범위는 설치 버전·설정·실제 실행 기록에서 다시 확인해야 합니다
1차 근거공개 문서의 편집 포맷 설명과 자체 벤치마크 — 독립 재현 결과는 아닙니다
한계검색 문자열이 정확히 일치하지 않거나 문맥이 오래되면 구조화된 블록도 의도와 다른 변경을 낼 수 있습니다
📌 블록은 변경 의도를 드러낼 뿐 — 변경의 정확성이나 실행 안전을 보장하지 않습니다. 대상 파일·일치 결과·테스트 결과·승인 표시를 함께 읽어야 합니다
지정한 파일과 요청 → 찾을 내용·현재 문맥 → search/replace 편집 블록 → 변경 제안 → 검토 뒤 반영. 일치 여부와 실제 반영 범위는 변경 이력과 실행 기록으로 확인합니다.

SWE-agent 최소 카드

칸내용
입구이슈 설명과 저장소 환경이 ACI를 거쳐 모델의 작업 요청으로 들어갑니다
상태검색, 파일 열람, 편집, 실행 관측이 다음 판단에 필요한 형식으로 남습니다
대표 행동구조화된 edit와 lint 피드백이 자유 셸 편집보다 좁은 편집 단위를 제공합니다
권한 경계논문의 ACI는 성능 실험의 인터페이스이며, 실제 환경의 파일·명령 권한 정책을 증명하지 않습니다
1차 근거NeurIPS 2024 논문이 ACI 구성과 SWE-bench Lite ablation을 공개합니다
한계18.0%와 10.3% 비교는 편집 기능을 제거한 해당 조건의 결과이며, 모델 세대와 과업이 바뀌면 차이도 달라질 수 있습니다
두 카드 모두 '권한 경계'와 '한계' 칸이 비어 있지 않다는 점이 중요합니다 — 소단원 ①의 카드 형식이 여기서 실제로 쓰입니다.

포맷이 항상 결정적인 것은 아닙니다

반대 근거를 함께 둡니다

③ 행동 포맷
이 절이 이 소단원의 균형입니다.

GPT-4에서는 차이가 거의 없었습니다

Aider 자체 벤치마크에서 GPT-4는 whole과 diff의 성능 차이가 거의 없었고, 비용 때문에 diff를 유지했다고 설명합니다.

따라서 포맷이 언제나 결과를 결정한다고 말할 수 없습니다
  • 다른 실패 원인이 더 클 수 있는 조건 — 모델이 포맷 차이를 충분히 흡수하는 조건, 변경 범위가 아주 작은 조건, 검색 문자열이 불안정한 조건
수치를 인용할 때 반대 근거를 함께 두는 습관이 이 중단원 전체의 읽기 규칙입니다.

같은 수정에서 바꿔 볼 변인을 정합니다

1작은 fixture 하나와 테스트 하나를 고정합니다
2같은 수정을 자유 텍스트와 search·replace 구조 포맷으로 각각 요청합니다
3두 실행에서 대상 파일을 처음 맞힌 횟수 · 변경 뒤 테스트 통과 여부 · 재시도 횟수를 기록합니다
🎯 포맷만 바꾼 관찰이 됩니다 — 한 번의 결과로 일반 결론을 내리기보다 모델·과업·포맷이라는 조건을 함께 남깁니다
  • 행동을 선명하게 만들어도 관측을 끝없이 쌓으면 다음 판단에 필요한 정보가 묻힙니다 — 그래서 다음 소단원이 컨텍스트 관리입니다
소단원 ②의 관찰 로그 형식을 그대로 쓰면 됩니다.

❓ 이해도 확인

Q1. 행동 포맷이 줄이는 실패는?
A1. 무엇을 고칠지 알아도 대상 경계·기존 내용·교체 내용을 모델이 다시 추정하다 생기는 실패. 확인 가능한 단위로 표현하게 한다.
Q2. SWE-agent의 18.0% vs 10.3%을 어떻게 인용해야 하나?
A2. SWE-bench Lite, 해당 구현의 편집 기능 제거 ablation이라는 조건과 함께. 모든 모델·편집도구로 일반화하지 않는다.
Q3. "구조화된 포맷이 항상 낫다"가 틀린 근거는?
A3. 같은 Aider 벤치마크에서 GPT-4는 whole/diff 차이가 거의 없었고 비용 때문에 diff를 유지했다.
Q4. 포맷 실험에서 기록할 세 가지는?
A4. 대상 파일 첫 시도 적중 · 테스트 통과 여부 · 재시도 횟수. fixture와 테스트는 고정한다.
Q2가 이 중단원의 인용 규율입니다.

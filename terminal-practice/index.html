1

터미널로 폴더를 탐험하고 만들기

안전 규칙 · 명령 · 세 단계

⑥ 실습 1
처음에는 바탕화면의 실제 파일 대신 terminal-practice 연습 폴더에서 실행합니다. 삭제 명령은 쓰지 않고, 공백이 있는 이름은 따옴표로 감쌉니다.

🎒 안전 규칙과 기본 명령

명령하는 일
pwd지금 있는 폴더의 전체 경로 출력
ls현재 폴더 안 파일·폴더 이름 보기
cd 폴더이름지정 폴더로 이동(cd ..는 한 단계 위)
mkdir 폴더이름새 폴더 만들기
touch 파일이름빈 파일 만들기(또는 수정 시각 갱신)
mv 원본 대상이동·이름 바꾸기 — 실행 전 원본·대상을 꼭 읽는다
🪟 Windows PowerShell — pwd·ls·cd·mkdir·mv는 같은 이름으로 동작. 둘만 다르다: touch가 없어 ni 파일이름, 폴더 여럿은 mkdir ideas, assets, archive처럼 쉼표.
안전 규칙 — 처음에는 삭제 명령(rm)을 쓰지 않고 연습 폴더에서만. 실제 중요한 파일에는 연습이 끝날 때까지 적용하지 않습니다.

🧭 세 단계 — 출력으로 확인

# 1단계 — 내 위치를 보고 연습 공간 만들기
pwd
ls
mkdir terminal-practice
cd terminal-practice
mkdir ideas assets archive
ls

# 2단계 — 파일을 만들고 이동하기
touch ideas/landing-page.txt          # PowerShell: ni ideas/landing-page.txt
mkdir assets/images
mv ideas/landing-page.txt assets/images/landing-page.txt
ls assets/images                       # landing-page.txt가 보일 때만 성공

# 3단계 — 길을 잃었을 때 돌아오기
cd ..
pwd
ls
mv 뒤 ls assets/images에 landing-page.txt가 보일 때만 성공 — 명령을 친 사실이 아니라 출력으로 확인. cd ..는 상위 폴더로. 화면 이름만 믿지 말고 이동할 때마다 pwd·ls를 번갈아.
이미 "File exists"가 나오면 같은 이름의 폴더가 있다는 뜻이니 ls로 확인하고 다음 단계로 갑니다. 현재 위치가 불안하면 pwd부터, mv는 대상 경로를 한 글자씩 확인한 뒤 실행합니다.
2

AI에게 폴더 정리를 맡기고 검토하기

dry-run · 체크리스트 · 승인

⑦ 실습 2
목표는 AI가 파일을 "치우게" 하는 것이 아니라, 분류 계획을 먼저 내고 내가 승인하는 협업입니다. 실제 바탕화면이 부담스러우면 terminal-practice에서만.

🤝 dry-run으로 계획부터 받는다

현재 작업 폴더의 파일과 폴더를 읽고 정리 계획을 세워줘.
규칙:
1. 삭제 명령(rm 등)은 절대 실행하지 마.
2. 먼저 dry-run으로 파일별 '현재 위치 → 제안 위치' 목록과 분류 기준만.
3. 이동은 내가 목록을 검토하고 '승인'이라고 답한 뒤에만 실행해.
4. 이름을 추측하지 말고, 확장자와 현재 이름을 근거로 분류해.
5. 실행 뒤에는 이동한 목록과 남은 파일 목록을 보여줘.
dry-run은 실제 변경 없이 "무엇을 할지" 미리 보여 주는 실행 계획. AI가 먼저 mv를 실행하려 하면 "아직 실행하지 말고 dry-run 목록만 보여줘"라고 바로 중단시킨다.
규칙 4가 특히 중요 — 이름을 추측해 분류하면 엉뚱한 폴더로 갑니다. 확장자와 현재 이름을 근거로 삼게 합니다.

✅ 산출물 검토 체크리스트

확인할 것통과 기준
이동 전 dry-run각 파일의 현재 위치·제안 위치가 목록으로 있다
삭제 방지삭제 명령·제안이 없고 보류 파일은 그대로
분류 기준확장자·용도 등 읽을 수 있는 기준, 애매한 파일은 질문
경로 안전작업 폴더 밖을 안 건드리고 중요한 폴더를 통째로 안 옮김
실행 후 확인ls·목록으로 이동 결과와 남은 항목을 보여줌
계획을 검토했어. .png와 .jpg만 images 폴더로 옮기고,
확장자를 알 수 없는 파일과 프로젝트 폴더는 그대로 둬.
삭제·이름 변경은 하지 마. 실행 후 이동 전후 목록을 비교해 보여줘.
승인은 범위를 좁혀 준다 — 무엇만 옮기고 무엇은 그대로 둘지, 무엇은 하지 말지.
애매한 파일은 AI가 질문하게 하는 것이 핵심입니다. 승인이라고 답하기 전까지 이동은 실행되지 않습니다.
3

직접 한 것과 AI에게 맡긴 것 비교 회고

두 방식의 강점 · 마무리 3문장

⑧ 실습 3
두 방식 중 하나가 항상 낫지는 않습니다. 직접 명령은 현재 위치와 각 파일을 세밀하게 이해하게 하고, AI 협업은 반복적인 목록화·계획 작성 속도를 높입니다.

🎯 이해도 확인 질문

Q1. mv로 파일을 옮긴 뒤 "성공"을 무엇으로 확인하나?
Q2. AI에게 폴더 정리를 맡길 때 dry-run을 먼저 요구하는 이유는?
Q3. 실습의 목표는 "AI가 치우게" 하는 것인가? 아니라면 무엇인가?
Q4. 직접 조작과 AI 협업은 각각 어디에 강한가?
Q5. 두 방식 어느 쪽이든 변하지 않는 책임은?
Q2와 Q5가 이 실습의 협업 원칙입니다.

✅ 정답 & 해설

A1. 대상 폴더에서 ls를 실행해 그 파일이 실제로 보일 때만 — 명령을 친 사실이 아니라 출력으로 확인.
A2. 실제 변경 전에 "무엇을 할지"를 미리 목록으로 보여 줘, 내가 검토·승인한 뒤에만 이동이 실행되게 하려고. rm은 금지시킨다.
A3. 아니다 — 분류 계획을 먼저 내고 내가 승인하는 협업. AI가 먼저 mv를 하려 하면 중단시킨다.
A4. 직접은 현재 위치·각 파일을 세밀하게 이해, AI는 목록화·계획 작성 속도.
A5. 실행 결과 검토는 내 책임 — 어느 쪽으로 하든 변하지 않는다.
A5가 이 강의 전체를 관통하는 태도입니다 — 지시하고, 확인하고, 판단한다.

1

가상환경 — 프로젝트별 Python 도구 상자

uv로 들어가고 나오기만

환경 충돌 방지
패키지를 컴퓨터 전체에 설치하면 한 실습의 버전이 다른 실습을 망가뜨릴 수 있습니다. 가상환경은 프로젝트 전용 폴더에 Python·패키지를 따로 둡니다.

📦 uv 가상환경 — 학생은 들어가고 나오기만

이 수업은 Astral의 uv를 사용. uv venv(환경 생성)·uv pip install(패키지)은 뜻만 알아두고 실행하지 않음 — 운영자가 requirements-*.txt로 미리 준비.

# 문서 실습 시작
source .venv-day15-ocr/bin/activate
python -c "import sys; print(sys.executable)"   # 경로 끝이 .venv-day15-ocr/bin/python인지 확인
deactivate                                        # 끝나면 나오기(삭제 아님)

# YOLO 실습 시작
source .venv-day15-yolo/bin/activate
activate=현재 터미널의 python이 그 도구 상자를 가리키게 함, deactivate=나올 뿐 삭제 아님. 패키지가 없으면 새로 설치하지 말고 오류를 기록해 대체 결과로 넘어감.
OCR용과 YOLO용 환경을 나눈 이유는 두 도구가 요구하는 패키지 조합이 다를 수 있기 때문입니다.

🤖 에이전트에 uv만 쓰게 + 준비된 PDF

▼ 환경 관련 지시에 붙이는 조건
Python 환경을 다룰 때는 uv만 사용해 줘.
pip, pip3, python -m venv, Conda, 전역 설치는 쓰지 않는다.
현재 활성화된 수업용 가상환경과 고정된 requirements를 바꾸지 않는다.
패키지가 없으면 새로 설치하지 말고 정확한 오류를 기록한다.
  • 기본 입력: 3쪽 이미지형 PDF → input/day15_sample.pdf — 1쪽 정비 지시서(항목·값·합계표), 2쪽 모의평가형(두 단·수식·선택지), 3쪽 시설 점검표(병합 셀·도장 겹침)
  • 공개 링크 ≠ 재배포 권리 — 외부 자료는 개인별 다운로드·수업 안에서만, 저장소엔 복사본 X. 파일명·다운로드 날짜·SHA-256만 기록
지시하지 않으면 에이전트는 익숙한 pip·전역 설치를 고를 수 있어, 환경 관련 작업엔 위 조건을 명시합니다.

네 개의 명령

동일 프롬프트가 아니라 동일 산출 계약

로컬 OCR → 문서 VLM → 범용 VLM → 비교표
일반 OCR은 자연어 프롬프트를 받지 않으므로 "모든 모델에 동일 프롬프트"가 아니라 동일 입력·동일 산출 계약을 맞춥니다.

① 로컬 OCR 두 종류 연결

▼ 명령 1 (요지)
input/day15_sample.pdf의 1~2쪽을 로컬에서 처리.
환경 명령은 uv만, 패키지/모델은 바꾸지 않는다.
- 두 페이지를 200dpi PNG로 한 번 변환, 같은 PNG를 두 OCR에 넣는다
- Tesseract 5: kor+eng · PaddleOCR: 한국어 PP-OCRv5 인식 모델
- 실제 선택된 탐지·인식 모델 이름을 기록
저장: input_pages/page_0N.png · tesseract/page_NN.tsv,.txt,_overlay.png
      paddleocr/page_NN_raw.json,.txt,_overlay.png · run_manifest.json
manifest: 패키지 버전·모델 이름·입력 SHA-256·실행 명령·시간·네트워크 사용 여부
가중치가 없으면 설치 말고 failure_log.md에 명령·오류 기록,
운영자 fallback이 있으면 그 경로를 manifest에 표시하고 계속.
🔑 채팅창에 "완료"가 나온 것은 통과 조건이 아닙니다. 두 OCR의 원시 결과와 서로 다른 이름의 오버레이 파일을 직접 열어 확인.
같은 PNG를 두 OCR에 넣어야 공정합니다. 오버레이(박스 그린 이미지)를 눈으로 확인하는 것이 핵심입니다.

② 문서 전용 VLM을 같은 입력에

기본 경로 = PaddleOCR-VL-1.6 전체 파이프라인을 준비된 GPU에서 직접 실행. 호스팅 추론 API로 임의 전환하지 않음.

▼ 명령 2 산출 계약 (요지)
input_pages의 두 PNG를 PaddleOCR-VL-1.6 전체 문서 파싱 파이프라인으로 처리.
준비된 GPU에서 직접 실행, 호스팅 API/다른 모델로 바꾸지 않는다.
- 페이지별 Markdown · 표는 Markdown표 또는 구조화 JSON
- 수식은 가능하면 LaTeX · 읽을 수 없는 곳은 [UNCLEAR]
- 원문에 없는 설명·요약·값 보정 금지 · 각 페이지 ## Page N
저장: paddleocr_vl/raw/ (원시), result.md (정규화)
manifest에 레이아웃 분석·VLM 인식 모델명·버전·시간·장치 추가.
5분 내 첫 페이지 없으면 오류 기록 후 운영자 fallback으로 계속.
⚠️ 구성요소 하나만 호출한 결과 ≠ 레이아웃 분석 포함 전체 파이프라인 결과. 실행 기록에 "전체 파이프라인"인지 "구성요소 직접 호출"인지 반드시 적음.
같은 모델 이름이라도 전체 파이프라인과 부분 호출은 결과가 다를 수 있어 무엇을 돌렸는지 기록해야 합니다.

③ Claude / ChatGPT에 같은 계약

둘 다 제품명 아래 실제 모델·전처리가 바뀔 수 있고 내부가 다 공개돼 있지 않음. 접근 가능한 한 서비스만 필수(다른 서비스는 확장). 새 대화에 두 페이지 PNG 첨부.

▼ 명령 3
첨부한 두 페이지를 페이지별 Markdown으로 전사해 주세요.
1. 표는 행과 열 관계를 유지 · 2. 수식은 LaTeX
3. 읽을 수 없는 곳은 [UNCLEAR]
4. 요약·추정·맞춤법 보정·금액 재계산 금지 · 5. 각 페이지 ## Page N
6. 마지막에 확실하지 않았던 위치만 페이지 번호와 함께 목록으로
응답을 general_vlm/result.md에, run_info.json에 서비스명·화면 표시 모델명·실행일·입력 파일명·프롬프트 기록. 앱의 비공개 전처리를 고정할 수 없으므로 정밀 벤치마크가 아니라 출력 성격 관찰.
범용 VLM은 문서 전용 OCR에서 출발한 게 아니라, 범용 언어 모델에 시각 입력을 연결해 문서도 다루게 된 계열입니다.

④ 기준값과 대조해 표로

▼ 명령 4 (요지)
네 갈래 결과를 읽어 comparison.md 생성.
없는 경로만 fallback에서 읽고 fallback_used=true 표시.
기준값 6개를 행, 도구를 열로.
exact/partial/missing/invented/unclear 중 하나로 표시.
각 판정 옆 원문 페이지·출력 경로.
처리시간·로컬/외부 전송 여부도 표에.
tool_choice.md의 선택 기준이 있으면
'상담 기준으로 다시 보기' 섹션 추가.

기준값 6개

① 문서번호 WO-2026-0715
② 차량번호 12가 3456
③ 작업 행 3개(엔진오일 68,000 등)
④ 공급가 103,000·부가세 10,300·합계 113,300
⑤ 2쪽 읽기 순서(좌 설명·F=ma → 우 12번)
⑥ 수식 F=ma / 답 ③

🔑 기준값이 있으므로 "그럴듯해 보인다"가 아니라 무엇이 달라졌는지를 같은 자로 비교. 원문 보고 정답을 다시 만들지 말고 제공된 기준값만 사용.
invented(원문에 없는데 지어낸 값)를 별도로 표시하게 하는 것이 환각을 눈에 보이게 만드는 핵심입니다.

결과 읽기 · 공정성 · 데이터 경로

한 도구가 모든 열에서 이길 필요는 없다

관찰과 기록
표가 나오면 그때부터 진짜입니다. 네 가지 질문으로 관찰하고, 예상과 다르면 예상이 아니라 결과를 기록합니다.

👀 결과를 볼 때 묻는 네 가지

질문확인 방법
글자를 얼마나 보존?숫자·기호·띄어쓰기와 [UNCLEAR] 위치를 원문과 대조
구조를 얼마나 보존?표 행 정렬, 두 단 읽기 순서, 병합 셀 관계 확인
근거를 되짚을 수 있나?페이지·좌표·원시 결과에서 출처를 찾을 수 있는지
빈자리를 메웠나?원문에 없는 요약·단위·재계산 값이 생겼는지
🔑 한 도구가 모든 열에서 이길 필요 없음 — Tesseract는 좌표·빠른 로컬, PaddleOCR는 한국어 글자 영역, 문서 VLM은 표·수식 구조, 범용 VLM은 질문 대응에서 편할 수 있음. 예상과 다르면 예상이 아니라 결과를 기록.
이 네 질문이 comparison 표의 판정 근거이자, 도구 선택의 실제 기준이 됩니다.

🧯 5분 안에 안 나오면, 그리고 공정성

  • 경로별 제한 — 로컬 의존성 없음/GPU·가중치 문제/서비스 접근 불가 → 5분 뒤 중단하고 fallback 결과 사용. 교사용도 없으면 not_run
  • 대체 결과 사용은 실패가 아님 — 사용 사실을 숨기거나 다른 모델로 조용히 바꾸는 것이 문제. 비교표·manifest에 fallback_used=true
⚖️ 비교가 공정하려면 — 같은 원본의 같은 PNG · 동일 산출 계약(동일 프롬프트 아님) · 앱 화면과 API 결과를 한 숫자로 섞어 "모델 성능"이라 부르지 않음 · 모델명·실행일·전처리·해시 기록 · 세 페이지로 순위 단정 금지. 그래서 표 제목은 "정확도 순위"가 아니라 "이 입력에서 관찰한 차이".
각 서비스의 비공개 전처리 차이는 조건을 지켜도 남습니다. 그래서 순위가 아니라 관찰입니다.

🖥️ 10분 제작 — 한 화면에 (Gradio)

▼ Gradio 앱 (요지)
기존 outputs를 읽어 한 화면에서 비교하는 Gradio 앱. 새 추론은 하지 않는다.
- 왼쪽: 원본 페이지 · 오른쪽 탭: Tesseract/PaddleOCR/PaddleOCR-VL/General VLM
- 좌표 있는 결과는 원본 위에 박스 오버레이 · Markdown은 페이지별 표시
- 기준값 6개 판정 표 · 비교표 CSV 다운로드 · 사용 모델·버전·로컬/외부 표시
- outputs에 없는 경로는 fallback에서 읽고 '대체 결과'라고 표시
apps/ocr/app.py에 만들고 .venv-day15-ocr/bin/python apps/ocr/app.py로 실행.
Gradio는 입력·출력 컴포넌트를 미리 갖춘 오픈소스 Python UI 도구 — 화면 프레임워크를 처음부터 만들지 않고 모델 결과 연결에 집중. 바이브코딩 실습에 적합.
새 모델 추론은 하지 않고 이미 만든 outputs만 읽어 보여주는 것이 원칙입니다.

답은 도구 이름이 아니라 입력·출력 자료형·근거·실패 조건으로 적습니다. "결과가 좋았다" 대신 "어떤 출력이 어떤 다음 작업에 바로 연결되는가"를 한 문장으로.
제출: outputs/ocr 폴더, comparison.md, 실행되는 apps/ocr/app.py. 모든 모델이 성공할 필요는 없고, 실패 경로엔 명령·모델명·오류·대체 사용 여부가 있어야 합니다.

📌 이것만은 꼭 — 핵심 6문장

1목표는 구현이 아니라 같은 페이지를 네 도구로 비교(자료형·실패 가시성·데이터 경로)
2OCR은 프롬프트를 안 받으니 동일 프롬프트가 아니라 동일 산출 계약을 맞춘다
3가상환경(uv)은 프로젝트별 도구 상자 — 학생은 activate/deactivate만, 없으면 오류 기록
4"완료" 채팅은 통과 아님 — 기준값 6개로 exact/partial/missing/invented 대조
5fallback 사용은 실패 아님 — 숨기거나 조용히 바꾸는 게 문제. fallback_used=true
6데이터 경로도 결과 — 공개 모델도 호스팅 호출이면 외부 전송
표 제목은 "정확도 순위"가 아니라 "이 입력에서 관찰한 차이"입니다.

🎯 이해도 확인 질문

Q1. 이 실습의 목표는? 비교하는 네 갈래는?
Q2. "동일 프롬프트"가 아니라 "동일 산출 계약"을 맞추는 이유는?
Q3. 가상환경이 필요한 이유? uv에서 학생이 하는 일은?
Q4. 채팅창의 "완료"가 통과 조건이 아닌 이유? 기준값으로 대조하는 이유는?
Q5. fallback(대체 결과) 사용은 실패인가? 진짜 문제는 무엇인가?
Q6. "데이터가 어디로 갔는지도 결과"의 의미는? 공개 모델이면 자동 로컬인가?
Q2·Q5·Q6이 이 실습이 지키려는 원칙입니다.

✅ 정답 & 해설

A1. OCR 구현이 아니라 이미 만든 기능을 연결해 같은 페이지를 비교. 네 갈래 = Tesseract · PaddleOCR · PaddleOCR-VL · Claude/ChatGPT(범용).
A2. 일반 OCR은 자연어 프롬프트를 받지 않기 때문. 그래서 같은 입력 PNG + 같은 출력 형식(계약)을 맞춘다.
A3. 실습마다 필요한 패키지 버전이 충돌하지 않게 프로젝트별로 격리하려고. 학생은 만들지 않고 activate/deactivate만, 없으면 설치 말고 오류 기록.
A4. 원시 결과·오버레이를 직접 열어 확인해야 하기 때문. 기준값이 있어야 "그럴듯함"이 아니라 무엇이 달라졌는지 같은 자로 비교(invented=환각까지 표시).
A5. 실패가 아니다. 진짜 문제는 사용 사실을 숨기거나 다른 모델로 조용히 바꾸는 것. 그래서 fallback_used=true를 남긴다.
A6. 실행 위치가 성능만큼 중요한 결과라는 뜻. 공개 모델이라도 호스팅 API를 호출하면 외부 전송이고, 상용이라고 조직 정책이 같지도 않다.
A5·A6이 감사 가능한 시스템의 기본 태도입니다.

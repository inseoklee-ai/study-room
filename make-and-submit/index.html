[과제] 원하는 포즈로 만들기

"이 자세로 한 장" 도구를 직접 만든다

ControlNet Pose · Colab · GitHub
앞서 본 ControlNet의 Pose 조건을 써서 도구를 직접 만듭니다. 강사가 노트를 주지 않고, FLUX.2-klein 4B Colab 노트를 출발점으로 삼아 포즈 조건을 얹는 방향으로 갑니다.

🧩 두 단계로 도구를 만든다

1포즈 조건을 넣어 도구 만들기 (30~60분) — 참조 사진 한 장 → OpenPose로 관절 추출 → ControlNet 전처리로 넣고 프롬프트와 함께 FLUX.2-klein 4B에. 결과는 참조와 같은 자세의 다른 인물/장면.
2다른 포즈·프롬프트로 바꿔 보기 (15분) — 같은 포즈에 프롬프트만, 같은 프롬프트에 다른 포즈 사진. 어느 쪽을 바꿨을 때 크게 달라지나를 관찰해 노트 마지막에 기록.
노트에는 처음 보는 사람도 따라 할 수 있게 한 셀 한 셀 적고, 셀마다 주석으로 '이 셀이 하는 일'을 — 모델 로드 · 포즈 추출 · 이미지 생성 · 결과 저장을 각 한 셀로.
도구가 한 번 돌아갔다면 조건을 바꿔 가며 잘 되는지 확인합니다. 이 관찰이 노트의 마지막 마크다운 셀에 '무엇을 바꿨고 어떻게 달라졌나'로 적혀 있어야 합니다.

  • GitHub public 저장소에 올리고 URL 한 줄을 제출. .ipynb는 GitHub가 노트 모양으로 보여 줌

만드는 일에는 만든 사람이 남습니다

읽기엔 오류가, 만들기엔 선택이 남는다

되짚기 · 남는 것
세 단어와 예순일곱 단어를 비교하는 것으로 시작해, 기계가 어떻게 만들어졌는지 따라가고, 직접 만들고, 포즈 도구까지 제출했습니다.

🔮 처음에 적은 예측과 맞춰 보기

처음의 질문오늘의 답
모델 교체 vs 프롬프트 수정, 뭐가 크게 바뀌나같은 모델·시드에서 프롬프트만으로 크게 갈렸다. 모델 교체는 대개 가장 늦게 — 먼저 빈 칸을 찾는다
오픈소스 모델, 회사 업무에 그대로?같은 이름도 크기에 따라 상업 가부가 갈린다. 제약이 가중치냐 산출물이냐도 구분
그래픽카드 없어도 직접 돌려 볼 수 있나된다 — 무료 GPU·브라우저. 오히려 노트북에서 무리하게 돌리는 쪽이 위험
"AI로 만들었다" 밝혀야 하나법적 의무는 사업자에게. 개인엔 바로 아니지만, 실제와 혼동될 자리엔 캡션 한 줄이 나를 지킨다
시작할 때 적어 둔 예측 표로 돌아가, 관점이 어떻게 바뀌었는지 확인합니다.

🫱 남는 것 — 선택

  • 읽어 내는 쪽 — 틀리면 오류. 검산하면 잡고, 잡으면 고친다
  • 만들어 내는 쪽 — 그런 정답이 없다. 대신 선택이 남는다: 어떤 장면을 · 어디까지 실제처럼 · 어디에 쓸지 · 무엇을 밝힐지
  • 이 넷은 모델이 결정해 주지 않고, 앞으로도 그럴 것
기술이 좋아질수록 이 선택의 무게는 오히려 늘어난다손가락 여섯 개는 누구나 알아본다 — 완벽해 보이는 그림은 아무도 못 알아본다. 그래서 완벽해질수록 더 따져 물어야 한다
다음 시간에는 하나의 모델이 글·그림·소리를 함께 받아들이기 시작하면서 입력의 경계가 흐려지는 이야기를 봅니다.

2노트는 셀마다 주석(모델 로드·포즈 추출·생성·저장), 마지막에 '무엇을 바꿨고 어떻게 달라졌나'.

✅ 정답 & 해설

A1. 참조 사진 → OpenPose로 관절 추출 → ControlNet 전처리로 넣고 프롬프트와 함께 모델에 → 같은 자세의 다른 인물/장면.
A2. 시드 고정 + 프롬프트·시드·모델명 기록 — 제출된 결과가 동일한 실험으로 재현되어야 한다.
A3. 모델을 갈아 치우는 것. 먼저 빈 칸을 찾고, 시드 고정·한 칸씩 수정을 거친 뒤에야 다른 것을 의심한다.
A4. 어떤 장면을 · 어디까지 실제처럼 · 어디에 쓸지 · 무엇을 밝힐지 — 모델이 결정해 주지 않는다.
A5. 완벽해 보이는 그림은 실제와 혼동돼도 아무도 못 알아본다 → 기술이 좋아질수록 용도·밝힘을 더 따져야 한다.
A4·A5를 자기 업무에 대보면 "만든 것에는 만든 사람이 남는다"가 실감납니다.

어제 만든 Todo 앱을
'AI가 아는' 앱으로

CLI + 규칙 파일 + 스킬 — 범용 AI를 내 앱 전용 조수로

지난 강의에서 우리는 에이전트에게 시켜 Todo 앱을 만들었습니다. 오늘 배운 것은 읽고 끝내면 남지 않으니, 그 Todo 앱을 재료로 범용 AI를 '내 앱을 아는 전용 조수'로 바꾸는 걸 직접 해 봅니다.

이 실습에서 하는 것 — 네 가지

1앱에 CLI(todo list·summary 같은 명령)를 갖추고, AGENTS.md(규칙 파일)에 사용법을 적는다
2AI에게 그 CLI를 실제로 돌리게 해 내 할 일 데이터를 읽는다 (이때 권한 승인을 관찰하고, 위험 작업 전 커밋으로 되돌릴 지점을 만든다)
3SKILL.md를 하나 만들어, 매번 반복하던 정리 작업을 한 번 적어 재사용한다
4(덤) 같은 걸 MCP로 붙이면 어떻게 다른지 짧게 체험한다
🧰 준비물 — 지난 시간에 로컬에 만든 Todo 앱 폴더(데이터가 todo.db 같은 내 컴퓨터 파일에 저장되는 형태) + 에이전트형 도구(Claude Code·Cursor 등) 하나
방향은 소단원 ⑤에서 본 흐름 그대로입니다 — 무거운 MCP부터 세우기보다, 앱에 CLI를 갖추고 그 사용법을 규칙 파일에 적어 두면 AI가 그 명령을 직접 돌려 내 데이터를 읽습니다. 클라우드 DB로 만들었다면 이 실습은 로컬 파일 기준으로 읽어 주세요.
1

1단계 — 앱에 '명령줄 사용법(CLI)'을 붙이기

얇은 진입점 하나만

⑥ 실습
지난 시간에 만든 Todo 앱은 아마 화면(웹)으로 쓰는 형태일 겁니다.

AI가 다루기 편한 창구는 명령줄입니다

🖱️ 화면(웹)

사람이 클릭하라고 있는 것 — AI가 붙잡기 번거롭다

⌨️ 명령줄(CLI)

"명령어를 쳐서 결과를 글로 받는" 방식 — AI가 그대로 실행하고 읽기 좋다

  • 앱을 새로 만들 필요는 없습니다 — 할 일을 추가·조회·완료하는 로직은 이미 앱 안에 있으니, 터미널에서 부를 수 있는 작은 입구(진입점) 하나만 더 얹으면 됩니다
  • 데이터도 앱이 쓰던 그 파일(todo.db)을 그대로 씁니다 — 새 데이터를 만드는 게 아니라 같은 데이터를 여는 문을 하나 더 다는 셈
📌 CLI 한 줄 정의 — 프로그램에 "무엇을 할지"를 화면 클릭 대신 명령어 + 값으로 전달하는 방식. node todo.js add "우유 사기"에서 add가 명령, "우유 사기"가 넘겨주는 값
여기서 학습자가 "내 앱을 다시 만드는 게 아니다"를 이해해야 부담 없이 시작합니다.

AI에게 이렇게 부탁합니다

"우리 Todo 앱의 기존 로직을 재사용해서 터미널에서 쓸 todo 명령을 만들어 줘.
 add(추가)·list(목록)·done(완료)·summary(오늘 완료 요약) 네 개면 돼.
 데이터는 지금 쓰는 todo.db를 그대로 쓰고,
 앱 코드를 갈아엎지 말고 얇은 진입점만 더해 줘."

그러면 이렇게 동작합니다.

$ node todo.js list
[x] 1. 발표 자료 초안 작성하기
[ ] 4. 헬스장 PT 예약 변경 문의하기
  • 앱이 파이썬이면 python todo.py list처럼, 쓰는 언어에 맞는 진입점이 생깁니다 — 형태만 다를 뿐 원리는 같습니다
  • ⚠️ summary가 '오늘 완료'를 세려면 완료한 시각이 데이터에 있어야 합니다. 없으면 AI에게 "완료 시각도 기록하게 해 줘"를 함께 부탁하세요
이하 편의상 todo …로 줄여 씁니다. AI가 실제로 만든 파일명은 cli.js처럼 다를 수 있으니, 나온 이름으로 바꿔 쓰면 됩니다.

사용법을 규칙 파일에 5~10줄로

# Todo 앱

## 개요
할 일을 추가·완료·조회하는 1인용 앱.

## 명령
- 목록: node todo.js list
- 추가: node todo.js add "<내용>"
- 완료: node todo.js done <번호>
- 오늘 완료 요약: node todo.js summary

## 규칙
- 데이터는 todo.db에 저장한다. UI 문구는 존댓말로.

## 하지 말 것
- todo.db(실데이터)를 직접 지우거나 덮어쓰지 말 것.
⚠️ 파일 이름은 도구를 탑니다 — Cursor 등은 AGENTS.md를 그대로 읽고, Claude Code는 CLAUDE.md만 자동으로 읽습니다(CLAUDE.md 첫 줄에 @AGENTS.md를 적어 불러와도 됩니다)
앱 폴더 맨 위(루트)에 둡니다. 소단원 ③에서 배운 네 항목(개요·명령·규칙·하지 말 것)이 그대로 들어갑니다.

  • 소단원 ④에서 본 "규칙 파일에 적은 건 리셋해도 유지된다"가 여기서 확인됩니다
새 대화를 여는 게 중요합니다. 같은 대화에서 물으면 방금 얘기한 내용을 기억하는 것과 구분이 안 됩니다.

2단계 — AI에게 그 CLI를 실제로 돌리게 하기

그리고 권한을 관찰하기

⑥ 실습
이제 진짜 재미있는 부분입니다.

"오늘 할 일 목록 좀 보여 줘"

규칙 파일을 읽은 AI는 스스로 node todo.js list를 실행해서 그 출력을 가져옵니다. 복사·붙여넣기 없이, AI가 내 앱을 직접 돌려 데이터를 읽는 거죠.

🎯 핵심은 소스 코드가 아니라 '실제 할 일 데이터'를 보는 것입니다
  • 소단원 ①의 루프가 여기서 눈에 보입니다 — 계획(어떤 명령?) → 실행 → 관찰(출력) → 답
학습자가 "AI가 내 컴퓨터에서 내 앱을 돌렸다"는 감각을 처음 갖는 순간입니다.

여기서 권한을 관찰하세요

1명령을 실행하기 직전, 도구가 "이 명령을 실행해도 될까요?"를 묻는다 — list·summary처럼 읽기만 하는 건 승인
2한 번은 일부러 위험한 걸 시켜 본다 — "todo.db 파일을 지워 줘." 승인창이 뜨면 거부하고, 규칙 파일의 '하지 말 것'과 연결해 '내가 문지기'라는 감을 익힌다
3뭔가 시키기 전에 git commit으로 되돌릴 지점을 먼저 만든다 — 잘못돼도 그 지점으로 되돌아갈 수 있다
💡 왜 CLI로 할까요? 소단원 ⑤의 '요즘 흐름' 그대로 — AI는 node·git 같은 명령을 이미 알고 있어서, 무거운 연결을 새로 세우지 않고 있는 명령을 그냥 부르는 게 가볍고 빠릅니다
소단원 ④의 '승인 93%' 이야기가 여기서 실습이 됩니다. 거부해 보는 경험이 이 실습의 숨은 목표입니다.

3단계 — 반복 작업을 스킬로 외워 두기

Claude Code 기준

⑥ 실습
Cursor 등 다른 도구는 스킬 위치가 다르니 개념만 봐도 됩니다.

매번 똑같이 시키는 일을 한 번 적어

"오늘 완료한 것만 뽑아 커밋 메시지 형식으로 정리해 줘" 같은 일이죠. 앱 폴더의 .claude/skills/todo-summary/SKILL.md에 이렇게 적습니다.

---
name: todo-summary
description: 오늘 완료한 할 일을 커밋 메시지 형식으로 요약할 때 사용
---

# 오늘 완료 요약

`node todo.js summary`를 실행하고, 그 출력을 그대로 보여준다.
🎯 핵심 — 스킬이 직접 데이터를 뒤지는 게 아니라, 앞서 만든 CLI를 대신 불러 준다는 것
Claude Code는 이 경로의 스킬을 자동으로 찾습니다. 스킬 폴더를 처음 만들었다면 도구를 한 번 재시작해야 인식됩니다.

그리고 다른 대화에서 한마디

내가"요약 스킬 써서
오늘 한 일 정리해 줘"
→
AI가스킬을 꺼낸다
→
실행todo summary
→ 결과 정리
  • 소단원 ③에서 배운 점진 공개가 실제로 동작하는 순간입니다 — 평소엔 description 한 줄만 알고 있다가, 지금 일이 맞을 때 본문을 펼칩니다
🧱 층이 쌓인 걸 보세요 — 규칙 파일(사용법) → CLI(실행) → 스킬(반복 자동화)
이 세 층이 오늘 강의의 MCP·스킬·규칙 중 두 개를 실제로 구현한 것입니다.

덤 — 같은 걸 MCP로 붙이면?

시간 남으면

⑥ 실습
비교해 보면 소단원 ⑤의 판단이 몸으로 이해됩니다.

파일시스템 MCP를 등록해 보기

{
  "mcpServers": {
    "todo-files": {
      "command": "npx",
      "args": ["-y","@modelcontextprotocol/server-filesystem","/내-Todo앱-경로"]
    }
  }
}
  • 붙여 두면 "우리 앱 소스에서 할 일을 어떻게 저장하는지 설명해 줘" 같은 걸 시켜 볼 수 있습니다
  • 다만 차이가 느껴질 거예요 — 이 서버는 파일(소스)을 읽는 데는 좋지만, 데이터가 담긴 todo.db는 이진 파일이라 내용까지 세어 주진 못합니다
  • 방금 CLI로 한 "오늘 완료 몇 건" 같은 건 결국 앱의 명령(todo summary)을 돌려야 나옵니다
🧭 그래서 오늘 배운 판단이 그대로 쓰입니다 — 혼자 작은 앱이면 CLI + 스킬이 가볍고, 여럿이 쓰고 권한·기록을 챙겨야 하면 MCP. 도구가 아니라 상황이 고릅니다
실패처럼 보이는 이 체험이 실은 가장 값진 학습입니다 — 도구마다 잘하는 일이 다르다는 것.

정리 — 오늘의 결과물

☐앱에 CLI(list·summary 등) + 규칙 파일(AGENTS.md, Claude Code면 CLAUDE.md)에 사용법
☐AI가 그 CLI를 직접 실행해 내 할 일 데이터를 읽음 (권한 승인창을 한 번은 거부, 위험 작업 전 git commit)
☐SKILL.md 1개(Claude Code 기준) — 다른 대화에서 한마디로 발동, 스킬이 CLI를 대신 호출
☐(덤) 같은 걸 MCP로도 붙여 보고 CLI와 비교
❓ 마지막 확인 — 범용 AI가 내 Todo 앱을 아는 조수로 바뀐 지점은 어디였나요? (규칙 파일? CLI 실행? 스킬?) 그 감각이 오늘의 핵심입니다
정답은 사람마다 다릅니다. 대개 "AI가 스스로 todo list를 실행했을 때"라고 답합니다 — 그 순간이 '말하는 AI'와 '움직이는 AI'의 경계입니다.

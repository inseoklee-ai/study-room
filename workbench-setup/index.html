🤖 왜 채팅 AI가 아니라 Claude Code인가

일반 챗봇

질문에 답하고 코드를 보여줄 뿐. 글 파일로 끝나면 서비스가 아니다

Claude Code

자연어로 지시하면 직접 파일을 만들고 고치고 명령을 실행. 그 파일이 내 컴퓨터에서 도는지 확인할 수 있다

'말하면 손이 움직이는' 협업이런 도구를 에이전틱 코딩 도구라고 부른다 — 그 과정이 눈에 보여야 배움이 남는다
웹서비스를 만들려면 답이 아니라 실제 파일이 필요하고, 그 파일이 도는지 확인해야 한다. 이 루프를 여는 것이 바이브 코딩의 핵심 역량.
바이브 코딩에서 중요한 일은 백지에서 코드를 손으로 다 쓰는 게 아니라, 자연어로 말하고 AI가 만든 파일을 읽고 위험한 부분을 찾아 다시 지시하는 루프를 돌리는 것입니다.

🖥️ Claude Code는 두 모습으로

Claude Desktop 안 (그래픽)

마우스로 조작. 변경내역(diff)을 시각적으로, 앱 미리보기까지 — 초심자가 검토하기 부담 적음. 여러 세션 병렬도

터미널의 claude (글자)

시작이 즉각적, 파일 시스템 전체 접근, 스크립트 자동화·Agent SDK. 공식 문서가 "가장 완전한 형태의 인터페이스"라 소개

둘은 같은 엔진을 쓰는 같은 도구. 초심자라면 Desktop으로 시작하고, 자동화 같은 고급 흐름이 필요하면 터미널로 넘어가면 된다(스크립팅·Agent SDK는 터미널에서만).
중요한 건 도구가 아니라 그 아래에서 자연어로 지시하고 결과를 판단하는 루프를 여는 것입니다. 이 과정의 예시는 두 모습 모두에서 따라갈 수 있습니다.

Git은 파일을 실제로 바꾸기 시작할 때 다시 다룹니다.

① Node.js — 자바스크립트를 브라우저 밖으로

  • 2009년 라이언 달이 브라우저 안에서 버튼을 움직이던 자바스크립트를 내 컴퓨터·서버에서도 실행할 수 있는 런타임으로 만들었다(Chrome의 빠른 엔진 V8 기반). 새 언어가 아니라 런타임
  • 한 언어로 화면 쪽·서버 쪽을 모두 다루는 길이 넓어졌고, React·Next.js 생태계도 Node.js 위에서 돈다
왜 알아야 하나 — AI가 만든 웹 코드는 글 파일로 끝나면 서비스가 아니다. 내 컴퓨터에서, 나중엔 서버에서 실행돼야 한다. npm run dev를 눌렀을 때 뒤에서 일하는 주인공이 Node.js.

🍽️ 논블로킹 I/O — 주문을 주방에 넘기고 준비되면 알려 달라 한 뒤 다른 손님을 돕는 직원. 파일 읽기·네트워크처럼 기다리는 시간이 긴 일에 강점. "무조건 빠르다"는 아니다(큰 계산은 별도 전략)

브라우저 전용이던 JS(1995 Netscape, Brendan Eich)가 2009 Node.js로 컴퓨터·서버로, 오늘 Next.js 개발 서버의 기반이 됐습니다. 표준 이름은 ECMAScript, ES6(2015)가 let·const·화살표 함수 등 현대 문법의 전환점. JavaScript는 Java의 가벼운 버전이 아니라 별개 언어입니다.

② npm — 혼자 처음부터 만들지 않게

  • 웹사이트·CLI·패키지 레지스트리로 이루어진 JS 패키지 생태계. React·Next.js처럼 누군가 공개한 기능을 찾아 설치하고 버전을 관리 — "세계에서 가장 큰 소프트웨어 레지스트리"
  • 바이브 코딩의 핵심은 매번 바퀴를 새로 만드는 게 아니라 필요한 기능을 검토해서 조립하는 것 — npm은 레고 창고, AI는 조립 파트너, 나는 "이 블록을 써도 되는가?"를 판단
⚠️ 공개 창고의 모든 블록이 안전한 건 아니다 — AI가 추천한 패키지도 이름·용도·다운로드 명령을 한 번 확인. 외부 패키지는 공짜 코드가 아니라 업데이트·보안이 필요한 공급망(2016 left-pad 삭제로 많은 빌드가 멈춘 일).
package.json은 어떤 블록을 쓰는지 적은 프로젝트의 부품 목록, 의존성은 내 앱이 작동하려고 기대는 외부 부품. package.json과 잠금 파일은 그 판단의 흔적입니다.

③ uv — 파이썬 AI 도구를 빠르게 준비

  • Ruff를 만든 Astral이 Rust로 만든 파이썬 패키지·프로젝트 관리자. 기존 pip 흐름과 호환되며 pip보다 10~100배 빠를 수 있다. 패키지뿐 아니라 파이썬 버전·의존성·실행 도구도 관리
  • 왜 지금 설치하나 — 뒤 모듈에서 MCP 서버나 파이썬 기반 AI 도구를 실행할 때 필요한 재료. 미리 갖춰 두면 AI가 "이 도구를 실행해 보자"고 할 때 설치부터 헤매지 않는다
가상환경 — 프로젝트마다 필요한 파이썬·패키지를 따로 담아 서로 버전이 충돌하지 않게 하는 작은 독립 작업실.
Claude Code는 파이썬 패키지가 아니므로 uv로 설치하지 않습니다. uv는 파이썬 프로젝트·도구 관리용입니다.

④ 터미널 — AI와 함께 일하는 작업창

  • 마우스로 아이콘을 누르는 대신 글자로 명령을 내리는 창. 검은 화면이 낯설어도 외울 명령이 많은 비밀 도구가 아니다 — Claude Code에 요청을 넣고, npm·uv·git 명령을 실행하고, AI가 남긴 로그·오류를 읽는 자리
  • 왜 GUI 대신 — 같은 명령을 복사·붙여넣기, 여러 단계를 스크립트로 자동화, AI가 무엇을 했는지 로그로 직접 확인

macOS

⌘ Space → Terminal 검색

Windows

시작 메뉴 → PowerShell 또는 Windows Terminal

처음 열었을 때는 아무것도 안 망가진다 — 명령을 실행하기 전엔 그냥 빈 작업창. 이해 안 되는 명령은 붙여넣기 전에 "이 명령이 무엇을 바꾸나요?"라고 AI에게 먼저.
터미널은 AI에게 일을 맡긴 뒤 "무슨 일이 일어났지?"를 함께 보는 대화창입니다. 한 줄씩 실행하고 결과를 읽으면 됩니다.

✅ 정답 & 해설

A1. 챗봇은 코드를 보여줄 뿐, Claude Code는 자연어 지시로 직접 파일을 만들고 고치고 명령을 실행한다 — 답이 아니라 실제 파일이 나와야 서비스가 된다.
A2. Claude Desktop 안(그래픽)과 터미널의 claude(글자), 같은 엔진. 초심자는 Desktop으로 시작하고 자동화가 필요하면 터미널로.
A3. JS를 브라우저 밖(내 컴퓨터·서버)에서 실행하게 하는 런타임(V8 기반). 새 언어가 아니라 실행 환경 — npm run dev의 주인공.
A4. 외부 패키지는 공짜 코드가 아니라 업데이트·보안·유지가 필요한 공급망 — left-pad 삭제로 많은 빌드가 멈췄듯, AI 추천도 이름·용도·문서를 확인해야.
A5. 명령을 복사·붙여넣기하고 스크립트로 자동화하며 AI가 무엇을 했는지 로그로 직접 확인할 수 있어서.
